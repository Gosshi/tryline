# Touchline PR 5-2: カレンダー

基点: `origin/main` の `a3cb836a`（#913 マージ後）。仕様: `specs/feat-touchline-redesign-web.md` の PR 5 と「守ること」1〜9。週ボードの構造は D020〜D023 / `specs/feat-calendar-week-board.md` を維持。仕様書・指示書は基点のまま参照し、改訂していない。

今回の対象は `/calendar` のみ。マージ後は仕様の順に順位表ページから続ける。

## 変更と判断

- h1 と週移動を、低い墨色の帯にまとめた。既存の A4 の斜線・細い線の装飾と真鍮の罫線を使用。写真・生成画像・新しいアニメーションは追加しない。
- 大会へのリンクは帯の直下で下線のタブにした。表示条件・行き先・計測値は同じ。
- 週ボードの日付は Outfit の大きな数字、時刻は墨色の小さい札、試合は紙色の面と罫線にした。略称を主・正式名を従にする2段構成は維持。大会の3pxバーと凡例も維持。
- 注目試合は淡い赤の斜めの面。注目試合の選択ロジックは変更しない。 hover の細線は既存の `getTeamColor` の値を使う。大会／チーム色を背景にした本文は作らず、文字は紙色または墨色の面に載せる。
- デスクトップには会場と TeamBadge を出さない。モバイルには従来の会場とバッジを残し、日付とカードの装飾のみ揃える。長い正式名は必要に応じて折り返し、省略で切らない。
- スコア・状態・P/R の札・視聴リンクの条件は維持。終了スコアは従来どおり、サーバー側で取得したネタバレ防止設定を `SpoilerScore` に渡す。数え上げは追加しない。
- 新しく整えた操作は44px以上を目安にし、既存のフォーカスとスコア開示のクリック・Enter・Spaceを維持。
- 日付／時刻のグループ化、1日だけの幅計算、複数日のグリッド式、空の日の扱いは変更していない。1日だけの入力で全面に引き伸ばす実装や fit-content は追加しない。
- 下部の説明・iCal購読・NewsletterSignup・IosAppCta は同じ中身と条件で、試合の後ろに維持。

## 幅の確認

極端な入力は公開日程から抽出して実装部品に渡した。**実際の全日程ではない**ことを画像内の注記で明示した。

| 入力 | 1440pxでの結果 | 画像 |
|---|---|---|
| 1開催日・1試合 | 日カード288px、最初の試合 y=518 | [1試合](one-1440.jpg) |
| 1開催日・5試合 | 日カード1088px（既存式の min(100%, 5×288+4×20)）、内側は既存の auto-fill | [複数試合](single-multiple-1440.jpg) |
| 7開催日・各1試合 | 257px×4列＋3列、最初の試合 y=518。最終段も900px内 | [7開催日](seven-1440.jpg) |

7開催日の画像は9月28日〜10月11日の**複数週の実日程から、異なるJST日付の試合を抽出**した構造試験。実際に7日すべてで試合がある1週間を確認したものではない。日付を架空の日程に書き換えていない。連続した7日を同一週に流すケースはコンポーネントテストの試験用 fixture でも確認した。

通常の21試合入力は、1440pxで最初の試合 y=523（公開画面）→473（変更後ローカルSSR）。390pxは y=524。変更後の通常入力・幅試験・ネタバレ防止入力に横はみ出しなし（documentElement.scrollWidth=viewport幅）。
