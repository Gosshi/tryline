# Tryline — Web / iOS デザイン提案

おすすめは **C「MATCH DESK」**。大会・試合に直接来る読者が、最初の画面で日程・順位・スコアにたどり着ける構成を優先します。ブランド刷新は青、端正な数字、細い罫線で十分に表現し、シネマティックな質感はトップの動画枠に集めます。

## モックを開く

大会は「第5節・日程」「第4節・結果」を切り替えられます。アプリ試合は初期状態でスコア非表示。「スコアを表示」で40–18が現れ、「試合データ」で得点推移と経過を確認できます。隠し直すと得点推移・得点経過も隠れます。アプリ画面外の文字サイズで100／135／200%を比較できます。iPhone枠は外寸430×932 CSS px。狭いブラウザでは枠全体を比例縮小し、中のコンテンツは独立してスクロールします。

動画は配置枠と静止ポスターのみです。再生、ログイン、課金、AI送信、アプリ設定などは実装していません。ストーリーズ入口は今回の対象であるアプリ試合画面へ移動します。Webのカレンダーボタンはトップ内の日程へ移動します。対象外の画面が完成したように見せるリンクは設けていません。

## A — THE TOUCHLINE

**狙い：週末の海外ラグビーをじっくり読むファンに、保存したくなる専門誌のような落ち着きと信頼感を。**

## B — FLOODLIGHT

トップは正方形に近い大きな映像キャンバス。動画本体は実画面を切らず、余白を背景で処理します。大会・試合ページに大きな映像は置かず、細い発光色の線とスコア帯だけで雰囲気を引き継ぎます。長文背景にはビジュアルや光を重ねず、単色にします。

## 共通の実装方針

### 動画・性能

- 紹介動画は15〜30秒、音なし、ループ。再生・停止操作を設け、画面外で止める。実画面内の文字を読み取れる解像度とし、切り抜かない。
- 動画枠は初回から寸法を確保。静止ポスターを先に表示し、動画の取得・デコードを主要な文章や試合データの表示より後にする。
- スマホとReduce Motionでは静止ポスターを既定にし、必要な人が明示的に再生する設計を提案。
- 3案とも連番画像・WebGL・重いスクロールライブラリを不要にする。背景はCSS、装飾はトップだけ。スクロールを奪わない。
- Webフォントを追加しない構成をまず試す。追加時には日本語フルセットの初期取得を避け、代替書体との高さの差も検証する。
- **LCP < 2.5秒、CLS < 0.1は目標であって達成済みではありません。** 本番と同等のデータ、動画、フォント、キャッシュ条件で計測する必要があります。静的HTMLの表示速度を本番の証拠にはしません。

### iOS

下部の「今週／大会／設定」はアイコンとラベルを維持し、各タブの遷移状態を保つ。戻る操作・スワイプバック・Safe AreaはExpo側のネイティブナビゲーションに任せる方針です。モックの戻るボタンはホームへの移動を近似しています。タブはトップレベルのナビゲーションとして扱い、画面内の操作ボタンを混ぜません。[Apple: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars?changes=la_11)

本文は17ptを基準にDynamic Typeへ追従させます。大文字時にはチーム名・スコア・操作を縦に並べ、行の高さを伸ばします。操作領域は44pt以上を設計目標にします。HTMLの200%表示はレイアウト検討であり、OSのアクセシビリティ適合を証明しません。[Apple: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility?changes=latest_maj_6_3&language=objc)

色やブランド見出しは共有し、本文・小さいラベルはシステム書体を優先する方針です。[Apple: Branding](https://developer.apple.com/design/human-interface-guidelines/branding)

結果非表示はスコアだけでなく、勝敗色、グラフ、経過、レビュー見出し、ストーリーの表紙、VoiceOverのラベルにも適用する必要があります。今回のモックはスコア・グラフ・可視イベントを同時に隠すところまで実装しました。実データやアプリ全体を通した漏れの検証はこれからです。
