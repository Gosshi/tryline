## 1. まず直視すべき事実

2026-08-09 の本番 DB 実測。

| 項目 | 実測値 |
|---|---:|
| 公開済みコンテンツ（`match_content` status=published） | **934本** |
| 登録試合（`matches`） | 1,115 |
| 大会数 | 32 |
| 登録ユーザー（`auth.users`） | **3** |
| 課金関連テーブル | **存在しない**（`push_subscriptions` のみ） |

**供給は潤沢で、需要がほぼゼロ。** 934本の記事を作る能力は既にあり、それを読む人がいない。

したがって本ロードマップの中心的な問いは「何を作るか」ではなく「**なぜ誰も来ないのか、どうすれば来るのか**」である。コンテンツ生産能力の増強を提案する前に、この点に答えること。

### 収益の算術も最初に置くこと

目標は Premium ¥980/月。**何人集めれば意味のある金額になるのか**を最初に計算し、そこから逆算した必要トラフィックと転換率をロードマップの前提に置くこと。

現在のインフラコスト（Supabase Pro $34.81/月、Vercel、OpenAI API）も踏まえ、**損益分岐に必要な購読者数**を明示する。この数字が出ていない提案は受け入れられない。

## 3. 既に試したこと・判明していること

**再提案しないこと。** 以下は検証済みまたは意図的に見送った。

### SEO

- index bloat（無意味な選手ページ）を noindex 化。2026-08-02 実測で **CTR 0.3% → 1.32%** に改善。インプレッションは70%減ったが、これは設計どおり
- **海外チーム名・大会名が英語のまま**（78/90 チーム）で、日本語クエリでの流入がほぼゼロ。カタカナ命名が被リンクより優先度が高いと判断済み
- GSC データは 2026-05 以降しかなく、**ピークシーズンを一度も経験していない**。8月の閑散期の数字で悲観しないこと

### 被リンク

- **日本語で海外ラグビーを継続的に扱う個人媒体はほぼ存在しない**。探索は凍結済み
- 休眠アカウントを最有力候補として提案する事故があった。**最終更新日を必ず確認すること**

### X（@tryline_rugbyjp）

- 2026-06 時点でフォロワー2人、投稿174件。reply-first に転換
- インプレッション**中央値17**、4週間目標50（2026-08-08 の投稿で60を達成）
- ハッシュタグのクリックは42投稿で**全件0**
- **自分の投稿への返信が他アカウントから見えない**（2026-08-09 Owner 確認）。URL を1st replyに置く運用は機能しない
- 自動投稿は停止済み。復活させない

### note

- 3タイプ制（A=試合翌日深掘り / B=テーマ型週次 / C=月1エバーグリーン）
- referral は 8セッション/28日が基準、目標15
- 告知漏れで閲覧1件に終わった事故あり

### その他

- **英語ニッチ**（Reddit / Medium）に着手。日本語での検証完了を待たずに例外的に開始
- **iOS アプリ**は App Store 審査で Guideline 3.1.1（IAP）により却下。RevenueCat での実装を決定、未着手
- **診断クイズ**の提案を 2026-08-07 に検討。実データと照合した結果、優先度は低いと判断
- **放送情報**は日本代表戦以外ほぼ空。自動取得は日本代表戦のみ実装済み

## 4. 制約

- **Claude Code は実装しない。** spec と `docs/codex-prompts/` の指示書を作り、Codex が実装する
- Owner は**個人開発者**。X 運用は10分/日、note は週75分が上限
- 期限は **RWC 2027（2027年10〜11月）**。それまでに有料購読者を積む
- 直近の集中対象は **2026年11月の日本代表欧州遠征**（Nations Championship、ウェールズ/イングランド/スコットランド戦）
- LLM コストは Owner 承認なしに増やさない
- スクレイピングは robots.txt と規約を厳守。**大手メディアほど規約が厳しい**（2026-08-07 監査で rugbypass / skysports / bbc / espn 等を除外済み）

## 5. 調査に使えるもの

- **本番 DB**: Supabase MCP で読み取り専用クエリ（`prod-investigation` スキルの作法に従う）
- **GA4**: `mcp__analytics__*` ツール
- **GSC**: `tools/gsc-pull.ts` で Search Analytics と URL Inspection を取得
- **Web 調査**: WebSearch / WebFetch。競合サービスや事例の調査に使う

---

## 6. 成果物に求めるもの

- **数字から出発すること。** 「認知を高める」「SNSを強化する」のような施策名だけの提案は不可
- **損益分岐点の試算**を含めること
- 施策ごとに「**何が起きたら成功か / 失敗と判断して撤退するか**」の基準を書くこと
- 期間を区切ること（例: 〜11月遠征 / 〜2027年前半 / RWC 直前）
- **Owner の時間予算（X 10分/日・note 週75分）に収まること**。収まらない提案は、何を捨てるかも書く
- 既存の意思決定と矛盾する提案をする場合は、**なぜ覆すべきかを明示**すること

## 7. 避けてほしいこと

- 出典のない市場規模やベンチマークの引用
- 934本という既存資産を無視した「まずコンテンツを増やす」提案
