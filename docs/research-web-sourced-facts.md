# 調査メモ: Web検索で信頼ソースから事実を取得しコンテンツを厚くする

> 作成: 2026-06-06 / Track B（プロダクト/アーキ調査）。実装前の意思決定材料。
> 背景: ja プレビューが「捏造なしだが浅い」（#375 で捏造は封じたが、入力データの薄さが深さの天井）。Web検索で**信頼ソースから事実を取得→言い換えて利用**（生再配信禁止＝不変条件）で深さの天井を上げられるか。
> 関連: `specs/fix-factual-grounding-over-length.md`(#375)／`specs/feat-lineup-aware-previews.md`／`p1-content-pipeline.md`（4段パイプライン）／Reddit は Responsible Builder Policy 待ち(D009)。

## 結論（先に）
方向性は **GO 可**。コスト軽微・AI開放の信頼ソースあり・「事実は自由利用＋言い換え」で著作権クリア。**真の論点はガバナンス（allowlist・引用enforcement・鮮度）と、抽出モデルの精度**。素朴に「書きながら web検索」は #375 と衝突するため不可 → **web検索は“事実抽出ステージ”として追加し、出典付き sourced_facts を #375 の grounding に統合**する設計が前提。

## ① コスト（事実上ノンイシュー）
- web_search 価格: **$10 / 1,000回 ＋ 1検索あたり約8,000入力トークン課金**（検索結果トークン）。
- 1検索の実コスト ≈ $0.012（gpt-4o-mini）〜$0.035（gpt-4o）。
- 1試合（1〜2検索・**試合単位キャッシュ**）＝ $0.02〜0.07。月（~120試合）＝ **$3〜18**。
- **呼出料 $0.01/検索が安モデルでは支配的**＝モデル間トークン差は小さい。

## ② 取得サイト選定（robots 実地調査 2026-06-06）

- 副次効果: **OpenAI web_search は OAI クローラ拒否サイト（ESPN等）を結果に返さない**＝弾くべきソースは自動的に入らない。
- allowlist 初版方針: **各リーグ/クラブ公式 ＋ RugbyPass** から開始。第三者メディアは ToS 確認の上で順次。
- 注意: robots＝クロール許可 ≠ 再利用許可。再利用は引用ポリシー(③)で担保。

## ③ 引用ポリシー（著作権）
- **事実と表現を分ける**: スコア・けが・出場・移籍等の**事実は著作物でない＝自由利用可**。守るのは表現（文章）。
- 原則: **事実を抽出 → 自前の日本語で記述**。原文の文・構成をなぞらない。
- 直接引用: **≤15語・出典明示・主従明確（著作権法§32）**。引用は「言葉自体が要点」（監督コメント等）の時だけ。
- **同一ソースから複数引用しない／非自明な事実は2ソース以上で裏取り**。
- **出典URLを内部保存**（監査・信頼性）。任意で「情報源」表示。
- 鮮度/憶測: 検索時点の事実のみ・「欠場確実/微妙」を区別・**公式確認を優先**。

## 次の一手: 4系で小規模 eval（Owner方針）
- **比較対象（4系・同一Responses経路）**: `gpt-4.1` / `gpt-4.1-mini` / `gpt-4o`。
  - 根拠: Responses API の web_search ツールは gpt-4.1/gpt-4o（+5系）で利用可。**gpt-4o-mini は search-preview（Chat Completions専用）＝別経路のため今回除外**（比較条件を揃える）。5.x・o系も見送り。
  - 実質の問い: 安い `gpt-4.1-mini` が `gpt-4.1` と同等に“捏造しない”か。同等なら mini、劣るなら 4.1。gpt-4o は現行参照。
- **手順**: 注目試合3〜5件で「web_search → 事実抽出（出典付き）」を各モデルで実行 → **人手で忠実性照合**（捏造ゼロ・出典一致・拾い漏れ）。コスト差が小さい以上、**“最も捏造しない”モデルを選ぶ**。
- **評価軸**: ①捏造ゼロ（最優先）②出典一致 ③有用事実の網羅 ④日本語化の素直さ。

## eval 結果・モデル決定（2026-06-06）

決勝（神戸×クボタ）1試合 × {gpt-4.1, gpt-4.1-mini, gpt-4o} を web_search で実行・人手照合。

- **全モデルでスコア捏造ゼロ**。H2H（神戸28-33クボタ R1 12/13／クボタ19-24神戸 5/10）は**DB照合で両方とも実在**＝以前の「リコー戦52-8」級の捏造は web 導入で消滅。むしろ DB に無かった R1 結果まで取得。
- **gpt-4o = 最良**：勝敗を分ける **Marx欠場（HT交代・決勝間に合わず）を唯一捕捉**＋Tyler Paul 負傷・カード5枚・レニー物語など **DBに無い深さ**。戦術は「出典なし＝書かない」と正直、不確実は medium で hedge。
- gpt-4.1：捏造なし・正直だが**浅い**（Marx見落とし＝肝を外す）。
- gpt-4.1-mini：SFスコアは◎だが **sportytrader（賭けサイト）混入**＋一般論戦術＝ガバナンス的に危険。

### 決定
- **抽出モデル = `gpt-4o`**（＝既存 narrative モデル。新規モデル不要）。※1試合1回の判定なので運用で再現性監視（recency=Marx捕捉が毎回効くか）。

### 最大の収穫
web検索が **(1) 捏造を消し (2) 本物の深さを足す**＝「浅い」を解くアプローチとして実証。出典付き sourced_facts を #375 grounding に統合する設計で進める。

### build spec に必須のガバナンス要件（eval で露呈）
1. **ソース allowlist を hard 制約に**：mini が「prefer」を無視し賭けサイトを引いた→**取得後に allowlist 外ソースを破棄する後段フィルタ**が必須（プロンプトの“優先”だけでは不十分）。
2. **2ソース裏取り＋公式優先**：色物事実（リモートTMO初/観客56,486/Retallick18トライ等）は外れ得る→非自明な事実は2ソース or 公式に限定。
3. **鮮度**：けが/欠場を確実に拾うため検索に recency 指示。
4. 抽出出力は**出典付き sourced_facts**＝#375 grounding に統合（捏造ガード維持）。
