## 0. note の役割（なぜやるか）

- **発見面の借用**: note内検索・おすすめフィード・ハッシュタグ・公式ピックという、フォロワーゼロでも新規読者に届きうる面を借りる。note の推薦は独自性・1記事1テーマ・一次情報を重視するため、「Tryline のデータから一つの問いを検証する記事」と相性が良い
- **SEO**: note 記事自体が検索に乗る（ドメインが強い）
- **送客**: 唯一 referral が計測できているチャネル（2026-07 時点 8セッション/28日 > X の3）。UTM で計測を徹底する
- **役割分担**: X は「今の出来事」を広げ、note は検索・推薦に残る記事を蓄積する。全試合の記録は Tryline 本体（カレンダー・recap）が担当し、note は「問い・背景・書き手の見方」を担当する

## 1. 絶対ルール（重複コンテンツ・捏造回避）

- **recap 全文を note に転載しない**。note は要約＋送客のみ（Google の重複判定で両方沈む）
- **数値は Tryline DB で確認できるもののみ**（スコア・得点経過・順位）。外部公式スタッツは sourced_facts 取り込み済みのもの以外使わない
- 直接引用は最小限・言い換え原則（著作権配慮）
- 「全データ分析」等と書きながら対象・方法・定義を示さない表現をしない

## 3. 送客導線（全記事・CTA 2段構成）

1. **主CTA 1本**: 記事内容に直接一致するページ（記事と無関係な過去試合を主CTAにしない）
2. **フッター固定**: カレンダーページ「今週の全試合日程（日本時間）は Tryline のカレンダーで」

**Tryline ドメインへの全リンク**に `utm_source=note&utm_medium=referral`（付与率100%。既にクエリがある URL には `&` で連結）。外部サイトへの出典リンクには付けない。

## 4. X 連動（note 公開のたびに実施）

単独の URL 告知投稿はしない。**タイプ別の親投稿**（A=試合直後の強い1本 / B=週末ガイド・結果分析の親投稿 / C=記事の最も強い結論を URL なしで先に親投稿）への**返信**で「記事で新たに分かったこと＋URL」→ 6〜12時間後に条件付き引用RT → 翌日に選択式質問投稿。親投稿の下書きは `x-post`、URL 返信は `x-reply` の責務。手順とチェックリストは `note-weekly` スキルの「X 連動」節が正。

## 6. 計測

- **開始前ベースライン（Owner、第1週開始前に1回）**: 直近5記事の7日/累計ビュー・スキ・コメント・note経由セッション・公開時刻・記事タイプを note 管理画面から記録
- **記録タイミング（測定時点と判定時点を一致させる）**: 全記事=公開24時間後・72時間後（X 表示・URLクリック・note ビュー・referral）/ A・B=7日後ビューを追加 / C=7日後＋30日後を追加
- **4週間の判定基準（相対値。予測値ではない）**: A=直近5記事の7日ビュー中央値の1.5倍 / B=直近5本の B の7日ビュー中央値以上（5本未満は全記事の7日中央値で代用。2本連続で下回ったら頻度を下げる）/ C=直近5本の C の30日ビュー中央値の2倍（5本未満の間は全記事の30日中央値で代用）or UTM referral 3件以上 / 全体=note referral 8→15セッション/28日
