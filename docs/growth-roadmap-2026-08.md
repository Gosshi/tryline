# Tryline 収益化方針と RWC 2027 までのグロースロードマップ

作成日: 2026-08-09

対象期間: 2026-08-09〜2027-11-13

目的: RWC 2027 までに、コンテンツ供給ではなく需要獲得と有料転換を成立させる

## 0. 結論 — 最初に見るべき数字

Tryline の月額 Premium は ¥980。Web 決済の手取りを約 ¥938/人・月と置くと、**現在の固定費を回収する損益分岐は有料購読者 12〜15人**である。費用変動と小さな超過を吸収するため、経営上の損益分岐目標は **18人**とする。

ただし、18人はサービス費用を払えるだけで、Owner の労務対価は含まない。月約10万円の貢献利益を残すには **約120人**が必要である。したがって本ロードマップの北極星は次の3段階とする。

| 段階 | 有料購読者 | 月間売上総額 | 固定費控除後の概算貢献利益 | 期限 |
|---|---:|---:|---:|---|
| 生存 | **18人** | ¥17,640 | 約 ¥3,000〜¥7,000 | 2027-03-31 |
| 事業性の兆し | **50人** | ¥49,000 | 約 ¥33,000〜¥36,000 | 2027-08-31 |
| RWC 目標 | **120人** | ¥117,600 | 約 ¥99,000〜¥102,000 | 2027-11-13 |

この目標は市場規模の予測ではなく、**意味のある金額から逆算した経営目標**である。現状は公開済みコンテンツ934本に対し登録ユーザー3人であり、商品供給ではなく需要が欠けている。RWC までの優先順位は一貫して「配布 → 登録 → 再訪 → トライアル → 継続課金」であり、記事本数の増加ではない。

## 1. 損益分岐の算術

### 1.1 前提

| 項目 | 前提 | 根拠・扱い |
|---|---:|---|
| Web 月額 | ¥980 | D005・現行料金ページ |
| Stripe Payments | 3.6% | 国内カードの標準料率 |
| Stripe Billing | 0.7% | 現行の継続課金を保守的に含める |
| Web 手取り | **¥937.86/人・月** | `980 × (1 - 0.036 - 0.007)` |
| 為替 | ¥150/$ | 予算計算用の丸めた仮定。実請求額で毎月更新する |
| Supabase | $34.81/月 = 約¥5,222 | 2026-08-09 の実請求値 |
| Vercel | $20/月 = 約¥3,000 | 商用運用として Pro を予算化。実請求が0なら下振れする |
| OpenAI API | $10〜30/月 = 約¥1,500〜4,500 | 実請求未取得のため幅で置く。新規の未承認呼び出しは増やさない |
| Apple Developer Program | $99/年 = 約¥1,238/月 | iOS を正式プロダクトラインとして月割り |
| RevenueCat | ¥0 | 月間追跡売上 $2,500 までは無料。初期の損益分岐には影響しない |

Stripe は国内カード決済3.6%、Billing は取引額の0.7%を公表している。RevenueCat は月間追跡売上 $2,500 まで無料、その後1%である。出典は末尾にまとめる。

### 1.2 固定費と損益分岐

予算上の月間固定費は次の範囲になる。

```text
低位: 5,222 + 3,000 + 1,500 + 1,238 = ¥10,960/月
高位: 5,222 + 3,000 + 4,500 + 1,238 = ¥13,960/月
```

Web 購読者だけで賄う場合は次のとおり。

```text
低位: ceil(10,960 / 937.86) = 12人
高位: ceil(13,960 / 937.86) = 15人
20%安全余裕込み: 15〜18人
```

よって、本文では **18人を「管理上の損益分岐」**として使う。

これは現金費用だけの試算で、Owner の労務、税、会計、ドメイン、メール、返金、チャージバックは含まない。毎月、実請求の3か月移動平均で更新する。

### 1.3 iOS 価格

Apple Small Business Program の手数料を保守的に15%とすると、iOS を Web と同じ ¥980 にした場合の手取りは約¥833で、Web より約¥105低い。**iOS は ¥1,100/月を推奨**する。このとき手取りは約¥935で、Web の約¥938とほぼ同じになる。

アプリ内では外部決済へ誘導せず、RevenueCat が返す現地価格を表示する。Web 契約者は既存 entitlement を使い、二重購入させない。価格差の最終決定は App Store Connect 設定時の Owner 判断とする。

### 1.4 低価格化をしない理由

現在は価格感度を判断できるだけの訪問者もトライアルもいない。¥980を¥500に下げても、需要ゼロは解決しない一方、損益分岐は約18人から約35〜40人へ悪化する。少なくとも **30件の完了トライアル**が溜まるまでは、月額を変更しない。

年間プランは、10人以上の実課金または30件以上の完了トライアルが得られた後に限り、**¥9,800/年（2か月分割引）**を第一候補として検証する。現時点では実装しない。

## 2. まず直視すべき事実

### 2.1 供給過多、需要不足

2026-08-09 の本番 DB 実測は次のとおり。

| 項目 | 実測 |
|---|---:|
| 公開済み `match_content` | **934本** |
| 登録試合 | 1,115 |
| 公開コンテンツ / 登録試合 | **83.8%** |
| 大会数 | 32 |
| 登録ユーザー | **3人** |
| 実顧客の有料購読者 | **0人** |
| 独立した課金台帳テーブル | なし |

934本を作れることは検証済みで、934本を読みたい人を集められることは未検証である。新しい大会、新しい記事形式、記事生成頻度の増加は、需要側の数字が動くまで原則として優先しない。

### 2.2 現在わかっている流入

| 指標 | 最新の利用可能な実測 | 読み方 |
|---|---:|---|
| GA4 セッション | 130/28日（2026-07-03） | 約4.6/日。事業ファネルを評価できる母数ではない |
| GSC CTR | 1.32%（2026-08-02） | index bloat 対策前の0.3%から改善 |
| GSC インプレッション | 対策前から約70%減 | 無意味な選手ページを落とした設計どおりの減少 |
| X 投稿インプレッション中央値 | 17、直近単発60 | 露出の小さな改善はあるが流入・登録に未接続 |
| note referral | 8セッション/28日 | 小さいが、過去実測では X より機能している |

GSC は2026年5月以降、GA4は6月9日以降しかデータがなく、ピークシーズンを経験していない。閑散期の絶対値だけで撤退は決めない。一方、「季節性が来れば自然に伸びる」ことも未検証なので、2026年11月の日本代表欧州遠征を最初の厳格なゲートにする。

### 2.3 計測は実装済みだが、収益の真値が欠ける

コード上は `page_view`、`cta_click`、`paywall_view`、`sign_up`、`trial_start`、`favorite_team_added`、`push_permission_granted`、`return_visit` を送れる。Checkout 成功は現在 `trial_start` のみを送り、`purchase` は送らない。これは7日無料トライアル開始を購入と誤計測しないためには正しい。

ただし、GA4 だけでは「トライアルが有料更新したか」「解約・失効したか」「Stripe と Apple のどちらか」を正確に追えない。**有料購読者数とMRRの真値は Stripe / RevenueCat / `user_profiles` の entitlement 照合**とし、GA4 は流入と行動の診断に使う。

登録ユーザー3人にはテスト・審査用アカウントが含まれる可能性が高い。今後の KPI では、内部・審査アカウントを除いた「実ユーザー」を別集計する。

## 3. 120人から逆算した必要需要

D005 の前提である登録ユーザーから有料への転換率3〜5%を維持する。訪問セッションから登録への転換率は実績がないため、5〜8%を作業仮説とする。

```text
セッション → 登録: 5〜8%（仮説）
登録 → 有料: 3〜5%（D005）
セッション → 有料: 0.15〜0.40%
```

| 有料目標 | 必要な実登録ユーザー | 必要な累計 qualified sessions | 意味 |
|---|---:|---:|---|
| 18人 | 360〜600人 | **4,500〜12,000** | 管理上の損益分岐 |
| 50人 | 1,000〜1,667人 | **12,500〜33,400** | 事業性の兆し |
| 120人 | 2,400〜4,000人 | **30,000〜80,000** | 月約10万円の貢献利益 |

`qualified sessions` はボット・内部アクセスを除き、試合、大会、カレンダー、料金、サンプルのいずれかを閲覧したセッションと定義する。

現在の130セッション/月が14か月続いても約1,820セッションにしかならず、この仮説では有料化は3〜7人に留まる。したがって **RWC までの平均流入を現状の少なくとも16〜44倍**にする必要がある。ここがロードマップの中心課題である。

転換率の仮説はベンチマークではない。各フェーズで実測に置換し、必要セッション数を再計算する。

## 4. 収益化方針

### 4.1 維持する商品構造

Free は検索・共有・再訪の入口、Premium は「試合後に深く理解する」価値に集中する。

| Free | Premium |
|---|---|
| スコア、日程、順位、ラインナップ、得点推移 | 日本語レビュー全文 |
| 日本語プレビュー全文 | 試合 AI チャット（現行の安全上限内） |
| 大会アーカイブ、放送情報 | 全大会・全対象試合のレビューアクセス |
| 固定またはローテーションする無料サンプル recap | Web / iOS 共通 entitlement |
| ログイン後、1試合1問の無料 AI チャット | 7日間無料トライアル後に月額課金 |
| お気に入り、Push通知 | — |

プレビュー、試合基本情報、放送情報を課金壁の後ろへ移さない。これらは検索流入と再訪の理由である。Premium の核はレビュー全文とチャットのままにし、低トラフィック段階でプランを増やさない。

### 4.2 当面やらない収益化

- **広告**: 現トラフィックでは収益が小さく、読みやすさと信頼を損なう。月1万 qualified sessions かつ50人の有料会員に到達するまで検討しない。
- **note 有料記事・メンバーシップ**: 本体 Premium と課金先が分裂するため、既存方針どおり実施しない。
- **投げ銭**: 支払意思の検証が「分析への対価」ではなく「応援」に混ざる。Premium のトライアルが30件溜まるまでは実施しない。
- **スポンサー営業**: 到達人数を説明できない段階では Owner 時間を浪費する。月5,000 qualified sessions またはPush許可500人のどちらかに達してから再評価する。
- **値下げ・多層プラン**: 母数不足を価格問題と誤認するため行わない。

## 5. フェーズ別ロードマップ

### Phase A: 収益ファネルを成立させる（2026-08-09〜10-31）

目標は「大量集客」ではなく、実ユーザーが登録し、トライアルを開始し、有料更新する一連の経路を1件以上通すこと。

実行:

1. **iOS IAP を最優先で通す。** App Store Guideline 3.1.1 の却下を解消し、RevenueCat 経由で購入・復元・entitlement 同期を成立させる。既にある `specs/feat-ios-in-app-purchase.md` を実装候補の権威とし、新しい設計を作り直さない。
2. **収益の真値を作る。** Stripe / RevenueCat / entitlement を月次で照合し、実ユーザーの active paid、trial start、trial conversion、cancel、MRR を1枚で追えるようにする。
3. **既存の X・note・英語ニッチを計測可能な実験として継続する。** 新規チャネルは増やさない。X の投稿中央値50達成だけでは成功とせず、サイト流入と登録で判定する。
4. **934本の生産を増やさない。** GSC で既に表示がある公開済みページを、ホーム・カレンダー・大会ハブ・投稿の着地先として再利用する。

ゲート（10月31日）:

| 成功 | 失敗・対応 |
|---|---|
| 実登録15人以上、trial start 5件以上、有料更新1件以上 | trial start 0なら、料金ではなく流入・CTA・認証経路を順に診断 |
| Stripe/Apple/DBの active paid が一致 | 一致しなければ有料集客を止め、計測・entitlement を修正 |
| 300 qualified sessions/28日以上 | 200未満なら新機能を止め、11月の配布準備だけに集中 |
| iOS が IAP 付きで審査通過 | 同理由で再却下なら、アプリ向けグロース投資を一時停止 |

### Phase B: 日本代表欧州遠征で最初の需要検証（2026-11-01〜11-30）

ウェールズ、イングランド、スコットランド戦を、一過性の閲覧ではなく「お気に入り登録 → Push → 次の試合へ戻る」検証に使う。新しい記事シリーズは作らず、既存の試合ページ、カレンダー、プレビュー、レビュー、note A記事を束ねる。

フェーズ目標:

| 指標 | 目標 |
|---|---:|
| qualified sessions / 28日 | 750〜2,000 |
| 累計実登録 | 60〜100人 |
| trial start | 10件以上 |
| active paid | **3人以上** |
| 30日以内の再訪 | 実登録者の20%以上 |

チャネル継続条件:

- **X**: 28日中央値50以上、プロフィールアクセス率1%以上、GA4で10セッション以上。2回連続の4週間窓で流入5未満かつ登録0なら、主要試合時だけに縮小する。
- **note**: referral 15セッション/28日以上かつ登録1人以上。2回連続で8未満かつ登録0なら、日本代表戦翌日のA記事だけに絞る。
- **英語ニッチ**: 8週間でreferral 50以上か登録2人以上。referral 20未満かつ登録0なら、RWC直前まで凍結する。
- **SEO**: GSCクリック30/28日以上、かつ日本語の非指名クエリからクリックが発生する。順位やインプレッションだけでは成功扱いにしない。

失敗判定: 750セッション以上あるのにtrial startが5未満ならオファーまたは導線の問題。750セッションに届かなければ配布の問題。両者を混同しない。

### Phase C: Six Nations 2027 で損益分岐（2026-12-01〜2027-03-31）

11月の勝ちチャネルだけを残し、Six Nations の毎週繰り返す試合リズムで獲得と再訪を検証する。

フェーズ目標:

| 指標 | 目標 |
|---|---:|
| 累計 qualified sessions | 4,500〜12,000 |
| 累計実登録 | 360〜600人 |
| active paid | **18人** |
| trial → paid | 30件到達までは件数併記、到達後は率で3%以上 |
| 30日再訪 | 実登録者の25%以上 |

実行判断:

- active paid が10人、または完了トライアルが30件に達した時点で年間プランのspec化を判断する。
- 30件の完了トライアル後も有料更新が5%未満なら、価格を下げる前に5〜10人へ解約・未更新理由を聞き、Premium の価値境界を見直す。
- 18人に達するまで、広告、Android、新しいSNS、ニュース量産を始めない。

失敗判定: 30件以上がトライアルを完了してactive paidが5人未満なら、現行PremiumのPMFは未達。RWC向けの新機能を増やす前に、レビュー全文とチャットのどちらに支払意思があるかを再検証する。

### Phase D: 継続率を固め、50人へ（2027-04-01〜08-31）

RWC前に必要なのは瞬間最大風速ではなく、課金が大会間でも残る理由である。お気に入り、Push、カレンダー、過去934本のアーカイブを使い、次の試合に戻る習慣を作る。

フェーズ目標:

| 指標 | 目標 |
|---|---:|
| 累計 qualified sessions | 12,500〜33,400 |
| 累計実登録 | 1,000〜1,667人 |
| active paid | **50人** |
| paid 60日継続 | 30コホート以上で60%以上 |
| Push許可 | 実登録者の25%以上 |

ゲート:

- 50人到達かつ60日継続60%以上なら、RWCで120人を取りに行く。
- 50人未満でもtrial→paidが5%以上なら獲得不足なので、勝ちチャネルへ集中する。
- trial→paidが3%未満、または60日継続40%未満なら、RWC前の主課題は獲得ではなく商品価値。広告出稿はしない。
- Android は、この時点でiOSのインストール→登録→有料が数字で成立した場合だけspec候補にする。

### Phase E: RWC 2027 で120人へ（2027-09-01〜11-13）

Men's RWC 2027 は2027年10月1日〜11月13日。9月は検索・アプリストア・Pushの受け皿確認、開幕後は運用の安定を優先し、大会中の大規模リデザインや新規パイプライン導入はしない。

フェーズ目標:

| 指標 | 目標 |
|---|---:|
| RWC期間の追加 qualified sessions | 17,500〜46,700 |
| 累計 qualified sessions | 30,000〜80,000 |
| 累計実登録 | 2,400〜4,000人 |
| active paid | **120人** |
| 月間売上総額 | **¥117,600** |

診断ルール:

- 追加流入17,500以上でnew paid 70人未満（またはactive paid 120人未満）なら、配布ではなく登録・トライアル・価値訴求の問題。
- 追加流入17,500未満でもtrial→paid 5%以上なら、商品より配布の問題。
- 120人到達後は新規獲得数より、RWC終了30日後と60日後の継続を主KPIに切り替える。
- 大会後60日継続が40%未満なら、RWC売上を恒常MRRとして扱わない。

## 6. Owner の時間予算

Owner は個人開発者なので、チャネル運用を増やさない。通常週の上限を **145分/週**とする。

| 作業 | 週予算 | ルール |
|---|---:|---|
| X | 50分 | 平日10分。主要試合週のみ週末分をnote枠から振替 |
| note | 60分 | A/B/Cの既存ルール。Aを出す週はBを休む |
| KPIレビュー | 20分 | GA4/GSC/課金真値を同じ表に追記 |
| 英語ニッチ | 15分平均 | 単独で追加せず、隔週でnoteのC枠を置き換える |
| 合計 | **145分** | 超える場合は最も登録寄与の低いチャネルを停止 |

note に75分必要な週は英語ニッチを0分、KPIレビューを翌週へまとめる。iOS審査対応など単発作業は、X・noteの運用を増やしたまま上乗せしない。

## 7. 週次スコアカード

インプレッションや記事本数だけでなく、収益に近い順に見る。

| 層 | 指標 | 真値 |
|---|---|---|
| 収益 | active paid、MRR、new paid、cancel、trial→paid | Stripe / RevenueCat / entitlement |
| 転換 | trial_start、sign_up、paywall→pricing、pricing→trial | GA4 + 課金真値 |
| 継続 | 7日・30日再訪、favorite_team_added、Push許可 | GA4 / DB |
| 獲得 | qualified sessions、チャネル別登録、GSC clicks | GA4 / GSC |
| 運用 | X・note・英語ニッチの使用時間 | Owner記録 |

毎月、次の式だけを更新する。

```text
実手取り単価 = 当月手取り売上 / active paid
実固定費 = Supabase + Vercel + OpenAI + Apple + RevenueCat + その他
実損益分岐人数 = ceil(実固定費 / 実手取り単価)
必要セッション = 残り有料目標 / 実測(session→paid)
```

サンプル数が小さい間は率だけを書かず、必ず `1/12` のように分子・分母を併記する。

## 8. 既に試したことの扱い

本ロードマップは次を新規提案しない。

- 選手ページのnoindex化、IndexNow、title/meta等の技術SEO衛生
- 被リンク先の再探索・休眠媒体への営業
- X自動投稿、ハッシュタグ最適化、URLを1st replyに置く運用
- reply-first、note 3タイプ制、英語ニッチの「開始」
- 診断クイズ、全試合の放送情報自動取得
- 新たな無料サンプルrecap設計、ペイウォール・料金ページの作り直し
- コンテンツ本数の増加

X、note、英語ニッチは「既存実験を再提案」しているのではなく、**継続・縮小・撤退の数値条件**を本ロードマップに接続している。

## 9. spec 化候補

実装の詳細設計はここでは行わない。必要になる順に候補だけを列挙する。

1. **既存 `specs/feat-ios-in-app-purchase.md` の実装**

   新規specではない。App Store却下を解消する最優先依存。D014の「v1はIAPなし」と現状が食い違うため、`docs/decisions.md` の更新は Claude Code + Owner が行う。
2. **`feat-revenue-source-of-truth`**

   Stripe / RevenueCat / entitlement の開始・更新・失効・返金を照合し、active paid、MRR、trial→paidを読み取り集計できるようにする。GA4の`trial_start`を売上扱いしない。
3. **`feat-first-touch-acquisition-attribution`**

   サインアップ時の最初のUTMをユーザー単位で保持し、課金元と獲得チャネルを結び付ける。既存のセッション単位UTMを置き換えず補完する。
4. **`feat-annual-premium-plan`**

   active paid 10人または完了トライアル30件のゲートを満たした場合だけ起票。Web ¥9,800/年を第一候補とし、Apple側の商品は手取り同等になる価格を別設定する。
5. **`feat-growth-scorecard-export`**

   Owner の週20分レビューに収めるため、個人情報を含まない集計値だけを出す。管理画面を先回りして作らず、read-onlyの最小出力から始める。

メールニュースレター、広告、スポンサー、Android は現時点のspec候補にしない。それぞれ本ロードマップの数値ゲートを満たしてから判断する。

## 10. 調査制約と更新手順

本書は、2026-08-09 ブリーフに記録された本番 DB 実測、過去に Supabase / GA4 / GSC から取得済みの監査値、現行コード・spec、公式料金情報を統合した。

この作成セッションでは Supabase/GA4 の専用MCPが公開されておらず、GSC ローカル取得は機密ファイルを読む必要があるため実行していない。認証済みブラウザでの代替アクセスも許可されなかった。そのため、**GA4の最新値は2026-07-03、GSCの最新値はブリーフ記載の2026-08-02**である。ロードマップ採用前に、Owner が次の3点だけを最新値へ差し替える。

1. GA4: 直近28日の qualified sessions、`sign_up`、`trial_start`、`paywall_view`、チャネル別セッション
2. GSC: 直近28日の clicks、impressions、CTR、日本語非指名クエリのclicks
3. 課金真値: 内部・審査アカウントを除く active trial / active paid / cancel

差し替えても、損益分岐の式とフェーズゲートは変えない。実測のsession→paidが出た時点で、必要セッション数だけを再計算する。
