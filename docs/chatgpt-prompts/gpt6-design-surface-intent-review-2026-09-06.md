### 前提の訂正

私（Claude Code）は当初「`design.md` に spacing / density / layout の記述が無い」と Owner に報告していましたが、**誤りでした。** D020（2026-08-31）で既に新設されており、現在は次を持っています。

- **Spacing**: 4px 基準、実装スケール 2/4/6/8/12/16/20/24/32/40px、`--space-*` が source of truth。小さい 2–8px は密な制御と試合データ内、12–20px は関連グループ間、24–40px はセクションのリズム
- **Layout**: 主コンテナ 1152px（`max-w-6xl`）、breakpoint は sm 640 / md 768 / lg 1024 / xl 1280。「`sm:` で分岐して止まってはならない」（実装は `sm:` 223 回に対し `lg:` 26 回、読者の 63% がデスクトップ）。リスト行の空白率上限 `maxEmptyRatio: 0.25`
- **Density**: モバイルは comfortable、デスクトップは compact。`components/calendar/week-schedule.tsx` の `WeekBoard` が参照実装

あなたの指摘は「規定が無い」ではなく「**ブランドの面と比較する表の余白規則を区別せよ**」という限定的なものだと理解しています。既存記述は肯定されている（「8/25 改稿後の方針を尊重する」）ものとして扱います。

### 追加した節（`design.md` の `## Elevation & Depth` の直前）

`## Surface Intent: Brand vs Data`

要旨:

1. 既存の Spacing / Layout / Density は**すべての面に一律に適用される**。それが欠落である。「ブランドを立てる面」と「読者が行を比較する面」を区別していない
2. 各面が 2 つの intent のどちらかを宣言する。判断基準は「**読者が何をしに来たか**」

| | Brand surface | Data surface |
|---|---|---|
| 読者の目的 | これが何かを理解し、関心を持つか決める | 日程・スコア・順位を見つける |
| 例 | ホームのヒーロー、pricing、大会 family ガイド、ニュースレター着地 | カレンダー、大会 season ハブ、順位表、試合詳細の記録、H2H |
| 縦のリズム | ブロック間は 24–40px が既定 | 12–20px が既定。24–40px は最上位セクション間のみ |
| 画像 | 全幅の帯を占めてよい | 「最初のデータ要素」の予算を超えて押し下げてはならない |
| ニュースレター／購読ブロック | fold より上に出てよい | 最初の完結したデータ単位の後。ヘッダーとデータの間に挟まない |

3. **「最初のデータ要素」の予算は未定**。あなたの監査の実測値を基準線として記載してあります（カレンダー 1440px で最初のカードが上端から約 591px、ホーム 375px でヒーローが最初の 900px をほぼ占有）。**これらは観測であって目標ではない**と明記しています

### 見てほしいこと

**1. 二分法は正しいか。**「ブランドの面」と「比較する表」を面の属性として宣言させる設計は、あなたの指摘の解になっていますか。それとも区別すべきは面ではなく**ブロック**（同じページに両方が同居する）でしょうか。ホームがまさにヒーロー（brand）と Matchday Board（data）を持ちます。

**2. 「最初のデータ要素」の予算をどう定義すべきか。** 節の末尾に 4 つの未解決質問を置いています。

- 固定 px か、viewport 高さの割合か、ブロック数の規則（「最初のデータ単位より上に brand ブロックは 1 つまで」）か
- px は検査しやすいが breakpoint をまたぐと脆い
- 既に `maxEmptyRatio: 0.25` という測定可能な規則の前例があります。同じ扱いにする価値がありますか

**3. 大会 family ガイドの位置づけ。** ブランドのコピーとして読めますが、読者がデータを求めて来るハブに載っています。`/c/<family>` を brand、`/c/<family>/<season>` を data と分けるべきか、1 ページが両方の intent を持ち順序の規則で解くべきか。

**4. 過剰な規定になっていないか。** `design.md` は実装に合わせて書かれた文書（D018）で、実装を文書に寄せる方針は明示的に却下されています。この節が「既存の面を作り直せ」という要求に読めるなら、それは意図と違います。**新規・再設計の面にのみ適用する**という書き方で足りていますか。

**5. 見落としている面の種別はないか。** brand / data の 2 つで足りますか。たとえば legal / support / newsletter の各状態ページ、404、`/en` はどちらでもない気がします。
