## 0. この依頼の趣旨

**11月の日本代表3試合の放送情報をサイトに載せたい。そのための経路を1本に確定してほしい。**

Claude Code が調査したが、**選択肢を出す → Owner が選ぶ → 別の障害が見つかる**
を4回繰り返して確定できなかった。同じことを繰り返さないため、
**あなたには「選択肢の列挙」ではなく「障害を全部潰したうえでの単一の推奨経路」を求める。**

推奨する経路について、**実行を妨げる要素が残っていないことを確認したうえで**提示すること。
確認できない要素がある場合は、それを「未確認」として明示し、**誰が何をすれば確認できるか**を書く。
「AとBがあります」で終わらせない。

**「載せるべきでない」という結論でも構わない。** その場合は根拠を示すこと。

## 2. Claude Code が確認済みの事実（2026-09-22）

**再調査してよいが、以下は実測なので出発点にすること。矛盾を見つけたら指摘すること。**

### 2.1 現在の取り込み経路

- 放送情報のソースは **JRFU（`https://www.rugby-japan.jp/schedule/`）のみ**
- 実装: `lib/scrapers/jrfu-match-broadcasts.ts` + `lib/broadcasts/ingest.ts`
- 日次 cron `cron-ingest-broadcasts.yml`（`15 3 * * *` UTC）

### 2.2 cron が10日連続で HTTP 500。ただしクラッシュではない

`app/api/cron/ingest-broadcasts/route.ts` の設計:

```ts
const hasRemainingWork = result.unlinkedPages.length > 0 || result.matchesStillMissing.length > 0;
const status = result.linked.length === 0 && hasRemainingWork ? 500 : 200;
```

`matchesStillMissing` は **14日以内**の試合が対象（`ingest.ts` の `fourteenDaysLater`）。
現在の14日以内はこうなっている。

| 大会 | 試合 | 放送情報なし |
|---|---:|---:|
| URC | 16 | 16 |
| Premiership | 10 | 10 |
| Top 14 | 7 | 7 |

**JRFU は日本代表戦しか載せないので、クラブ大会は永久に埋まらない。**
日本代表戦が14日窓に無い期間は必ず500になる。9/12に赤くなったのはPNC終了で日本戦が窓から外れたため。
**このアラートは常時赤で信号価値がない。**

### 2.3 JRFU に3試合は載っているが、放送欄が空

本物のパーサに通した結果:

```
schedule.year = 2026          ✓
matchUrls に /match/30145 を含む  ✓
dateLabel = "11.07 Sat"        → 許容日付 {2026-11-07, 2026-11-08}
DB の 2026-11-08 01:40 JST と照合  → 一致する ✓
broadcasts = []                ← ここだけ空
```

`/match/30145` の HTML を直接検査したところ、
**「WOWOW」「放送」「配信」「J SPORTS」がいずれも0件**。ページに放送情報が存在しない。

**照合ロジックは正常。** `allowedJstDates = new Set([date, addDays(date, 1)])` で
翌日も許容するため、現地時間とJSTの1日ずれは手当て済み。

### 2.4 WOWOW をスクレイプ対象にする案は規約で見送った

- `www.wowow.co.jp/robots.txt` はクリーン（`User-agent: *` の Disallow は3ページのみ、番組ページは対象外）
- **非会員向けのサイト利用規約は存在しない。** `/rule/` は全て加入者契約。
  `/guidance/attention/`「サイトポリシー」は推奨ブラウザの説明のみ
- **WOWOW WEB会員規約（`/guidance/webmem/`）に禁止条項がある**
  - 第14条(7) 「所定の方法以外でWEBサービスにアクセスする…行為」を禁止
  - 第14条(9) 「WEBサービスを利用した営利を目的とする行為」を禁止
  - 第17条2項 「自己の私的利用の目的にのみ使用するものとし、営利目的での利用及び
    他者への転送や、**一般公衆が閲覧できるホームページ等への掲載等を行なってはならない**」

**争点**: これは「WEBアカウントをお持ちの方」を拘束する会員規約であり、
非会員が公開ページを読む行為を拘束するかは文言上明確でない。**ここの法的判断を求める（下記 B）。**

### 2.5 J SPORTS はカバー範囲が狭い

`www.jsports.co.jp/rugby/` の実測: リーグワン6件・ネーションズチャンピオンシップ6件・日本代表12件。
**URC / プレミアシップ / Top 14 / スーパーラグビーは全て0件。**
`robots.txt` は Sitemap 行のみで Disallow ゼロ。

### 2.6 Discord の手動入力では放送欄を埋められない

`app/api/discord/interactions/route.ts:484` は **`match_sourced_facts` にしか書かない**。
放送情報の表示は **`match_broadcasts`** という別テーブル。

`match_broadcasts` の列: `id` / `match_id` / `service_name` / `url` / `kind` / `display_order` /
`verified_at` / `source_url` / `created_at`。
`kind` の既存値は `tv`（15行）と `streaming`（12行）の2種のみ。

既存 `service_name` に表記揺れがある: `WOWOWプライム` と `WOWOW プライム`、
`J SPORTSオンデマンド` と `J SPORTS オンデマンド` が両方存在。

### 2.7 運用上の制約

- **Claude Code は INSERT / DELETE / DDL を実行しない**（CLAUDE.md）。
  Owner が Supabase SQL エディタで実行するか、Codex に実装を依頼する
- Claude Code は実装コードを書かない。仕様書を書いて Codex に渡す運用
- スクレイピング対象は `specs/` に明記されたソースのみ。新規ソースは robots.txt と規約の監査が必要
- 判定基準: **A型（行為そのものを禁止する条項）= 除外 / B型（著作権ベースの複製制限）= 許容**

## 3. 答えてほしいこと

### A. 情報の所在

**A-1.** 11月の3試合の放送・配信について、**現時点で公表されている一次情報はどこにあるか。**
URL と発表日、記載内容（チャンネル名・放送日時・配信の有無）を具体的に示すこと。
**「WOWOWが放送する」だけでなく、試合ごとにどのチャンネルか**まで特定できるかを明示する。

**A-2.** 放送開始時刻が未発表の場合、**いつ頃発表される見込みか。** 過去の同種イベント
（2025年の秋の遠征、Six Nations 等）で、JRFU および放送局が何日前に詳細を出していたかを調べること。

**A-3.** JRFU の試合ページ（`/match/30145` 等）に放送欄が追加されるのは通常いつか。
**過去の日本代表戦のページで、放送情報がいつ載ったか**を確認できれば、それが最良の証拠になる。

### B. 法的判断

**B-1.** 2.4 の WOWOW WEB会員規約は、**アカウントを持たない第三者が公開番組ページを
自動取得する行為を拘束するか。** 日本法の一般的な解釈として答えること。

**B-2.** 放送予定（チャンネル名・日時）は**事実情報として自由に再掲載できるか。**
著作権法上の保護対象になるか、編集著作物やデータベースの著作物に当たる可能性はあるか。

**B-3.** 上記を踏まえ、**Tryline が放送予定を自社サイトに掲載すること自体**に
法的リスクがあるか。あるとすればどの程度か。
**「リスクがある」で止めず、実務上どう扱われているか**（他媒体が同種情報を掲載している実態）も示すこと。

### C. 経路の確定

**C-1.** 以下を踏まえ、**推奨する単一の経路**を示すこと。

- 11月3試合を確実に埋められること
- 年10〜12試合ある日本代表戦で繰り返し使えること
- Owner の稼働 10分/日・週5時間に収まること
- 2.7 の運用制約に反しないこと

**C-2.** 推奨経路について、**実行を妨げる要素が残っていないことを確認したうえで**提示すること。
確認できない要素は「未確認」と明示し、誰が何をすれば確認できるかを書く。

**C-3.** 実装が必要な場合、**何を作るのか**を具体的に書くこと
（対象ファイル、新規/変更の別、想定行数の桁）。Claude Code が仕様書に落とせる粒度で。

**C-4.** クラブ大会33試合（URC/Premiership/Top 14）の放送情報は、
**そもそも埋めるべきか。** 埋めるとすれば情報源はあるか。無ければ
「埋まらないことを前提に運用する」ための提案をすること（2.2 の常時赤アラートの扱いを含む）。

### D. 現行実装の扱い

**D-1.** 2.2 の「常時赤になる500」は直すべきか。直すとすればどう直すか。
**「日本代表戦の放送情報が入ったか」だけを検知する**形にできるか。

**D-2.** JRFU の更新を待つ場合、**更新されたことに気づく仕組み**は必要か。
必要なら最小の形は何か。

## 4. 制約と作法

- **選択肢の列挙で終わらせない。** C-1 は単一の推奨であること
- 推定には根拠と手法を書く。「一般的に」「と言われている」は不可
- 2章の実測値はそのまま使ってよいが、検算して矛盾を見つけたら指摘すること
- 法的判断は断定を避けてよいが、**実務上の落としどころ**まで書くこと
- 公開リポジトリと本番サイトは自由に読んでよい
- **本依頼で本番データの変更・実装・PR作成は行わない**
