# 木金土 12:00 — 翌日キックオフのプレビュー

**ChatGPT のスケジュール実行に、このプロンプト全文をそのまま登録してください。**

**1つのスケジュールを木曜・金曜・土曜の3日に発火させます。** 対象は「**翌日**にキックオフする試合」で固定です。

| 実行日 | 対象（JST キックオフ） | 入力の締切 | 記事が生成される時刻 |
|---|---|---|---|
| **木曜** | 金曜 | **木 14:30** | 木 15:00 |
| **金曜** | 土曜 | **金 14:30** | 金 15:00 |
| **土曜** | 日曜 ＋ 月曜未明 | **土 14:30** | 土 15:00（月曜未明の試合は日 15:00） |

**締切は生成時刻の30分前です。** プレビューは `lib/cron/orchestrate.ts` が **JST キックオフ日の前日 15:00** に1回だけ生成し、以後は作り直しません。締切を過ぎて入れた事実は DB に残るだけで記事に反映されません。

**土曜の回で月曜未明の試合も扱うのは、その分の生成が日曜 15:00 だからです。** 日曜に調査枠を置いていないので、土曜のうちに入れておきます。**手動入力の事実は削除されず、後の生成でそのまま使われます**（`lib/llm/sourced-facts/fetch.ts:109`）ので、1日早く入れて問題ありません。

**実行を12:00に置いているのは、読んで確認して貼る時間を2時間半確保するためです。** GitHub Actions の cron は実測で1〜10時間遅れますが、**遅れを当てにしないでください。**

**1回あたりの試合数は以前より減ります。** 従来は木曜の回で木金土の3日分をまとめていましたが、いまは1日分だけです。

対象は常に「**翌日**（日本時間）にキックオフする試合」です。

- **今日が木曜なら**: 対象は金曜キックオフ。今週の月曜 = 今日の3日前。カレンダーは1ページだけ読む
- **今日が金曜なら**: 対象は土曜キックオフ。今週の月曜 = 今日の4日前。カレンダーは1ページだけ読む
- **今日が土曜なら**: 対象は日曜キックオフ **＋ 月曜未明キックオフ**。今週の月曜 = 今日の5日前 / 翌週の月曜 = 今日の2日後。**カレンダーを2ページ読む**

それぞれ `YYYY-MM-DD` 形式にして、次の URL の `week=` に入れてください。

https://www.trylinerugby.com/calendar?week=（今週の月曜）
https://www.trylinerugby.com/calendar?week=（翌週の月曜。土曜の回だけ）

**最初に、今日の曜日・計算した日付・対象とするキックオフ日を明記してください。**

**土曜の回で2ページ必要な理由**: 日曜夜の欧州キックオフは日本時間で月曜未明になり、翌週のページに入ります。1ページ目には存在しません。

## 守ってほしいこと

**対象日の試合をすべて扱ってください。** 情報量が少ない試合を勝手に省かないでください。調べても何も見つからない試合は「情報なし」と明記してください。**試合を落とすことが一番困ります。**

**対象日以外の試合は扱わないでください。** 翌日にキックオフしない試合を含めないでください。

**事実だけを書いてください。** 意見・予想・感想・評価は書かないでください。「面白い」「注目」「〜だろう」は不要です。

**その出典が実際に書いていることだけを書いてください。** 複数の記事の内容を1つの出典にまとめないでください。

**関係者のコメントは引用せず、要旨を1文にしてください。** 原文をそのまま写さないでください。

試合ごとに、出典 URL 単位でまとめてください。

- <事実>

## 1件の書き方

- **1行に1件。300字以内**
- 主語を明示する（「日本は」「南アフリカは」）
- 数字を入れる（順位・スコア・キャップ数・通算成績・負傷の期間）
- **選手名・監督名はカタカナ**（例: Gaël Fickou → ガエル・フィクー）
- チーム名はカレンダーの表記に合わせる

## 出典について

**同じ記事を3試合以上の出典にしないでください。** 各試合について、その試合を扱った記事を探してください。

有料記事しか見つからない場合は、そのことを明記してください。

- 昨季の順位、今季の補強、古巣対決
- ホーム／アウェーの成績、連勝・連敗
- 会場・開催の節目

## 先発メンバーが揃うかどうか

**多くの協会はキックオフ 24〜48 時間前にメンバーを発表します。** 前日 12:00 の調査はその後に当たるため、従来の木曜 18:00 の回より**先発が揃っている可能性は高い**です。

**ただし発表が前日夕方にずれ込む協会もあります。** その場合、12:00 時点では出ていません。**出ていないものを推測で埋めないでください。**「発表前」と明記してください。

---

## 貼る前に必ず確認すること

**URL が生きていることはシステムが確認しますが、その記事がその事実を書いているかは確認できません**（`docs/decisions.md` の D026）。

**初回テスト（2026-09-04）で実際に食い違いが出ています。** 「リコ・イオアネが23人から外れる」の出典タイトルが `Dave Rennie drops Fabian Holland` で、別の選手名でした。

**数字・選手名・負傷の詳細は、貼る前に出典を開いて確認してください。**

**カタカナ表記は Claude に照合させてください。** 既存 DB と割れます（マルコム・マークス／マルクス、レノ／レン・イキタウ など実例あり）。ChatGPT は既存 DB を知らないので、プロンプトでは直りません。

---

## 締切を過ぎたときの復旧

`.github/workflows/cron-weekend-preview-refresh.yml` を **`workflow_dispatch` から手動で起動**し、`from` / `to` に対象日（JST、`YYYY-MM-DD`）を入れてください。その範囲の scheduled な試合について `fetch-sourced-facts?force=true` → `generate-content` が走り、入力済みの事実を含めて作り直されます。

**定期実行はしません。** 前日 15:00 の生成が最新の事実を使う前提なので、上書き用の cron は置いていません（`docs/decisions.md` の D030）。
