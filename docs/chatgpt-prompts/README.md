# ChatGPT による試合事実の収集

**Owner が ChatGPT に調査させ、結果を Discord から `match_sourced_facts` に入れる運用のプロンプト集。**

背景と適法性の整理は `docs/decisions.md` の **D026**、入力経路の仕様は `specs/feat-discord-research-fact-entry.md`。

## スケジュール

**時刻は再生成の走る時刻から逆算しています。締切を過ぎて入れた事実は、DB に入るだけで記事に反映されません。**

| 実行 | プロンプト | 対象 | 入力の締切 | 締切の根拠 |
|---|---|---|---|---|
| **木金土 12:00** | [weekend-preview-facts.md](weekend-preview-facts.md) | **翌日**キックオフのプレビュー（土の回は月曜未明も） | 当日 **14:30** | `orchestrate` が **JST キックオフ前日 15:00** に1回だけ生成する（D030） |
| **土日 18:00** | [weekend-recap-facts.md](weekend-recap-facts.md) | その時点で終わった試合のレビュー素材 | 土=**20:30** / 日=**月 09:05** | 土は `live-pipeline` 21:00 の初回生成、日は `cron-post-match-recap-refresh` の月曜の回 |

**ChatGPT のスケジュール枠の上限に合わせて2本に統合しています**（2026-09-05）。**どちらも1つのスケジュールを複数日に発火させ**、プロンプト内で曜日を判定します。プレビューは木・金・土の3日、レビューは土・日の2日です。

**プレビューが「翌日の1日分」だけになったのは、生成が前日 15:00 の1回に一本化されたからです**（2026-09-10、D030）。締切は生成の30分前＝当日 14:30 で、曜日によらず同じです。**1回あたりの試合数は従来より減ります**（従来の木曜の回は木金土の3日分をまとめていました）。

**土曜の回を残しているのは、日本代表の国内戦を当日に反映させるためです。** 日曜だけにすると反映が月曜09:05＝試合終了から約40時間遅れになり、アクセスのピークを過ぎます。

手動で追加する枠は下記。

| 手動で回す場合 | いつ | 締切 | 使うプロンプト |
|---|---|---|---|
| **JST 月曜未明の欧州戦** | 月 20:00 | **火 09:05** | `weekend-recap-facts.md` に翌週の月曜 URL を追加 |

**2本とも ChatGPT のスケジュール実行にそのまま登録できます。** 日付はプロンプト内で ChatGPT 自身が計算します（曜日ごとに「今日の N 日前が今週の月曜」と指定済み）。**手で日付を埋める必要はありません。**

**プレビュー側を登録し直すときは、発火日を木・金・土の3日にしてください。** 従来の木・金の2日のままだと、日曜キックオフの試合（実測で週45件）が調査対象から丸ごと落ちます。

**登録するときは、そのファイルの ``` で囲まれたブロック全文**をタスクの指示に貼ってください。ブロックの外（締切の説明・検証の作法）は Owner 向けの手順なので、貼らなくて構いません。

**プレビューを12:00、レビューを18:00〜20:00に置いているのは、読んで確認して貼る時間を確保するためです。** GitHub Actions の cron は実測で1〜10時間遅れますが、**遅れを当てにしないでください。**

## 土曜の締切は「結果が取り込まれていれば」の話（2026-09-05 実測）

**`live-pipeline` の初回生成は、試合が `finished` になっていることが条件です。** `status` とスコアは `ingest-live-competitions` が外部ソースから取り込みます。

**日本代表の国内戦は、取り込み元の ja.wikipedia の更新が遅れます。** 2026-09-05 の日本×カナダは、試合終了（16:40 JST）から4時間半後の 19:11 の回でも `status=scheduled` のままでした（Wikipedia 側が「- - 前半-」で未記入）。

**この場合、土曜20:30に間に合わせても初回生成は走りません。** 入れた事実は `content_type=recap` で DB に残り、**結果が取り込まれた次の回でそのまま使われます。**

**土曜枠は「間に合えば得、間に合わなければ日曜枠と月曜09:05が拾う」という位置づけで扱ってください。** 確実性を求める枠ではありません。

## なぜ締切があるのか

`lib/cron/orchestrate.ts` の `live-pipeline` は、**既存コンテンツがある試合を除外します**（`EXISTING_CONTENT_STATUSES = ["draft","published"]`）。**一度生成されたら作り直しません。**

**プレビューは JST キックオフ日の前日 15:00 に1回だけ生成されます**（D030、2026-09-10）。定期的な上書きリフレッシュはありません。締切 14:30 を過ぎたら、`cron-weekend-preview-refresh.yml` を `workflow_dispatch` から手動で回す以外に反映手段はありません。

**レビューを作り直す経路は `cron-post-match-recap-refresh` の2本（月 09:05 / 火 09:05）だけです。**

火曜の回（PR #756 でマージ済み）は**手動で事実を入れた試合だけ**を対象にします。**何も入力しなければ0件で何も走りません。**

**レビューの主戦場を日曜夜にしているのは、反映が1日早いからです。** 月曜夜に入れると反映は火曜朝になり、**日本代表戦のようにアクセスのピークが試合直後〜翌日に来る記事では山を過ぎます。** 月曜夜の枠は、日曜20時にまだ終わっていない欧州戦（JST 月曜未明キックオフ）のための保険です。

## 入力した事実は消えません

リフレッシュが `fetch-sourced-facts` を再実行しても、**`entry_method = "manual"` の行は削除対象から除外され**（`lib/llm/sourced-facts/fetch.ts:109`）、**allowlist 外ドメインでも読み取り時に例外扱いされます**（同 `:400`）。**再生成のたびに使われます。**

## 再生成しても通知は増えません

- `lib/llm/pipeline.ts:774` の upsert は既存行を更新し、`discord_notified_at` を書き換えない
- `notify-discord` は `.is("discord_notified_at", null)` で絞る
- push は `push_notification_log` の `match_id:kind` で重複排除する

## 5日を2枠に収めている理由

**ChatGPT のスケジュール枠に上限があるため、1タスクを複数日に発火させて曜日で分岐させている。** 日を落とすと次のものが失われる。

| 曜日 | 枠 | 落とすと失うもの |
|---|---|---|
| **木** | プレビュー | 金曜キックオフ（実測17件）。前日 15:00 の生成が手動の事実なしで走る |
| **金** | プレビュー | **土曜キックオフ（実測76件）。週の最大の山。** |
| **土** | プレビュー | **日曜キックオフ（実測45件）＋ 月曜未明の欧州戦。** 日曜に調査枠が無いので、月曜未明分もここで入れる |
| **土** | レビュー | **日本代表の国内戦の当日反映。** `live-pipeline` 21:00 の初回生成に載せられずコストが増え、反映は月曜09:05＝約40時間遅れ |
| **日** | レビュー | 週末の大半のレビュー素材 |

**プレビュー枠を木・金・土に移したのは、生成が「前日 15:00」になったからである**（D030）。旧設計では木21:05・金21:05 のリフレッシュに間に合わせる必要があり、木の回で3日分をまとめていた。**いまは各回が翌日1日分だけを見る。**

**参考: 2026-09-05 の実測（9/5〜12/31 の148試合、JST 曜日別）**

| 月 | 火 | 水 | 木 | 金 | 土 | 日 |
|---:|---:|---:|---:|---:|---:|---:|
| 9 | 1 | 0 | 0 | 17 | 76 | 45 |

**この表は曜日枠の要否を決める根拠にしてはいけない。** キックオフ日と、メンバー発表・試合終了のタイミングは別物である。加えて**金曜17件と土曜09時台41件はすべて URC で、キックオフ時刻が 00:00 UTC のプレースホルダ**（時刻未定）であり、実時刻が入れば分布は変わる。

## 量の目安

**週5回**（プレビュー木金土＋レビュー土日）。**1回あたりの試合数は旧設計より減る**（プレビューは3日分→1日分）が、**1回あたりのブロック数は 2026-09-10 時点で未実測。** 旧設計の10〜12ブロックをそのまま当てはめないこと。

**9/25 に URC 144試合とプレミアシップ90試合が開幕すると、対象試合が週20〜30増えます。** 全部は回りません。**既存の事実が少ない試合に絞ってください。** どの試合が薄いかは Claude が DB から出せます。

## 貼る前に必ず

1. **数字・選手名・負傷の詳細を出典で確認する。** URL が 200 でも記事がその事実を書いている保証はない（D026）
2. **カタカナ表記を Claude に照合させる。** 既存 DB と割れる（マルコム・マークス／マルクス など実例あり）
3. **除外ドメインを避ける。** `planetrugby.com` `rugbypass.com` `world.rugby` `espn.com` `bbc.com` は A型（行為禁止）として除外済み
