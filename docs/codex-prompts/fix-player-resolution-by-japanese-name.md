## 何を直すか

**日本代表戦の得点経過が、選手を1件も解決できずに投入を止められています。**

2026-09-07 の本番実行で解析自体は成功しました（単調性・合計・見出しすべて通過）が、**`unresolved_players_all_skipped: 1` で投入されませんでした。**

原因は `resolvePlayerId`（`lib/ingestion/events.ts:94`）です。

```ts
.eq("team_id", params.teamId)
.ilike("name", `%${params.playerName}%`)
```

**`players.name`（英語表記）だけを見ています。** JRFU が返すのは `岡部崇人`・`ベン・ガンター` という日本語表記なので一致しません。

## 実測データ（2026-09-07）

| | |
|---|---|
| 日本の選手 | 81人。うち `name_ja` を持つのは **11人** |
| カナダの選手 | 43人。`name_ja` は **0人** |

**`name_ja` は `岡部 崇人`（姓名の間に全角空白）**、JRFU は `岡部崇人`（空白なし）。**空白の有無だけで一致しません。**

```
name_ja で JRFU 表記を検索した結果:
  岡部崇人  → 0件
  原田衛    → 0件
```

## 既存の挙動を壊さないでください（最重要）

**`resolvePlayerId` は Wikipedia 由来のイベント取り込みでも使われています。** `upsertMatchEvents` を経由するすべての経路に影響します。

**英語名による解決を先に試し、一致しなかった場合にのみ日本語表記を試してください。** 既存の一致結果が変わってはいけません。**回帰テストを入れてください。**

## 実装の条件

- **`name_ja` と入力の両方から半角空白・全角空白を除去して比較する**
- **完全一致にする**（部分一致にしない）。日本語の氏名は短く、部分一致では別人に当たります（例: `原田` が複数人いる場合）
- **一致が1件のときだけ ID を返す。** 0件および2件以上では null。**これは現行の `data.length === 1` の方針をそのまま踏襲するものです**
- `name_ja` が null の選手を候補に含めない
- `team_id` で絞る

**DB 側で空白除去の式を書くより、チームの選手を取得して照合するほうが単純です**（実測で日本81人・カナダ43人）。ただし方法は問いません。

## 期待される効果と限界

**日本側の主要選手が解決できるようになります。** `name_ja` を持つ11人には岡部崇人・原田衛・下川甲嗣・竹内柊平・齋藤直人など、この試合の得点者が含まれます。

**カナダ側は `name_ja` が0人なので引き続き解決できません。これは想定内です。** `player_id` は nullable で、部分的な未解決は許容されます。

**目的は `unresolved_players_all_skipped` のガードを抜けることです。** 全件未解決という異常状態を脱すれば十分です。
