`/specs/fix-middleware-auth-scope.md` の仕様を実装してください。

コンテキスト:
- プロジェクト規約は `AGENTS.md` を読む
- `middleware.ts` は現状、`matcher` にマッチする全リクエストで `supabase.auth.getUser()` を無条件に実行し、Supabaseへのネットワーク往復が発生している
- 匿名ユーザー（認証Cookieなし）の公開ページアクセスでもこの処理が走っており、TTFB悪化の一因と推測される

やること:
- `middleware.ts` を変更し、リクエストにSupabase認証関連のCookieが存在する場合のみ `supabase.auth.getUser()` を実行する
- Cookie名の正確なパターンは `@supabase/ssr` の実装・ドキュメントを確認して特定すること（推測で決め打ちしない）
- **調査済み: このコードベースには認証必須ルートが存在しません**（`redirect()`は全て正規URL変換用）。「認証必須ルートを除外する」ロジックは不要です。Cookieの有無のみで判定してください

処理すべきエッジケース:
- 認証Cookieがない場合はトークンリフレッシュ処理をスキップし、そのまま `NextResponse.next()` を返す
- 認証Cookieがある場合は従来通りの挙動を維持する
- （認証必須ルートは存在しないため考慮不要）

完了の定義:
- specs の受け入れ条件1〜4を満たす
- `pnpm test` / `pnpm tsc --noEmit` / `pnpm lint` / `pnpm build` clean
- 変更ファイル一覧を報告する

要件:
- `matcher` 設定自体（除外パターン）は変更しない
- Cookieが存在する場合のトークンリフレッシュ仕様自体は変更しない
- 曖昧な箇所や仕様書と実環境の食い違いがあれば、その場で実装を停止して質問する

完了時:
- 実装内容・変更ファイルを要約する
- 判定に使ったCookie名パターンとその根拠（ドキュメント参照等）を報告する
- 仕様書からの逸脱があれば理由を明示する
- 未解決の質問があれば記載する
