## 直すのは3点

**1. Atom 形式に対応する**

`parseRss`（`lib/news-links.ts:48-49`）が RSS の `<item>` しか走査していません。`stuff.co.nz` は **Atom（`<entry>`）で30件配信している**のに0件でした。

Atom は3箇所が違います。

| | RSS | Atom |
|---|---|---|
| 要素 | `<item>` | `<entry>` |
| リンク | `<link>URL</link>` | **`<link href="URL"/>`** |
| 日付 | `<pubDate>` | `<published>` / `<updated>` |

**現行の `tag()` ヘルパ（`:41-46`）では `<link href>` を取れません。** 開始タグと終了タグに挟まれたテキストを取る実装なので、自己終了タグの属性値には対応していません。

**RSS の既存動作を壊さないでください。** RNZ は正常に12件取れています。

**2. チームの通称辞書を追加する**

最も重要な取りこぼしです。この記事が紐付きませんでした。

> `Springbok captain Siya Kolisi cleared to face All Blacks in second test`

**8/30 の第2テストそのもの**の記事で、この仕組みが最も拾うべきものです。見出しが `Springbok` / `All Blacks` という通称しか使っておらず、`teams` の `South Africa` / `New Zealand` を含まないため落ちました。

あわせて **未来の試合を優先**してください。現行は「キックオフが最も近い試合」を選ぶだけで過去も候補に入るため、実際に**終わった 8/25 の試合**に紐付きました。

**3. NZ Herald を Sport フィードに変更する**

ラグビー専用フィードが1記事しか返しません（実測）。Sport フィードに切り替えます。URL は spec に記載。

**変更後の件数を実測して PR 本文に書いてください。** それでも少なければ NZ Herald 自体の要否を再検討します。

## やってはいけないこと

- **設計の境界を越えること。** 記事本文・要約の取得・保存・LLM への投入は引き続き禁止です。**LLM に渡すのは見出し1行だけ**
- **Discord 通知フォーマットの変更。** 後続 spec が末尾の `match_id: <uuid>` 行に依存しています
- `news_links` のスキーマ変更（不要です）
- 新規ドメインの追加（本 spec の範囲外）
- 通称辞書を網羅しようとすること。**実際に見出しで使われるものだけ**入れてください

## 誤爆に注意してください

`Boks` のような短い語や、`Lions`（ブリティッシュ&アイリッシュ・ライオンズ／URC のライオンズ／NRL のライオンズ）のような多義語は誤爆します。**単語境界を考慮**してください。
