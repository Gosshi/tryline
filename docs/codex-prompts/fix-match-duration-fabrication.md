# Codex 指示: 「90分」を決定的に弾く（ラグビーは80分）

## 仕様書

`specs/fix-match-duration-fabrication.md` を読んでから着手すること。以下は補足であり、仕様の置き換えではない。

## 何が問題か（一文）

**記事が「90分」と書き、QA を通過して公開されている。** ラグビーユニオンは80分である。

## 実際に公開された本文（2026-08-21）

> 互いの先発構成にどこまで圧力をかけられるかを測る**90分**となる

Owner が気づいて手作業で修正した。

**2回目である。** 2026-08-13 の日本代表戦プレビューでも「90分の主導権」という同じ誤りがあった（`project_lineup_preview_timing_gap` に記録）。

**2回とも QA を通過している。**

## なぜ検出されないか（自分で確認すること）

```
grep -rn "80分" lib/ --include="*.ts"   →  0件
```

**正しい試合時間がコードのどこにも書かれていない。** モデルはサッカーの一般知識に引きずられている。

そして `lib/content/fabrication-guard.ts` のガードは5つあるが、**競技の基本ルールに関するものが1つも無い**。

`containsUnsupportedStatistic` は「データに存在しない統計値」が対象で、**「90分」は統計値ではなく競技の前提**なので、入力データと突き合わせても引っかからない。

## 先に実読すべきファイル

| ファイル | 何を確認するか |
|---|---|
| `lib/content/fabrication-guard.ts:3-12` | issue 定数6つ。**同じ形式で足す** |

## やること

1. 試合時間の誤りを検出する決定的ガードを `fabrication-guard.ts` に追加
2. `shared-prompt-blocks.ts` に「80分（40分ハーフ）」を明示
3. retry 上限を超えないことを確認

## 設計上の注意

**主軸はガード。プロンプトへの追記は補助。** `fix-recap-opening-variety-v2.md` が「禁止句を足しても別の表現に乗り換えて再発する」と記録している。**文言だけで解決したことにしないこと。**

**緩めすぎないこと。** 「90分」はラグビー記事で試合時間以外に出る場面が実質無い。まず単純な検出で始めてよい。**多少の誤検出は再生成で吸収できるが、見逃しは記事に残る。** 2回とも公開直前まで誰も気づかなかった。

**表記ゆれは実データを見てから決める。** `90分間` / `九十分` 等に手を広げる前に、現行の生成物に実際に現れる形を確認すること。

**共有ブロックに置くこと。** preview と recap の両方に効かせるが、両ファイルで重複定義しない。

## 絶対にやってはいけないこと

1. **競技ルール全般の検証に広げない。** 試合時間だけ。範囲を広げると `selectCorePattern` と同じ硬直に陥る
2. **QA の採点ルーブリック・閾値を変えない**
3. **セブンズに対応しない。** Tryline は15人制のみ
4. **英語コンテンツを変えない。** `preview@2.0.0-en` は別経路
5. **既存記事の点検・修正をしない。** ガードを作るまで
6. **recap の既存出力を変えない**（80分の追記を除く）
7. **retry 上限を変えない**
8. **モデル ID を直書きしない。** `lib/llm/models.ts`

## テストで押さえる点

- **仕様書背景の実文**「互いの先発構成にどこまで圧力をかけられるかを測る90分となる」が**検出される**。この文をフィクスチャに含めること
- 「80分」を含む正しい本文が**検出されない**
- 試合時間に言及しない本文が検出されない
- preview / recap 双方のプロンプト出力に80分の記述が含まれる
- **共有ブロックに1箇所だけ定義されている**（両ファイルで重複していない）
- ガード発火時に retry 上限を超えて再生成し続けない
- `preview` / `language: "en"` の出力が変わっていない
