## 状況

**2026-08-31 21:39 JST、週次メールが初めて実配信されました。** PR #734 で GET/POST 不一致を直して以来はじめてです。

**しかし届いたメールで Markdown が生表示されています。**

```
# 【今週の海外ラグビーまとめ】南アフリカがニュージーランドを撃破…
## グレイテスト・ライバルリー・ツアー オールブラックス 南アフリカ遠征

```

`#` `##` `###` `[text](url)` `---` がすべて記号のまま見えています。**購読者が受け取る最初のメールがこれです。**

## 原因は「1つの出力を2経路に流している」ことです

```
SYSTEM_PROMPT（route.ts:34）「note.com への投稿原稿を生成してください」
                             「出力形式: Markdown形式」
        ↓
   同じ出力を2経路へ
        ├→ Discord に note 原稿として投稿（:228）  ← Markdown が正しい
        └→ メールへ text として送信（:237）        ← Markdown が壊れる
```

`lib/newsletter.ts` は **`text` しか持ちません**（`:10` の型、`:121` の送信）。`html` フィールドがありません。

## 直し方は「HTML 化」ではありません

**note 原稿の生成そのものをやめます。**

note の週次B型は **D017（2026-08-15）で停止済み**です。`project_growth_channel_decision` に「routine『note週次まとめドラフト』の停止が必要」と未完了で記録されており、**停止漏れが初回配信で表に出ました**。

**Owner 判断（2026-09-01）: この生成器をメール専用にする。** そうすれば Markdown を出す理由が消え、問題が構造的になくなります。

**`lib/newsletter.ts` を HTML 対応させないでください。** 負債が増えるだけです。

## 直すのは4つです

**1. Discord への note 原稿投稿をやめる**（`:228`）

`DISCORD_WEBHOOK_WEEKLY_DIGEST` を配信結果の通知に転用しても構いませんが、**note 原稿ではないと分かる文面**にしてください。「念のため残す」で note 原稿を送り続けないでください。

**2. プロンプトをメール本文向けに書き換える**

- **Markdown 記法を出力させない**（`#` 見出し・`[text](url)`・`**太字**`・`---`）
- **URL は裸で書く**（`→ https://…`）
- 見出しは記号に頼らない表現にする

**3. 日本語チーム名を渡す**

現在のクエリ（`:183-185`）はチームを `name` しか取っていません。大会は `name_ja` を取っているので、**チーム名だけ英語**になります。

```
home_team:teams!… ( name, name_ja )
away_team:teams!… ( name, name_ja )
```

`buildUserPrompt` で **`name_ja` 優先・null なら `name` にフォールバック**してください。大会名の `competition?.name_ja ?? "大会名未設定"` と同じ流儀です。

**4. 試合データを拡充する**

現在の `buildUserPrompt`（`:99-105`）はスコア・チーム名・大会名しか渡していません。だから本文が「33-26で下しました。7点差の熱戦となりました」とスコアの言い換えで終わります。

**`match_events` と `match_sourced_facts`（`content_type='recap'`）を渡してください。**

同じ週末の試合について、DB にはこれだけありました。**1つも使われていません。**

- `match_events` 17件（コリシの38分トライ、コルビの7本のキック）
- `match_sourced_facts` 8件（デュトイの100キャップ、入場者数56,589人、試合後コメント）

## 最重要の落とし穴

**「Markdown を使うな」と書くだけでは不十分です。**

LLM は指示に反して記法を出します。**出力後に検証してください。** 少なくとも次を検出できること。

- 行頭の `#`
- `[…](…)` 形式のリンク
- `---` の区切り

**検証に引っかかったときの挙動を定義してください**（再生成・記法の除去・エラーのいずれか）。**黙って配信しないでください。** 壊れたメールが購読者に届きます。
