## 4つの必須事項

### 1. 既存イベントがある試合に触らない

既存の `upsertMatchEvents`（`lib/ingestion/events.ts:59`）は、**対象試合のイベントを全削除してから挿入します。**

```
.from("match_events").delete().eq("match_id", params.matchId)
```

**「既存があれば触らない」は upsert の外側で判定してください。** 呼ぶ前に件数を数え、**0件でなければ対象から外します。** Wikipedia から入った正しいイベントを解析ミスで消す事故を防ぐためです。

### 2. 投入前にスコアと突き合わせる（最重要）

**イベントから計算した合計が `matches.home_score` / `away_score` と一致しなければ、1件も投入しないでください。**

重みは `try` 5 / `conversion` 2 / `penalty_goal` 3 / `drop_goal` 3。

**不一致なら期待値と実際値をログに出してスキップします。**

**これが無いと事態が悪化します。** 誤ったイベントを入れると `eventIntegrity` が通ってしまい、**間違った得点経過でレビューが生成されます。** イベントが無くて生成されないより悪い結果です。

**ペナルティトライに注意してください。** 過去に5点として扱うバグがありました。**JRFU の表記を確認し、判別できなければその試合をスキップしてください。**

### 3. 得点種別は実 HTML から判別を決める

**`try` / `conversion` / `penalty_goal` / `drop_goal` の判別方法は、実際の HTML を見て決めてください。**

確認時点では「視覚的な指標で区別される」ことしか分かっていません。**クラス名・アイコン・テキストのどれで判別するかを実物で確定してください。**

**推測で決めないでください。** 手作りのフィクスチャは実データで壊れます。**実ページの HTML をフィクスチャに使ってください。**

### 4. www を付ける

**`rugby-japan.jp`（www なし）は証明書が期限切れでアクセスできません**（2026-09-06 実測）。

**日程ページの `href` は www なしで出てきます。** 既存の `normalizeUrl` は base で正規化しているので現状は動いていますが、**新しいコードで href をそのまま使うと失敗します。**

## 選手の解決

**既存の `resolvePlayerId({ playerName, teamId })` を使ってください。**

**解決できなくても投入は続けてください。** `player_id` は nullable です。**解決できなかった名前はログに残してください。**

JRFU には `/player/<id>` のリンクがありますが、**それを `players` に紐づける仕組みは現在ありません。** 本 spec では名前による解決に留めます。

## リクエスト数

- 日程ページ: 1回
- 試合ページ: **対象試合ぶんのみ**
- **1回あたりの最大試合数を定数で定義してください。推奨5**
- **`fetchWithPolicy` を使ってください**（D026 の例外は適用されません）

対象は「スコアありでイベント0件の日本代表戦」なので、通常は0〜1件です。

## テスト

- 全種別の得点
- スコア一致 → 投入
- **スコア不一致 → 1件も投入しない**
- 既存イベントあり → 触らない
- 選手未解決でも投入継続
- 上限超過

**フィクスチャは実ページの HTML を使ってください。**
