## 検証の作法（過去に踏んだ罠）

- **Playwright MCP は Vercel のプレビューに SSO で弾かれます。** `claude-in-chrome` 拡張のみ使えます（`reference_preview_visual_verification_limits`）
- **`resize_window` は viewport 幅を実際には変えません**（`innerWidth` が変わらない）。幅の検証に使えません

- **トークン名ではなく、実際に描画される値で計算してください**（上記 `--color-paper` の件）

## 成果物の形

### 1. spec と Codex 指示書（本体）

`specs/<名前>.md` と `docs/codex-prompts/<同名>.md` を対で作ってください。片方だけにしないでください。

spec には次を含めてください。

- **スコープと対象外**（対象外を書かないと Codex が広げます）
- **受け入れ条件**（Codex が検証できる粒度。「見栄えが良い」は不可）
- **未解決の質問**（Owner が決めるべきこと）

### 2. 判断の記録

`design.md` の方針そのものを変える提案が含まれる場合、`docs/decisions.md` に追記する D番号つきの決定文案も添えてください。

**ただし D018 の方針（design.md は実装に合わせる。実装を文書に寄せない）を覆す提案には、それ相応の根拠が必要です。**

### 3. 判定方法

提案した変更について、**効いたかを後から判定する方法**を書いてください。滞在時間・直帰・スクロール深度など、GA4 で測れる形が望ましいです。

## やってはいけないこと

- **アプリケーションコードの実装**（Codex の仕事）
- **ダークモードを既定にする提案。** ユーザーのグローバル規約で「自動的にダークモードにしない」と定められています
- **解決済み項目の再提案**（コントラスト・reduced-motion・Taste Skill 6件）
- **試合ページの見た目に時間を使うこと。** 3.6秒しか見られていません
- **design.md を「あるべき論」で書き換えること**（D018 で却下された方向）
- **テンプレート的な提案。** ユーザーのグローバル規約に anti-template ポリシーがあります。既定のカードグリッド、中央寄せヒーロー＋グラデーション、均一な角丸と余白は禁止です
- **実測できていない数字の使用**
