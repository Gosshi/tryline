仕様書 `specs/fix-japanese-player-name-spacing.md` を実装してください。**先に全文を読んでください。**

## 何が問題か

`players.name_ja` を持つ選手は 23 人。うち**空白ありが 11 人、空白なしが 12 人**（2026-09-09 本番実測）。ほぼ半々で割れています。

```
空白あり: 齋藤 直人
空白なし: 木田晴斗
```

表示側は `name_ja` をそのまま出しており（`components/match-events-section.tsx:281` / `components/match-lineups-section.tsx:183,186` / `components/team-stats-panel.tsx:187`）、同じ画面に両方の書式が並びます。

## 最重要の制約

監査の原文です。

> 日本語姓名の表示規則を定義し、DB原典表記と表示正規化を分離。**外国名の区切りを一律削除しない。**

**空白を機械的に削除しないでください。** `Seungsin Lee` やカタカナ表記の姓名区切りが壊れます。

| 入力 | 扱い |
|---|---|
| `齋藤 直人` | 規則を適用 |
| `木田晴斗` | 規則を適用 |
| `Seungsin Lee` | **触らない**（ラテン文字） |
| `リーチ マイケル` | **触らない**（カタカナ） |
| `null` / 空文字 | **触らない** |

**カタカナを対象に含めないでください。** カタカナの姓名区切りは外国人選手で意味を持ちます。

## やること

1. 「漢字・ひらがなの姓名を空白で区切るか詰めるか」を決め、**根拠とともに `docs/` または `design.md` に残す**。実装だけ入れて規則が残らないと、次に別の人が逆向きに直します
2. 表示用の正規化関数を `lib/format/` 配下に作り、上記 3 コンポーネントに適用する

**表示用であることが名前から分かる関数名にしてください。** 同時に投げている `fix-venue-footnote-display-leak` で、`normalizeVenue`（照合キー用・`.toLowerCase()` 済み）と表示用を取り違えかけた前例があります。

判定は決定論的に行ってください。

## やってはいけないこと

- **`players.name_ja` の DB 値を書き換えること。** 原典表記は保持し、表示側で揃えます
- **LLM に姓名の境界を推測させること。** それ自体が捏造の経路になります
- `players.name`（英語名）の表示を変えること
- `name_ja` のカバレッジを増やすこと（`fix-player-name-ja-coverage.md` の範囲）
- 選手同一性（`Lee` / `Seungsin Lee` の重複）を直すこと（同じく別 spec）

## 完了の定義

受け入れ条件 1〜11 を満たすこと。特に:

- 表示規則が文書化され**根拠が書かれている**（条件 1）
- **`Seungsin Lee` の空白が保持される**（条件 3）
- **カタカナ姓名の空白が保持される**（条件 4）
- 漢字とラテン文字が混在する名前でラテン側が壊れない（条件 6）
- **`players.name_ja` への `UPDATE` が差分に無い**（条件 8）

採用した規則（空白あり / なし）と根拠を PR 本文に書いてください。

テストは `tests/format/` と `tests/components/` 配下へ（`exclude` 非該当。確認済み）。

git worktree で `origin/main` から切ってください（`docs/runbooks/codex-worktree.md`）。
