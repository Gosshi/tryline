# Codex 指示: QA にラインアップと得点イベントを渡す（同型の非対称・3度目）

## 仕様書

`specs/fix-qa-lineups-and-events-grounding.md` を読んでから着手すること。以下は補足であり、仕様の置き換えではない。

## 何が問題か（一文）

**生成側は見えていて、判定側からは見えない。** ラインアップも得点イベント本体も QA に渡っていないため、正しい記述が「入力データにない」と却下される。

## 実際に起きたこと（2026-08-23、本番）

recap が **事実根拠 2/5 で reject**。

```
入力データにない先発・ポジション情報（ホランド、ラブ、コルビら）を断定しています。
得点イベントに記録されていない各得点の正確な時刻を断定しています。
```

**2件とも誤り。** 本番 DB で全件照合済み。

- `match_lineups` に **46件**あり、本文の背番号（先発5番ホランド、10番ラブ、14番コルビ、7番ジェイコブソン）は**全部一致**
- `match_events` に **14件**が分単位で入っており、本文の時刻は**全件一致**。スコア推移も合致

再取得・再生成しても **3/5 のまま**。過検出が実害になっている。

## 根本原因（自分で確認すること）

```
grep -c "projected_lineups" lib/llm/prompts/qa-content.ts   →  0
```

`QaMatchContext`（`qa-content.ts:21-35`）は `recent_form` / `sourcedFacts` / `teamStats` / `formStats` 等を持つが、**ラインアップが無い**。

`match_events` も本体は渡っていない。引数は `hasEvents`（真偽値、43行）と `playerStatNames`（得点者名の配列、42行）だけ。**分・種別・スコア推移が QA から見えない。**

一方 `generate-recap.ts` は `JSON.stringify(assembled.match_events)` で**全体を生成側へ渡している**。

## これは3度目である（最重要）

| spec | 渡したもの |
|---|---|
| `fix-qa-prompt-missing-form-and-match-metadata.md` | 集計値（大会名・会場・平均得点） |
| `fix-qa-form-stats-individual-results.md` | 直近5試合の個別スコア |
| **本件** | **ラインアップと得点イベント本体** |

**前回の spec が「3度目が起きたら機械的な差分検出を検討する」と書いている。3度目が起きた。**

だから本件は**フィールドを2つ足して終わりにしない。** 「生成側にあって QA 側に無いフィールド」が今後増えたときに**気づける仕組み**まで作ること。

過去3回とも、気づいたのは**本番で記事が落ちてから**だった。

## やること

1. `QaMatchContext` にラインアップと得点イベントを追加
2. `formStatsBlock` と同形式のブロックを2つ追加
3. `pipeline.ts` で配線（**出どころは生成側と同一**）
4. **生成側／QA 側のフィールド差分を検出する仕組み**を追加
5. `PROMPT_VERSION` を上げる

## 設計上の注意

**QA 用に DB を引き直さない。** 生成プロンプトが見ている `assembled` の値をそのまま渡す。前回・前々回の spec が同じ警告を出しており、そこを外すと4度目が起きる。

**選手名は日本語で照合できる必要がある。** 本文はカタカナ。ラインアップの選手名が英語のままだと QA が照合できず、**修正しても効果が出ない**。`recent_form` が `resolveTeamName(..., language, ...)` を通しているのと同じ確認をすること。実データで確かめ、**どう解決したかを PR 本文に書くこと**。

**差分検出の形は判断してよい。** 型レベルの網羅、テスト、リンタ、どれでもよい。要件は「増えたときに気づける」こと。

## 絶対にやってはいけないこと

1. **プログラム側ガードの判定ロジックを変えない**（`containsUnsupportedStatistic` / `containsUngroundedPlayerReference` 等）
2. **採点ルーブリック・閾値を変えない**
3. **`playerStatCheckBlock` の文面と役割を変えない。** 「ここでは正誤判定をしない」という設計は正しい
4. **生成プロンプトに触らない**
5. **h2h・順位表を配線しない。** 落ちた実例が無い。憶測で広げない
6. **カード情報に手を出さない。** `match_events` に入っていない。別 spec
7. **既存の4ブロック（formStats / teamStats / matchMetadata / recentForm）の出力を変えない**
8. **既存記事を再生成しない**
9. **モデル ID を直書きしない。** `lib/llm/models.ts`

## テストで押さえる点

- **修正前はラインアップも得点イベントも出力されないことを固定するテスト**
- 先発・リザーブ・背番号を含むブロックが出る
- 得点イベントの分・種別・得点者を含むブロックが出る
- 値が空 → それぞれのブロックが出ない
- 既存4ブロックが引き続き出る
- 配線の出どころが生成側と同一
- **差分検出の仕組みが、現在の欠落ゼロを確認できる**
- 仕様書背景の実データ（先発5番ホランド、47分のトライ）でブロックに値が現れる。**LLM の採点結果はテスト対象にしない**
