## 何が起きたか

**PR #778 が投入した得点経過が誤っていて、そこから生成されたレビューが本番で公開されました。**

`JRFU の試合ページは前半と後半で分数を振り直しています。**

```
前半: 5' 6' 15' 16' 19' 19' 22' 22' 27' 27' 42' 43'
後半: 1' 2' 8' 8' 8' 9' 11' 11' 11' 16' 18' 18'   ← 1分から再スタート
```

パーサが両セクションを区別せず `.time` をそのまま `minute` にしたため、**後半のイベントが前半の中に混ざりました。** 結果、生成された本文は「前半を48―12で折り返した」（実際は31–7）「後半もカナダを無得点に封じた」（実際は60分に失点）と書きました。

**`verdict=publish` / `density=5` で QA を通過しています。**

**発見後、`match_content` を `draft` に戻し、`match_events` 18件を削除しました。** 現在の状態は `finished` / `57-12` / events 0件 / recap `draft` です。

## 整合チェックが機能しなかった

PR #778 は**イベント合計とスコアの一致**を条件にしました。**合計は 57–12 で一致していました。** チーム配分も正しかった。**壊れていたのは時系列だけです。**

**これは私の spec の欠陥です。** 「合計が合っていれば順序も正しい」という前提を置いていました。

## 直すこと（3点）

### 1. 後半に +40 のオフセット

- **`前半` / `後半` の見出しでセクションを判別する**（実測で `前半` 3箇所・`後半` 2箇所存在）
- 後半の分数に **40 を加算**。定数で定義する
- **前半のロスタイム（`43'` など）には加算しない**
- **見出しが見つからなければ投入せずスキップし、ログに残す**。推測でセクションを分けない

### 2. 単調性を検証する

**単調非減少を「ハーフごと」に検証してください。境界は検証しないでください。**

- 前半のイベント列が単調非減少
- 後半のイベント列が単調非減少
- **前半末 → 後半頭は検証しない**

**2026-09-07 訂正**: 初版は「全体で単調非減少」と書きましたが誤りでした。実本番で `timeline_order_skipped: 1` となり投入が止まりました。

```
前半:  5  6 15 16 19 19 22 22 27 27 42 43
後半: 41 42 48 48 48 49 51 51 51 56 58 58   （+40 適用後）
連結: … 42, 43, 41, 42, …   ← 43 → 41 で減少
```

**前半のロスタイム（43分）が後半1分（=41分）より大きくなるためです。** ラグビーの前半はほぼ必ずロスタイムがあるので、全体で検証すると**実質すべての試合が止まります。**

この重なりは JRFU の採番（前半の `40+3` を `43'` と書く）に由来する正常な状態です。**重なりを許し、各ハーフ内の順序だけを見てください。**

**同一分の複数得点は違反として扱わないでください**（実データに `19' 19'` `8' 8' 8'` があります）。

あわせて**前半の小計が合計を超えていない**ことも確認してください。既存の「合計が `home_score` / `away_score` と一致する」条件は**維持してください**。

### 3. 全件の選手未解決を異常として扱う

**投入された18件すべてで `player_id` が `null` でした。** `resolvePlayerId` が1件も引けていません。

**イベントが1件以上あって解決できた件数が0なら、投入せずスキップしてください。** ログにイベント件数・解決件数・試みた選手名を出します。

**部分的な未解決は許してください**（既存の挙動を維持）。**全件未解決だけを異常とします。**

**原因の調査は本 spec の対象外です。** 投入を止める条件としてだけ入れてください。
