## 背景: なぜこれを調べるのか

| 区分 | ユーザー | セッション |
|---|---|---|
| 新規 | **153** | 153（**1人あたり1回**） |
| 再訪 | 14 | 78（1人あたり5.6回） |

**新規153人が誰一人戻ってきていない。** 再訪14人は Owner を含む少数の回遊とみられる。

同期間の流入は「今どの大会が開催中か」に完全連動していた。7月に74ユーザーを集めた `/c/nations-championship/2026` は、NC の試合が止まった8月に8ユーザーへ崩落（−89%）。代わりに8月開催の3大会（リポビタン19・PNC 17・greatest-rivalry 15）が立ち上がった。

**つまり漏斗は壊れていない。試合がある間だけ人が来て、終わると戻る理由が無い。** 11月に日本代表欧州遠征と NC 再開が重なるが、受け皿が無ければ増えた新規もまた全員消える。

## 有力な仮説（ただし鵜呑みにしないこと）

Web Push については、`NotificationSettings` コンポーネントの呼び出し元が `components/user-menu.tsx:137` **1箇所だけ**であることを確認済み。つまり**オプトインがログインの内側にある**可能性が高い。新規153人はほぼ全員が1回きりの訪問なので、ログインを通る人はほぼいない。

**この仮説を検証しつつ、他の原因も潰してほしい。** 「仮説が当たっていた」で終わらせず、以下を切り分けること。

1. **導線が無い / 届かない場所にある** — UI の入口がログイン内側だけ、等
2. **実装が未完** — API はあるが呼ばれていない、service worker が登録されていない、等
3. **環境変数が未設定** — `lib/env.ts:20-22` に `VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY` / `VAPID_SUBJECT` の定義がある。本番に値が入っているかは**コードからは判断できないので、判断できないと明記すること**（値そのものを読もうとしないこと）
4. **動くが誰も押していない** — 導線は届く場所にあるが、文言や配置の問題

## 3手段それぞれについて答えてほしい問い

各手段ごとに、以下を**エンドツーエンドで**追跡すること。

1. **入口はどこにあるか。** ページ URL とコンポーネント。ログインが要るか。何回スクロールした先か
2. **登録処理は完結しているか。** クライアント → API → DB の経路が繋がっているか。途中で止まる分岐はあるか
3. **送信側は動いているか。** cron / API ルート / 手動スクリプトのどれか。実際に送られた形跡（`push_notification_log` 37件が何なのか）
4. **登録0（または1）の最も可能性が高い原因は何か。** 確信度つきで
5. **動く状態にするための最小の変更は何か。** 実装はしないが、規模感（S/M/L）と触るファイルを挙げる

## メール購読について特に見てほしい点

`email_subscribers` は1件のみ。ただし `components/newsletter-signup.tsx` は**大会ハブのヒーロー直下に露出している**（Web Push と違いログイン不要）。

**露出しているのに1件しか取れていない**のは Web Push とは別の問題である可能性が高い。導線の問題ではなく、文言・タイミング・信頼性の問題かもしれない。

あわせて**週次配信の cron が実際に動いているか**を確認してほしい。2026-08-17 が初回実行の予定だったが、実行された形跡があるかどうか。

## 裏取りルール（必ず守る）

このリポジトリでは過去に、監査レポートの誤検知や「実装済みなのに未着手と誤報」した事故が複数回起きている。

1. すべての指摘に `ファイルパス:行番号` を付ける
2. 「〜が無い」と書く前に `grep` で全体を検索して0件を確認し、**使った検索コマンドをレポートに併記する**
3. 確信度を3段階（確実 / 要確認 / 推測）でラベルする。**コードから判断できないこと（本番の env 値、実際のユーザー行動）を「確実」にしない**
4. **本番 DB に接続しない。** 上表の数値は与えられたものとして使い、自分で取りに行かない
5. 環境変数の**値**を読もうとしない。定義の有無だけ確認する
