# Codex 指示: 選手名バックフィルの漢字推測を止める（試し焼きの差し戻し）

## 仕様書

`specs/fix-player-name-ja-kanji-inference.md` を読んでから着手すること。以下は補足であり、仕様の置き換えではない。

## 前提

PR #720 の `tools/backfill-player-name-ja.ts` は**マージ済み**。本件はその**試し焼きで判明した欠陥の修正**であり、ツールごと作り直すものではない。

## 試し焼きの結果（2026-08-23、本番・DB 非書き込み）

**外国籍選手は狙いどおりだった。ここは触らないこと。**

```
Romain Taofifénua  → ロマン・タオフィフェヌア
Théo Attissogbé    → テオ・アティソグベ
Duarte Torgal      → ドゥアルテ・トルガル
Darcy Rae          → ダーシー・レイ
Francois Cros      → フランソワ・クロ
```

**問題はこの2件。**

```
Yoshimitsu Yasue   → 安江祥光          ← ローマ字から漢字を推測
AsaeliAi Valu      → アサエリ愛・ヴァル ← 同上（元データも壊れている）
```

**ローマ字から漢字は一意に決まらない。** 「Yoshimitsu」は祥光・義光・吉光・良光…と無数にある。モデルが選んだ1つに根拠は無い。

**`players.name_ja` に書き込むと固定され、以後すべての記事に使われる。** カタカナの揺れより深刻。

日本代表11名の漢字は PR #600 で**検証済みデータからバックフィル**している。**漢字は確定できる情報源から入れる**のが方針。

## もう1点: 既に日本語の646人が候補に入っている

```ts
// tools/backfill-player-name-ja.ts:138-143
.from("players")
.select("id, name, name_ja, team:teams!players_team_id_fkey(country)")
.or("name_ja.is.null,name_ja.eq.")
```

`name` の文字種を見ていない。本番実測。

```
name が既に日本語        646人（漢字364 / カタカナのみ282）
ローマ字で name_ja 未設定  1,799人
合計                     2,456人
```

試し焼きでも `ハニテリ・ヴァイレア` `ディック・ウィルソン` が対象に入り、同じ文字列がそのまま返ってきた。

## 国籍で判定しないこと（重要）

「日本人選手を除外する」を国籍やチームで判定する方式は**必ず破綻する**。

- マイケル・リーチは日本代表だがローマ字表記
- `Asaeli Ai Valu` はトンガ系の日本代表
- `Yoshimitsu Yasue` は `team_id` が null で国が引けない
- リーグワンには外国籍選手が多数いる

**heuristic を作らないこと。**

## 解き方: 出力の文字種で判定する

**モデルが漢字を出したこと自体が「日本人名を推測している」というシグナル。** それをそのまま検出条件にする。

```
生成結果が カタカナ・長音符・中黒・空白 のみ  → 採用
ひらがな・漢字・ラテン文字を含む            → スキップ（name_ja は空のまま）
```

国籍データも heuristic も不要で、決定的。

## やること

1. `name` が日本語文字を含む選手を候補から除外
2. 生成結果がカタカナ以外を含む場合はスキップ
3. 試し焼きの出力にスキップ人数と理由を表示

## 実装上の注意

**件数一致チェックの扱いを見直すこと。** 現在 `generated.length !== candidates.length` でエラーにしている。スキップを入れると件数が合わなくなる。

**「モデルが返さなかった」と「文字種で弾いた」は区別できる必要がある。** 前者は従来どおりエラー、後者は正常なスキップ。ここを一緒くたにすると、モデルの取りこぼしを見逃す。

## 絶対にやってはいけないこと

1. **外国籍選手向けの生成プロンプトを変えない。** 試し焼きで妥当性を確認済み
2. **国籍・チームによる heuristic を作らない**
3. **日本人選手の漢字を別の方法で埋めようとしない。** スキップして空のまま残す。確定できる情報源が要る話であり、本件の範囲外
4. **壊れた `name`（`AsaeliAi Valu` 等）を修正しない。** 別のデータ品質問題
5. **重複した選手行を統合しない**
6. **既存 `name_ja` を上書きしない挙動を壊さない**（PR #720 の結果）
7. **べき等性を壊さない**
8. **全件バックフィルを実行しない**
9. **モデル ID を直書きしない。** `MODELS.FAST`
