## やること

`app/api/discord/interactions/route.ts` の `/調査事実を追加` の保存のあと（今の `after()` の中）で、次の 3 条件をすべて満たすときだけ `generateMatchContent(matchId, "preview", "ja")` を呼ぶ。

1. 保存した事実の `content_type` が `preview`
2. この送信で新しく保存した事実が 1 件以上
3. その試合の日本語プレビュー（`match_content`、`status` が `published` か `draft`）がある

生成の前に返信を「保存しました。プレビューを作り直しています…」に更新し、終わったら結果（公開／公開中の版を残した／失敗と理由）を書き足す。

## 触るファイル

- `app/api/discord/interactions/route.ts`
- テスト（既存の Discord のテストに足す）

## 守ること

- 生成は既存の `generateMatchContent` を呼ぶだけにする（公開中の版を守る仕組みをそのまま使う）。
- 生成の失敗で、事実の保存を取り消さない。
- ルートの `maxDuration` が生成に足りない場合は `export const maxDuration = 300` にする（ほかの設定は変えない）。
- レビュー、英語、前日 15:00 の生成の時刻は変えない。

## 検証

- `pnpm lint`、`pnpm typecheck`、`pnpm test` を実行する（**3 つとも必ず実行し、結果を完了報告に含める**）。
- 「壊して落ちる」確認（コミットしない）: 条件 3 の判定を外すと、受け入れ条件 2 の「日本語プレビューがまだ無い」のテストが落ちること。内容と結果を PR 本文に書く。

## 追記（2026-09-26）: レビューにも広げる

仕様書の末尾「追記（2026-09-26）: レビューにも広げる」を正とする。保存した事実の `content_type`（`preview` / `recap`）と同じ種類の日本語の記事があれば、`generateMatchContent(matchId, <その content_type>, "ja")` で作り直す。レビューで整合ゲートにより生成が止まった場合（`status: "skipped"`）は、返信に「作り直しを見送りました: <理由>」と書く。受け入れ条件のテストもレビューの分を足す。
