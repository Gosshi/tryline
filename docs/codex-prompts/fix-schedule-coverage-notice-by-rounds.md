## これは PR #750 のやり直しです

PR #750 の「未取得の可視化」部分だけを、**判定方法を変えて作り直します。**

**PR #750 の取得窓シフト（`getTop14LnrForwardRoundSlugs`）とシーズン定数の是正は問題ありません。触らないでください。**

## なぜ作り直すか

PR #750 のプレビューで `/calendar?week=2026-10-26` に実際にこう出ました。

> シックスネイションズ **2021**・パシフィック・ネーションズカップ 2026の日程は開催が近づいてから掲載されます。

**5年前の大会が名指しされ、この作業の主題である Top 14 は出ませんでした。** `/c/top-14/2026-27` にも注記は出ませんでした。

原因は `lib/ingestion/live-ingest.ts:60`:

```ts
end_date: dates.at(-1) ?? null,   // dates = 取り込んだ試合のキックオフ日
```

**`end_date` は取り込んだ試合から作られます。** だからライブ取り込みの大会では `end_date === latestKickoffAt` が常に成立し、比較が真になりません。Top 14 はこの経路なので**構造的に検出できません**。

| 大会 | `end_date` | 取込最終 | #750 の判定 |
|---|---|---|---|
| six-nations/**2021** | 2021-10-30 | 2021-03-26 | **★載る** |
| pnc/2026 | 2026-09-19 | 2026-09-12 | **★載る** |
| **top-14/2026-27** | 2026-09-13 | 2026-09-13 | **載らない** |
| urc/2026-27 | 2027-05-15 | 2027-05-15 | 載らない（正しい） |

**`end_date` を判定に使わないでください。** spec 初版の「最終キックオフより後の週か」も同じ理由でだめでした（どちらも取り込んだ試合から導いた値だった）。

## 新しい判定（Owner 決定 2026-09-01）

```
未取得 = total_rounds が null でない
      かつ 取り込み済みの相異なる節数 < total_rounds
```

**基準（`total_rounds`）を、取り込みと独立したデータとして持ちます。**

### 本番実測（再調査不要）

節は `external_ids.round ?? external_ids.wikipedia_round`（整数）に入っています。

| 大会 | 試合 | 取込済みの相異なる節数 | 節の範囲 | 本来 |
|---|---|---|---|---|
| **top-14/2026-27** | 14 | **2** | 1〜2 | **26** |
| urc/2026-27 | 144 | 18 | 1〜18 | 18 |
| premiership/2026-27 | 90 | **17** | 1〜18 | **18**（第4節が丸ごと欠落） |
| greatest-rivalry / puma-trophy / rwc / lipovitan | — | **0** | なし | 節を持たない |

### 「最大の節番号」ではなく「相異なる節数」で比べてください

- Top 14: 最大2 < 26 → どちらでも拾える
- **プレミアシップ: 最大18 = 18 だが、第4節が欠落していて相異なる節数は17。** 最大値で比べると**中抜けを見逃します**

## マイグレーション

```sql
alter table public.competitions add column total_rounds integer;
```

**nullable が重要です。** 節を持たない大会は null のままにし、**null なら注記も「全N節」も出しません。**

投入するのは3件だけ。`family` と `season` の組で特定してください。

| family / season | 値 | 根拠 |
|---|---|---|
| top-14 / 2026-27 | **26** | `buildTop14RegularSeasonRoundSlugs()` が j1〜j26 を生成 |
| urc / 2026-27 | **18** | 144 ÷ 8 = 18。実測の範囲と一致 |
| premiership / 2026-27 | **18** | 実測の範囲が 1〜18 |

**他の大会・過去シーズンには投入しないでください。**

## 絶対に守ること

**`lib/ingestion/` から `total_rounds` を書き込まないでください。**

取り込みが基準値を上書きすることが、#750 と spec 初版が失敗した原因そのものです。受け入れ条件9で `grep -rn "total_rounds" lib/ingestion/` が0件であることを機械的に確認します。

## ついでに直るもの

`app/c/[competition]/[season]/page.tsx:133` の `getSeasonProgress` は、**取り込み済みの相異なる節数を「全N節」として表示しています。** そのため `/c/top-14/2026-27` は本番で **「0節 / 全2節」** と嘘をついています。

分母を `total_rounds` があればそれに変えてください。**分子（完了節数）の算出は変えないでください。**

- `/c/top-14/2026-27` → 「0節 / **全26節**」
- `/c/urc/2026-27` → 「0節 / 全18節」（現状維持）
- `total_rounds` が null の大会 → 表示を変えない
