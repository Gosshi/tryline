## 何を作るか

**日本代表戦の結果が Wikipedia に載らないと、レビューが永久に生成されません。**

2026-09-05 の日本×カナダは、試合終了から28時間経っても `status=scheduled` / score=null / レビュー未生成でした。取り込み元の ja.wikipedia が未記入だったためです（`lib/cron/orchestrate.ts` のレビュー生成は `status = "finished"` の試合しか対象にしません）。

**`https://www.rugby-japan.jp/schedule/` には 57–12 が出ています。** 日本代表の全試合が日付・対戦相手・スコアつきで並ぶ単一の URL です。これを**補完ソース**として足します。

## 既存コードの読みどころ

### 1. 同じページのパーサが既にある

`lib/scrapers/jrfu-match-broadcasts.ts` の `parseJrfuScheduleHtml` が `https://www.rugby-japan.jp/schedule/` を解析しています。**ただし取り出しているのは `matchUrls` と `year` だけで、スコアは見ていません。**

**セレクタの当て方（`.game-card a[href*='/match/']` 等）は参考にしてください。** ただし**そのファイルは変更せず**、新しいモジュールを作ってください。

### 2. 試合ごとのハードコードを繰り返さない

```
lib/scrapers/wikipedia-lipovitan-challenge-cup-results.ts:27
const JAPAN_FIJI_JRFU_URL = "https://www.rugby-japan.jp/news/54073";
```

**記事 ID は予測できないため、この方式では日本代表戦ごとに PR が必要になります。** 日程ページを使えば1本で足ります。**新しい記事 URL を足す方向に進まないでください。**

## 3つの必須事項

### 既存の結果を上書きしない

**次を全て満たす試合だけ更新してください。**

- `status` が `"finished"` **でない**
- `home_score` と `away_score` が**どちらも null**
- JRFU 側にスコアが**両方**入っている

**すでに結果がある試合には触らないでください。** 解析ミスで正しい結果を壊す事故を防ぐためです。**Wikipedia と食い違う場合は何もせず、ログに残すだけにしてください。**

### チーム名は明示的な対応表で解決する

JRFU の日程ページは日本語表記です（例: `リポビタンDチャレンジカップ2026　カナダ代表戦`）。

**文字列操作で対戦相手を導出しないでください。** 日本語表記 → `teams.slug` の対応表を定数で持ってください。

**過去に同じ形で失敗しています。** Top 14 の取り込みで、分割できないスラッグを分割して対戦チームを求めようとし、**機能しないコードが数か月放置されました**（`resolveTop14TeamsFromLnrSlug` → PR #742 で `TOP14_TEAM_SLUG_BY_LNR_NAME` の明示表に置換）。

**対応表に無い相手は、更新せずログに残してスキップしてください。** 推測で埋めないでください。

### 日付を主キーにしない（2026-09-06 訂正）

**指摘のとおり、JRFU の日程ページは現地時間で表示しています**（`※試合日時は現地時間を表示しています`）。当初の「JST で突合」は誤りでした。**停止して確認したのは正しい判断です。**

**会場のタイムゾーンを推定しないでください。** 次の規則で突合します。

1. 対戦相手を明示的な対応表で `teams.slug` に解決する
2. その相手と日本の試合のうち、**JRFU が示す日付から前後2日以内**にキックオフするものを候補とする
3. **候補がちょうど1件のときだけ更新する**
4. **候補が2件以上、または0件なら更新せずログに残す**

**前後2日にしているのは、現地時刻と UTC の差が最大でも1日のずれしか生まないためです。** 同一シリーズの連戦は7日以上離れており（2026年の日本×オーストラリアは 8/8 と 8/15）、この窓で取り違えることはありません。

**これでタイムゾーンの知識が一切不要になります。** 国内開催でも海外開催でも同じ規則で動きます。

## robots.txt

**`fetchWithPolicy`（`lib/scrapers/fetcher.ts`）を使ってください。**

`rugby-japan.jp` は許可ドメインです。**D026 の「robots.txt を参照しない」例外は Discord の出典 URL 存在確認に限った話で、ここには適用されません。**

**リクエストは1回だけ。** 日程ページ1枚に全試合が載っています。

## テスト

**パーサのテストは実際の HTML 構造に基づいて書いてください。** 手作りの最小 HTML はフィクスチャとして通っても実データで壊れます（`feedback_scraper_test_fixture_realism`）。

覆ってほしいケース。

- スコアあり → 抽出できる
- スコアなし（未実施の試合）→ 更新対象にしない
- 対応表に無い相手 → スキップし、表記がログに出る
- **海外開催で JRFU の日付が DB のキックオフ日と1日ずれる**ケース → 正しい試合に紐づく
- **同一相手との連戦**（8/8 と 8/15 のような7日差）→ 窓内に候補が1件だけ入る
- **候補が2件以上**→ 更新せずスキップし、ログに出る
- **既に `finished` の試合** → 触らない
- 片方だけスコアがある → 更新しない
