# Codex 指示書: recap が「試合前の順位」を捏造する問題

仕様書: `specs/fix-recap-standings-delta-fabrication.md`
受け入れ条件は仕様書を正とする。ここでは繰り返さない。

## 直したいこと

プロンプトが**入力に存在しない値**（試合前の順位）を書けと要求している。
`competition_standings` は現在値のスナップショット1枚しか持たず、before が無い。
モデルは指示に従って before を作り出し、捏造ゲートに弾かれて draft 止まりになる。

実際に出た本文:

> 試合前の順位表ではトゥールーズが1試合を終えて勝ち点1の10位、ヴァンヌが勝ち点0の13位だった。

**差分を要求するのをやめ、現在値として言えることだけを言わせる。**

- `lib/llm/prompts/generate-recap.ts`
- `tests/llm/prompts/generate-recap.test.ts`

`lib/llm/stages/assemble.ts` は触らない。`lib/llm/stages/qa.ts` の閾値も触らない。
preview 側のプロンプトとテストも触らない。

## 書いてよいこと / 書いてはいけないこと

| | 例 |
|---|---|
| 要求してよい | 「この試合を終えた時点で◯位」「勝ち点◯」 |
| 要求してはいけない | 「試合前は◯位だった」「◯位から◯位へ上がった」「順位を上げた/下げた」 |

さらに `:341` の禁止列挙
（`"入力にない統計・スコア・負傷・欠場・発言・選手名を推測・創作してはならない。"`）に
**順位・勝ち点・試合前の順位を加える**。ここに順位が無かったことが素通りの一因。

## 処理すべきエッジケース

1. `:94` の見出しを変えるなら `:101` の字数目標側も同じ名前にする。**両方で同じ文字列**にすること
2. `:103` に「上記5つの見出し以外は絶対に追加してはならない」という制約があり、
   禁止見出しの例示を列挙している。見出し名を変えたら整合を確認する
3. 出力セクションは 5 つのまま。増やさない・減らさない
4. 字数目標（450-550字）は維持する。順位の話を削った分を他で埋められるよう、
   セクションの内容指示は残すこと
5. `competition_standings` が空の大会（pnc-2026 は 0 行）でも破綻しないこと。
   PNC の recap は現在 `factual_grounding: 5` で published なので**退行させない**
