# Codex 指示: 大会ガイドの参照情報検索クエリを family 単位で上書き可能にする

## 仕様書

`specs/feat-competition-guide-search-query-override.md` を読んでから着手すること。以下は補足であり、仕様の置き換えではない。

## 何が問題か（一文）

`searchContext` の検索語が **`nameJa` から機械的に組み立てられている**ため、**新設大会だと「歴史」を検索しても直近の報道しか返らず、「伝説の名場面」セクションが今シーズンの試合で埋まる。**

## 実際に起きたこと（2026-08-18、実生成）

`greatest-rivalry` のガイドを生成したら、「伝説の名場面・選手」4 項目のうち **2 項目がこのツアーの直近試合**になった。

```
✓ 1996年の南アフリカ長期遠征        … 両国の対戦史。妥当
✓ ハカと対峙するスプリングボクス      … 両国の対戦史。妥当
✗ 2026年8月7日 ストーマーズ戦       … このツアーの試合。しかもフランチャイズ戦
✗ 8月11日 シャークス戦（ノヌ）       … 同上
```

さらにストーマーズ戦の項目に **「13人となる時間帯を耐え」** とあったが、**本番の `match_events` にこの試合のカードは 1 件も無く裏付けが取れなかった。**

**1995年 RWC 決勝も 2013年エリスパークも、両国の古典的名場面は 1 つも入らなかった。**

Owner が該当箇所を手で削って公開したため、現在の伝説セクションは **2 項目**しかない（プロンプトの要求は 3〜5）。

## context では直らない理由

PR #703 で `context` に「ツアーの歴史ではなく両国の対戦史を扱う」というリダイレクトを既に入れてある。**それでも半分しか効かなかった。**

**`context` はプロンプトを直せるが、検索結果は直せない。**参照情報に両国の対戦史が無い状態で、厳守事項が「参照情報に無い年号を書くな」と縛るため、モデルは手元の材料（ツアー報道）に寄る。

**直すべきは検索語のほう。**

## 先に実読すべきファイル

| ファイル | 何を確認するか |
|---|---|
| `tools/generate-competition-guides.ts:8-12` | `CompetitionGuideFamily` 型。ここに足す |
| 同 `:60-68` | `searchContext`。**`${nameJa} ラグビー 歴史 有名試合 伝説的選手 エピソード` の組み立て** |
| 同 `:76`, `:81` | プロンプトのセクション3が年号・スコアを要求し、厳守事項が参照情報外を禁じている板挟み |
| 同 `greatest-rivalry` のエントリ | 既存 `context`。**消さない** |

## やること

1. `CompetitionGuideFamily` に検索クエリ上書き用のフィールドを追加
2. `searchContext` が上書きを使う。**未指定なら従来どおり**
3. `greatest-rivalry` に上書きクエリを設定

上書きクエリは**大会名ではなく対戦カードを主語にする**こと。例:

```
オールブラックス スプリングボクス ラグビー 歴史 名勝負 伝説的選手 エピソード
```

英語（`All Blacks Springboks rugby history famous matches legendary players`）のほうが良い参照情報を得られる可能性がある。**採否は判断してよいが、英語を使う場合は既存プロンプトの引用制限（15語超の直接引用禁止）との兼ね合いを確認すること。**

## 絶対にやってはいけないこと

1. **既存 11 家族の検索語を変えない。** 上書きを設定するのは `greatest-rivalry` のみ
2. **`greatest-rivalry` の既存 `context` を削除しない。** 検索とプロンプトの両方から寄せる
3. **プロンプト本文（セクション構成・厳守事項）を変えない**
4. **`numResults` / `maxCharacters` を変えない**
5. **生成を実行しない。** スクリプト変更とテストまで。再生成と検品は Owner
6. **テストで実 API を叩かない。** Exa / OpenAI クライアントはモックする
7. **モデル ID を直書きしない。** `MODELS.NARRATIVE`
8. 手修正済みの `supabase/seeds/competition-guides-greatest-rivalry.sql` を書き換えない
9. `nations-championship` に手を付けない（同種の弱点がある可能性は高いが、まず `greatest-rivalry` で方式を確立する）

## テストで押さえる点

**回帰防止が核心。既存 11 家族の検索語が変わると全ガイドに影響する。**

- **上書きなしの family → 従来の `${nameJa} ラグビー 歴史 有名試合 伝説的選手 エピソード` がそのまま Exa に渡る**
- 上書きありの family → その文字列が Exa に渡る
- `numResults` / `maxCharacters` が従来値で渡る
