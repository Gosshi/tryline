# Codex 指示: プレビューのラインアップ羅列を止め、根拠を伴う言及だけを残す

## 仕様書

`specs/fix-preview-roster-enumeration.md` を読んでから着手すること。以下は補足であり、仕様の置き換えではない。

## 何が問題か（一文）

プロンプトが**人数のノルマ**（「最低3名」）を課しているため、モデルは背番号と名前を並べるだけでそれを満たし、**記事の4分の1が同じページにある表の言い直しになっている。**

## 実際に公開された本文（2026-08-21、QA 情報密度 5/5）

```
## 前方の密度と9番・10番の選択が攻撃の輪郭を決める
南アフリカは1番オックス・ンチェ、2番マルコム・マークス、3番ウィルコ・ラウを先発させ、
4番エベン・エツベト、5番ルアン・ノーチェが続く。後方には9番グラント・ウィリアムズ、
10番サーシャ・ファインバーグ＝ムンゴメズル、12番ダミアン・デアレンデ、13番ジェシー・クリエル、
14番チェスリン・コルビ、15番ダミアン・ヴィレムセが並ぶ。ベンチには16番…
```

**約25名の列挙で1,944字中およそ500字。**

- `components/match-lineups-section.tsx` が**同じページに同じ情報を表で出している**
- 見出しは「9番・10番の選択が…」と約束しているのに、本文は誰が出るか並べただけ
- このセクションで情報があったのは「ホランドがトゥイプロトゥに代わる唯一の変更」の一文のみ

## 重要: 文言を足すだけでは直らない

`lib/llm/prompts/qa-content.ts:125` には**既にこう書いてある。**

```
単なる列挙や不自然なこじつけは反映として数えないこと。
```

**それでも情報密度 5/5 が付いた。** だから本件は決定的なガードで解く。プロンプト修正は補助であって主軸ではない。

## 検出ロジックの考え方

- 本文を `。` で文に分割
- 1文に「背番号＋選手名」のペアが**3つ以上**あれば**列挙文**
- 列挙文の合計文字数が本文に占める割合が閾値超で検出

**閾値は判断してよいが、以下2つを必ず満たすこと。**

- 上に引用したセクションを含む本文が**検出される**
- 「2名の実名＋それぞれの起用理由」の段落が**検出されない**

**PR 本文に、選んだ閾値・根拠・上記2ケースの実測値を書くこと。**

背番号の表記ゆれ（`9番` / `九番` / `No.9`）は**実データを見てから**対応範囲を決める。現行の生成物に出る表記だけで足りる。

## 絶対にやってはいけないこと

1. **「最低3名」を「最低N名」に置き換えるだけにしない。** 人数の下限がある限り羅列で満たされる。**下限そのものを外す**
2. **選手名への言及を禁止しない。** 根拠を伴う言及は**増やしたい**
3. **`components/match-lineups-section.tsx` に触らない。** 表は正しい。重複しているのは本文のほう
4. **`sourcedFactsBlock` の「できるだけ多く反映」を撤回しない。** PR #709 の結果は維持する
5. **`is_starter` の先発・リザーブ区別を消さない**
6. **`projected_lineups` / `match_events` に無い選手名を創作しない禁止を消さない**
7. **片側だけラインアップがある場合の片側限定ルールを消さない**
8. **`qa-content.ts:125` の既存文言を削除しない。** 具体化して足す
9. **recap と英語 preview の出力を変えない**
10. **`lib/llm/content-length.ts` に触らない**
11. **既存記事を再生成しない。** コードとテストまで
12. **モデル ID を直書きしない。** `lib/llm/models.ts`
