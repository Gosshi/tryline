## 何が起きているか

**Top 14 2026-27 は開幕節から1試合もスコアが入っていません。**

```
節   試合  finished  スコアあり
j1     7        0         0     ← 開幕節、9/5 に終了済み
j2     7        0         0
j3     7        0         0
```

**lnr.fr の j1 には7試合すべてがスコア付きで載っています**（`Aviron Bayonnais 27 - 26 RC Toulon` など、2026-09-07 確認）。取り込みは毎回走り、現在節も `j1` のままです。**パーサが1件も返していません。**

## 原因は2つ

### 1. 日付のセレクタが実在しない

```ts
lib/scrapers/top14-lnr-results.ts:277-285
.closest(".calendar-results__line")
.prevAll(".calendar-results__fixture-date")   ← 実HTMLに0件
```

`.calendar-results__line` は存在しますが、**`.calendar-results__fixture-date` はありません。** `findFixtureDateContext` が null を返し、`kickoffAt` が null になり、**`if (!kickoffAt) return;`（`:349`）で7試合すべてが捨てられています。**

日付はページにあります。**`.calendar-results__inner`（試合行の2つ上の親）のテキスト先頭に `Journée 1 samedi 05 septembre` として入っています。**

### 2. 時刻が存在しない

```ts
lib/scrapers/top14-lnr-results.ts:239-243
const time = ... .match(/^(\d{1,2})h(\d{2})$/);
if (!date || !time) return null;
```

**`.match-line__time` は空文字です**（実測）。**セレクタを直して日付が取れても、時刻が無いため null を返し続けます。**

現在の節ページに試合開始時刻の表記は見当たりません。

## 直すこと（3点）

### 日付の取得元を変える

**`.calendar-results__inner` のテキストから取ってください。** ただし**そこには全試合ぶんが連結されている**ので、**先頭の日付表記だけを取り出してください。**

**`parseDateParts` は変更しないでください。** `05 septembre` を解釈し、`monthIndex >= 7` からシーズン開始年（2026）を補う既存のロジックがそのまま使えます。

**同じ節に複数の日付がある場合を確認してください。** Top 14 は金〜日に分かれることがあります。**日付の区切りが複数あるなら、試合ごとに直近の日付を引く形にしてください。1つと決めつけないでください。**

### 時刻が無くても捨てない（2026-09-07 確定・当初案を撤回）

**既定時刻を使わないでください。既存の `kickoff_at` を保持してください。**

**「00:00 Europe/Paris を既定値にする」という当初の推奨は誤りでした。指摘は正しいです。**

`lib/ingestion/upsert.ts:77` は **`kickoff_at: candidate.kickoffAt` で無条件に上書きします。** 既存の照合は `top14_lnr_id` で先に行われるので試合は正しく特定されますが、**その直後に時刻が既定値で塗り替えられます。**

**現在 DB にある時刻は Wikipedia 由来で正しい値です。**

| | 現在 | 00:00 Paris を適用 |
|---|---|---|
| UTC | 2026-09-05 17:05 | 2026-09-04 22:00 |
| **JST** | **9/6 02:05** | **9/5 07:00** |

**JST で丸1日ずれます。** カレンダーの週の割り当てが狂うだけでなく、`cron-weekend-preview-refresh` と `cron-post-match-recap-refresh` は **JST の日付で対象を絞っている**ため、リフレッシュの割り当ても壊れます。

**採用する方式**

- **日付が取れていれば試合は取り込む**（スコアと `status` を更新する）
- **時刻が取れない場合、`kickoff_at` は既存の値を保持する**
- **DB に既存の試合が無く、かつ時刻も無い場合は取り込まない**（`kickoff_at` を捏造しない）。スキップしてログに残す

**`lib/ingestion/upsert.ts` に「時刻が無ければ既存を保持する」分岐を入れてください。** `keepExistingFinishedScore` と同じ形にできます。

**この変更は他大会にも影響します。** `kickoffAt` は現在必須の文字列なので、**任意にする場合は全ソースの呼び出しを確認してください。** 影響を避けたい場合は Top 14 の経路でのみ既存値を引き回す形でも構いません。**方法は問いませんが、他大会の `kickoff_at` の挙動を変えないでください。**

### 0件を異常として検知する

**節ページに要素があるのに返却が0件なら `console.warn` を出してください。**

**開幕から2日、誰も気づけなかった原因はここです。** 診断が `unknownTeamNames: []` と `0件` しか返さず、どこで落ちたか分かりませんでした。

- 最終的な**返却数**
