## 何が問題か

`/c/rwc/2027/bracket` は 200 を返しますが、常に `PendingState` を表示します（`app/c/rwc/2027/bracket/page.tsx:69`）。

`matches` は `round !== null && round >= 5` で絞られます（`:45-47`）。しかし**本番の RWC 2027 は 36 試合すべて `round` が null** です（2026-09-09 実測）。

```
round=null   36 件   2027-10-01 〜 2027-10-17
```

`round` は DB 列ではなく `external_ids.round` / `external_ids.wikipedia_round` から導出されます（`lib/db/queries/matches.ts:513-516`）。ノックアウトの試合が 1 件も入っていないので、**フィルタは必ず 0 件になります。**

そして `PendingState`（`:17-30`）の文言はこれだけです。

```
ノックアウトステージの対戦表を準備中です。
```

**実際には状態が 2 つあり、意味が全く違います。**

| 状態 | RWC 2027 での実際 |
|---|---|
| チーム未確定 | プール戦が 2027年10月なので当然まだ決まらない。**正常であり直しようがない** |
| 日程未取得 | ノックアウトの日程は公表されているが DB に 0 件 |

前者を「準備中」と書くと、大会の性質上そうであるだけのことが、サイトの遅れに見えます。

## やること

`PendingState` を状態で分けてください。

| 条件 | 表示 |
|---|---|
| ノックアウト0件 かつ プール戦未終了 | **チーム未確定**である事実 + プール戦の日程（36試合ある）+ いつ確定するか |
| ノックアウト0件 かつ プール戦終了済み | **未取得**である事実 + 確認状況 |
| ノックアウト1件以上 | 現状どおり `KnockoutBracket` |

`competition` が取得できない場合（`:35-42`）の `PendingState` も、上と混ざらないようにしてください。

プール戦の終了判定は既にある 36 試合の `status` と `kickoff_at` から決定論的に行ってください。**現在日時をハードコードしないでください。**

「いつ確定するか」は **DB にあるプール戦の最終 `kickoff_at`（2027-10-17）から導いてください。文言に日付を直書きしないでください。**
