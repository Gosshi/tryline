すべて JST。作成 2026-09-14。 一次情報は .github/workflows/cron-*.yml / vercel.json / lib/cron/preview-window.ts / docs/chatgpt-prompts/README.md。

最初に読むこと — cron は名目時刻どおりに走らない

GitHub Actions の cron は実測で1〜10時間遅延する。2026-09-14 の月曜 09:05 の回は 実際には 13:47 に走った。本書の時刻はすべて名目値である。

したがって「実行時の時計が21時台か」で分岐する実装は採ってはいけない。 遅延した回が永久に条件を満たさず、生成が止まる。判定は必ず「直近に過ぎた境界」で行う。

D. 修正内容

1. レビューの初回生成を後ろ倒しする

候補選択に上限を1つ足す。2条件の AND。

条件意図
kickoff_at ≤ now − 12時間 試合直後は各社の記事が存在せず、自動取得が空振りする。
※実測では経過時間と取得件数に相関は無く、支配要因は大会だった（Top 14 は119時間待っても1〜3件）。 件数が増える根拠は無い。試合直後の空振りを防ぐ安全弁として置く。
kickoff_at ≤ 直近の20:30 − 2時間 ChatGPT の調査枠（18:00、締切20:30）が終わってから生成する。
−2時間は試合時間の見込み。matches に終了時刻の列が無いため、推定をここ1箇所に閉じ込める。

2. プレビューをキックオフ24時間以内に限定する

現在は「前日 15:00」固定のため、キックオフ時刻によって9.5〜33時間前とばらつく。 翌日23:00の試合は32時間前に確定し、多くの協会のメンバー発表（24〜48時間前）より前になる（D030 の背景が指摘した問題）。

3経路のうち orchestrate の候補選択にだけ入れる。 audit-prekickoff-readiness と matches-with-late-lineups は 「前日15:00 までに生成されるべきだった試合」を探す用途なので、24時間に狭めると点検漏れ・救済漏れになる。

3. ChatGPT のレビュー枠に月曜を足す

既存タスクの発火日を1日増やすだけで、ChatGPT のスケジュール枠は消費しない。 月曜未明の試合はその月曜から始まる週のページに載るため、 プレビュー側の土曜のような2ページ読みは不要。
