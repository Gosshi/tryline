### 第1週（10/12〜10/18）：購入導線の穴をふさぐ

**T1 認証後に購入を再開する（P0）**　spec: `specs/fix-auth-purchase-intent-return.md`
- 変更：
  - `PricingForm` → `AuthModal` → callback の順に、購入意図（`intent=subscribe`）と戻り先（`next`）を引き継ぐ。Google と Magic Link の両方で行う。
  - callback で `next` を検証する。`/` で始まり、`//`・`/\`・`@` を含まない相対パスだけを許可し、それ以外は `/` にする。
  - 購入意図付きで戻ってきたら、Checkout を作成する（決定A）。
  - 既に Premium（`hasPremiumAccess`）の人は Checkout を作らず、`/account` に戻す。
- 完了条件：
  - 単体テストで次を確認する。
    - 両方の方式で `redirectTo`／`emailRedirectTo` に `next` が入る。
    - 不正な `next` 6種が `/` になる。
    - Premium の人は Checkout が作られない。
  - Owner が Vercel プレビューでテストモードを使い、Magic Link で Stripe テスト Checkout の画面まで到達する（購入はしない）。
- 規模：Codex 1〜2日。依存なし。
- **結果（2026-10-11）：** PR #933 マージ。本番で3ケース（Magic Link・Google・既存 Premium）を確認済み。Google ログインは Supabase で無効のままだったため、同日 Owner が有効化した。追加修正（`auth_error` の持ち越し・`begin_checkout` と `sign_up` の取りこぼし・ログイン失敗の案内）は `specs/fix-auth-return-followups.md`。

**T2 不正な形式の試合IDで500になる不具合（既存の残タスク）**　spec: `specs/fix-invalid-match-id-404.md`

- **結果（2026-10-11）：** PR #932 マージ。本番で9通りの URL が期待どおりになったことを curl で確認した。

**T6 試合ページの登録状態を診断する（Claude・読み取りのみ）── 2026-10-11 実施済み**
- Codex の固定50件（`tmp/tryline-revenue-audit-20261011/sample-50.csv`）に GSC の URL 検査をかけた。結果は `inspection-50-claude-merged.json`。

| Google の分類 | 件数 | 試合からの日数（中央値） | 30日以内 |
|---|---:|---:|---:|
| 登録済み | 38 | 598日 | 0 |
| 未認識（URL が Google に認識されていません） | 11 | 28日 | **6（30日以内の6件すべて）** |
| クロール済み・未登録 | 1 | 728日 | 0 |

- 宣言した canonical と Google が選んだ canonical の不一致は0件。
- 登録済み38件のうち、直近56日に表示が出たのは9件だけ。**古い試合は登録されているが、検索されていない。**
- **新しい試合は1か月たっても Google に見つかっていない。** 例：日本対米国（`1e74662b…`、28日前）は今期 H2H で最も検索された対戦なのに、試合ページが未認識。
- **GSC のサイトマップ記録では、Google が最後に `sitemap.xml` を読んだのが 2026-06-08（4か月前）。** 当時の送信数は3,076件で、現在は1,563件。サイトマップは 200 を返し、`robots.txt` にも記載がある。登録済みの古い試合の `lastmod` が 2026-06-13 前後に集中していることと矛盾しない。
- 結論：試合ページの改修（品質・構造化データ・文字数）は不要。直すのは「新しい URL を Google に読ませること」。→ T6b

**T6b 新しい試合ページを Google に見つけてもらう（Owner 1分＋Claude 読み取り）**
- Owner：GSC（URL プレフィックスのプロパティ）の「サイトマップ」で `sitemap.xml` を再送信する。API のサービスアカウントは読み取り専用なので、Claude からは送信できない。
- Claude：10/25 に、未認識だった11件と、直近14日に公開した試合から20件を URL 検査する。サイトマップの最終読み込み日時が更新されたかも見る。
- 再送信しても読み込み日時が動かない、または新しい試合が未認識のままなら、原因を調べる spec を作る（候補：サイトマップの容量・応答時間、Google の巡回頻度、ホームや大会ページから新しい試合へのリンク）。
- 注意：`gsc-pull --inspect matches` は sitemap の先頭（更新日が新しい順）から取るので、全体の割合の推定には使わない。
