# 日次運用 SOP — 「判断だけする」体制の回し方

> 作成: 2026-07-04。Owner の日次運用を「毎朝 /today → 承認キューを処理 → 終了」に一本化するための手順書。
> 関連: `.claude/skills/today/SKILL.md`（司令塔スキル）/ `tools/ops/codex-queue.sh` / `docs/ai-team-guide.md`

## 毎朝の手順（目安 15 分）

1. Claude Code を開いて `/today` と打つ（または「今日のやること」）
2. 出てきた「本日の承認キュー」（最大5件）を上から判断する
   - 承認 → その場で「1 は承認、pr-merge で」「2 の reply 出して」のように指示。実働は各スキルが行う
   - 保留 → 「3 は明日」でよい。/today が翌日また拾う
3. 終わり。**スキル名を覚える必要はない**（/today が委譲先を提示する）

## 何が自動で仕込まれているか（クラウド routine）

| routine | 発火（JST） | 成果物 | 回収方法 |
|---|---|---|---|
| note週次まとめドラフト | 月曜 7:00 | `draft: note週次まとめ` の PR | 月曜の /today が検品して承認キューに乗せる |
| 週末ニュースダイジェスト | 金曜 18:00 | `draft: 週末ニュースダイジェスト` の PR | 金曜夜〜土曜の /today が検品・reply ネタ化 |

- 管理画面: https://claude.ai/code/routines （停止・削除はここから）
- routine はクラウド実行のため**ローカルの鍵（GSC/Supabase）は使えない**。公開ページ経由で読める情報のみ扱う設計
- 期待日に PR が無い → /today が「発火していない可能性」を警告する。管理画面で実行履歴を確認する

## 週内のリズム

| 曜日 | 自動（routine） | Owner の判断（/today 経由） |
|---|---|---|
| 月 | note ドラフト PR が朝に届く | note 公開可否・GA4 数字の異変確認 |
| 火〜木 | — | Codex PR のマージ可否・reply 投稿可否 |
| 金 | ニュースダイジェスト PR が夕方に届く | ダイジェスト採用・週末 reply の仕込み |
| 土日 | — | 試合結果ポストの可否（x-post が下書き） |

## Codex パイプラインの見方

```bash
bash tools/ops/codex-queue.sh        # 直近21日
bash tools/ops/codex-queue.sh 60     # 遡り日数を変える
```

状態ラベルの意味と次のアクション:

| 状態 | 意味 | 次のアクション |
|---|---|---|
| PR オープン（レビュー待ち） | Codex が実装済み | `codex-review` → マージ判断 |
| Codex 待ち（プロンプト作成済み） | Owner が Codex に貼るだけ | `docs/codex-prompts/<slug>.md` を Codex に貼る |
| spec のみ（プロンプト未作成） | 委譲プロンプトが未作成 | 「Codex に渡すプロンプトを」（`codex-handoff`） |
| ブランチあり・PR なし（要確認） | 中断 or PR 化忘れの可能性 | ブランチを見て、続けるか捨てるか判断 |
| マージ済みらしい（ログ一致） | 完了と推定（文字列一致の推定） | 通常は何もしない |

> 判定はファイル名・ブランチ名・コミットメッセージの突合によるヒューリスティック。疑わしいときは `git log --grep=<slug>` で裏取りする。

## 止まったときのトラブルシュート

- **/today が数字を出せない** → GA4 MCP の認証切れが多い。数字はスキップされるので運用は止まらない。必要なら `growth-analysis` で個別取得
- **codex-queue.sh がエラー** → `gh auth status` を確認。gh が死んでいても spec 一覧部分は動く
- **routine が2週連続で PR を作らない** → 管理画面の実行ログを確認し、プロンプト修正はこの会話で「routine を更新して」と言う（/schedule 経由で更新可能）

## この体制の原則（再掲）

- 実行（投稿・公開・マージ・課金）はすべて Owner の承認後。AI は下ごしらえまで
- 数字は実測のみ・期間明記。取れなかったら「取得できず」
- 週5時間・毎日10分の枠を超える運用提案はしない
