# AI チーム（スキル・サブエージェント）の使い方

> Claude Code に整備したプロジェクトスキル 23 本とサブエージェント 3 体の使い方。定義の実体は `.claude/skills/<name>/SKILL.md` と `.claude/agents/<name>.md`。
> 整備日: 2026-07-02（初期6本）/ 2026-07-03（一括整備）。

## 基本の使い方

- **スキル**: Claude Code との会話で下表の「起動フレーズ」を言うだけ。`/x-reply` のようにスラッシュで明示指名もできる。スキル = そのタスクの手順書・制約・過去の教訓が焼き込まれた指示書で、Claude が自動で読み込んで従う
- **サブエージェント**: 基本は Claude が必要と判断したときに自分で使う。明示的に使わせたいときは「◯◯（agent名）でやって」と言う。メイン会話のコンテキストを消費せずに重い作業（多ページ監査・Web調査・並行レビュー）を外出しするためのもの
- **全メンバー共通の権限境界**: 実行（投稿・送信・マージ・課金操作）は Owner の許可制。実装コードは Codex。本番（Supabase/GA4/GSC）は読み取り専用

## よく使うフロー（スキルの連携例）

1. **機能開発**: 「◯◯を設計しよう」(`spec-writing`) → 「Codex に渡すプロンプトを」(`codex-handoff`) → Owner が Codex に貼る → 「実装したから確認して」(`codex-review`) → 「問題なければマージして」(`pr-merge`)
2. **月曜の週次運用**: 「今週の運用タスク」(`weekly-ops`) → note ドラフト(`note-weekly`) → 公開後の reply 転用(`x-reply`)
3. **画像作成**: 「◯◯のサムネ案を」(`image-gen`) → 出てきたプロンプトを Gemini/ChatGPT に貼って生成 → 画像をこの会話に貼る → 検品 → 採用なら `public/visuals/` へ保存
4. **事故対応**: `prod-investigation`（調査）→ Codex が修正 → `incident-postmortem`（振り返り）→ `decision-log`（記録）

## 定期実行（クラウド routine）での自動化

Claude Code に「routine を設定して」「◯◯を毎週自動でやって」と言うと、cron スケジュールのクラウドエージェントを設定できる（管理画面: https://claude.ai/code/routines ）。

**制約（重要）**:
- クラウド実行のため**ローカルの秘密情報が使えない** → `growth-analysis`（GSC鍵）と `prod-investigation`（Supabase）は自動化不可。本番サイト（公開ページ）経由でデータを読む設計なら可
- クラウドは GitHub からリポジトリを checkout する → **スキル定義が main にマージされていることが前提**
- 成果物は「ブランチにコミットして PR を開く」形で届く。投稿・送信は従来通り Owner
- 1回の実行 = 1クラウドセッション分の使用量。最初は1〜2本推奨

**実現性の目安**: ◎ = note 週次ドラフト（サイト経由で結果取得）・ニュースダイジェスト（WebSearch のみ）/ ○ = コンテンツ品質チェック（公開ページ経由）/ ✗ = GSC/GA4 実測（秘密情報が必要。対話セッションで実行する）

## スキルの追加・変更

- スキル: `.claude/skills/<name>/SKILL.md`（frontmatter に `name` と `description`。description の「〜と言われたら起動」が発火条件になる）
- サブエージェント: `.claude/agents/<name>.md`（frontmatter に `name` / `description` / `tools`）
- 変更したら次のセッションから自動反映。Claude Code に「◯◯のスキルを作って/直して」と頼めばよい
