現行 — やわらかモダン

本番と同じ

本番 /calendar の再現。日付は左の濃色チップ、試合は幅いっぱいの白カード。 チーム名の終端から時刻までの空白が本番実測で 542〜696px（カード幅1008pxの54〜69%）。デスクトップでは行の半分以上が空きます。 大会名が全行に出るため、同じ大会が7行続く日は同じ文字列が7回繰り返されます。

候補A — 密なプロダクト表

density: compact

ブランドは変えません。配色（#c93a40）も書体（Zen Maru Gothic + Outfit）も角丸トークンも現行のまま、 密度と桁揃えだけを変えます。時刻を左の固定列に置いて同時刻の試合をひとつの時間帯にまとめ、 大会は色の細バーで示します。10月31日の「09:00 JST」の7回の繰り返しが1回になり、 大会名を毎行書かないぶんチーム名が行の主役になります。

候補B — 週ボード

calendar as calendar

情報の並べ方そのものを変える案。「今週の試合カレンダー」を実際にカレンダーとして、開催日を横に並べます。 やわらかモダンの角丸・影・白カードはそのまま使うので、ブランドの見え方は現行に最も近いまま。 週全体が一望でき、「今週末どれを見るか決める」という実際の用途に直結します。 弱点も正直に出しています——1日に7試合ある日は列が伸び、列の高さが揃いません。

ユナイテッド・ラグビー・チャンピオンシップ プレミアシップ 視聴情報あり

候補B3 — 略称を主・正式名を従

採用

「チーム名を JPN のようにして、正式名を下に小さく」という案。Owner が採用（2026-09-01）。 固定幅のラテン文字が左端に揃うので視線の足がかりができ、実測でも一番短く、一番多く1画面に入ります。
当初この案には実データ由来の欠陥が2つありましたが、両方とも下記のとおり潰した状態で描画しています。

時刻はすべて日本時間（JST）

潰した欠陥①: 略称の重複。 当初この週には LEI が2回出て、10/30 がレンスター、10/31 がレスター・タイガースを指していました。 本番 teams 91件のうち重複は LEI（レンスター／レスター・タイガース）と CHI（チリ／チーフス）の2組、略称なしが2件（ホンコンチャイナ・ジンバブエ）。 マイグレーションで直す前提で、ここではレスターを TIG（Tigers）として描いています。
潰した欠陥②: 正式名の切れ。 当初はスラッシュ区切りの1行で、 「ブリストル・ベアーズ / レスター・タイガース」（23文字）と「サラセンズ / ニューカッスル・ファルコンズ」（22文字）の2件が省略記号になっていました。 略称を知らない人ほど長い名前で困るのに、そこで保険が切れるため、正式名を2行に分けました。
正式名は「必要なときだけ折り返す」形にしています。14件中12件は1行のまま、長い2件だけが2行になります。 2行固定にすると 648px・1画面目10/14 まで後退しますが、この形なら 575px・12/14 で収まります。
残る前提: 代表（JPN・NZL）はともかく、URC・プレミアシップのクラブ略称は読者の前提知識になります。ここは実データでは検証できません。

候補B4 — バッジを固定アンカーに

対案

B3 の狙い（左端に固定幅の足がかりを作る）はそのままに、略称を文字として増やさない案。 略称は既存の TeamBadge（大会カラーの丸に3文字）の中に入れます。これは現行の試合カードで既に使われている部品です。
・左端が22pxで揃うので視線の足がかりができる ・略称が重複しても色と名前で区別できる ・文字数は B2 と同じ 186 のまま（バッジ内の文字は読むものではなく形として効く）

時刻はすべて日本時間（JST）

1日開催の週をどう出すか

要判断

86週のうち14週（16%）が1日開催で、そのうち6週は1試合・4週は2試合。稀な例外ではありません。 週ボードは「開催日を横に並べる」設計なので、日が1つだと並べるものがなく、幅1152pxに対して列が1本しか立ちません。
実データ2週で3つの処理を比べます。データは加工していません。

この比較で決めたいこと

これはブランド変更の比較ではありません。3案とも同じ色・同じ書体・同じ角丸トークンを使っています。 違うのは spacing と density と layout —— まさに現行の design.md が 1行も定義していない3つの軸です。

どれを選んでも design.md には spacing.scale / spacing.density（mobile と desktop で別値）/ layout.breakpoints / layout.listRow の節を新設する必要があります。 refero から別スタイルを持ってきても、この空欄は埋まりません。

「現行のまま」も正当な選択肢です。その場合に受け入れることになるのは、 14試合週での長いスクロールと、1画面目に試合が1件も入らないデスクトップ表示です。

2026-09-01 の決定（最終）: 候補B3 を実装対象とする。 B2 の文字削減を土台にしたうえで、チーム名を略称（3文字）を主・正式名を小さく従にする。 実測: 575px / 1画面目 12 / 14 / 正式名の切れ0件 / 略称の重複0件。 前提として 本番の short_code を2件直すマイグレーションが必要（レスター・タイガース→TIG、チーフス→CHF、 未設定のホンコンチャイナ→HKG・ジンバブエ→ZIM）。

2026-09-01 の中間案: 候補B2。 B の「文字が多くて見るのがしんどい」への対応として作成し、B3 の土台になった。会場は出さない。文字数は B の573文字（会場込み）から 264文字へ54%削減し、高さは 500px → 559px（余白を広げたぶん微増）。 チーム名の省略（ellipsis）は0件で、全91チーム最長15文字まで収まることを実測で確認済み。
