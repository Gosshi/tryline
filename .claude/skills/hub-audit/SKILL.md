# 大会ハブ監査

検索の着地点・回遊の起点である大会ハブページを、**大会開幕の3〜4週間前**に監査する。根拠: GSC 実測で流入が発生しているのは大会ページのみ（平均順位10.4位・PNC 2026 でクリック発生。`docs/marketing-strategy-2026-07-06.md` §2・§4）。検索需要は「いま試合がある大会」に発生するため、開幕前の整備が最も費用対効果が高い。

## 開幕カレンダー（監査トリガー）

| 時期 | 対象 | 監査期限 |
|---|---|---|
| 開催時期未確定 | Rugby's Greatest Rivalry（`docs/decisions.md` D011。従来のラグビーチャンピオンシップ2026は不開催、その後継大会。ハブは別途 Owner が作成予定） | ハブ作成後、判明した開幕日の3〜4週間前 |
| 2026年9〜10月開幕 | Premiership / URC / Top 14 | 2026年8月末 |
| 2027年2月開幕 | シックスネーションズ 2027 | **2026年12月中（1月から検索が立ち上がる年間最大の商戦）** |
| 2027年2月開幕 | スーパーラグビー・パシフィック 2027 | 2027年1月中 |
| 2027年10月開幕 | RWC2027 | `rwc2027` スキルが専任 |
| 進行中大会（NC / PNC 等） | 各ラウンド終了時に軽く（順位表・recap リンク切れ） | — |

## 理想形チェックリスト（1ハブにつき）

- [ ] title が「{大会名} {年} 日程・順位・結果【日本時間】」型で、狙うクエリ（`docs/marketing-strategy-2026-07-06.md` §4 の表）と一致しているか
- [ ] 日程が日本時間で表示され、全試合が試合ページへ内部リンクしているか
- [ ] 順位表が最新か（データ欠落があれば `prod-investigation` で原因調査）
- [ ] 視聴方法セクションがあるか: 放送局・配信・「YYYY年M月時点」の明記。**放送権は変動するため四半期に一度 WebSearch で確認**
- [ ] 直近結果→recap、次節→プレビューへの内部リンクが生きているか（3層構造: ハブ→試合→recap）
- [ ] 構造化データ（SportsEvent）と FAQ(「どこで見られる？」「何時から？」)があるか
- [ ] GSC で対象大会クエリの現在順位・インプレッションを記録（Before 値。効果測定用。取得は `growth-analysis` の手順）

## 手順

1. 対象ハブを WebFetch / Playwright で実測（スクショはスクロール位置を反映しない点に注意 — 断定前にソース確認。`feedback_screenshot_audit_caveat`）
2. チェックリストの不足を列挙
3. 実装が必要なものは spec 化候補として Owner に提示（`spec-writing` へ。**勝手に spec を作らない**）
4. 監査結果は `docs/notes/` にメモ（数値は実測値＋期間を明記）

## 制約

- このスキルは**読み取り専用**。実装は Codex（spec 経由）
- 視聴方法・日程の事実は一次ソース（放送局・大会公式）で裏取りする。推測で書かない
- UI の変更を提案する前に `git log --oneline -- <path>` で過去の判断を確認（`feedback_spec_history_check`）
