# Codex 委譲プロンプト作成

仕様書完成後、Owner が Codex に貼るプロンプトを作る。

## 手順

1. **テンプレートを使う**: `docs/codex-prompts.md` に公式テンプレートがある（仕様書実装 / 小さな個別変更 / バグ修正 / リファクタリング）。これをベースにする。
2. **保存場所**: `docs/codex-prompts/<spec名と同名>.md` に保存する（既存例多数あり。命名を揃える）。
3. **原則**:
   - 仕様書ファイルをパスで参照し、内容をインラインで繰り返さない
   - 入出力の具体例を 1〜2 個示す
   - Codex が処理すべきエッジケースを列挙する
   - 「完了」の定義を明確にする（テスト、変更されるファイル、実行コマンド）
   - 参考にすべき既存コードのパターンをファイルパスで指す（`lib/llm/stages/`、`lib/db/queries/` など）
   - ビジュアル/UI/動画等の目視評価を伴う成果物は、参照デザイン・使用トークン（サイト系なら `app/globals.css` の CSS変数）・「避けるべき表現」を明記し、完了の定義にスクリーンショットや生成物の提出を含める

## プロンプトに必ず含める定型

- `AGENTS.md` の規約に従う（`CLAUDE.md` は Claude Code 向けなので Codex には指定しない）
- 曖昧な箇所や仕様書と実環境の食い違いがあれば、その場で実装を停止して Owner に確認する（実装後に末尾で質問しない）
- スコープ対象外は実装しない
- 受け入れ条件に対するテストを書く（`tests/` 配下の既存構成に倣う）

## 完了後

Owner に「このプロンプトを Codex に貼ってください」と伝え、実装が返ってきたら `codex-review` スキルでレビューする流れを案内する。
