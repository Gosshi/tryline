## 振り返りの型（5項目・簡潔に）

1. **何が起きたか**: 影響範囲を数字で（件数・期間・ユーザー影響）
2. **タイムライン**: 混入 → 検知 → 復旧の各時点。検知が遅れた理由も
3. **根本原因**: 「ミス」で止めない。型に分類（制約の矛盾 / ガード欠如 / 記録欠如 / 一括実行 / 検証不足）
4. **再発防止**: 下記の落とし先3種から選ぶ
5. **うまくいったこと**: 復旧を早めた要因も1つは書く（次回も再現するため）

## 再発防止の落とし先（3種の使い分け）

- **コード/パイプラインのガード** → `spec-writing` で Codex へ（最も強い。人が忘れても機械が止める）
- **decisions.md** → `decision-log` スキルで（Owner・Codex も読むプロジェクト公式記録）
- **メモリ / スキル更新** → Claude 自身の作業手順を変えるもの（例: 試し焼き必須、fetch してから比較）

「気をつける」で終わる再発防止は書かない。**必ず上記どれかの仕組みに落とす。**

## 保存

レポートは `docs/postmortem-<事象>-YYYY-MM-DD.md`。軽微なものはメモリ更新＋decisions.md 追記のみでもよい（Owner と相談）。
