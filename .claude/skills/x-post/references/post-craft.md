# X投稿の構成と作例

2026-09-12のOwner提供文を編集上の参考にする。以下の実名入り抜粋は文体の例であり、出場・日数・開催情報を検証した記録ではない。別の投稿へ数字や選手情報を流用しない。新たな調査や投稿の権限はこの資料から生じない。

## まず中心の話を選ぶ

手元の根拠から「誰の、何が、今特別なのか」を一文にする。復帰、同じポジションの対決、シリーズの決着、日本でなじみのある選手などから、今回の読者にとって最も具体的な軸を選ぶ。使わない材料は削ってよい。ニュースが薄い日は短い事実投稿にする。

Owner例の「リッチー・モウンガ、1051日ぶりにオールブラックスの10番へ。」は、人物・時間の隔たり・役割が一文で分かる。狙うのはこの具体性であって、毎回「○日ぶり」を探すことではない。

## 材料がある試合前投稿の流れ

これは構成の候補。すべての段落を必須にせず、主役や試合に合わせて順序も変える。

1. **フック**: 一番強い確認済み事実。固有名詞と変化を早く出す。
2. **観戦の足場**: JSTの日付・曜日・キックオフ、対戦カード、必要なら会場やシリーズ何戦目か。
3. **事実の重み**: 前回出場や役割の変化を示し、何が特別なのかを説明する。
4. **対決と勝敗の意味**: 相手の具体名、シリーズ制覇など今回の結果で決まること。
5. **比較できる根拠**: 同じ条件の少数の数字と、その範囲で言える意味。
6. **日本のファンとの接点**: リーグワンで知られる選手など、中心の話を深める材料。名簿の網羅は不要。
7. **冒頭を受ける結び**: 復帰した選手の何を見るか、シリーズがどう動くか。最後に内容の分かるCTA。

読み返したとき、各段落が「なぜ今この試合を見るのか」を深めているか確認する。「注目の一戦です」「目が離せません」で済ませた箇所は、具体的な対決や条件へ置き換えるか削る。

## 数字を読み物にする

数字は見せる前に意味を決める。比較は本文で読める改行で表し、横幅を必要とするMarkdown表は使わない。

```text
直近5試合の平均は、

得点
NZ 34.8
南ア 32.6

失点
南ア 22.2
NZ 26.4

この5試合では、得点はNZ、失点の少なさは南アが上回ります。
```

上記の数値はOwner提供例の抜粋で、確認済みデータではない。実際の投稿では対象5試合、基準日、各スコア、計算を確認する。対戦相手が違う平均値は直接対決の予測や戦術の証明にならない。「取るNZ、止める南ア」と圧縮するなら、直近5試合の得失点に限った表現だと近くに示す。僅差を「圧倒」と書かない。

数字がない場合も成立させる。確認済みのメンバー変更とシリーズ状況だけで軸を組み、平均値や負傷理由を補完しない。

## 強い表現ほど根拠を確かめる

- **「○日ぶり」**: 起点・終点と時差を確認して暦日差を計算する。テスト出場、先発、10番での先発を混同しない。日数が未確認なら、確認済みの「○年W杯以来」までに留める。
- **キャップ数・先発**: 現在の通算と出場すれば到達する数を区別する。メンバー発表後でも試合前は「先発予定」「出場すれば○キャップ目」など時点に合う表現にする。
- **負傷・欠場**: 欠場の確認と理由の確認を分ける。診断や復帰時期、心理、勝敗への影響を推測で加えない。
- **勝敗条件**: シリーズの現在成績と規定を確認する。2勝2敗という算術からトロフィー共有まで推測しない。引き分けなど未確認の分岐を消して二者択一にしない。
- **「日本でおなじみ」**: 所属・在籍時期と当該試合での先発/控えを確認する。過去のリーグワン在籍を現在所属に読み替えない。
- **日程・情報鮮度**: JSTの月日・曜日・時刻が一致するか、延期や直前のメンバー変更がないかを許可された経路で確認する。本文と画像で対象試合を揃える。

Ownerが提供しただけの事実、一次資料で確認した事実、算出値、解釈を編集メモで区別する。確認不能でも残せる事実から下書きを進め、欠損をもっともらしい語りで埋めない。

## 投稿の種類に合わせて変える

- **試合後**: 結果と最も意味のある事実を早く示す。試合前の「どちらが勝つか」は使わず、確認できる転機と次戦の注目点へ進む。得点経過だけで戦術の成功や失敗を断定しない。
- **単一ニュース・公式発表**: 発表内容と日本のファンへの意味を短くつなぐ。対決や統計の段落を無理に足さない。
- **note告知**: 記事で答える問いと、本文で得られる発見を一つ示す。記事の答えを誇張せず、全文の圧縮や単独URL告知にしない。

URL配置・タグ・文字数・出力形式は親のSKILL.mdに従う。文体例の末尾にURLや3タグがあることを配置ルールとして扱わない。
