# 意思決定の記録・参照（decisions.md）

`docs/decisions.md` を意思決定の単一の正とする運用。**記録しない判断は数週間後に必ず再発明される**（2026-07-03 の実例: 「大会ガイドは折りたたまない」がコミットメッセージにしか残っておらず、同じ折りたたみを再導入して本番リグレッションになった）。

## 追記の型（D0XX 形式）

```markdown
## D0XX: <決定の一行要約>（YYYY-MM-DD）

**決定**: <何をすることにしたか / しないことにしたか>
**背景**: <何が起きて判断が必要になったか。事故由来なら事象を1行で>
**理由**: <選んだ理由と、捨てた選択肢>
**再検討の条件**: <何が変わったらこの決定を見直すか（任意）>
```

番号は既存の最大値+1。既存の書式と大きくずれる場合は既存に合わせる。

## 記録すべき判断の基準

- UI/UX の「やらない」判断（例: 折りたたまない・自動投稿しない・英語化しない）— **コードから消えると痕跡が残らない**ため最優先で記録
- チャネル・運用の方針転換（X reply 運用の目標下方修正等）
- 一度やって戻したこと（revert には必ず理由を残す）

書かなくてよいもの: コードを読めばわかる実装詳細、spec に書いてある内容の重複。

## 参照の手順（「前に決めたっけ？」への答え方）

1. `docs/decisions.md` を grep
2. **無ければ git log も掘る**: `git log --oneline --all -i --grep=<キーワード>` と対象ファイルの `git log --oneline -- <path>`。コミットメッセージにだけ残っている判断がある（メモリ `feedback_spec_history_check`）
3. git log で見つかった「隠れた判断」は、その場で decisions.md への追記文案を出して Owner に確認する（サルベージ）

## 関連

- 戦略判断の壁打ちは `biz-strategy`（決定に至ったらこのスキルで記録）
- メモリ（`~/.claude` 配下）は Claude 個人の作業記憶、decisions.md はプロジェクトの公式記録。**Owner・Codex も読む判断は必ず decisions.md 側に**
