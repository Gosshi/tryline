# ラグビーニュース・情報調査

WebSearch / WebFetch で海外ラグビーの一次情報を調査し、用途（reply 素材 / note 素材 / 壁打ち）に合わせて要約する。**これは Claude Code の手動調査であり、パイプラインのスクレイパーとは別物**（スクレイパーに新ソースを足すのは `specs/feat-web-sourced-facts.md` の allowlist 管理に従い、必ず spec 経由）。

## 調査の作法

1. **一次情報を優先**: 大会公式（premiershiprugby.com、sixnationsrugby.com、super.rugby 等）、クラブ公式、World Rugby。二次（RugbyPass、BBC Sport 等）は補助
2. **出典を必ず記録**: すべての事実に「ソース URL + 確認日時」を添える。出典のない情報は使わない
3. **確度を区別**: 公式発表 / 複数ソース一致 / 単一ソースの報道 / 憶測、をラベル分けして返す
4. **日本語ソースも見る**: rugby-rp.com（ラグビー共和国）、J SPORTS コラム等。日本語圏でまだ話題になっていない情報は reply・note の差別化ネタになる

## 引用・再配信の制約（CLAUDE.md 準拠）

- **直接引用は15語以内・1ソース1回まで**。原則言い換え
- 記事の全文・段落丸ごとの転載は出力にも含めない
- 調査結果を Tryline のコンテンツ（recap/preview）に直接流し込まない。パイプラインに乗せる事実は sourced_facts の仕組み（allowlist・出典必須）経由のみ（`specs/fix-sourced-facts-zero-fabrication.md`）

## 用途別の出力

| 用途 | 形式 |
|------|------|
| X reply 素材 | 事実1つ＋出典。140字で使える形に圧縮（`x-reply` スキルへ渡す） |
| note 素材 | 見出し案＋裏取り済み事実のリスト（`note-weekly` スキルへ） |
| 試合前の予習 | 両チームの直近ニュース・負傷/出場停止・注目マッチアップを箇条書き |
| 壁打ち・戦略 | 大会の構造変化（放映権・フォーマット変更等）は `biz-strategy` に接続 |

## 注意

- 負傷・移籍情報は変化が速い。**確認日時を必ず明記**し、古い調査結果を再利用しない
- 選手の私生活・スキャンダル系は扱わない（プロダクトのトーンに合わない）
- ニュースにある統計値も「そのソースがそう報じている」として扱い、Tryline の DB 実データと混同しない
