# note-weekly

共通参照: [運用方針と測定基準](../today/references/operating-baseline.md)。

`docs/decisions.md` D017/D019を正とする。A型は当面note継続、B型は停止、C型は判断保留。旧タイプのテンプレート・月次KPIを実行手順に残さない。停止済み施策を自動で再提案しない。

## 執筆
1. セッション内にあるOwnerの論点・一次情報・未確定事項を使い、不足する必須情報だけを聞く。未入手の一次情報を作らない。独立して進められる出典整理は先に行う。
2. 当該match_idのスコア、match_events、match_sourced_facts、previewを読取専用で照合する。得点経過はproduction-data-integrityで整合確認されたものだけを使う。player_id未解決でもmetadata.player_nameを確認する。
3. 1記事1つの問い、強い確認済み事実→論点→根拠と解釈→次戦への含意を組む。見出しごとに数字を義務化して欠損を埋めない。得点変化だけで戦術因果を断定しない。
4. 本文は日本語で言い換える。recap全文を転載せず、15語超・同一ソース複数回の直接引用をしない。外部数値は承認済みのsourced_facts、またはOwnerが明示提供した出典を確認方法とともに使う。自動取得allowlist外の手動事実を一律に無効としない（D026）。URLが200というだけでは事実の裏取りにならない。
5. 画像はOwner撮影で利用可能なもの、またはimage-genで作る記事固有の案。表の代わりにnoteで読める本文/箇条書きを使う。

## タイトル・導入・本文のつなぎ方

Ownerが2026-09-12に示したX文例の「具体的な人物・事実で入り、背景を重ね、冒頭の関心へ戻る」書き方をnoteにも活かす。Xの改行密度や試合前の煽りをそのまま長くせず、読者が一つの問いへの答えを持ち帰れる記事にする。今回の改善はA型の文章に適用し、海外戦プレビューや停止中のB/C型へ掲載対象を広げない。

- **タイトル**: チーム・選手などの具体名と、その試合で確かめたい問い/変化を組み合わせる。「日本代表戦を振り返る」だけでは終えない。「敗因」「勝因」「なぜ」と因果を約束するタイトルは本文にその根拠がある場合だけ使う。根拠が得点経過だけなら「どこで点差が広がったか」のように答えられる問いにする。
- **導入**: 最も強い確認済み事実やOwner提供の具体的な観戦場面→結果や背景→この記事で答える問いを、数段落で示す。一般的な大会説明を長く続けず、初見の読者にも対戦相手と結果が分かるようにする。現場の空気、選手の内心、見ていないプレーを創作しない。
- **本文**: 「何が起きたか→根拠→どこまで言えるか」を一まとまりにする。数字の羅列で止めず意味を説明し、得失点と戦術因果を分ける。試合全体を時系列で再掲せず、問いに答える場面を掘る。
- **対比**: 前半/後半、期待/実際、両チームの違いは比較条件を揃える。主張に合わない事実も扱い、数字で「圧倒」「完敗」などを過剰に演出しない。リーグワンとの接点は今回の論点に役立つときだけ使う。
- **見出しとリズム**: 「試合概要」「まとめ」だけで済ませず、その節で分かることを具体的に書く。短い段落でつなぎ、一文ごとの改行や問いかけの連発を避ける。見出し数・文字数を埋めるための背景説明は足さない。
- **結び**: 冒頭の問いに根拠の範囲で答え、未確定の部分と次戦で観察したい点を分ける。「今後に期待」で終わらず、読者が次の試合で見る対象を示す。記事の答えは本文内で渡し、TrylineのCTAには追加で確認できる情報を具体的に書く。

タイトル案は切り口の違う3本を標準とし、推奨案を選んで本文を完成させる。Owner指定があれば案数を合わせる。タイトルが約束する内容を本文が回収しているか、知らない試合でも導入だけで論点が分かるかを読み返す。閲覧や拡散の伸びを保証する言葉は使わない。

## 公開用の完成形
本文へ主CTA（当該試合）とカレンダーのフッターリンクを組み込む。Trylineへのリンクだけにutm_source=note&utm_medium=referralを付け、既存クエリとの連結を確認する。ドラフトは`docs/notes/YYYY-MM-DD-deep-dive.md`。
親投稿はx-post、告知返信はx-replyへ渡す。返信が別アカウントで見えると確認できたときだけ返信にURLを置き、未確認/不可視なら親投稿本文へ置く。本文URLの既存回数制約は維持する。B/C型の親投稿を作らない。
公開・送信はOwner。タイトル案と推奨理由1文、推奨タイトルの本文、出典、画像、URL配置が完成した状態で渡す。コピペ用本文と編集メモを分け、メモにはOwner提供情報/確認済み事実/解釈の区別、確認日、残る未確認事項を示す。確認できない数字・場面・URLを公開用本文へ混ぜない。
