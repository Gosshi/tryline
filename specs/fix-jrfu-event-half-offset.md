# JRFU の得点経過が後半で1分に戻る問題を直す

## 背景

**2026-09-06 に本番で、誤った得点経過からレビューが生成され公開された。**

`feat-jrfu-match-event-fallback`（PR #778）で日本×カナダの `match_events` 18件を投入したが、**分数がすべて前半の範囲（1'〜43'）に収まっていた。** 実際には80分の試合で、カナダの2トライ目は60分である。

そこから生成されたレビューは次のように書いた。

| 生成された本文 | 実際 |
|---|---|
| 1分、原田衛のトライで先制 | **5分、岡部崇人** |
| **前半を48―12で折り返した** | **31–7** |
| 後半もカナダを無得点に封じた | **60分にベン・ルサージュがトライ** |

**QA は `verdict=publish` / `density=5` で通過した。** 公開後に発見し、`match_content` を `draft` に戻して `match_events` を削除した（通知は飛んでいなかった）。

## 原因

**JRFU の試合ページは前半と後半で分数を振り直している。**

実フィクスチャ（`tests/fixtures/jrfu-match-29975.html`）の `.time` を出現順に並べると、こうなる。

```
前半: 5' 6' 15' 16' 19' 19' 22' 22' 27' 27' 42' 43'
後半: 1' 2' 8' 8' 8' 9' 11' 11' 11' 16' 18' 18'
```

**後半が 1' から再スタートしている。** パーサは両セクションを区別せず `.time` の数値をそのまま `minute` に入れたため、**後半のイベントが前半の中に混ざった。**

ページには `前半` / `後半` の見出しが存在する（実測で `前半` 3箇所・`後半` 2箇所）。

## 整合チェックが機能しなかった理由

`feat-jrfu-match-event-fallback` は**イベント合計とスコアの一致**を投入条件にした。

**合計は 57–12 で一致していた。** チーム配分も正しかった。**壊れていたのは時系列だけで、合計では検出できなかった。**

**これは spec の欠陥である。** 「合計が合っていれば順序も正しい」という前提を置いていた。

## もう1つの見落とし

**投入された18件すべてで `player_id` が `null` だった。** `resolvePlayerId` が1件も引けていない。

`feat-jrfu-match-event-fallback` は受け入れ条件13で「選手が解決できなくても投入を続ける」と定めた。**個別の未解決を許すのは妥当だが、全件未解決は解析が誤っている兆候である。** これも検出条件にすべきだった。

## スコープ

対象:
- 後半の分数にオフセットを加える
- **整合チェックをハーフタイムスコアまで広げる**
- **全件の選手未解決を異常として扱う**

対象外:
- `lib/llm/pipeline.ts`（ゲートは正しい）
- `lib/scrapers/jrfu-match-broadcasts.ts`
- `lib/ingestion/jrfu-result-fallback.ts` のスコア補完
- 得点種別の判別（`icon-try` / `icon-conversion` / `icon-pg` / `icon-dg` は正しく動いている）
- `supabase/`

## 1. 後半にオフセットを加える

**セクションを `前半` / `後半` の見出しで判別し、後半の分数に 40 を加えること。**

- 前半の `43'` は前半のロスタイムであり、**そのまま 43 とする**（40 を超えても前半なら加算しない）
- 後半の `1'` は **41** になる
- 後半の `18'` は **58** になる

**オフセット値 40 を定数として定義すること。**

**見出しが見つからない場合は、その試合をスキップしてログに残すこと。** 推測でセクションを分けない。

### 期待される結果（検証に使う）

日本×カナダ（`match_id = 63b2d83f-db46-42f0-a1ed-59c2d8a39ec7`）で、後半の得点が **41分以降**に並ぶこと。特に**カナダの2トライ目が 58〜60分の範囲**に入ること。

## 2. ハーフタイムスコアも検証すること

**投入前に、前半終了時点のスコアが妥当かを確認すること。**

現時点で DB にハーフタイムスコアの列は無い。**したがって外部の期待値と突き合わせることはできない。** 代わりに次を確認する。

- **前半のイベントだけで計算した小計**と、**全イベントの合計**の両方を求める
- **合計が `matches.home_score` / `away_score` と一致する**（既存の条件、維持する）
- **前半の小計が合計を超えていない**
- **後半にオフセットを加えた結果、分数が単調非減少になる**（同一分の複数得点は許す）

**単調性が崩れたら投入しないこと。** 今回の破壊はまさに単調性の違反として現れる（後半の 1' が前半の 43' の後に来る）。

**ハーフタイムスコアを DB に保存するかは本 spec の対象外。**

## 3. 全件の選手未解決を異常として扱うこと

**イベントが1件以上あるのに `player_id` が解決できた件数が0の場合、投入しないこと。**

ログに次を出す。

- イベント件数
- 解決できた件数（0）
- 解決を試みた選手名の一覧

**部分的な未解決は許す。** 全件未解決だけを異常とする。

**今回18件すべてが未解決だった原因の調査は本 spec の対象外。** ただし**投入を止める条件としては入れる。**

## 受け入れ条件

1. **後半の分数に 40 が加算される**
2. オフセット値が**定数として定義されている**
3. **前半のロスタイム（40 を超える分数）に加算されない**
4. **`前半` / `後半` の見出しで判別している**
5. 見出しが見つからない試合は**投入せずスキップし、ログに残る**
6. **オフセット適用後の分数が単調非減少であることを検証している**
7. **単調性が崩れた試合は1件も投入せずスキップし、ログに残る**
8. 同一分の複数得点が単調性違反として扱われない
9. **前半の小計が合計を超えていないことを検証している**
10. 既存の「合計が `home_score` / `away_score` と一致する」条件が**維持されている**
11. **イベントが1件以上あって解決できた選手が0件のとき、投入せずスキップする**
12. そのとき**イベント件数・解決件数・試みた選手名**がログに出る
13. **部分的な未解決では投入が続く**（既存の挙動を維持）
14. 得点種別の判別（`icon-try` / `icon-conversion` / `icon-pg` / `icon-dg`）に差分が無い
15. ペナルティトライのスキップ処理に差分が無い
16. `lib/llm/pipeline.ts` に差分が無い
17. `lib/scrapers/jrfu-match-broadcasts.ts` に差分が無い
18. `lib/ingestion/jrfu-result-fallback.ts` のスコア補完に**振る舞いの変更が無い**
19. `supabase/` に差分が無い
20. `counts` に**見出し判別失敗・単調性違反・全件未解決**の3つが追加されている
21. **既存のフィクスチャ（`tests/fixtures/jrfu-match-29975.html`）を使ったテストが、後半の分数が 41 以降になることを検証している**
22. テストが次を覆っている: 後半オフセット / 前半ロスタイムに加算しない / 見出しなし → スキップ / **単調性違反 → 投入しない** / **全件未解決 → 投入しない** / 部分未解決 → 投入継続 / 合計不一致 → 投入しない
23. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` がすべて clean

## 検証方法

**本番で日本×カナダの `match_events` を再投入し、分数を目視で確認する。**

現在の状態（2026-09-06 時点）。

| | |
|---|---|
| `matches` | `finished` / `57-12` |
| `match_events` | **0件**（誤ったものを削除済み） |
| `match_content` recap/ja | **`draft`**（誤った本文が残っている） |

**マージ後、デプロイが READY になってから実行すること。** マージ3分後に実行して古いデプロイに着弾させた失敗が同日にある。

確認するのは次の3点。

1. `match_events` が18件入り、**後半の得点が41分以降**にある
2. **カナダの2トライ目が 58〜60分**にある
3. レビューが再生成され、**前半のスコアが 31–7 と書かれている**

**3が満たされなければ、`draft` のまま止めること。**

## 未解決の質問

- **18件すべてで選手が解決できなかった原因。** 本 spec は投入を止めるだけで、原因は調べていない。JRFU の表記（`岡部崇人` のような姓名間の空白なし）と `players` の格納形式が合っていない可能性がある。**別途調査が必要**
- **ハーフタイムスコアを DB に持つか。** 持てば外部の期待値と突き合わせられるが、`matches` への列追加が必要になる
- **`draft` に残った誤った本文をどうするか。** 再生成が成功すれば上書きされるが、失敗し続ける場合は手で消すか放置するかを決める必要がある
