# fix-mobile-ios-audit-findings-batch1: iOS自律監査で確認したUI不具合（束1）

対象リポジトリ: **tryline-mobile**。`fix-mobile-story-swipe-worklet-crash` とは独立で並行実装可。

## 背景

2026-07-22〜23、mobile-mcp（iOS Simulator を実際に操作する MCP サーバー）を使った自律型 UI 監査（Claude Sonnet）の指摘のうち、ソースコードで裏取りが取れた 4 件を修正する。監査自体の一次指摘には誤診断も含まれていたため（後述「対象外」）、本 spec は実コード確認済みの項目のみを対象にする。

## スコープ

対象:

1. **大会詳細画面に戻る手段がない**: `app/(tabs)/competitions/[slug].tsx` は `app/(tabs)/competitions/_layout.tsx` で `headerShown: false` が指定されており、ネイティブ戻るボタンが出ない。画面側にも独自の戻るボタン実装がなく、iOS のエッジスワイプでしか前の画面に戻れない
2. **マッチストーリーの出典リンクがタップに反応しない**: `src/stories/MatchStoriesSection.tsx` の出典リンク（553-568行目、`testID="story-source-link"`）は `onPress` 自体は正しく実装されている（`Linking.openURL` を呼ぶ）。しかし後続に描画される全画面ナビゲーション用タップゾーン（580-599行目 `tapAreas`、スタイル上 `bottom: 96` まで到達）が、出典リンクを含む `storyTextPanel`（817-823行目、`bottom: 112` から上に伸びる可変高さ）と垂直方向で重なっており、JSX 上で `tapAreas` が後続の兄弟要素のため、タップがストーリー送り用のゾーンに奪われていると推定される
3. **スポイラーガードがイベントタイムラインに効いていない**: `src/matches/MatchDetailScreen.tsx` 87-99行目のイベントタイムラインは、スコアのマスク状態（`masked` / `isRevealed`、53-55行目で `spoilerGuard` から算出）と無関係に常時全件描画される。得点者名・分数がそのまま見えるため、スコアはマスクされていても結果が逆算できてしまう
4. **週送り後もホーム見出しが更新されない**: `app/(tabs)/index.tsx` 32行目の `<Screen ... title="今週のラグビー">` が固定文字列で、`weekOffset`（前週/今週/翌週の状態）を反映していない

対象外:
- Match Stories スワイプの worklet 違反（`fix-mobile-story-swipe-worklet-crash` で別途対応）
- 順位表の国名行タップの挙動（監査自体が「仕様か不明、要追加調査」としており本 spec では扱わない。次回の判断材料として記録のみ）
- 順位表の空状態メッセージ不整合（未検証、優先度低のため別途）
- **ホーム空状態の「翌週を見る」CTA**: 監査は「上部セグメントの翌週ボタンは動くのに CTA 側だけ反応しない」と報告したが、ソースコード確認では両者が完全に同じハンドラ（`app/(tabs)/index.tsx` 37行目・50行目、`setWeekOffset((current) => current + 1)`）を呼んでおり、`EmptyState` の `action.onPress`（`src/components/States.tsx` 37行目）への配線にも問題が見当たらない。誤検出（タップ座標のずれ等）の可能性が高いため本 spec の対象外とし、実機での再現確認が取れてから必要なら別途 spec 化する

## UI サーフェス（修正内容）

1. **戻る導線**: `[slug].tsx` に戻る手段を追加する。ヘッダーを表示して標準の戻るボタンを使うか、画面内に独自の戻る Pressable（`router.back()`）を置くか、実装方法は Codex の裁量。大会一覧からの遷移・大会詳細内の別大会への遷移、どちらの経路でも機能すること
2. **出典リンクの重なり解消**: `tapAreas`（`previousTapArea` / `nextTapArea`）と `storyTextPanel` の重なりを解消する。対応方針例（Codex の裁量で選択可）:
   - `storyTextPanel` の実高さ分だけ `tapAreas` の `bottom` を大きくし、垂直方向の重なりをなくす
   - または出典リンク（`storySourceLink`）が確実にタップを受け取るよう、タップゾーン側の当たり判定を除外する
   いずれの方法でも、出典リンクタップで `Linking.openURL` が呼ばれることと、ストーリーの前後送りタップ操作が引き続き機能することを両立させる
3. **スポイラーガードのタイムライン適用**: イベントタイムライン全体を `isRevealed`（または同等の開示状態）でガードする。非開示時は選手名・分数を表示せず、`ScoreText` と同じ `onReveal` / `revealMatch` を使った開示導線に統一する。開示後（`isRevealed === true`）は現状通り全件表示する
4. **週見出しの動的化**: `Screen` の `title` を `weekOffset` に応じて切り替える（例: 前週 = 「先週のラグビー」、今週 = 「今週のラグビー」、翌週 = 「来週のラグビー」。文言は Codex の裁量で、既存の日本語表現に揃える）

## データモデル変更 / API サーフェス / LLM 連携

なし。

## 受け入れ条件

1. 大会詳細画面から戻る操作（ボタンタップ）で、iOS のエッジスワイプに頼らず前の画面へ遷移できることを確認するテストまたは手動確認手順
2. マッチストーリー内で出典リンクをタップすると `Linking.openURL` が正しい URL で呼ばれることを確認するテスト。かつ同じ画面でストーリーの左右送りタップが引き続き機能することを確認する回帰テスト
3. スポイラーガード有効・未開示の試合詳細で、イベントタイムラインに選手名・分数が表示されないことを確認するテスト
4. スポイラーガード解除後（`isRevealed === true`）は、修正前と同じくイベント全件が表示されることを確認する回帰テスト
5. `weekOffset` が -1 / 0 / 1 のそれぞれでホーム画面見出しが対応する文言になることを確認するテスト
6. TypeScript strict・lint・test green
7. **Owner 目視**: 実機または iOS Simulator で上記 1〜4 の解消をスクリーンショットまたは操作で確認する

## 未解決の質問

- 出典リンクの重なり解消方法（タップゾーンの縮小 or 当たり判定の除外）は、Codex の実装を見て Owner が最終確認する
- 順位表の国名行タップの挙動・空状態メッセージ不整合は本 spec 未対応。再現確認の上、必要なら別途 spec 化するかを Owner が判断する
