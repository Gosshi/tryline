# 代表チームとクラブを区別し、ツアー中のテストマッチを判別できるようにする

## 背景

2026-08-23〜09-13 の Greatest Rivalry Tour 2026 は、**南アフリカ代表とのテストマッチ 4 戦**と、**南アフリカのフランチャイズとのツアー戦 4 戦**が 1 つの大会に混在している。

大会ハブ `/competitions/greatest-rivalry-2026` の日程表では、**この 2 種類が完全に同列に並んでいる。**

### 実測（2026-08-18、本番 DB）

この大会に登場する 6 チーム。

| slug | name_ja | country | world_ranking | flag_code |
|---|---|---|---|---|
| south-africa | 南アフリカ | ZAF | 1 | 🇿🇦 |
| new-zealand | ニュージーランド | NZL | 2 | 🇳🇿 |
| bulls | ブルズ | ZAF | null | 🇿🇦 |
| lions | ライオンズ | ZAF | null | 🇿🇦 |
| sharks | シャークス | ZAF | null | 🇿🇦 |
| stormers | ストーマーズ | ZAF | null | 🇿🇦 |

**`teams` に代表とクラブを区別するカラムが無い**（全カラム: `id / slug / name / short_code / country / logo_url / external_ids / created_at / updated_at / english_name / name_ja / world_ranking / world_ranking_updated_at / flag_code`）。

さらに **4 フランチャイズすべてに `flag_code: 🇿🇦` が入っている。** ハブ上では南アフリカ国旗を掲げた「ストーマーズ」が「南アフリカ」と並ぶため、**訪問者には両方が代表チームに見える。**

### なぜ困るか

- **テスト第1戦（8/23）がツアー戦と同じ重みで表示される。** シリーズの山がどこか分からない
- 大会ガイドで文章として説明しても（`feat-generate-competition-guide-per-family`）、**日程表そのものが誤解を生む構造は残る**
- Bing 流入の 86% が大会ハブに着地し滞在 107 秒。**ハブは実質的な入口**で、ここでの誤解は直接効く

### 既存の代用手段が使えない理由

`world_ranking is not null` で代表を判定できそうに見えるが、**使ってはいけない。**

`world_ranking` は `scripts/ingest-world-rankings.ts` が投入する値で、**ワールドランキングに載らない代表チームは null になる**。取り込み失敗時も null になる。**「ランキングが無い代表」を club と誤分類する**ため、判定の根拠にできない。

## スコープ

対象:
- `teams` に種別カラムを追加するマイグレーション
- 既存 91 チームのバックフィル
- 大会ハブの日程表で、テストマッチとツアー戦を視覚的に区別する
- `lib/format/competition.ts` の `COMPETITION_FAMILY_COLORS` に `greatest-rivalry` を追加
- 上記に対応するテスト

対象外:
- **`flag_code` の値の変更**（フランチャイズから国旗を外すかは別途判断。所在国を示す用途もありうる）
- 試合詳細ページ・選手ページ・チームページの表示変更
- `matches` テーブルへのカラム追加（**種別はチーム側の属性であり、試合側に持たせない**）
- 大会ガイドの生成（`feat-generate-competition-guide-per-family` の範囲）
- 放送情報（投入済み）
- 他大会の日程表の表示変更。**まず greatest-rivalry で成立させる**

## データモデル変更

`teams` に種別カラムを 1 本追加する。

```
kind  text  not null  default 'club'
      check (kind in ('national', 'club'))
```

**バックフィルの方針:**

- **代表チームの判定に `world_ranking` を使わない**（上記の理由）
- 既存の代表チームは、`competitions.family` が代表大会のもの（`six-nations` / `nations-championship` / `autumn-nations` / `pnc` / `rwc` / `rugby-championship` / `lipovitan-challenge-cup`）に出場している team、を起点に洗い出す
- **洗い出した一覧を Owner が目視確認してから適用する。** 91 件は目視可能な件数

**2026-08-18 に本番で実測したところ、分類は機械的に確定する。**

| 分類 | 件数 |
|---|---|
| 代表大会にのみ出場 → `national` | 25 |
| クラブ大会にのみ出場 → `club` | 62 |
| **代表大会とクラブ大会の両方に出場（曖昧）** | **0** |
| 試合が 1 件もない | 4 |

- **曖昧なチームは 1 件も無い。** 代表大会とクラブ大会の両方に出るチームは存在しないため、上記の起点クエリだけで 87 件が確定する
- **バーバリアンズ・U20・A 代表・招待チームは 1 件も存在しない**（`barbarian` / `u20` / `XV` / `% A` / `invitational` / `select` / `development` / `academy` で検索、いずれも 0 件）。**`'national' | 'club'` の 2 値で破綻しない**
- 試合が 1 件もない 4 件は `lyon`（Lyon OU） / `rebels`（Melbourne Rebels） / `vannes`（RC Vannes） / `us-montauban`（US Montauban）で、**すべてクラブ**。デフォルト `'club'` が正しい値になるため、個別対応は不要
- それでも**適用前の一覧提示は省略しない。** 将来チームが増えた時に同じ前提が成り立つとは限らない

> **重要**: 過去に複数回の事故（#577 等）があったとおり、**新カラムを読むページコードをマージする前に、本番へマイグレーションを適用すること。** 順序を逆にすると本番が落ちる。

## API サーフェス

**新規ルートなし。**

既存の team を返すクエリ（`lib/db/queries/competitions.ts` など）の戻り値に `kind` を含める。型定義（`lib/db/types.ts`）の再生成が必要。

## UI サーフェス

大会ハブ `/competitions/[slug]` の日程表のみ。

**要件は「区別がつくこと」であり、具体的な見せ方は Codex の判断でよい。** ただし以下を満たすこと。

1. **テストマッチ（両チームが `national`）が、ツアー戦より視覚的に強い**こと
2. ツアー戦に、代表戦ではないと分かる**ラベル**が付くこと。**文言は「ツアー戦」で確定**（Owner 判断、2026-08-18）。**「親善試合」は誤りなので使わない** — 公式なツアーマッチである
3. 区別が**色だけに依存しない**こと（テキストラベルを併用する。アクセシビリティ要件）
4. **他大会のハブの見た目を壊さない。** 全チームが `national` の大会（シックスネイションズ等）、全チームが `club` の大会（プレミアシップ等）では、**従来どおりラベルなしで表示されること**

`COMPETITION_FAMILY_COLORS`（`lib/format/competition.ts:51-62`）に `greatest-rivalry` が無く、`getCompetitionFamilyColor` が既定値 `#1e293b` を返している。**この大会用の色を 1 つ追加すること。**

## LLM 連携

**なし。** LLM 呼び出しは発生しない。

ただし `kind` は将来的にコンテンツ生成の入力として有用（クラブ戦で「代表」と書く誤りを防げる）。**本 spec では生成側を変更しない。**

## 受け入れ条件

### データモデル

1. `teams.kind` が追加され、`'national' | 'club'` の check 制約を持つ
2. デフォルトが `'club'` で not null
3. バックフィル対象の一覧が**出力され、Owner が確認できる形**になっている（適用前に一覧を提示すること）
4. **`world_ranking` を判定根拠に使っていない**
5. 本大会の 6 チームが正しく分類される: `south-africa` / `new-zealand` が `national`、`bulls` / `lions` / `sharks` / `stormers` が `club`

### UI

6. Greatest Rivalry のハブで、テスト 4 戦とツアー戦 4 戦が区別して表示される
7. ツアー戦にラベルが付き、**色だけに依存しない**
8. シックスネイションズのハブ（全 `national`）で、**従来どおりラベルが表示されない**
9. プレミアシップのハブ（全 `club`）で、**従来どおりラベルが表示されない**
10. `COMPETITION_FAMILY_COLORS` に `greatest-rivalry` が追加されている

### テスト

11. 混在する大会でテスト戦とツアー戦が区別されることのテスト
12. 全 `national` の大会・全 `club` の大会でラベルが出ないことのテスト（**回帰防止。ここが壊れると全大会に影響する**）
13. `pnpm test` と型チェックが通る

### 手順

14. **マイグレーションを本番へ適用してから**、ページコードをマージすること
15. Codex はバックフィルを**実行しない。** 一覧の提示までで止め、適用は Owner が行う
