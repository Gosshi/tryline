# fix-home-width-expansion

## 背景

トップページの主要コンテナは `max-w-6xl`（1152px）で統一されている（`app/page.tsx:254`, `330`, `358`）。GPT-5.6の試算とOwnerの実機確認（1920px幅でのスクリーンショット）で、大画面では左右の余白が過大であることを確認した。

- 1440px画面: コンテンツ1152px、左右余白合計288px
- 1920px画面: コンテンツ1152px、左右余白合計768px（画面の約40%）

Trylineは長文記事の読み物ページではなく、試合・写真・大会情報を並べるダッシュボード的なホームであるため、本文幅の読みやすさを優先する `max-w-3xl` 的な制約は不要で、もっと横方向に情報を展開できる。

## スコープ

対象:
- トップページの主要コンテナ幅を `max-w-6xl`（1152px）から `max-w-[1536px]` 程度に拡張する（`app/page.tsx:254`, `330`, `358` の該当箇所）
- 拡張後、大画面（1920px以上）でコンテンツが間延びして見えないよう、`feat-homepage-editorial-photos.md` ・ `feat-upcoming-fixture-visual-redesign.md` と合わせて、空いた横幅を「写真領域の拡大」「セクションの2カラム化（最近レビュー等）」に配分する。単純にカードを横に引き伸ばすだけの実装は避ける
- 長文になりうるテキストブロック（説明文等）がある場合は、そのブロックだけ内側で `max-w-2xl`〜`max-w-3xl` 相当に制限し、読みやすさを維持する

対象外:
- `app/c/[competition]/page.tsx`（大会ハブページ）の幅変更（別spec `fix-competition-hub-width.md` で対応）
- `app/pricing/page.tsx` の幅変更（本specのスコープ外。将来必要なら別途判断）
- ヘッダー・フッターの幅（`components/site-header.tsx` の `max-w-6xl` はナビゲーションバーとして適切な幅のため変更しない）

## UI サーフェス

- 使用トークン: Tailwindの `max-w-*` ユーティリティ、または `design.md` に定義があればそれに従う（現行design.mdには具体的な最大幅定義がないため、本specの実装値がその後のdesign.md更新の参考値となる）
- 避けるべき表現: 単純な横幅拡大による間延び（テンプレ感の助長）。GPT-5.6提案の「写真8カラム＋試合ボード4カラム」のような非対称グリッドを参考に、拡張した横幅を意味のある形で使うこと
- **完了の定義にビジュアル確認を含める**: 1440px・1920px・375pxの3幅でスクリーンショットを取得し、Ownerが「余白が間延びしていない」ことを確認・承認すること

## 受け入れ条件

1. トップページの主要コンテナが1536px前後の最大幅になっていることをコードレビューで確認する
2. 1920px幅で表示した際、左右の余白合計が拡張前（768px）より明確に小さくなっていることを確認する
3. モバイル幅（375px前後）の表示がこれまで通り正しく機能すること（横幅拡張はデスクトップ表示にのみ影響し、モバイルのレイアウトを崩さないこと）
4. 長文テキストブロックの可読性が拡張によって損なわれていないこと（1行あたりの文字数が読みにくいほど長くなっていないか目視確認）
5. `pnpm test` / `pnpm tsc --noEmit` / `pnpm lint` / `pnpm build` が通る
6. Owner によるスクリーンショット目視確認（1440px・1920px・375px）で承認を得ること

## 未解決の質問

- 空いた横幅を具体的にどのセクションへ配分するか（2カラム化の対象セクション等）は、`feat-homepage-editorial-photos.md` ・ `feat-upcoming-fixture-visual-redesign.md` の実装と合わせて調整が必要になる可能性がある。3つのspecの実装順序はOwnerが決定すること
