# iOS 通知の本文から「（スコアは開いてから）」と見出しの重複を外す

## 背景

- iOS のプレビュー・レビューの通知の本文は、`lib/push/notifications.ts` の `buildBody` が作る。今の文面:
  ```ts
  if (kind === "preview") {
    return `プレビュー公開: ${home} v ${away}`;
  }

  return `試合レビュー公開: ${home} v ${away}（スコアは開いてから）`;
  ```
- 見出し（`buildTitle`）はすでに「プレビュー公開」「試合レビュー公開」なので、本文の先頭で同じ言葉を繰り返している。
- 「（スコアは開いてから）」は、通知にスコアを出さない（ネタバレを避ける。`specs/p2-push-notifications.md`）ことの説明書きだが、Owner から「邪魔」と指摘があった（2026-09-29）。**スコアを本文に出さない方針は変えない。** 説明書きだけを外す。

## スコープ

**対象**
- `buildBody` のプレビューとレビューの本文。

**対象外**
- 見出し（`buildTitle`）。
- 試合前の通知（`prematch`）の本文。
- 通知にスコアを出すこと（出さないまま）。
- iOS アプリ。

## データモデル変更

なし。

## API サーフェス

`lib/push/notifications.ts` の `buildBody` を次にする（試合前の分岐は今のまま）:

```ts
if (kind === "preview" || kind === "recap") {
  return `${home} v ${away}（${displayCompetitionName(match.competition)}）`;
}
```

- 例: 見出し「試合レビュー公開」、本文「オーストラリア v 南アフリカ（オーストラリア対南アフリカ テストマッチ 2026）」
- 大会名は、試合前の通知と同じ `displayCompetitionName` を使う。

## UI サーフェス

iOS の通知の本文だけ。

## 受け入れ条件

1. レビューの通知の本文が `日本 v フランス（<大会名>）` になり、「スコアは開いてから」「試合レビュー公開」を含まない。
2. プレビューの通知の本文が `日本 v フランス（<大会名>）` になり、「プレビュー公開」を含まない。
3. 見出しは今のまま（「プレビュー公開」「試合レビュー公開」）。
4. 本文にスコアの数字（`home_score`・`away_score`）が入らない。
5. 既存のテスト（`tests/api/ios-push-cron.test.ts:561`・`:565` の本文の assert）は、新しい文面に合わせて書き換える（テストは消さない）。
6. **壊して落ちる確認（コミットしない）:** 「（スコアは開いてから）」を戻すと、受け入れ条件 1 のテストが落ちること。
7. `pnpm lint`、`pnpm typecheck`、`pnpm test` が通る。**3 つとも実行して、結果を完了報告に含める。**
