# コンテンツが無い将来試合ページをnoindexにする

## 背景

2026-07-10、Codex（新モデル）による集客分析で指摘された課題。過去の選手ページindex bloat対策（`fix-index-bloat-players-teams.md`）と同種の問題が、試合ページにも存在する。

本番DB確認: RWC 2027の36試合（プール戦全試合）は全て `match_content` が0件（プレビュー・レビューとも未生成）。これは仕様通りの挙動で、プレビュー生成は現状キックオフの12〜72時間前の窓でのみ実行される（`lib/cron/orchestrate.ts` の `PREVIEW_WINDOW_START_HOURS`/`PREVIEW_WINDOW_END_HOURS`）。つまりRWC 2027のような1年以上先の試合ページは、長期間「対戦カード・日程だけ」の薄いページとしてWeb上に存在し続ける。

`app/matches/[id]/page.tsx` の `generateMetadata`（66行目）を確認したが、`robots` フィールドの設定が無く、コンテンツの有無に関わらず全試合ページがデフォルトでインデックス可能な状態になっている。

## スコープ

対象:
- `app/matches/[id]/page.tsx` の `generateMetadata` に、以下の条件で `robots: { index: false }` を設定するロジックを追加する:
  - `match_content`（preview・recapとも）が1件も無い
  - かつ、キックオフまで一定期間以上（例: 7日以上）ある試合
- プレビュー生成の対象期間に入り、実際にコンテンツが生成された時点で自動的にインデックス可能になる（`match_content` の有無を都度判定するだけでよく、フラグの手動管理は不要）

対象外:
- 既にキックオフが近い（プレビュー生成対象期間に入っている）が、何らかの理由でまだコンテンツが生成されていない試合の扱い（この場合は通常通りインデックス可能のままでよい。生成が遅れているだけの一時的な状態を過剰に制御しない）
- 試合終了後、何らかの理由でrecapが生成されなかった試合へのnoindex適用（対象は「未来の薄いページ」に限定し、終了済み試合は対象外とする）

## データモデル変更

なし。

## API サーフェス

なし。

## 受け入れ条件

1. RWC 2027のようにコンテンツが1件も無く、キックオフまで7日以上ある試合ページの `<head>` に `<meta name="robots" content="noindex">` 相当が出力される
2. プレビュー生成後（`match_content` が1件以上できた後）は、同じ試合ページが通常通りインデックス可能になる
3. 既に開催済み・進行中・直近の試合ページには影響がない（noindexが誤って適用されない）
4. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
5. 本番デプロイはOwner承認後に別途行う

## 未解決の質問

- 「7日以上先」という閾値は暫定値。Codexの実装時判断で調整してよい（プレビュー生成の実際の窓である72時間より余裕を持たせる意図）
