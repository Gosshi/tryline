# fix-mobile-spoiler-and-article-polish: ネタバレ中央列の固定表示と記事組版の改善

対象リポジトリ: **tryline-mobile**。`feat-team-flag-identity` とは独立（API 依存なし）で並行実装可。

## 背景

2026-07-15 のデザイン監査後の Owner × GPT-5.6 壁打ちで、2 つの見た目の弱点が特定された。

1. `●–●`（ネタバレマスク）は文字グリフに依存し崩れやすく、「スコアを表示」ラベルの有無でカード高さが変わっている（`feat-mobile-editorial-polish` の受け入れ条件「マスク時もカード高さ不変」が数字グリフレベルでは未達）
2. 記事本文（プレビュー/レビュー）がカード全面を本文で埋めており、読み物としての組版がされていない

## スコープ

対象:
1. **ネタバレ中央列の固定表示**: `ScoreText` のマスク表現を `●–●` テキストから、固定サイズ領域＋アイコン＋ラベルに変更
2. **記事本文の組版改善**: `ContentSection` の見出し・本文スタイル調整

対象外:
- ネタバレ防止の挙動（開示条件・永続化）
- Match Stories（別途保留中）
- チーム識別（`feat-team-flag-identity` で対応）

## UI サーフェス

### ネタバレ中央列（`ScoreText.tsx`）

- 中央領域を幅 72〜80pt・高さ 48pt に固定（開示前後で不変）
- マスク時: eye-off 相当のアイコン＋「表示」
- 開示後: 同じ領域にスコア数字（`tabular-nums` 維持）
- タップ領域は最低 44×44pt
- `accessibilityLabel`: マスク時「スコアは非表示です。タップして表示」、開示後は実スコア
- カレンダー・試合詳細の両方に適用（実装は共通コンポーネント `ScoreText` のため自動的に両方へ波及）

### 記事本文（`ContentSection.tsx`）

- 見出し（プレビュー/レビュー）の下に赤い罫線
- 導入文（本文の最初の段落）を本文よりわずかに太いウェイトにする
- 本文サイズ 17pt、行高 29〜30pt
- 段落間 16pt
- コンテンツカードの外枠（border/角丸）を外し、紙面の一部として見せる（`feat-mobile-editorial-polish` のカード内カード解消の延長）

## データモデル変更 / API サーフェス / LLM 連携

なし。

## 受け入れ条件

1. マスク時・開示時で中央領域のサイズが変わらない（コンポーネントテストで高さ・幅を比較）
2. マスク時のタップ領域が 44×44pt 以上
3. マスク時・開示時それぞれで正しい `accessibilityLabel` が設定される（テスト）
4. 記事見出し下に罫線があり、コンテンツカードに外枠が存在しない（テスト）
5. 本文の `fontSize`/`lineHeight` が仕様値と一致する（テスト）
6. 既存テストのリグレッションなし（`feat-mobile-editorial-polish` で追加したペイウォール左罫・マスク案内タップ開示の挙動は維持）
7. TypeScript strict・CI green
8. **Owner 目視**: カレンダー・試合詳細でのマスク表示、プレビュー/レビューの読みやすさをスクリーンショットで確認
