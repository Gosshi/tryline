# 大会ガイドの参照情報検索クエリを family 単位で上書きできるようにする

## 背景

2026-08-18 に `greatest-rivalry` の大会ガイドを実生成したところ、**「伝説の名場面・選手」セクションの 4 項目中 2 項目が、このツアーの直近の試合になった。**

生成された内容（実物）:

| 項目 | 内容 | 問題 |
|---|---|---|
| 1996年の南アフリカ長期遠征 | 両国の対戦史 | 妥当 |
| ハカと対峙するスプリングボクス | 両国の対戦史 | 妥当 |
| **2026年8月7日 ストーマーズ戦** | **このツアーの直近試合** | **すぐ陳腐化。しかもフランチャイズ戦で両国の対戦史ではない** |
| **8月11日 シャークス戦（ノヌ）** | **このツアーの直近試合** | **同上** |

さらに、ストーマーズ戦の項目には **「13人となる時間帯を耐え」** という記述があったが、**本番の `match_events` にこの試合のカードは 1 件も無く、裏付けが取れなかった。**

1995 年 RWC 決勝や 2013 年エリスパークといった、**両国の古典的な名場面は 1 つも入らなかった。**

Owner 判断で、該当箇所を手で削除して公開した（`supabase/seeds/competition-guides-greatest-rivalry.sql`）。伝説セクションは 2 項目になり、**プロンプトが要求する 3〜5 項目を下回っている。**

### 原因

`tools/generate-competition-guides.ts:60-68` の `searchContext` は、**検索語を `nameJa` から機械的に組み立てている。**

```ts
async function searchContext(exa: Exa, nameJa: string): Promise<string> {
  const results = await exa.searchAndContents(
    `${nameJa} ラグビー 歴史 有名試合 伝説的選手 エピソード`,
    { numResults: 5, text: { maxCharacters: 1500 } },
  );
  ...
}
```

`greatest-rivalry` の `nameJa` は **「グレイテスト・ライバルリー・ツアー」**。これは 2026 年のこのツアー用に付いた呼称なので、**「歴史」「伝説的選手」を付けて検索しても、返るのは今月のツアー報道**（J SPORTS の記事群など）である。

一方でプロンプトのセクション 3（`:76`）は「**年号・スコア・具体的な状況**を盛り込んで 3〜5 つ」を要求し、厳守事項（`:81`）は「**参照情報に載っていない具体的なスコアや年号は書かない**」を要求する。

**モデルは手元にある材料（＝ツアー報道）で書くしかなかった。**

### なぜ context では直らないのか

PR #703 で `greatest-rivalry` の `context` に

> 「伝説の名場面・選手」セクションでは、オールブラックスとスプリングボクスの100年以上にわたるライバル関係で語り継がれる名場面・名選手のエピソードを書くこと。このツアー自体は2026年に始まったばかりなので、ツアーの歴史ではなく両国の対戦史を扱う。

というリダイレクトを入れた。**それでも半分しか効かなかった。**

**`context` はプロンプトを直せるが、検索結果は直せない。**参照情報に両国の対戦史が入っていない以上、「参照情報に無い年号を書くな」との板挟みで、モデルは手元の材料に寄る。

### 今後も再発する

新設・改称された大会すべてで同じことが起きる。

- `nations-championship`（2026 年初開催）— 既存ガイドは生成済みだが、同じ弱点を抱えている可能性がある
- 今後 Tryline が扱う新大会

**大会名が新しくても、その大会が扱う「対戦」や「競技」には歴史がある。**検索語をそちらへ向けられれば解決する。

## スコープ

対象:
- `CompetitionGuideFamily` 型に、参照情報の検索クエリを上書きするフィールドを追加
- `searchContext` が上書きクエリを使えるようにする
- `greatest-rivalry` に上書きクエリを設定
- 上記に対応するテスト

対象外:
- **既存 11 家族の再生成**（触らない。上書きクエリを設定するのも `greatest-rivalry` のみ）
- `nations-championship` のガイド内容の見直し。**同種の弱点がある可能性は高いが、まず `greatest-rivalry` で方式を確立する**
- プロンプト本文（`generateGuide` 内のセクション構成・厳守事項）の変更
- `numResults` / `maxCharacters` の変更
- 生成の実行（Owner が行う）
- 手で修正済みの `supabase/seeds/competition-guides-greatest-rivalry.sql` の内容

## データモデル変更

**DB の変更なし。**

`tools/generate-competition-guides.ts:8-12` の型を拡張する。

```ts
export type CompetitionGuideFamily = {
  family: string;
  nameJa: string;
  context?: string;
  searchQuery?: string;   // 追加。未指定なら従来どおり nameJa から組み立てる
};
```

フィールド名は Codex の判断でよい。**未指定時に従来の挙動を保つこと**が要件。

`greatest-rivalry` に設定する検索クエリは以下に相当するもの（文言は調整可）:

```
オールブラックス スプリングボクス ラグビー 歴史 名勝負 伝説的選手 エピソード
```

**大会名ではなく「対戦カード」で引く**のが要点。英語で引いたほうが良い結果が出る可能性もあるため、`All Blacks Springboks rugby history famous matches legendary players` を併用・置換するかは Codex が判断してよい。

## API サーフェス

**なし。** CLI の引数は変更しない。

## UI サーフェス

**なし。**

## LLM 連携

生成スクリプト内の **Exa 検索**のみ変更する。

- **OpenAI の呼び出し回数・モデルは変わらない**（`MODELS.NARRATIVE`。モデル ID を直書きしない）
- Exa の呼び出し回数も **1 family あたり 1 回のまま**
- 検索語が変わるだけなのでコスト増はゼロ

## 受け入れ条件

1. `CompetitionGuideFamily` に検索クエリ上書き用のフィールドが追加されている
2. **未指定の family は従来どおり `${nameJa} ラグビー 歴史 有名試合 伝説的選手 エピソード` で検索する**（既存 11 家族の挙動が変わらない）
3. 指定がある family は、その文字列で Exa を検索する
4. `greatest-rivalry` に上書きクエリが設定されており、**大会名ではなく両国（オールブラックス／スプリングボクス）を主語にしている**
5. `numResults` / `maxCharacters` が従来値のまま
6. **`greatest-rivalry` の既存 `context`（PR #703 で追加したリダイレクト指示）を削除しない。** 検索とプロンプトの両方から寄せる
7. `pnpm test` と型チェックが通る

### テスト

8. 上書きなしの family で、従来の検索語が Exa に渡ることのテスト（**回帰防止。ここが壊れると既存 11 家族に影響する**）
9. 上書きありの family で、その検索語が Exa に渡ることのテスト
10. **Exa クライアントはモックする。実 API を叩かない**

### 生成物の検品（Owner）

11. Codex は**生成を実行しない。** スクリプト変更とテストまでで止めること
12. Owner が `greatest-rivalry` を再生成し、以下を確認する:
    - 「伝説の名場面・選手」が **3〜5 項目**あり、**すべて両国の対戦史**である（このツアーの試合が混ざっていない）
    - 年号・スコアが参照情報に基づいている（裏付けの取れない断定がない）
    - 大会概要・見どころ・視聴方法が従来どおり成立している
13. 検品を通ったら、**手修正版を置き換えて** Supabase ダッシュボードで SQL を実行する

## 未解決の質問

1. **`nations-championship` のガイドにも同種の弱点がある可能性が高い。** 2026 年初開催の大会で、`context` に「参加12カ国の代表チームで語り継がれる歴史的な名場面」というリダイレクトが入っているが、検索語は大会名のまま。**本 spec 完了後に内容を点検する価値がある**（再生成するかは別判断）
2. 検索クエリを日本語で持つか英語で持つか。日本語のラグビー史コンテンツは層が薄く、英語のほうが良い参照情報が得られる可能性がある。**ただし返ってきた英語を日本語ガイドに使うことになるため、既存プロンプトの引用制限（15 語超の直接引用禁止）との兼ね合いを Codex が確認すること**
3. 生成されたガイドの事実確認をいつ・どうやるかの運用が未定（`competition_guides.verified_at` が全 11 件 null）。今回のように **Owner が手で削る運用が続くなら、検品チェックリストを仕組み化する**価値がある
