# fix-preview-window-upper-bound-boundary

> GPT-6 再レビュー 2026-09-11 の **F3**（P2）。**JST 00:00 キックオフの試合だけ、公開窓へ 24 時間早く入る。** 実装は `feat-preview-generation-day-before-1500` の記載どおりで、**誤っているのは仕様の境界定義である。**

## 背景

`lib/cron/preview-window.ts:9-30` の `previewDueUpperBound` は、直近に過ぎた JST 15:00 から **+33 時間**を返す。

```ts
:29  // その 15:00 が担当する JST キックオフ日は「翌日」。その日の終わり = +33 時間
:30  return new Date(lastReleaseJst + 33 * HOUR_MS - JST_OFFSET_MS).toISOString();
```

15:00 + 33h = **翌々日 00:00 JST**。関数の doc コメント（`:6-7`）は「**この値以下**の kickoff_at を持つ試合が生成期限に達している」としており、呼び出し側は 3 経路とも `lte`（**以下**）で使う。

| 呼び出し元 | 行 | 比較 |
|---|---|---|
| `lib/cron/orchestrate.ts` | `:221` → `:97` | `.lte("kickoff_at", ...)` |
| `app/api/cron/audit-prekickoff-readiness/route.ts` | `:42` | — |
| `app/api/cron/matches-with-late-lineups/route.ts` | `:52` | `.lte("match.kickoff_at", ...)` |

**「翌日の終わり」を翌々日 00:00 と表現し、それを inclusive で比較しているため、翌々日 00:00 ちょうどのキックオフが窓に入る。**

| JST | 本来 | 現在 |
|---|---|---|
| 9/11 15:00 実行 | 9/12 キックオフ分を生成 | 上限 9/13 00:00 かつ inclusive |
| 9/13 00:00 キックオフ | 生成期限は 9/12 15:00 | **9/11 15:00 に候補になる（24 時間早い）** |

D030 の「キックオフ前日 15:00」より 24 時間早く初回生成されうる。**既存コンテンツがある試合は通常の初回生成対象から除外されるため、早く作られた後の更新は別の救済条件に依存する。**

**実装者の逸脱ではない。** `feat-preview-generation-day-before-1500` に掲載されたコードと検算表がこの形である。**仕様の境界定義を訂正し、実装を追随させる。**

## 変更詳細

**返り値と比較演算子をセットで直すこと。** 片方だけ直すと同じ穴が残る。

方針は 2 つある。**どちらでもよいが、3 経路すべてで揃えること。**

| 方針 | 返り値 | 比較 |
|---|---|---|
| A | 翌日 23:59:59.999 JST（inclusive な最終時刻） | `lte` のまま（呼び出し元 3 経路とも無変更） |
| B | 翌々日 00:00 JST（exclusive 境界） | 3 経路とも `lt` に変更 |

**A のほうが変更が小さい**（呼び出し元に触れない）。ただし**関数の doc コメント（`:6-7`）を、返り値の意味と一致させること。**

**採用した方針と、3 経路すべてで揃っていることを PR 本文に書くこと。**

### 仕様書の訂正

`specs/feat-preview-generation-day-before-1500.md` の境界定義と検算表を、**訂正の経緯つきで**直す。「なぜ 33 時間だったのか」「なぜ誤りか」を残す。**次に読んだ人が同じ 33 時間に戻さないため。**

## 受け入れ条件

1. **JST 翌々日 00:00 ちょうどのキックオフが、窓に入らない**ことを検証するテストがある
2. **その 1 ミリ秒前（翌日 23:59:59.999 JST）は窓に入る**ことを検証するテストがある
3. **翌日 00:00 ちょうどのキックオフは窓に入る**ことを検証するテストがある（下端が動いていないことの証拠）
4. 実行時刻が JST 15:00 ちょうど / 14:59:59.999 / 15:00:00.001 のそれぞれで、上限が期待どおりになることを検証するテストがある
5. **3 経路（`orchestrate.ts:221` / `audit-prekickoff-readiness/route.ts:42` / `matches-with-late-lineups/route.ts:52`）で、返り値と比較演算子の組が揃っている**
6. `previewDueUpperBound` の doc コメントが、返り値の意味と一致している
7. `specs/feat-preview-generation-day-before-1500.md` の境界定義と検算表が訂正され、**訂正の経緯が書かれている**
8. **JST 15:00 という公開時刻に差分が無い**
9. cron のスケジュールに差分が無い
10. LLM 呼び出しが差分に含まれない
11. `pnpm lint` / `pnpm typecheck` / `pnpm test` が green

**テストの置き場所**: `tests/lib/` または `tests/cron/`（`exclude` 非該当を確認すること）。**日付を固定すること**（`vi.setSystemTime`）。実行日に依存するテストにしない（2026-09-11 に `tests/app/team-page.test.tsx` が同じ理由で CI を落とした）。
