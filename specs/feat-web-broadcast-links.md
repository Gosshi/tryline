# feat-web-broadcast-links: Web の試合ページ・カレンダーに日本の視聴先リンクを表示

## 背景

`matches.broadcast_jp_url` は 2026-04 のテーブル作成時から存在するが、Web 側に UI 参照がゼロのまま（`docs/remaining-tasks-2026-06.md` で確認済み、データも 0/1,054 件）。iOS アプリ v1 は既にこのカラムを「視聴する」ボタンとして表示する（`specs/feat-ios-app-mvp.md`）。

「日本での視聴方法」は D014 の差別化の柱であり、重要試合への手動データ投入（iOS ロードマップ Phase 1 の最優先）を始める前に、**Web 側の表示面を先に用意する**。これにより 1 件投入した瞬間から Web・iOS の両方で価値が出る。`specs/feat-weekly-match-calendar.md`（19 行目）が「データ整備後の次段」として予告していた項目の実施。

## スコープ

対象:
- 試合詳細ページ（`app/matches/[id]/page.tsx`）: `broadcast_jp_url` 非 null 時に「視聴する」リンクを表示
- カレンダーページ（`app/calendar/page.tsx`）: 該当試合の行に視聴先リンクを併記

対象外:
- データの投入（別途 Owner 手動運用。本 spec は表示面のみ）
- 配信サービス名・放送/配信区分などの構造化（現状はカラムが URL 1 本のみ。構造化が必要になったら別 spec）
- iOS アプリ側（実装済み）
- OG 画像・SEO メタへの反映

## データモデル変更

なし。既存の `matches.broadcast_jp_url`（text, null 可）を読むだけ。

## API サーフェス

なし（RSC がクエリ経由で読む）。既存クエリが `broadcast_jp_url` を select していない場合は、対象クエリの select に追加するか、モバイル BFF で使った `getBroadcastUrlsForMatches`（`lib/api/v1/server.ts`）を再利用する。**新しい SQL を書く前に既存の再利用を検討する**。

## UI サーフェス

- **試合詳細**: スコアボード付近（キックオフ情報の近く）に「視聴する」リンク。外部リンク（`target="_blank" rel="noopener noreferrer"`）で公式視聴ページを開く
- **カレンダー**: 試合行にコンパクトな視聴先リンク（アイコン＋「視聴」程度）。行の主情報（チーム名・時刻）を圧迫しない
- null の試合では**何も表示しない**（「視聴情報なし」等のプレースホルダを出さない — データが 0 件から始まるため、空表示の羅列を避ける)
- スタイルは `app/globals.css` の既存トークン（`--color-accent` 等）を使用し、既存の試合詳細ページのボタン・リンク類の見た目に揃える。テンプレ的な汎用ボタンを新造しない
- 未終了試合・終了試合の両方で表示する（アーカイブ視聴の URL も入り得る）

## LLM 連携

なし。

## 受け入れ条件

1. `broadcast_jp_url` が非 null の試合の詳細ページに、該当 URL への外部リンクが `rel="noopener noreferrer"` 付きでレンダリングされる（テスト）
2. null の試合ではリンク・プレースホルダとも表示されない（テスト）
3. カレンダーページで、`broadcast_jp_url` 非 null の試合行にのみリンクが表示される（テスト）
4. 既存クエリの select 追加による他ページへの影響がない（既存テスト全 pass）
5. `pnpm test`・`pnpm build` pass
6. **Owner 目視評価**: テストデータを 1 件入れた状態のスクリーンショット（試合詳細・カレンダー、モバイル幅）で、既存デザインと馴染んでいることを確認（機械的条件のみで完了としない）

## 未解決の質問
