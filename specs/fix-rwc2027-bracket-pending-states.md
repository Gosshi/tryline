# fix-rwc2027-bracket-pending-states

> GPT-6 監査 A-5 bracket（P1）。「チーム未確定」と「日程未公表」を区別せず、どちらも「準備中」と表示している。

## 背景

`/c/rwc/2027/bracket` は 200 を返すが、常に `PendingState` を表示する（`app/c/rwc/2027/bracket/page.tsx:69`）。

```tsx
{matches.length === 0 ? <PendingState /> : <KnockoutBracket matches={matches} />}
```

`matches` は `round !== null && round >= 5` で絞られる（`:45-47`）。**本番の RWC 2027 は 36 試合すべて `round` が null である**（2026-09-09 実測）。

```
round=null   36 件   2027-10-01 〜 2027-10-17
```

`round` は DB 列ではなく `external_ids.round` / `external_ids.wikipedia_round` から導出される（`lib/db/queries/matches.ts:513-516`）。**ノックアウトの試合が 1 件も入っていないため、フィルタは必ず 0 件になる。**

そして `PendingState`（`:17-30`）の文言はこれだけである。

```
ノックアウトステージの対戦表を準備中です。
```

**「準備中」が何を指すのか分からない。** 実際には状態が 2 つある。

| 状態 | RWC 2027 での実際 |
|---|---|
| **チーム未確定** | プール戦が 2027 年 10 月なので、当然まだ決まらない。**これは正常であり、直しようがない** |
| **日程未公表 / 未取得** | ノックアウトの日程は公表されているが、DB に 1 件も入っていない |

読者から見ると「サイトの準備が遅れている」ようにしか見えないが、前者は**大会の性質上そうであるだけ**である。

監査の指摘（原文）: 「200だが準備中。P1で公式発表済みの日程・対戦枠を提供し、チーム未確定と日程未公表を分ける。」

RWC 2027 は North Star（`project_growth_strategy`）の入口であり、**この面が「準備中」の一言で終わっているのは機会損失**である。

## スコープ

対象:
- `PendingState` を、**チーム未確定**と**日程未取得**で分ける
- プール戦の日程が既にある（36 試合）ことを利用し、「いつ決まるか」を示す
- テスト

対象外:
- **ノックアウト試合の取り込み**。データソースの選定と robots.txt 確認が必要で、別 spec。**本 spec は取り込みを行わない**
- `KnockoutBracket` コンポーネント（`components/knockout-bracket.tsx`）の表示。**データが入ってから**
- `round` の導出ロジック（`lib/db/queries/matches.ts:513-516`）
- RWC 2027 大会ページ本体（A-4 9 は #763 で対応済み）
- **プール戦の対戦組み合わせから決勝トーナメントの対戦を予測すること。** 未確定を確定のように見せない

## UI サーフェス

`app/c/rwc/2027/bracket/page.tsx` の `PendingState`。

**区別すべき状態**:

| 条件 | 表示 |
|---|---|
| ノックアウト試合が 0 件 かつ プール戦が未終了 | **チームは未確定**である事実 + プール戦の日程（既に 36 試合ある）+ いつ確定するか |
| ノックアウト試合が 0 件 かつ プール戦が終了済み | **日程/結果が未取得**である事実 + 確認状況 |
| ノックアウト試合が 1 件以上 | 現状どおり `KnockoutBracket` |

**「準備中」という言葉だけで済ませないこと。**

`competition` が取得できない場合（`:35-42`）の `PendingState` も、上と混ざらないようにする。

## LLM 連携

なし。コスト $0。**「ノックアウトの日程を教えて」と LLM に尋ねない。**

## 変更詳細

プール戦の終了判定は、既にある 36 試合の `status` と `kickoff_at` から決定論的に行う。**現在日時をハードコードしないこと。**

「いつ確定するか」は、**DB にあるプール戦の最終 `kickoff_at`（2027-10-17）から導く**。文言に日付を直書きしない。

## 受け入れ条件

1. ノックアウト 0 件かつプール戦未終了のとき、**チーム未確定であることが分かる**文言が出ることを検証するテストがある
2. 同じ状態で、**プール戦の日程への導線**が出ることを検証するテストがある
3. 同じ状態で、**いつ確定するかが DB の値から導かれている**ことを検証するテストがある（日付をハードコードしていない証拠）
4. ノックアウト 0 件かつプール戦終了済みのとき、**未取得であることが分かる**文言が出ることを検証するテストがある
5. ノックアウト 1 件以上のとき、現状どおり `KnockoutBracket` が出ることを検証するテストがある
6. `competition` が取得できないときの表示が、上の 2 状態と混ざらないことを検証するテストがある
7. **「準備中」だけの文言が残っていない**
8. **未確定の対戦を確定のように見せていない**
9. 既存 URL が 200 を返し続ける
10. LLM 呼び出しが差分に含まれない
11. DB への `UPDATE` / `INSERT` / マイグレーションが差分に含まれない
12. `pnpm lint` / `pnpm typecheck` / `pnpm test` が green

**テストの置き場所**: `tests/app/` 配下（`exclude` 非該当。確認済み）。既存の `tests/app/rwc2027-hub-page.test.tsx` を壊さないこと。

## 未解決の質問

**本 spec で解決しないと明示するもの**:

- **ノックアウトの日程は入らない。** 本 spec は「今なぜ空なのかを説明できるようにする」ところまで。実際の日程取り込みは別 spec で、データソースの選定と robots.txt 確認が要る
- **チーム未確定は 2027 年 10 月まで解消しない。** これは不具合ではなく大会の性質である
