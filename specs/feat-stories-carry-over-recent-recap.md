# マッチストーリーズに直近のレビューを繰り越す

## 背景

2026-08-11 のスクリーンショット制作中に判明した。**週をまたいだ瞬間、直前の試合のレビューが既定画面から消える。**

`app/api/v1/stories/route.ts` は `from` / `to` の指定が無いとき `getCurrentJstWeekRangeUtc()` を使い（62〜71行）、**JST の月曜〜日曜の試合しか対象にしない**。

2026-08-11（火）時点の実測:

| 範囲 | ストーリーの内訳 |
|---|---|
| 今週（8/10〜8/16、既定） | `preview` / `news` / `news`（8/12 シャークス vs ニュージーランド。未実施） |
| 先週（8/3〜8/9、明示指定） | `preview` / `news` / `result` / **`recap`**（8/8 日本 vs オーストラリア ほか） |

8/8 の**日本代表戦のレビューは存在する**（API で 200 を確認）。にもかかわらず、8/10（月）以降は既定のフィードから消えていた。

### 現状でも「見られなくはない」

ホーム画面には週送り（前週 / 今週 / 翌週）があり、`app/(tabs)/index.tsx:33` が `trylineApi.stories(range)` を選択中の週で呼ぶ。**「前週」を押せば先週のレビューストーリーは表示される。** データもUIも欠けていない。

問題は**既定表示から消えること**である。日本代表戦は年に数回しかない集客の山で（`docs/notes/2026-08-10-acquisition-plans.md` H6: 発表〜翌日の4日間で流入が3倍）、その山の翌週明けに、最も読ませたいレビューが1タップ奥に隠れる。訪問者の大半は週送りを操作しない。

## スコープ

対象:
- `app/api/v1/stories/route.ts` の**既定範囲（`from`/`to` 未指定時）のみ**に、直近のレビューを繰り越す挙動を追加

対象外:
- **`from` / `to` を明示指定したリクエストの挙動**（週送りは「その週だけ」を返す現行のままにする。ここに繰り越しを入れると週送りの意味が壊れる）
- `V1MatchStories` / `V1StoryItem` への**フィールド追加**（API コントラクト変更を伴わない範囲で収める）
- モバイル（`tryline-mobile`）側の変更。週送り・`weekLabel`・`seenStore` の週単位保存はそのまま
- Web 側の UI
- ストーリーの生成・OG 画像（いずれも正常に動作している）

## データモデル変更

**なし。マイグレーション不要。** 既存クエリ `getMatchesInRange` の呼び出しを1回追加するのみ。

## API サーフェス

`GET /api/v1/stories` のレスポンス**形状は変えない**。既定範囲のときに `data.matches` の末尾に要素が増えうる、という違いのみ。

### 繰り越しの条件

既定範囲（`from`/`to` 未指定）のときだけ、次をすべて満たす場合に繰り越す。

1. 今週のストーリーに **`type === "recap"` の item が1件も無い**
2. 今週の直前7日間（今週開始の JST 前日から遡って7日間）に、**`recap` を持つ試合が存在する**

条件1を付ける理由は、今週すでにレビューがあるなら繰り越しは不要で、情報量を無駄に増やさないため。

### 繰り越す量

- **最大1試合**。キックオフが最も新しいものを1件だけ選ぶ
- その試合の `items` は**現行の組み立てロジックをそのまま通す**（`recap` だけを抜き出すのではなく、通常どおり `preview` / `news` / `result` / `recap` が並ぶ）
- `data.matches` の**末尾**に置く。今週のぶんより前に出さない

### 既存の制約との関係

- `MATCH_LIMIT = 12`（39行）は今週ぶんの上限。**繰り越しの1件をこの上限の外で加算するか、今週ぶんを11件に抑えて合計12件に収めるかは実装者が決め、理由を PR に書く**
- `data.week`（`from` / `to` / `label`）は**今週のまま変えない**。繰り越しは週の定義を変えるものではない

## UI サーフェス

**変更なし。** モバイルのセクション見出しは `${weekLabel}のマッチストーリーズ`（`src/stories/MatchStoriesSection.tsx:99`）のままで、既定時は「今週のマッチストーリーズ」と表示される。

繰り越された試合は先週のものなので、**見出しと厳密には一致しない**。ストーリーカードにはチーム名、ビューアには試合日が表示されるため実害は小さいと判断する（「未解決の質問」を参照）。

## LLM 連携

なし。

## 受け入れ条件

1. `from`/`to` 未指定で、今週に `recap` が1件も無く、直前7日間に `recap` を持つ試合がある場合、その試合のストーリーが `data.matches` の**末尾**に1件だけ追加される。
2. 1 の条件で追加される試合は、直前7日間で**キックオフが最も新しい**もの。
3. 今週に `recap` が**1件でもある**場合、繰り越しは発生しない。
4. 直前7日間に `recap` を持つ試合が無い場合、繰り越しは発生せず、レスポンスは現行と同一。
5. **`from`/`to` を明示指定したリクエストでは、繰り越しが一切発生しない**（週送りの挙動が変わらない）。
6. `data.week` の `from` / `to` / `label` が今週のままで、繰り越しによって変化しない。
7. 繰り越された試合の `items` が、通常の試合と同じ組み立てロジックを通っている（`recap` 単体ではなく、該当する種別が並ぶ）。
8. レスポンスの型が `V1StoriesData` のままで、新しいフィールドが増えていない。
9. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` clean。

## 未解決の質問

1. **見出しとの不一致を許容するか。** 既定時の見出しは「今週のマッチストーリーズ」だが、繰り越された試合は先週のものになる。厳密に揃えるならモバイル側で見出しを変えるか、レスポンスに繰り越しフラグを足す必要があり、いずれも API コントラクト変更とモバイル改修を伴う。**本 spec では許容し、実データで違和感が出たら別途起票する。**

2. **繰り越しの窓を7日で良いか。** 2週間空く大会（Six Nations の中断週など）では、7日では拾えない場合がある。広げると古いレビューが残り続ける副作用がある。**まず7日で入れ、11月の日本代表欧州遠征（3試合・12日間の窓）で実測してから判断する。**
