# fix-season-faq-broadcast-hardcoding

## 背景

大会シーズンページ `app/c/[competition]/[season]/page.tsx:611` に、**全大会共通の固定文**がある。

```
answer: "日本ではDAZN・J SPORTS 等の配信サービスで視聴できます。",
```

FAQの構造化データは表示本文と事実の整合を保つために更新する。GoogleのFAQリッチリザルト露出を改善効果として約束しない。

一方、ページ上の可視の視聴ガイドは「確認中」と正しく表示している大会がある。**同じページで、目に見える箇所は「確認中」、機械可読の JSON-LD は「DAZN・J SPORTS で視聴できます」と断定している。**

放送情報は `feat-broadcast-auto-ingest` / `feat-match-broadcasts` で試合単位に取り込む仕組みがあり、確認日も保持している。**検証済みデータがあるのに、FAQ はそれを読まずに固定文を出している。**

Tryline は「間違いを書かないこと」を差別化価値としており（`project_ai_labeling` の「敵は AI でなく間違い」）、放送されない大会について視聴できると断定するのは、読者の視聴行動を直接誤らせる。

## スコープ

対象:
- `app/c/[competition]/[season]/page.tsx` の `seasonFaqs`: 視聴方法の回答を、検証済みの放送データから生成する
- 可視の視聴ガイドと JSON-LD が**同じデータ源から同じ内容**を出すようにする

対象外:
- RWC 2027 ハブ（`fix-rwc2027-match-count-and-broadcast-claims.md` が扱う）
- 放送データの取り込み経路（`lib/broadcasts/*` に触れない）
- 放送対応表の不足そのもの（JRFU 日程ページの制約は既知の別課題）
- 他の FAQ 項目（開催期間・次の試合・順位表の3項目は現状の実装を維持する）

## データモデル変更

なし。既存の放送データを読むのみ。

## API サーフェス

なし。

## UI サーフェス

FAQ の視聴方法の回答を次の分岐にする。

| 状態 | 回答 |
|---|---|
| 当該シーズンに検証済みの放送データがある | **実際に確認されたサービス名のみ**を挙げ、確認日を添える |
| 検証済みデータが無い | サービス名を挙げず、確認中である旨と、公式情報を確認する導線を示す |

**「等」で断定を曖昧にしない。** 確認できたサービスだけを列挙し、確認できていないものは書かない。

JSON-LD と可視表示の文言は**同じ関数から生成する**。片方だけを直すと再び乖離する。

## LLM 連携

なし（コスト影響ゼロ）。**FAQ の文面を LLM で生成しない。** 決定論のテンプレートと検証済みデータの組み合わせで作る。

## 受け入れ条件

1. `app/c/[competition]/[season]/page.tsx` に `"日本ではDAZN・J SPORTS 等の配信サービスで視聴できます。"` という固定文字列が存在しない
2. 放送データが無い大会シーズンのページで、JSON-LD の視聴方法の回答に **`DAZN` / `J SPORTS` / `WOWOW` / `NHK` のいずれのサービス名も含まれない**ことを検証するテストがある
3. 放送データがある大会シーズンで、**確認されたサービス名のみ**が回答に含まれ、確認されていないサービス名が含まれないことを検証するテストがある
4. 可視の視聴ガイドと JSON-LD の視聴方法が、同一のデータ源から生成されている（同じ関数を呼んでいる）
5. FAQ の他の3項目（開催期間・次の試合・順位表）に差分が無い
6. 実際の本番ページで、JSON-LD をパースしたときに未検証のサービス名が出ないことを、放送データの無い大会 1 件以上で確認する
7. `pnpm test` と `pnpm typecheck` が green

## 表示範囲の契約
match_broadcastsに登録された対象試合と確認日・出典を根拠にする。1試合以上あるだけでは「大会全試合を視聴できる」と書かない。回答は「掲載中の一部試合に視聴情報があります。対象試合の案内をご確認ください」とし、確認済み対象だけにサービス名を添える。未登録は視聴不可の断定ではなく未確認とする。過去シーズンの記録を現行放送権の根拠にしない。

「検証済み」の定義は既存の放送データが持つ確認日フィールドの有無とする。**新しい検証フラグをスキーマに足さないこと。**
