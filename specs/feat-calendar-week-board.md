# `/calendar` をデスクトップで週ボードにする

## 背景

`docs/decisions.md` の **D020**（2026-08-31、Owner 承認済み）の決定3。比較モック `docs/design/mock-hub-direction-2026-08-31.html` の**候補B**を Owner が選定した。

### 現状の実測（本番 `/calendar?week=2026-10-26`、Chrome 1336×759、14試合週）

| 指標 | 実測 |
|---|---|
| ページ最上部から最初の試合行まで | **724px** |
| 1画面目（759px）に入る試合 | **0件** |
| 一覧全体の高さ | 2674px（**3.52画面**） |
| 1行の高さ | 94px |
| チーム名の終端 〜 キックオフ時刻の開始 | **542〜696px = カード幅1008pxの 54〜69%** |

**読者の63%がデスクトップ**（GA4、2026-07-31〜08-27、Windows デスクトップ 107 / 171ユーザー）。`/calendar` の平均滞在は 120秒超で、`project_hubs_are_the_product` のとおり試合ページ（3.6秒）より遥かに読まれている**主力面**である。

現状はモバイル用の縦積みレイアウトを 1152px 幅に引き伸ばしただけで、行の半分以上が空いている。

### モック実測（同一の実データ14試合、幅1152px）

| 案 | 1行の高さ | 行内空白率（14行平均） | 一覧全体 | 1画面目に入る試合 |
|---|---|---|---|---|
| 現行 | 89px | **62%** | 1439px | **3 / 14** |
| 候補A 密なプロダクト表 | 46px | 22% | 938px | 4 / 14 |
| 候補B 週ボード | 50px | 0% | 500px | 13 / 14 |

### B2 → B3 の決定（2026-09-01、Owner 採用）

B2 を見た Owner が **「チーム名を JPN とかにし正式名を下に小さく書くのは？」** と提案し、比較のうえ **B3 を採用**した。

各試合セルは次の2段になる。

```
GLA – LIO                          ← 略称（Outfit・tabular-nums・太字）
グラスゴー・ウォリアーズ 対 ライオンズ   ← 正式名（小さく・淡色）
```

**利点（実測）**: 固定幅のラテン文字が左端に揃い、視線の足がかりになる。1行の高さ・1画面目に入る件数は B2 と同じ（56px / 12件）。

**この案には実データ由来の欠陥が2つあり、両方とも本 spec で潰す。**

#### 欠陥1: 略称が重複している

本番 `teams` 91件の実測（2026-09-01）:

| `short_code` | 衝突している2チーム |
|---|---|
| `LEI` | **レンスター** / **レスター・タイガース** |
| `CHI` | チリ / チーフス |

さらに `short_code` が未設定のチームが2件（ホンコンチャイナ・ジンバブエ）。

**`LEI` の2チームは同じ週に出る。** 2026-10-26週で 10/30 がレンスター、10/31 がレスター・タイガース。**略称を主にすると、同じ画面に「LEI」が2回出て別チームを指す。**

`short_code` は**表示専用**である（実測: 一意制約なし・nullable、`eq()`/`in()`/`find()` 等の照合キーとして使っている箇所は**0件**）。ただし `lib/llm/stages/assemble.ts:657-658` で**LLM の入力に含まれている**。

#### 欠陥2: 正式名が、必要なときに限って切れる

正式名を1行固定・省略記号にすると、実測で2件が切れる:

- `ブリストル・ベアーズ 対 レスター・タイガース`（23文字）
- `サラセンズ 対 ニューカッスル・ファルコンズ`（22文字）

**略称を知らない読者ほど、名前の長いチームで困る。そこで保険が切れる。**

2行固定にすると解決するが **648px・1画面目10/14** まで後退する。**「必要なときだけ折り返す」形が最善**で、実測 **575px・12/14・切れ0件**、14件中12件は1行のままだった。

### B → B2 の経緯（2026-09-01）

Owner が候補B を見て **「文字が多くて見るのがしんどい」** と指摘した。文字数を実測して分解した結果:

| 内訳 | 候補B | 候補B2 |
|---|---|---|
| チーム名（削れない中身） | 186 | 186 |
| 列ヘッダ・時間帯ヘッダ（装飾） | 95 | **49** |
| 凡例 | 34 | **29** |
| **会場**（当初この spec が足す予定だった） | **+258** | **出さない** |
| **合計** | **573** | **264（54%減）** |

**当初の spec は会場を足す設計で、それだけで文字量が +79% になるところだった。** B2 は中身（チーム名）を1文字も削らずに、それ以外を削っている。

高さは 500px → 559px と微増する（余白を広げたため）。**文字を減らして余白を増やすほうが、詰めるより読みやすい**という判断。チーム名の省略（ellipsis）は**実測で0件**。

### 列数は4で足りる（実測済み）

本番 DB の全86週（2025-08 〜 2027-07）における、**1週あたりの開催日数の分布**:

| 開催日数 | 週数 | 割合 |
|---|---|---|
| 1日 | 14 | 16% |
| 2日 | 33 | 38% |
| 3日 | 33 | 38% |
| 4日 | 6 | 7% |
| **5日以上** | **0** | **0%** |

最多は 2025-12-29 週の4日・12試合。**5日以上開催の週は1件も存在しない。**

### 列幅はチーム名に足りる（実測済み）

`teams` 全91件が `name_ja` を保有（欠損0）。表示名の長さは**中央値6文字 / p90 12文字 / 最大15文字**（「埼玉パナソニックワイルドナイツ」「クボタスピアーズ船橋・東京ベイ」）。

1152px を4列・gap 14px で割ると1列 **277px**。パディングと大会カラーバーを引いても240px以上が本文に使え、15文字は収まる。

## データモデル変更

**`teams.short_code` の値を4件更新するマイグレーションを1本追加する。** スキーマ変更ではなくデータ更新。

| slug で特定するチーム | 現在 | 変更後 | 根拠 |
|---|---|---|---|
| レスター・タイガース | `LEI` | **`TIG`** | `LEI` はレンスターと衝突。Tigers は当該クラブの通称で、URC のレンスターと混同しない |
| チーフス | `CHI` | **`CHF`** | `CHI` はチリ（World Rugby の国コード）と衝突。国コードのほうを優先する |
| ホンコンチャイナ | （未設定） | **`HKG`** | World Rugby / IOC の国コード |
| ジンバブエ | （未設定） | **`ZIM`** | 同上 |

**レンスター（`LEI`）とチリ（`CHI`）は変更しない。**

実装上の注意:

- **`slug` で対象行を特定する。** `short_code` を条件に使うと2チームまとめて書き換わる
- マイグレーションは `update ... where slug = '...'` の4文。**`insert` / `delete` / DDL を含めない**
- 適用後に `select short_code, count(*) from teams where short_code is not null group by 1 having count(*) > 1` が**0行**になることを確認する
- **週ボードの UI をマージする前にマイグレーションを本番適用する**（適用前にマージすると同じ画面に `LEI` が2回出る）

**再発防止（任意・Owner 判断）**: 重複解消後なら `create unique index ... on teams (short_code) where short_code is not null` を張れる。ただしこれは DDL であり、昇降格で新チームを入れるときに失敗しうる。**本 spec では張らない。** Codex は可否だけ PR 本文で報告すること。

## UI サーフェス

### A. ヘッダの構成順を変える（`app/calendar/page.tsx`）

**行の密度だけを直しても1画面目に試合は入らない。** 現状ヘッダが724pxを占めているため。

現在の順序:

```
パンくず → eyebrow → H1 → 週の範囲 → 週移動(前週/今週/翌週)
 → 大会別に見るチップ → 説明文 → 3列CTA帯(iCal購読 / ニュースレター / iOSアプリ)
 → [ここから試合]
```

変更後:

```
パンくず → eyebrow → H1 → 週の範囲 → 週移動 → 大会別に見るチップ
 → [ここから試合]
 → 説明文 → 3列CTA帯(iCal購読 / ニュースレター / iOSアプリ)
```

- **3列CTA帯（`カレンダー購読` / `NewsletterSignup` / `IosAppCta`）を試合一覧の下へ移す**
- **説明文（「月曜 00:00 JST から翌月曜 00:00 JST まで…」）も試合一覧の下へ移す**
- CTA帯と説明文の**中身は変えない**。位置だけ変える
- 目標: ヘッダ（パンくずから大会チップまで）を **380px 以下**に収める

### B. デスクトップの週ボード（`lg:` 以上）

参照実装: `docs/design/mock-hub-direction-2026-08-31.html` の**候補B2**（B に文字削減を施した版）。

**構造**

- 開催日ごとに1列。**試合が0件の日は列を作らない**
- 列数は開催日数に一致させる
- **開催日が5日以上の週が来たら、列を折り返して2段目に流す**（実データには存在しないが破綻させない）
- 列の高さは揃えない（`align-items: start`）。**試合数が偏る週で短い列に空きが出るのは Owner が承認済みのトレードオフ**（D020）

**列の中身**

1. 列ヘッダ: 日（数字を大きく、`--font-number` + `tabular-nums`）と曜日。**「月」は最初の列だけ。試合数バッジは出さない**（数えられるため）
2. 同一キックオフ時刻の試合を**1つの時間帯にまとめる**。時刻は時間帯ごとに1回だけ表示する
   - 実データで 2026-10-31 は7試合中6試合が 09:00 JST。現行は「09:00 JST」を6回繰り返している
   - **「JST」は盤面の外に1回だけ書く**（「時刻はすべて日本時間」）。時間帯ごとに繰り返さない
   - **「◯試合同時」のような注記を出さない**
3. 各試合セル: 大会カラーの縦バー（3px）+ **2段構成**
   - 1段目: **略称**（`teams.short_code`）を `ホーム – アウェイ` の形で。`--font-number`（Outfit）+ `tabular-nums` + 太字。区切りのダッシュは淡色
   - 2段目: **正式名**（`name_ja`）を `ホーム 対 アウェイ` の形で、小さく淡色
   - **正式名は省略記号で切らない。必要なときだけ折り返す**（`white-space: nowrap` と `text-overflow: ellipsis` を使わない）。2行固定にもしない
4. **凡例の大会名は短縮形を使う**（例: 「ユナイテッド・ラグビー・チャンピオンシップ」ではなく「URC」）

**保持しなければならない情報**（現行リストにあるもの。落とさないこと）

| 要素 | 週ボードでの扱い |
|---|---|
| チーム名（ホーム / アウェイ） | **略称を1段目、正式名を2段目。正式名は省略記号で切らない**（必要時のみ折り返す） |
| `TeamBadge` | **週ボードでは出さない**（略称が文字として出るため重複する。モバイルの縦積みには従来どおり出す） |
| キックオフ時刻（JST） | 時間帯ヘッダに集約 |
| 大会 | **カラーバー＋列外の凡例**で示す。全セルに大会名テキストを繰り返さない。`getCompetitionFamilyColor(family)` を使い、色をハードコードしない |
| 大会ハブへのリンク | ヘッダの「大会別に見る」チップが担う。**`cta_id: "calendar_competition_list"` の計測を壊さないこと** |
| 会場 | **出さない**（Owner 判断、2026-09-01。後述） |
| 試合ページへのリンク | セル全体をリンクにする |
| **スコア（終了済み）** | **必須。`SpoilerScore` でラップし、`spoilerGuardEnabled` を尊重する** |
| ステータスバッジ（`getStatusPresentation`） | `scheduled` 以外で必須 |
| レビュー / プレビューのバッジ | 必須 |
| 「視聴」リンク（`hasBroadcasts`） | 必須。`/matches/<id>#broadcasts` |
| 注目試合（`highlightMatchId`） | 必須。現行と同等の強調 |

**過去の週（全試合終了済み）でも成立すること。** モックは予定試合しか描いていない。スコア・ステータス・スポイラーガードが入った状態で列幅が破綻しないことを必ず確認する。

### B-2. 開催日が1日の週（86週中14週 = 16%）

**フォールバックは作らない。週ボードのままにする。** ただし**素直に `auto-fit` で実装してはいけない。**

`grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))` に日が1つだけ入ると、**カードが幅1078pxまで伸びて中に1試合だけが左端に乗る**。これは D020 が直そうとしている「チーム名の右に800px空く」状態そのもので、**修正が自分の直した問題を再発させる**。

**その日の試合数から幅を決める**（実データ2週で検証済み、2026-09-01）:

```
日カードのコンテナ:
  max-width: min(100%, calc(N * 288px + (N - 1) * 20px))   /* N = その日の試合数 */

日カード内の試合グリッド:
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 0 20px;
```

実測結果（モックに実データを流して計測、2026-09-01）:

| 週 | 試合数 | カード幅 | 内側の列数 | 一覧の高さ | 行末から右端 |
|---|---|---|---|---|---|
| 2026-12-07 | 1 | **288px** | 1 | 168px | 18px |
| 2027-05-28 | 5 | **1078px** | **4** | **252px** | 18px |

**注意: この2週は本番 `/calendar` では開けない。** `MAX_WEEK_OFFSET = 8`（`lib/format/week.ts`）により、現在週から±8週を超える `?week=` は**無言で現在週にフォールバックする**。上の数値はモックでの計測値である。

比較（2027-05-28 の5試合）: 全幅に伸ばす=396px / 288px固定で左寄せ=409px / **本ルール=252px**。

**`width: fit-content` は使わないこと。** 内側の `auto-fill` が幅を決められず1列に潰れる（実測: 1試合も5試合もカード幅324px・内側1列）。

**この幅計算は開催日が1日のときだけ適用する。** 2日以上は現行の日別列のままでよい。

### C. モバイル・タブレット（`lg:` 未満）

**現行の曜日別縦積みリストから変更しない。** マークアップ・クラス・挙動すべて現状維持。**会場もモバイルでは従来どおり表示する**（縦積みなので幅に余裕があり、情報の後退にならない）。会場を出さないのは**デスクトップの週ボードだけ**。

### D. 使われていない `compact` prop

`WeekScheduleProps.compact` は**どこからも `true` で渡されていない**（実測: `/calendar` からの1箇所のみで未指定）。本 spec で**削除してよい**。削除する場合は関連する分岐（`components/calendar/week-schedule.tsx` の `:107`, `:141`, `:152`, `:158`, `:227`, `:239`, `:247`, `:264`）もあわせて整理する。

## 受け入れ条件

**すべてデスクトップ幅 1440 と 1336 の両方で確認すること。** モバイルは 390 で非回帰を確認する。

### 密度（D020 の目標値）

1. `/calendar?week=2026-10-26`（14試合）をデスクトップ 1336×759 で開いたとき、**1画面目に試合が5件以上表示される**（現行は0件）
2. 同じ週で、試合一覧ブロック全体の高さが **900px 以下**（現行2674px、候補B2 のモック実測559px）
3. ページ最上部から最初の試合セルまでが **420px 以下**（現行724px）
4. 週ボードの試合セルに、主要テキストの終端から次の要素までの水平の空白が**行幅の25%を超える箇所が無い**（列組みのため通常0%になる）
5. スクロールなしで、その週に試合がある日の**列ヘッダがすべて視認できる**

### 文字量（2026-09-01 の指摘への対応）

5b. `/calendar?week=2026-10-26` の週ボード領域の**総文字数が 400 文字以下**（候補B3 の実測は347文字。候補B は会場込みで573文字）。数え方は「週ボードのルート要素の `textContent` から空白を除いた長さ」
5c. 「JST」という文字列が週ボード領域に**1回以下**しか出ない
5d. 時間帯ヘッダに試合数（「6試合」等）が**含まれない**
5e. 列ヘッダに試合数バッジが**含まれない**
5f. 「月」の表記が列ヘッダに**1回だけ**（最初の列のみ）
5g. 凡例の大会名が短縮形である（`formatCompetitionTitle` のフルネームを使っていない）
5h. **チーム名が省略記号で切れている要素が0件**（`scrollWidth > clientWidth` の要素を数えて確認する）。最長は15文字（「埼玉パナソニックワイルドナイツ」）

### 略称表示（B3）

5i. 各試合セルの1段目が `teams.short_code` による `ホーム – アウェイ` であり、`--font-number` と `tabular-nums` が当たっている
5j. 2段目に `name_ja` の正式名が両チーム分出ている
5k. **正式名に `text-overflow: ellipsis` / `white-space: nowrap` が当たっていない**（切らずに折り返す）
5l. **正式名を2行固定にしていない。** `/calendar?week=2026-10-26` で、正式名の要素のうち**1行に収まっているものが10件以上**（実測は14件中12件）
