# PNC 2026 の凝縮フォーマット（準決勝・3位決定戦・決勝）を正しく取り込む

## 背景

2026-07-08 の集客・データ品質分析（Fable/Codex）で、「PNC 2026（GSCで唯一クリックが出ている大会）の試合データが2試合しかない」ことが判明した。本番DB実測で確認したところ `matches` テーブルには `pnc-2026` の試合が2件のみ（いずれも `scheduled`）。

Wikipedia の実ページ（`2026_World_Rugby_Pacific_Nations_Cup`）を直接確認したところ、**今年の PNC は伝統的な6か国総当たり戦ではなく、Fiji・Canada・Japan・United States の4か国による凝縮フォーマット**であることが判明した:

- 準決勝2試合（2026年9月12日）: Fiji vs Canada、Japan vs United States
- 3位決定戦（2026年9月19日）
- 決勝（2026年9月19日）

つまり「多くの試合が欠落している」のではなく、**全4試合のうち既に2試合（準決勝）は正しく取り込み済み**で、残り2試合（3位決定戦・決勝）が未取り込みという状態である。

**根本原因**: `lib/ingestion/sources/wikipedia-pnc.ts` の `POOL_SECTION_IDS = ["Pool_A", "Pool_B"]` は、伝統的なプール戦フォーマットを前提にしたセクション探索ロジックだが、今年のページには Pool A/B セクション自体が存在しない（凝縮フォーマットのため）。準決勝2試合が取り込めているのは、別の見出し・vevent 構造がたまたまマッチしたためと推定され、3位決定戦・決勝の見出しは異なる構造のため拾えていない可能性が高い。

さらに、3位決定戦・決勝の対戦カードは準決勝の結果（9/12）に依存するため、**現時点ではまだ Wikipedia 側にも確定した対戦カードが存在しない**（"Winner SF1 vs Winner SF2" 形式のプレースホルダーの可能性がある）。

## スコープ

対象:
- `lib/ingestion/sources/wikipedia-pnc.ts` のセクション探索ロジックを、今年の凝縮フォーマット（Pool セクションが存在しない場合のフォールバック）に対応させる
- 3位決定戦・決勝の日程（日付・時刻・会場）を、対戦カード未確定でも取り込めるようにする（チーム未定の試合レコードの扱いは既存の類似ケース〈RWC のプールステージ後の決勝トーナメント等〉のパターンがあれば踏襲する）
- `competitions` テーブルの `pnc-2026` の `end_date` が正しく9/19（決勝日）まで反映されるようにする（現状 `start_date`/`end_date` が9/12のみになっている可能性を確認・修正）

対象外:
- 準決勝2試合（既に正しく取り込み済み）の再取り込み
- 過去シーズン（PNC 2022/2024/2025）のフォーマット・パーサー（今回の凝縮フォーマットは2026年限定の変更と推定されるため、過去シーズンには影響しない前提。実装時に念のため確認してよい）
- 準決勝の結果が出た後の3位決定戦・決勝の対戦カード確定（それは試合当日以降、既存の自動cronが通常運用で取り込む。本specはそれまでの「取りこぼしなく仕組みを用意する」ことが目的）

## 実装詳細

### 1. セクション探索のフォールバック

`wikipedia-pnc.ts` の `POOL_SECTION_IDS` ベースの探索が0件の場合、ページ全体から日付付き vevent ブロックを横断的に探すフォールバックを追加する（`lib/ingestion/sources/wikipedia-nations-championship.ts` 等、既に「複数の見出しパターンに対応する」実装があれば参考にする）。

### 2. 対戦カード未確定の試合の扱い

3位決定戦・決勝がまだ「Winner SF1 vs Winner SF2」等のプレースホルダー表記の場合、この段階では対戦カード確定済みの試合として無理に取り込まず、実装時に以下のいずれかを選択する（Codexの裁量、判断根拠を完了報告に明記）:
- (a) 準決勝の結果が出るまで取り込みを見送り、既存の自動cronが試合日以降に自然に反映するのを待つ
- (b) 日程・会場だけを先に確定試合として登録し、対戦チームは準決勝結果確定後に別途更新する

### 3. `competitions.end_date` の確認・修正

`pnc-2026` の `end_date` が9/19（決勝日）を正しく反映しているか確認し、9/12のみになっている場合は修正する。

## LLM 連携

なし。

## 受け入れ条件

1. `POOL_SECTION_IDS` に依存しないフォールバック探索により、Pool セクションが存在しないページ構造でも試合データが取得できることをユニットテストで確認する
2. 3位決定戦・決勝の日程（日付・時刻・会場）が、対戦カード確定前でも取り込み可能な設計になっている、またはその見送り判断が完了報告に明記されている
3. `pnc-2026` の `end_date` が正しい大会終了日を反映する
4. 既存の準決勝2試合の取り込み結果に変更がない（回帰なし）
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る

## 未解決の質問

- 過去シーズン（2022/2024/2025）が本当に伝統的なプール戦フォーマットだったか、実装時に該当年のWikipediaページを確認してから、フォールバックロジックが過去シーズンの取り込みに悪影響を与えないことを確認してほしい
- 3位決定戦・決勝の対戦カード未確定期間の扱い（上記実装詳細2の(a)/(b)選択）は、Owner の運用上の好みにもよるため、迷う場合は選択肢を提示して質問してほしい
