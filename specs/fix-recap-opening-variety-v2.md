# recap冒頭の紋切り型再発防止（構造レベルの禁止への一般化）

## 背景

`fix-recap-opening-variety.md`（実装済み）で、published recap の37%が「得点力」フレーミングで冒頭を始めていた問題に対処し、`shared-prompt-blocks.ts` の `PROHIBITIONS_BLOCK` に「得点力の差が注目」等の特定フレーズを禁止句として追加した。

2026-07-08 のコンテンツ品質監査で、直近15件の published recap を確認したところ、**8件（53%）が新しい紋切り型「〜という圧倒的なスコアで」または「〜というスコアが示す(ように/通り)」で冒頭を開始**していることが判明した。この2フレーズはいずれも現行の `PROHIBITIONS_BLOCK`（`shared-prompt-blocks.ts:18-32`）に含まれておらず、禁止対象外のまま繰り返し使われている。

**根本原因**: 現行の対処法は「特定の禁止フレーズをリストに追加する」という対症療法であり、モデルが禁止されていない別の紋切り型フレーズに乗り換えるだけで再発する（今回で少なくとも2周目）。「得点力」→（今回発見）「圧倒的なスコアで／スコアが示すように」という交代が起きており、リストを追加し続けても次のフレーズに移るだけで根本解決にならない。

## スコープ

対象:
- `lib/llm/prompts/shared-prompt-blocks.ts` の `PROHIBITIONS_BLOCK` に、今回発見した具体的フレーズを禁止句として追加する（応急処置）
- `lib/llm/prompts/generate-recap.ts` に、個別フレーズの禁止ではなく**冒頭文の構造そのもの**を制約する指示を追加する（恒久対策）: 「`# この試合の核心` の最初の文は、スコアとその形容（『圧倒的な』『示すように』等）から書き始めてはならない。代わりに、試合の中の具体的な瞬間・決定・戦術的文脈のいずれかから書き始めること」

対象外:
- `generate-preview.ts`（preview の冒頭は `fix-preview-variety.md` で別途対応済み）
- 見出し構造自体（`# この試合の核心` / `# 試合全体像` 等の固定見出し名は変更しない）
- QA プロンプト・スコアリングロジックへの反映（本 spec はナラティブ生成プロンプトのみ対象。QA側で冒頭パターンを検出したい場合は別 spec）

## データモデル変更

なし。

## API サーフェス

なし。

## 実装詳細

### 1. `PROHIBITIONS_BLOCK`（`shared-prompt-blocks.ts:18-32`）に追加

既存の「得点力」関連禁止句（29行目）の直後に追加:

```
"- 「〜という圧倒的なスコアで」「〜というスコアが示すように」「〜というスコアが示す通り」など、スコアの形容から文を始めるパターン（代わりに試合の中の具体的な瞬間・決定・戦術的文脈から書き始めること）",
```

### 2. `generate-recap.ts` に構造レベルの指示を追加

`dataSparseBlock` や既存の冒頭関連指示（`generate-recap.ts:198` 付近）とは別に、全ケース共通の指示として以下を追加する（文言はCodexの裁量で調整可。要件は「個別フレーズでなく構造を縛る」こと）:

```
「# この試合の核心」の最初の一文は、以下のいずれかから始めること:
- 試合を決定づけた特定の瞬間（分・選手・プレー）
- 試合前の予想との対比
- 対戦構図・大会文脈における意味
「[スコア]という[形容]で」「[スコア]が示すように」のような、スコアの形容から始まる文型は、上記のどれにも該当しないため使用しないこと。
```

この指示は `PROHIBITIONS_BLOCK`（禁止リスト）とは別に、ポジティブな構造指示として独立させる。理由: 禁止リストへの追加だけでは次の言い回しへの乗り換えを防げないことが今回で実証されたため、「何を書くべきか」を先に指定し、禁止リストは補助的な網とする二段構えにする。

### 3. `PROMPT_VERSION` の更新

既存の慣例（`fix-recap-heading-format.md` 等）に従い、`generate-recap.ts` の `PROMPT_VERSION` をインクリメントする。

## LLM 連携

パイプライン Stage 3（ナラティブ生成）のプロンプト変更のみ。コスト増なし。

## 受け入れ条件

1. `PROHIBITIONS_BLOCK` に「圧倒的なスコアで」「スコアが示すように」「スコアが示す通り」の禁止句が追加されている
2. `generate-recap.ts` に、冒頭文の構造を指定するポジティブ指示（瞬間/対比/文脈のいずれかから始める）が追加されている
3. `PROMPT_VERSION` が更新されている
4. 既存のプロンプトテスト（`tests/llm/prompts/` 配下、存在すれば）が新しい禁止句・指示を反映して更新されている
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本 spec は再生成を伴わない（プロンプト変更のみ）。既存の該当recap（8件確認済み）の是正は対象外とし、今後生成される新しい recap から適用される

## 未解決の質問

- 既に公開済みで「圧倒的なスコアで」パターンを使っている recap（今回サンプルで確認した5件を含む）を遡及的に再生成するかは、`content-regen` の試し焼き手順を経て Owner が判断する。本 spec はプロンプト修正のみを完了条件とする
- 「ポジティブな構造指示」だけで本当に多様性が生まれるか（3周目の紋切り型が別の形で現れないか）は、修正後の生成物を数週間観測して再評価する必要がある。恒久的な監視方法（例: 定期的な冒頭300字のn-gram重複率チェック）は別 spec 候補
