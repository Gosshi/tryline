# ネタバレ防止モード（spoiler guard）をUIに接続する

## 背景

2026-07-10、Codex（新モデル）による集客分析で提案された施策。「深夜開催の海外試合を翌朝見る日本人ファン」という固有の課題に対応する。

本番DB確認: `push_subscriptions` テーブルには既に `spoiler_guard` カラム（boolean, default false）が存在し、`app/api/push/subscribe/route.ts` も既にリクエストボディの `spoiler_guard` パラメータを受け付けている。しかし**このオプションを設定できるUIがどこにも存在しない**（`components/notification-settings.tsx` を含め、全コンポーネントを確認したが接続箇所なし）。バックエンドの土台はあるのに使われていない状態。

ネタバレ防止モードの意図: 深夜〜早朝にキックオフする海外試合（南半球・北米開催等）を、日本のファンは翌朝以降に結果を知らずに追いたい場合がある。スコアが常に画面に表示されていると、意図せず結果が見えてしまう。

## スコープ

対象:
- `components/notification-settings.tsx` に「ネタバレ防止モード」のトグルを追加し、`app/api/push/subscribe/route.ts` の既存 `spoiler_guard` パラメータに接続する
- ネタバレ防止モードがONのユーザーには、以下の箇所でスコア・結果を初期非表示にし、タップ/クリックで開示する仕組みを追加する:
  - ホームページの `HomeMatchdayBoard`（今週の注目試合ボード）
  - `/calendar` ページの試合カード
  - 試合詳細ページ（`/matches/[id]`）のスコアヘッダー
- Push通知本文にも、ネタバレ防止モードがONの場合はスコアを含めない（「試合終了」等の結果を伏せた文言にする）

対象外:
- ネタバレ防止モードのタイマー機能（例: 24時間後に自動開示）。今回はユーザーの明示的なタップ操作のみで開示する、シンプルな実装に留める
- ログイン不要でのゲスト向けネタバレ防止（Push通知購読ユーザー向けの機能として実装し、非ログインユーザーへの適用は対象外）

## データモデル変更

なし（既存 `push_subscriptions.spoiler_guard` カラムをそのまま使用）。

## API サーフェス

なし（既存の `app/api/push/subscribe/route.ts` がそのまま受け付ける）。

## UI サーフェス

- `components/notification-settings.tsx`: 「ネタバレ防止モード」のトグルスイッチを追加
- スコア表示箇所（ホームの試合ボード・カレンダーカード・試合詳細ヘッダー）: ネタバレ防止モードON時はスコアの代わりに「結果を隠す」的なプレースホルダーを表示し、クリック/タップで実際のスコアに切り替える（ページ再読み込み不要、クライアントサイドの表示切り替えでよい）
- 現在ログイン中のユーザーの `spoiler_guard` 設定値をどう画面側で参照するか（Push購読状態から読むか、別途ユーザー設定として保持するか）は実装時にCodexが判断してよい。既存の `push_subscriptions` との紐付け方法を確認した上で決めること

## 受け入れ条件

1. `components/notification-settings.tsx` にネタバレ防止モードのトグルがあり、ON/OFFが `app/api/push/subscribe/route.ts` 経由で保存される
2. ネタバレ防止モードがONのユーザーがホーム・カレンダー・試合詳細ページを開くと、スコアが初期非表示になり、クリック/タップで表示に切り替わる
3. ネタバレ防止モードがOFF（デフォルト）のユーザーには、現在と同じ挙動（スコア常時表示）が維持される
4. Push通知の本文が、ネタバレ防止モードON時はスコアを含まない文言になる
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本番デプロイはOwner承認後に別途行う

## 未解決の質問

- 非ログイン・Push未購読ユーザーへのネタバレ防止モード提供（Cookie等でのローカル設定）は対象外としたが、将来的な拡張候補としてCodexの完了報告に記載してよい
- スコア開示のUI（タップで即座に表示 vs 確認ダイアログを挟む等）の具体的な見た目はCodexの実装判断に委ねる
