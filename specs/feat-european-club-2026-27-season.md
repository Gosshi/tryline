# 欧州クラブ3大会を 2026-27 シーズンへ繰り上げる

## 背景

2026-08-09 の本番実測で、**Premiership・URC・Top 14 のいずれも 2026-27 シーズンが1試合も登録されていない**ことが判明した。

| 大会 | 最新シーズン | 試合数 | 状態 | 期間 |
|---|---|---:|---|---|
| Premiership | 2025-26 | 75 | **全て finished** | 2025-09-25 〜 2026-06-20 |
| URC | 2025-26 | 150 | **全て finished** | 2025-09-26 〜 2026-05-16 |
| Top 14 | 2025-26 | 5 | **全て finished** | 2026-06-13 〜 2026-06-27 |

**Premiership 2026-27 は 2026年9月25日に開幕する。** 現状のままでは、開幕後も大会ハブページが前シーズンの終了済み試合しか表示せず、順位表も更新されない。

### なぜ急ぐか

グロースロードマップ（`docs/growth-roadmap-2026-08.md` および `-claude.md`）は、**2026年11月の日本代表欧州遠征を初のピーク検証**と位置づけている。

そこで集めた来訪者が他大会へ回遊したとき、**着く先が「終わった試合しかないページ」では離脱する**。日本代表戦の記事だけでは滞在が続かず、リテンションの起点にならない。

両ロードマップともこの件を P0 に挙げている。

### 根本原因

シーズンがハードコードされている。

`lib/ingestion/sources/wikipedia-premiership.ts` の `buildWikipediaUrl(season)`（36-38行）は引数を取る設計になっているが、呼び出し側が固定値を渡している。

```ts
export async function fetchPremiership202526(): Promise<ParsedLiveMatch[]> {
  const sourceUrl = buildWikipediaUrl("2025-26");
```

URC（`wikipedia-urc.ts` 163行）と Top 14（`wikipedia-top-14.ts` 187行）も同じ構造で、**関数名にもシーズンが埋まっている**。

`lib/ingestion/live-competitions.ts`（90-112行）の登録も `competitionName` / `competitionSlug` / `season` がすべて固定値である。

### 2026-27 の Wikipedia ページは既に存在する

2026-08-09 に `https://en.wikipedia.org/wiki/2026–27_Premiership_Rugby` を確認したところ、**全18ラウンドの日程と会場が掲載済み**だった（開幕 2026年9月25日、決勝 2027年6月19日）。

したがって**開幕を待たずに登録できる**。登録すれば、9月より前から「今後の試合」として日程が表示される。

**ただし未実施の試合はスコアが `0-0` として表示されている。** これをそのまま取り込むと「0-0で終了した試合」が大量に生成される。**本 spec で最も重要な注意点である。**

## スコープ

対象:
- Premiership / URC / Top 14 の取得関数をシーズン引数化する
- 2026-27 シーズンの `competitions` 行を追加する
- `lib/ingestion/live-competitions.ts` に 2026-27 の3エントリを追加する
- **未実施試合の `0-0` をスコアとして取り込まない**ことを保証する

対象外:
- **Top 14 のパーサ問題**（下記「別課題」参照）。本 spec はシーズン繰り上げのみを扱う
- 各パーサの解析ロジック変更（`parsePremiershipLiveHtml` 等）
- 2025-26 シーズンのデータ削除。**過去シーズンのページは残す**
- 大会ハブページ・順位表 UI の変更
- チームの新規登録（昇降格があれば実装時に確認し、報告する）
- 他大会（League One、SRP 等）のシーズン繰り上げ

## データモデル変更

**スキーマ変更なし。マイグレーション不要。** `competitions` への行追加のみ。

追加する行（`start_date` / `end_date` は Wikipedia の実データで確認して設定すること）:

| slug | name | season |
|---|---|---|
| `premiership-2026-27` | Premiership 2026-27 | 2026-27 |
| `urc-2026-27` | URC 2026-27 | 2026-27 |
| `top-14-2026-27` | Top 14 2026-27 | 2026-27 |

## API サーフェス

### 1. 取得関数のシーズン引数化

3モジュールの `fetchXxx202526()` を、シーズンを引数に取る形へ変更する。

`LiveCompetitionSource.fetch` は `() => Promise<ParsedLiveMatch[]>` のため、登録側でクロージャを使う。

```
fetch: () => fetchPremiership("2026-27"),
```

**既存の `fetchPremiership202526` 等をどう扱うかは実装時に判断する。** 呼び出し元が `live-competitions.ts` のみであれば置き換えてよい。他から参照されている場合は残すこと。

### 2. 2025-26 エントリの扱い

3大会とも 2025-26 は全試合が `finished` で、シーズンは完了している。**巡回対象から外してよい**（無駄な取得を避けられる）。

ただし外す場合、**過去シーズンのハブページが DB のデータで引き続き表示されること**を確認すること。取り込みを止めても既存データは消えない。

判断と根拠を報告すること。

### 3. 未実施試合の `0-0` を取り込まない（最重要）

Wikipedia の 2026-27 ページは、未実施の試合を `0-0` として表示している。

**キックオフ前の試合が `status='finished'`、あるいは `home_score=0 / away_score=0` として登録されてはならない。**

既存パーサがこれをどう扱うかを**実装前に確認すること**。既に適切に処理していれば追加対応は不要。処理していなければ、キックオフ日時が未来の試合、または結果セクションに現れない試合をスコア無しとして扱う分岐を入れる。

**この点はテストで必ず担保すること。** 誤って取り込むと、大会ハブに「0-0で終わった試合」が並び、recap 生成の対象にもなる。

## UI サーフェス

なし。既存の大会ハブテンプレートが `competitions` の行を元に描画する。

## LLM 連携

なし。取り込みのみ。ただし試合が登録されることで、既存の orchestrate パイプラインがプレビュー生成の対象に含めるようになる。**開幕前の大量生成が起きないか**、コスト面で実装時に確認すること。

## 受け入れ条件

1. Premiership / URC / Top 14 の取得関数がシーズンを引数に取る。
2. `live-competitions.ts` に 2026-27 の3エントリが登録されている。
3. **未実施試合が `finished` として登録されない。またスコアが `0-0` として登録されない。** テストで担保すること。
4. 2025-26 の既存データ（Premiership 75件・URC 150件・Top 14 5件）が削除・変更されない。
5. Wikipedia ページが存在しないシーズンで例外を投げず空配列を返す（既存の `isMissingWikipediaPage` の挙動を維持）。
6. 2025-26 を巡回対象から外した場合、過去シーズンのハブページが引き続き表示される。
7. 既存の他大会の取り込みに影響がない。
8. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` がすべて clean。

## 別課題: Top 14 のパーサは2シーズン連続で壊れている

本 spec の対象外だが、記録として残す。

| シーズン | 取り込み件数 | 期間 |
|---|---:|---|
| 2024-25 | 6 | 2025-06-13 〜 2025-06-28 |
| 2025-26 | 5 | 2026-06-13 〜 2026-06-27 |

Top 14 の正規シーズンは182試合（14チーム総当たり2回）ある。**取れているのは6月のプレーオフのみで、9月〜5月の正規シーズンが丸ごと欠落している。**

シーズンを 2026-27 へ繰り上げても、この状態は変わらない。**別 spec が必要。**

## 未解決の質問

1. **昇降格によるチームの入れ替わり。** Premiership・Top 14 には昇降格があり、2026-27 に `teams` へ未登録のクラブが含まれる可能性がある。実装時に確認し、未登録があれば報告すること（本 spec ではチーム追加を対象外としている）。

2. **URC と Top 14 の 2026-27 Wikipedia ページの存在は未確認。** Premiership のみ 2026-08-09 に確認済み。他2つは実装時に確認し、無ければ空配列が返ることを確認したうえで報告すること（ページが後から作られれば自動的に取り込まれる）。

3. **開幕前のプレビュー生成コスト。** 日程だけが登録された状態で orchestrate が走ると、開幕前の試合に対してプレビューを作りにいく可能性がある。Premiership だけで18ラウンド分あるため、コストへの影響を確認すること。既存の生成条件（キックオフまでの日数等）で抑制されていれば問題ない。
