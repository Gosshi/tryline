# RWC 2023 シーズンページ: ラウンド別フィルターの追加

## 背景

`https://www.trylinerugby.com/c/rwc/2023` は約 54 試合を全展開しており、
フィルターもページネーションも存在しない。全ページ中最大のスクロール量となっており UX が破綻している。

RWC は以下のフェーズに分かれる:
- プールステージ: プール A〜D（各 10 試合）
- ノックアウトステージ: 準々決勝・準決勝・3 位決定戦・決勝

これをラウンド（フェーズ）別にフィルタリングできるようにする。

## スコープ

対象:
- `app/c/[competition]/[season]/page.tsx` — フィルター UI の追加（試合数 20 件以上のシーズンのみ）

対象外:
- 他大会のシーズンページ（Six Nations 等、20 件未満では表示しない）
- ページネーションの実装（フィルターで絞れれば不要）
- データ取得ロジックの大幅変更（クライアントサイドフィルタで対応）

## データモデル変更

なし（`matches.round` カラムが存在する前提。形式は要確認）

## API サーフェス

### URL パラメータ

```
/c/rwc/2023?round=pool-a
/c/rwc/2023?round=knockout
/c/rwc/2023               （省略時 = 全試合）
```

## UI サーフェス

### フィルターボタン群

シーズンタイトルの下・試合リストの上に配置:

```
[ 全試合 ] [ Pool A ] [ Pool B ] [ Pool C ] [ Pool D ] [ ノックアウト ]
```

- 選択中ボタンをハイライト（`--color-accent` アクセントカラー）
- フィルター適用後は該当試合のみ表示
- ボタンクリックで URL search params を更新（ブラウザバックで状態が戻る）

### 表示条件

試合数 ≥ 20 のシーズンにのみフィルター UI を表示する。
20 件未満では表示しない。

### 実装方針

- フィルターボタンは Client Component（`useRouter` + `useSearchParams` 使用）
- 試合リスト本体はサーバーコンポーネントを維持し、全試合を props で渡す
- クライアントサイドで `round` パラメータに応じてフィルタする（54 件程度なので問題ない）

`matches.round` の実際の値形式（`"Pool A"` / `"pool-a"` / `1` 等）を
DB で確認してからフィルタ条件のマッピングを実装すること。

## LLM 連携

なし

## 受け入れ条件

1. `https://www.trylinerugby.com/c/rwc/2023` にフィルターボタンが表示される
2. Pool A〜D・ノックアウトの各フィルターが動作し、該当試合のみ表示される
3. `?round=pool-a` が URL に反映され、ブラウザバックで状態が戻る
4. 試合数 20 件未満のシーズンページ（Six Nations 等）ではフィルターが表示されない
5. `tsc --noEmit` でビルドエラーなし

## 未解決の質問

- RWC 2027 でも同じフィルターを使うか Owner が確認すること
