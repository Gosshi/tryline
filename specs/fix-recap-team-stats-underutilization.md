# recap生成が team_stats を十分に活用しない問題の修正

## 背景

2026-07-13、`feat-derive-team-stats-from-sourced-facts.md`・`fix-qa-team-stats-new-fields-unsupported.md`（PR #554・#555・マージ済み）により、日本 vs アイルランド戦の`assembled.team_stats`にはポゼッション・テリトリー・タックル数・キャリー・ラインアウト成功率・スクラム成功率・ターンオーバー・獲得メートルの**8項目**が正しく格納されるようになったが、実際に生成されたrecap本文で具体的な数値とともに引用されたのは**ラインアウト成功率・スクラム成功率の2項目のみ**だった。ポゼッション・テリトリー・タックル数・キャリー・ターンオーバー・獲得メートルの6項目は本文に一切反映されなかった。

さらに、実際に引用された2項目についても「アイルランドはラインアウト成功率90%を誇り、安定した基盤からの攻撃が展開された」「スクラム成功率は85%と高く、セットプレーでの主導権を握ったことが大きかった」のように、数値の後に因果関係の説明が付いてはいるものの、**「安定した基盤から」「主導権を握った」といった定型的な言い回しに留まり**、「なぜその数値が試合結果に影響したか」という一段具体的な戦術的因果関係までは踏み込めていない。本specの目的は単なる引用数の確保ではなく、**team_statsの数値を具体的な戦術的考察につなげること**にある。

### 根本原因（特定済み）

`lib/llm/prompts/generate-recap.ts`の`teamStatsBlock`（L204-210）の指示文は:

```
"【チームスタッツ team_stats】以下は公式サイトから取得した実際のチームスタッツです。ポゼッション率・成功率等の数値表現をそのまま使ってよい。"
"スクラム・ラインアウト・タックル・キャリー・ペナルティ等の差は、戦術描写の具体化に積極的に使うこと。ただし、このJSONに存在しない統計は推測して書かないこと。"
```

「使ってよい」「積極的に使うこと」という**推奨止まり**で、最低何項目引用すべきかの数値目標が無い。`team_stats`は`JSON.stringify()`でまるごとプロンプトに渡されるだけで、優先順位付けの指示も無いため、LLMは限られた字数配分の中でストーリーに合う一部の項目（今回はセットプレー関連）だけを選び、残りを取りこぼす。

副次的な効果として、字数下限（2,000字）未達によるreject/draft化が過去に複数回観測されている（`content-regen`の試し焼き履歴参照）。team_statsの活用を強制すれば、具体的な数値描写が自然に増え、字数不足の解消にも寄与すると見込まれる。

## スコープ

対象:
- `lib/llm/prompts/generate-recap.ts`の`teamStatsBlock`（L204-210）に、最低引用数の明示的な要求を追加する

対象外:
- `lib/llm/prompts/generate-preview.ts`（previewは`team_stats`を使用していない。試合前のため対象外で妥当）
- QAステージでの決定的な「引用数カウント」ガードの追加（本specはプロンプト指示の強化のみ。プロンプト強化後も同様の取りこぼしが繰り返し観測される場合は、`buildTeamStatsFactStrings()`の出力が本文に何個含まれるかをカウントする決定的ガードを別途spec化する。「未解決の質問」に記載）
- `derived_stats`・`sourced_facts`等、他のブロックの指示文変更

### 実装方針

`teamStatsBlock`（L204-210）に一文追加:

```ts
const teamStatsBlock = !assembled.team_stats
  ? ""
  : [
      "【チームスタッツ team_stats】以下は公式サイトから取得した実際のチームスタッツです。ポゼッション率・成功率等の数値表現をそのまま使ってよい。",
      "スクラム・ラインアウト・タックル・キャリー・ペナルティ等の差は、戦術描写の具体化に積極的に使うこと。ただし、このJSONに存在しない統計は推測して書かないこと。",
      "以下のJSONに含まれる項目のうち、最低3種類は本文中で両チームの具体的な数値とともに引用すること（例:「ポゼッションは日本48%・アイルランド52%」のように両チームの値を対比させる）。1〜2項目のみの引用に留めず、この試合の勝敗を最も特徴づける項目（ポゼッション・テリトリー・タックル数・ターンオーバー等、優劣が明確な項目）を優先して選ぶこと。",
      "数値を引用する際は、「安定した基盤からの攻撃が展開された」「主導権を握った」のような一般論で終わらせず、その数値が具体的にどのプレー・展開に結びついたかを一段深く説明すること（例:「ラインアウト成功率90%の安定感により、ゴール前でのモール連続攻撃が可能になり、◯◯のトライに直結した」のように、数値→試合中の具体的な事象→結果、という因果の連鎖を示すこと）。ただし入力データに存在しない具体的なプレー描写を創作してはならず、match_events・sourced_facts等、他のブロックに実際に存在する事実の範囲内で因果関係を組み立てること。",
      JSON.stringify(assembled.team_stats),
    ].join("\n");
```

3〜4行目が追加分。既存2行はそのまま維持する。

## 受け入れ条件

1. `tests/llm/prompts/generate-recap.test.ts`に新規テストケースを追加:
   - `assembled.team_stats`が非nullの場合、プロンプトに「最低3種類」（または実装した具体的な数値表現）を含む文字列が含まれること
   - `assembled.team_stats`が非nullの場合、プロンプトに因果関係の説明を求める一文（「一般論で終わらせず」「具体的な事象」「因果の連鎖」等、実装した表現）が含まれること
   - `assembled.team_stats`がnullの場合、`teamStatsBlock`は空文字列のままであること（既存動作、リグレッションなし）
2. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通ること
3. 本spec自体は再生成を伴わない。日本 vs アイルランド戦を含む対象試合の再生成は、本specマージ後に別途`content-regen`手順で試し焼きし、実際に(a)3項目以上のteam_statsが本文に反映され、かつ(b)「安定した基盤から」等の定型句ではなく具体的な因果関係の説明が付いているかを目視確認する

## 未解決の質問

- 「最低3種類」という数値がプロンプト指示だけで確実に守られるかは未検証。本specの適用後、試し焼きで効果が薄い（相変わらず1〜2項目しか使われない）場合は、`fix-recap-penalty-fabrication-qa-gap.md`と同様のパターンで、`buildTeamStatsFactStrings()`の出力のうち何個が本文に実際に含まれるかをカウントする決定的ガードをQAステージに追加する方向で再度spec化する
- 「最低3種類」の数字自体の妥当性（多すぎて不自然な統計羅列にならないか、少なすぎて今回のような取りこぼしが解消されないか）はOwnerの読後感で調整してよい
