# 日程が未取得の大会を、節数の比較で検出して伝える

## 背景

`specs/fix-top14-season-fixture-coverage.md` の「未取得の可視化」部分を、**判定方法を設計し直して切り出したもの。** PR #750 で実装した最初の版が実データで機能しなかったため。

### 何を伝えたいか

`/calendar` は「月曜 00:00 JST から翌月曜 00:00 JST までの試合を、**全大会横断で**曜日ごとにまとめています」と明示し、前後8週まで移動できる。しかし **Top 14 は取り込みが節単位（現在節・+1・+2、D024）**のため、数週先を見ると Top 14 だけが消える。

利用者には「その週に Top 14 の試合が無い」のか「まだ取り込んでいない」のか区別がつかない。**それを区別できるようにする。**

### 失敗した2つの判定方法（どちらも実データで検証済み）

**方法1: 取り込み済み最終キックオフより後の週か**（`fix-top14-season-fixture-coverage.md` の初版）

シーズンが実際に終了した大会でも成立してしまう。URC は 2027-05-15 が最終戦なので、2027年6月の週で「未取得」と誤って出る。**spec 段階で懸念として書いたまま採用してしまった。**

**方法2: `competitions.end_date` と比較する**（PR #750 の実装）

`lib/ingestion/live-ingest.ts:60` が

```ts
end_date: dates.at(-1) ?? null,   // dates = 取り込んだ試合のキックオフ日
```

としているため、**ライブ取り込み経路の大会では `end_date === latestKickoffAt` が定義上いつでも成立**し、比較が真にならない。Top 14 はこの経路なので**構造的に検出できない**。

逆に `end_date` が別経路（シード・Wikipedia）由来で古い大会だけが引っかかる。本番実測:

| 大会 | `end_date` | 取込最終 | 方法2の判定 |
|---|---|---|---|
| six-nations/**2021** | 2021-10-30 | 2021-03-26 | **★注記に載る** |
| pnc/2026 | 2026-09-19 | 2026-09-12 | **★注記に載る** |
| **top-14/2026-27** | 2026-09-13 | 2026-09-13 | **載らない** |
| urc/2026-27 | 2027-05-15 | 2027-05-15 | 載らない（正しい） |

PR #750 のプレビューで、`/calendar?week=2026-10-26` に実際にこう出た。

> シックスネイションズ **2021**・パシフィック・ネーションズカップ 2026の日程は開催が近づいてから掲載されます。

**5年前の大会が名指しされ、主題の Top 14 は出ない。シグナルが反転している。**

**どちらの方法も「取り込んだ試合そのもの」から導いた値を基準にしている点が共通の誤り。** 基準は取り込みと独立していなければならない。

### 方法3（本 spec が採用）: 節数を比べる

Owner 判断（2026-09-01）。**「その大会が本来持つ節数」と「取り込み済みの節数」を比べる。**

本番実測（`external_ids.round ?? external_ids.wikipedia_round`、2026-09-01）:

| 大会 | 試合 | 取込済みの相異なる節数 | 節の範囲 | 本来の節数 |
|---|---|---|---|---|
| **top-14/2026-27** | 14 | **2** | 1〜2 | **26** |
| urc/2026-27 | 144 | 18 | 1〜18 | 18 |
| premiership/2026-27 | 90 | **17** | 1〜18 | **18**（第4節が欠落） |
| six-nations/2027 | 15 | 5 | 1〜5 | 5 |
| nations-championship/2026 | 36 | 6 | 1〜6 | 6 |
| super-rugby-pacific/2026 | 83 | 19 | 1〜19 | — |
| greatest-rivalry / puma-trophy / rwc / lipovitan | — | **0** | なし | **節を持たない** |

**この方法なら Top 14（2 < 26）を検出でき、URC（18 = 18）は検出しない。**

### 副次的な効果: ハブの「全N節」の嘘も同時に直る

`app/c/[competition]/[season]/page.tsx:133` の `getSeasonProgress` は、**取り込み済みの相異なる節数を「全N節」として表示している。**

```ts
const matchesByRound = new Map<number, MatchListItem[]>();
// ... matchesByRound.size が「全N節」になる
```

そのため `/c/top-14/2026-27` は本番で **「0節 / 全2節」** と表示している。実際は全26節。**同じ「本来の節数」を使えば、この表示も正しくなる。**

## スコープ

対象:
- **`supabase/migrations/` — `competitions` に `total_rounds` 列を追加するマイグレーション（新規1本）**
- `lib/format/schedule-coverage.ts` — 判定を節数比較に置き換え
- `lib/db/queries/competitions.ts` — `total_rounds` と取り込み済み節数の取得
- `app/c/[competition]/[season]/page.tsx` — `getSeasonProgress` の「全N節」を `total_rounds` 由来にする
- `components/schedule-coverage-notice.tsx` — 文面の調整（必要な場合のみ）

対象外:
- **PR #750 の取得窓シフト（`getTop14LnrForwardRoundSlugs`）とシーズン定数の是正。** レビュー済みで問題なし。**触らない**
- `lib/ingestion/live-ingest.ts:60` の `end_date` の算出。**本 spec では直さない**（`end_date` を使うのをやめるだけ）
- **プレミアシップ 2026-27 の第4節が欠落している件。** 別の取り込み不具合。本 spec は「検出して伝える」までで、**データの補完はしない**
- `pnc/2026` の節番号が `101` になっている件。異常値だが本 spec では扱わない
- 節を持たない大会（テストマッチ形式）への対応。`total_rounds` が null なら対象外になる、で足りる

## データモデル変更

**`competitions` に `total_rounds integer` 列を追加する（nullable）。**

```sql
alter table public.competitions add column total_rounds integer;
```

**nullable であることが重要。** 節を持たない大会（greatest-rivalry・puma-trophy・rwc・lipovitan-challenge-cup 等）は null のままとし、**null なら注記も「全N節」も出さない。**

同じマイグレーションで、現行シーズンの値を投入する。

| 大会（family / season） | `total_rounds` | 根拠 |
|---|---|---|
| top-14 / 2026-27 | **26** | `buildTop14RegularSeasonRoundSlugs()`（`lib/scrapers/top14-lnr-results.ts:80-82`）が j1〜j26 を生成する |
| urc / 2026-27 | **18** | 144試合 ÷ 8試合/節 = 18。実測の節範囲 1〜18 と一致 |
| premiership / 2026-27 | **18** | 実測の節範囲が 1〜18（第4節が欠落しているため相異なる節数は17） |

**それ以外の大会は投入しない（null のまま）。** 過去シーズンにも投入しない。

**`total_rounds` は取り込み処理で上書きしてはならない。** これが方法1・方法2の失敗の原因だったため、**`lib/ingestion/` から `total_rounds` を書かないこと**を受け入れ条件で機械的に確認する。

## UI サーフェス

### A. 判定

```
未取得 = total_rounds が null でない
      かつ 取り込み済みの相異なる節数 < total_rounds
```

**「最大の節番号」ではなく「相異なる節数」で比べる。** 末尾の欠落（Top 14: 1〜2 のみ）と中抜け（プレミアシップ: 第4節欠落）の**両方**を拾うため。

`/calendar` では、これに加えて **表示中の週にその大会の試合が1件も無い**ことを条件にする（試合が出ている週に「未取得」と出すと矛盾するため）。

### B. `/calendar` の注記

- 一覧の近くに出す。**該当する大会がある週にだけ**
- 大会名は `formatCompetitionTitle` を通す（**スラッグや family を生で出さない**）
- **未取得の試合数・日程を推測して出さない**
- PR #750 の `components/schedule-coverage-notice.tsx` の見た目を流用してよい

### C. `/c/[competition]/[season]` の注記

同じ判定で、その大会自身が未取得なら注記を出す。

### D. ハブの「全N節」

`getSeasonProgress` の分母を **`total_rounds` があればそれ**、無ければ現行どおり（取り込み済みの相異なる節数）にする。

- `/c/top-14/2026-27` は **「0節 / 全26節」** になる（現在は「0節 / 全2節」）
- **分子（完了節数）の算出は変えない**

## 受け入れ条件

### マイグレーション

1. `supabase/migrations/` に新規マイグレーションが1本あり、`competitions` に `total_rounds integer`（**nullable**）を追加している
2. 同マイグレーションが `top-14/2026-27 = 26` / `urc/2026-27 = 18` / `premiership/2026-27 = 18` を投入し、**他の大会には触れていない**
3. 対象を `family` と `season` の組で特定している
4. 適用後、`select count(*) from competitions where total_rounds is not null` が **3**

### 判定ロジック

5. 判定が `total_rounds` と**取り込み済みの相異なる節数**の比較になっている。`end_date` を使っていない
6. `lib/format/schedule-coverage.ts` に `endDate` への参照が**残っていない**
7. **「最大の節番号」ではなく「相異なる節数」**で比較している（中抜けを拾うため）
8. `total_rounds` が null の大会は**常に未取得と判定しない**
9. **`lib/ingestion/` 配下から `total_rounds` を書き込んでいない**（`grep -rn "total_rounds" lib/ingestion/` が0件）
10. 大会名・family のハードコードが無い（`top-14` という文字列で分岐していない）

### 表示（プレビューで実測）

11. `/calendar?week=2026-10-26` に注記が出て、**Top 14 が名指しされている**
12. 同じ注記に **シックスネイションズ 2021 が含まれない**
13. `/calendar?week=2026-09-07`（Top 14 が7試合ある週）に**注記が出ない**
14. `/c/top-14/2026-27` に注記が出る
15. `/c/urc/2026-27` に注記が**出ない**
16. `/c/premiership/2026-27` に注記が出る（第4節が欠落しているため。**これは正しい検出**）
17. 注記に未取得の試合数・日程の**推測値が含まれていない**
18. 大会名が `formatCompetitionTitle` 由来で、スラッグが露出していない
19. `/calendar` の「全大会横断」という説明文が**削除・改変されていない**

### ハブの「全N節」

20. `/c/top-14/2026-27` の進行バンドが **「0節 / 全26節」**（現在は「0節 / 全2節」）

### 共通

## 未解決の質問

1. **`total_rounds` を将来どう保守するか。** 新シーズンごとに手で入れる必要がある。`TOP14_LNR_SEASON` と同じ「毎年手で更新する定数」がもう1つ増える。**本 spec では手動投入とし、自動化は別途**。Codex は保守の手間を PR 本文で指摘してよい
2. **プレミアシップ 2026-27 の第4節欠落（5試合が節情報なし）。** 本 spec では検出するだけで直さない。**別の取り込み不具合として spec 化する価値があるか、Owner が判断する**
3. **`pnc/2026` の節番号が `101`。** 異常値だが `total_rounds` が null なので影響しない。本 spec では扱わない
4. **注記の文面。** PR #750 の「開催が近づいてから掲載されます」は、末尾の欠落（Top 14）には合うが**中抜け（プレミアシップ第4節）には合わない**。両方を1つの文面で表すか、分けるかは Codex が提案し Owner が決める
