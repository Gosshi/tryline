# プレビュー生成タイミングをメンバー発表後に近づける

## 背景

2026-07-10、週末ニュースダイジェスト（金曜18:00 JST発火のルーティン、Web検索でメンバー発表・負傷情報を収集しX reply/note素材にする）と、サイト自身のプレビュー生成タイミングを比較したところ、順序が噛み合っていないことが判明した。

本番DB実測: 2026-07-11開催のNations Championship 6試合のプレビューは全て2026-07-08 06:59〜2026-07-09 00:50 UTC（キックオフの約58〜88時間前）に生成されていた。一方、今夜の調査（`docs/notes/news-digest-2026-07-10.md`）で確認した各国協会のメンバー発表タイミングは、JRFU（日本代表）が キックオフ約37時間前、他の協会（IRFU・Springboks・Scottish Rugby等）も概ねキックオフ24〜48時間前が一般的。

つまり現在の `lib/cron/orchestrate.ts` の `PREVIEW_WINDOW_START_HOURS = 12` / `PREVIEW_WINDOW_END_HOURS = 72`（キックオフ12〜72時間前の窓）では、多くの試合でメンバー発表**前**にプレビューが生成されてしまっている。今夜有効化した `sourced_facts`（`feat-sourced-facts-nations-championship.md`、Web検索で最新チーム情報を収集する仕組み）も、生成タイミングが早すぎるとメンバー発表・負傷情報を拾えず、恩恵を活かせない。

`cron-live-pipeline.yml` により `orchestrate` は6時間おき（00/06/12/18 UTC）に実行されるため、`PREVIEW_WINDOW_END_HOURS` を縮小するだけで、次回の定期実行時から自然に新しいタイミングでプレビューが生成されるようになる。

なお、リーグワンは既存のWikipediaラインアップ取得が独立して機能している（過去実測で9/9件成功）ため、本specの影響は主にNations Championship等の `sourced_facts` 依存大会が対象になる。

## スコープ

対象:
- `lib/cron/orchestrate.ts` の `PREVIEW_WINDOW_END_HOURS` を `72` から `48` に変更する（キックオフ48時間前〜12時間前の窓に縮小）
- 変更後、次回のプレビュー生成が実際にメンバー発表後のタイミングに近づくことを、今後生成される試合で確認する（本spec作業時点では次回実行を待つ必要があるため、コード変更自体の完了をもって受け入れ条件とする）

対象外:
- 大会ごとに異なる窓を設定する仕組み（全大会一律の変更に留める。将来的に大会ごとの調整が必要になれば別specの候補とする）
- `PREVIEW_WINDOW_START_HOURS`（12時間前、下限）の変更
- 週末ニュースダイジェストのルーティン自体の変更（このままで問題ないため触れない）
- recap生成のタイミング（`RECAP` 側のウィンドウ設定があれば、それは対象外）

## データモデル変更

なし。

なし。

## 受け入れ条件

1. `PREVIEW_WINDOW_END_HOURS` が `48` に変更されている
2. 既存のテスト（`orchestrate` 関連のユニットテスト）が、新しい窓の値に合わせて更新され、パスする
3. `PREVIEW_WINDOW_START_HOURS`・recap関連のウィンドウ設定など、他の定数に意図しない変更が無い
4. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
5. 本番デプロイはOwner承認後に別途行う

## 未解決の質問

- `48時間` という具体的な値は暫定的な見積もり（メンバー発表の目安24〜48時間前に基づく）。実際に運用してみて、生成タイミングとメンバー発表タイミングの実測にズレがあれば、Owner判断で再調整してよい
