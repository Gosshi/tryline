# プレビュー本文のセクション見出しラベル露出を除去

## 背景

2026-07-03 のデザイン・UI・集客横断レビュー（`docs/design-ui-growth-review-2026-07-03.md` B-7）で、未開催試合のプレビュー本文に `# セクション1: 両チームの現状` のような**機械的なラベルがそのまま見出しとして表示されている**ことが判明した。実例: `/matches/42bebc1f-9225-452b-9786-9e0a1fbaa34a`（アルゼンチン vs スコットランド）で「セクション1: 両チームの現状」「セクション2: キープレイヤーと注目マッチアップ」「セクション3: 試合の展望」という見出しが表示されている。

recap（試合後レビュー）では同種の問題が `specs/fix-recap-heading-format.md`（`recap@4.2.0` → `4.3.0`）で既に修正済み。本 spec はその preview（試合前プレビュー）版にあたる。

## 根本原因

`lib/llm/prompts/generate-preview.ts:101-105` の `structureInstruction`:

```typescript
const structureInstruction = hasLineups
  ? "構成: 3セクション構成（セクション0を除く）。1)400-500字 2)600-700字 3)300-400字。全体で1,500字以上を下限とし、下回ってはならない。各セクションの見出し名はこの試合の特性に応じて自由に設定すること（「両チーム現状」に固定しない）。3セクションのうち1つはキープレイヤー/注目マッチアップを扱うセクションにすること。"
  : isDataSparse
    ? "構成: 3セクション構成（セクション0を除く）。1)500-600字 2)400-500字 3)400-500字。..."
    : "構成: 3セクション構成（セクション0を除く）。1)400-500字 2)600-700字 3)300-400字。...";
```

この指示文自体が「1)」「2)」「3)」という**セクション番号の列挙形式**で書かれているため、モデルが出力見出しにも同じ「セクションN:」という番号ラベルを反映してしまっている。recap の `fix-recap-heading-format.md` で判明したのと同じ「指示の書式がそのまま出力にコピーされる」パターンだが、原因の構文は異なる（recap は `# 見出し（字数）` の1行結合、preview は `1) 2) 3)` の番号列挙）。

`buildCoreQuestionBlock`（`generate-preview.ts:58-90`）が生成する「セクション0」も同様に `## セクション0（必須、200字以内）: # この試合の核心` という指示文だが、これは `# この試合の核心` という固定見出し名を明示指定しているため実害はない（実際の画面でも「セクション0」というラベルは表示されていない）。問題は自由設定セクション（1〜3）側のみ。

## スコープ

**対象:** `lib/llm/prompts/generate-preview.ts` のみ（recap と異なりプロンプトの構造自体は変えず、番号列挙をやめて自由記述に寄せる）

**対象外:**
- `lib/llm/prompts/generate-recap.ts`（対応済み、変更不要）
- `components/match-content-section.tsx` / `components/match-content.tsx`（見出しテキストをそのまま描画するだけの表示コンポーネントで、ロジック変更不要。原因はプロンプト側にある）
- 既存 preview コンテンツの再生成（本 spec は新規生成分の見出しフォーマットのみを直す。過去分の扱いは「未解決の質問」参照）

## 実装詳細

### バージョン更新

```typescript
export const PROMPT_VERSION = "preview@3.6.0";
```

### `structureInstruction` の3ケースを書き直す

「1) 2) 3)」という番号列挙をやめ、見出し出力に関する明示的な禁止文を追加する。3ケースとも共通で以下の禁止文を末尾に追加すること:

```
"見出し行には内容を要約した具体的なタイトルのみを書くこと。「セクション1」「セクション2」「Section 1」等の連番ラベルや「セクション0」を見出しに含めてはならない。"
```

`hasLineups` の場合の例（他2ケースも同様のパターンで書き換える）:

「1)400-500字 2)600-700字 3)300-400字」という番号列挙の記法自体を「1セクション目◯字、2セクション目◯字」という文章に置き換える点が recap 修正と同じ思想（=モデルへの指示フォーマットと出力フォーマットを分離する）。

`buildCoreQuestionBlock` のセクション0部分（58-90行目）は変更不要（実害なしのため）。

## 受け入れ条件

1. `PROMPT_VERSION` が `preview@3.6.0` になっている
2. 新規生成されたプレビューの見出しが「セクション1:」「セクション2:」「Section 1」等の連番ラベルを含まない
3. 生成された見出しは依然として試合の特性に応じた具体的な内容（例:「両チームの現状」「キープレイヤーと注目マッチアップ」）になっている
4. 全体字数が既存基準（1,500字以上）を満たしている
5. `hasLineups` / `isDataSparse` / 通常ケースの3パターンそれぞれで少なくとも1件テスト生成し、見出しに連番ラベルが出ないことを目視確認する（**少件数の試し焼き→検品→必要なら追加生成**という段階を踏むこと。一括再生成は行わない）

## 未解決の質問

- 既存の公開済みプレビュー（連番ラベルが既に露出しているもの）を再生成するかどうかは Owner 判断。再生成する場合は `content-regen` スキルの試し焼きルールに従うこと。本 spec は新規生成分の予防にとどめ、既存分の一括再生成はスコープ外とする
- `# セクション0` という文言が `buildCoreQuestionBlock` の指示コメント内に残るが、これは実際の出力見出しには影響しないため変更不要と判断した。もし将来的に別の問題が見つかった場合は別 spec で対応する
