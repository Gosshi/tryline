# Web 検索で事実を集める処理の費用を下げる

## 背景

2026-09-26、Owner から「OpenAI の料金の減りが異様に早い」と相談があった。OpenAI の管理画面（直近 7 日、2026-09-20〜26）と `pipeline_runs` を突き合わせた結果は次のとおり。

| 項目 | 金額（7 日） |
|---|---:|
| 合計 | $16.88 |
| `gpt-5.6-terra`（入力・出力・キャッシュ書き込み・キャッシュ読み込み） | 約 $12.2 |
| Web 検索ツールの呼び出し | $2.37 |
| `gpt-5.6-luna` | 約 $2.05（9/24 の人名監査を含む） |
| `pipeline_runs` に記録された本文生成（段 3、`gpt-5.6-terra`）| 約 $4.7 |

- `gpt-5.6-terra` の $12.2 のうち、記録された本文生成と試し焼きを除いた**約 $7 は、Web 検索で事実を集める処理**（`fetchSourcedFactsForMatch`、`lib/llm/sourced-facts/fetch.ts`）と見られる。検索結果が大量に入力に入るため。この処理は `pipeline_runs` に記録されていない。**推定であり、実測するためにこの spec で記録を足す。**
- 検索ツールの $2.37 と合わせ、**事実を集める処理だけで週 $9〜10**。本文生成（週 $5 前後）の約 2 倍。
- 9 月の支出は $49.72 で、予算の $20 を超えている。

費用が膨らむ仕組み（コードで確認）:

1. **プレビューで、手で入れた事実と自動の検索が重なっている。** Owner は週 3 回 ChatGPT で翌日の試合を調べて Discord から入れている（`/調査事実を追加`）。直近 3 週間で、手で事実を入れたプレビュー 18 試合のうち 16 試合で、自動の Web 検索も走っていた。2026-09-25 から、ChatGPT の調べ物は翌日の全試合が対象になった。
2. **レビューでは、事実が 0 件か数値の事実が無いと、続けて 2 回目の検索をする**（`fetch.ts` の `searchSourcedFacts` を 2 回呼ぶ箇所）。
3. **事実が 0 件だった検索は記録が残らず、次に同じ試合を処理するときにまた検索する。** キャッシュの判定（`fetch.ts:517-535`）は、保存された事実が 1 件以上あるときだけ効く。

## スコープ

**対象**
1. プレビューで、その試合に手で入れた事実が 1 件以上あれば、自動の Web 検索をしない。
2. レビューの 2 回目の検索をやめる。
3. Web 検索を 1 回するたびに `pipeline_runs` に 1 行記録し、事実が 0 件だった検索もキャッシュとして扱う。
   - あわせて、Web 検索の費用（トークンの分）を記録する。今は記録の外にある費用が見えるようになる。

**対象外**
- 検索に使うモデルの変更（`MODELS.WEB_SEARCH` は `gpt-5.6-terra` のまま）。
- 検索のプロンプト、事実の選び方、生成に渡す件数。
- 料金表（`lib/llm/pricing.ts`）へのキャッシュ書き込みの料金の追加。別の問題として扱う。

## データモデル変更

なし（テーブルは増やさない）。`pipeline_runs` の既存の列を使う。

- `stage = 5`（Web 検索で事実を集める段。今は 0〜4 が使われている。`stage` に制約はない）
- `content_type`、`match_id`
- `output`: `{ "facts_found": <保存した件数>, "prompt_version": SEARCH_PROMPT_VERSION, "skipped_reason": <下の 1 で検索しなかった場合の理由 or null> }`
- `cost_usd`: 検索の応答の `usage`（入力・出力トークン）から `calculateCostUsd` で出した値。**検索ツールの呼び出し料金は含まない**（`usage` に出ないため）
- `status`: `success`（検索できた。0 件を含む）/ `failed`（例外）
- `duration_ms`、`input_hash`（`hashInput({ matchId, contentType, promptVersion })` でよい）

## API サーフェス

### 1. 手で入れた事実があるプレビューでは検索しない（`fetchSourcedFactsForMatch`）

- `contentType === "preview"` で、読み込んだ事実（`loadAllowedSourcedFactRows` の結果）の中に `model_version = "manual"` の行が **1 件以上**あれば、Web 検索をせずに、今ある事実（手で入れた事実と、それまでに保存された自動の事実）を返す。
  - 戻り値は、今のキャッシュを使った場合と同じ形（`cached: true`、`fetched: false`）にする。
  - `pipeline_runs` に `stage = 5`、`status = "success"`、`output.skipped_reason = "manual_facts_present"`、`cost_usd = 0` の行を記録する（あとで効果を数えるため）。
- **`force: true` でも、この判定を優先する**（ラインアップ到着後の再生成など、`force=true` で呼ぶ経路でも、手で入れた事実があれば検索しない）。
- レビュー（`recap`）には、この判定を使わない（手で入れる事実はプレビューが中心で、レビューは数値の事実を自動の検索に頼っているため）。

### 2. レビューの 2 回目の検索をやめる

- `fetch.ts` で、レビューのときに `searchSourcedFacts()` をもう一度呼ぶ処理を削除する。検索は 1 回だけにする。

### 3. 検索を記録し、0 件の結果もキャッシュにする

- Web 検索（`searchSourcedFacts`）を 1 回するたびに、上の形で `pipeline_runs` に 1 行記録する。例外で失敗したときも `status = "failed"` で記録する。
- キャッシュの判定（今の `fetch.ts:517-535`）に、次の条件を足す。
  - 保存された自動の事実が 0 件でも、同じ試合・同じ `content_type` で、**今の `SEARCH_PROMPT_VERSION` の `stage = 5`・`status = "success"` の記録**があれば、その記録の時刻を `fetchedAt` として `shouldUseCachedFacts` に渡し、`true` なら検索しない（今ある事実を返す）。
  - つまり、プレビューはキックオフ 72 時間前より前なら記録があれば検索しない、72 時間以内なら 24 時間以内の記録があれば検索しない。レビューは記録があれば検索しない（今の `shouldUseCachedFacts` と同じ）。
- `force: true` のときは、今までどおりキャッシュを使わずに検索する（ただし 1 の判定が優先）。

## LLM 連携

- 呼び出しの回数が減るだけで、モデル・プロンプトは変えない。
- 効果の見込み（週あたり）: プレビューの検索が大きく減り（手で入れた事実がある試合）、レビューの検索は 2 回目が無くなる。事実を集める処理の週 $9〜10 のうち、半分以上が減る見込み。**実測はマージ後に `stage = 5` の記録で行う。**

## 受け入れ条件

1. **手で入れた事実があるプレビュー:** `model_version = "manual"` の事実が 1 件ある試合のプレビューで、`createWebSearchJsonResponse` が呼ばれない。`force: true` でも呼ばれない。`pipeline_runs` に `stage = 5`・`skipped_reason = "manual_facts_present"` の行が記録される。
   - 確認方法: 判定を外すと、このテストが落ちること。
2. **手で入れた事実が無いプレビュー:** 今までどおり検索する。
3. **レビューは 1 回だけ検索する:** 1 回目の検索で事実が 0 件でも、`createWebSearchJsonResponse` は 1 回だけ呼ばれる。
   - 確認方法: 2 回目の検索を戻すと、このテストが落ちること。
4. **検索の記録:** 検索するたびに `stage = 5` の行が 1 行記録され、`output.facts_found`・`output.prompt_version`・`cost_usd`（`usage` から計算）が入る。検索が例外を投げたときは `status = "failed"` で記録され、例外はこれまでどおり呼び出し元に伝わる。
5. **0 件の結果のキャッシュ:**
   - レビューで、同じ試合に今の版の `stage = 5`・`success`・`facts_found = 0` の記録があれば、検索しない。
   - プレビュー（キックオフまで 72 時間以内）で、同じ記録が 24 時間以内なら検索せず、24 時間より前なら検索する。
   - 記録の `prompt_version` が今の版と違えば検索する。
   - `force: true` なら、記録があっても検索する（手で入れた事実が無い場合）。
6. `pnpm lint`、`pnpm typecheck`、`pnpm test` が通る。**3 つとも実行して、結果を完了報告に含める。**
