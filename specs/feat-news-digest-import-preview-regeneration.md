# ダイジェスト取り込み後にプレビューを再生成できるようにする

## 背景

2026-07-11、`feat-news-digest-sourced-facts-bridge.md`（`scripts/import-news-digest-facts.ts`、PR #543）で週末ニュースダイジェストの事実を`match_sourced_facts`に取り込む仕組みができたが、**タイミング上の問題**が判明した。

プレビュー生成（`orchestrate.ts`の6時間おきcron）は、試合がキックオフ48時間前の窓に入り次第すぐに生成される（`fix-preview-generation-window-timing.md`で72→48時間に調整済み）。一方、週末ニュースダイジェストは金曜18:00 JST固定で発火する。

土曜19:10 JST開催の試合の場合:
- プレビュー生成対象になるのは木曜19:10 JST（48時間前）、次のcron実行（木曜21:00 JST）で**その時点で生成完了**
- ダイジェストが出るのは金曜18:00 JST — プレビュー生成の約21時間後

つまり、ダイジェストの事実を`import-news-digest-facts.ts`で取り込んでも、対象試合のプレビューは既に生成・公開済みで、記事本文には反映されない。

ダイジェストの金曜18:00 JST発火タイミングは、メンバー発表の実際のタイミング（キックオフ24〜48時間前が一般的）に意図的に合わせたものであり、これを前倒しするとダイジェストの価値（発表後にしか分からない情報）が失われる。そのため、**プレビュー生成側が新しい事実の到着に追従する**方向で解決する。

## スコープ

対象:
- `scripts/import-news-digest-facts.ts`に`--regenerate-preview`フラグを追加する。このフラグが指定された場合、事実が正常にマッチ・保存された試合について、既存のプレビュー記事（`match_content`、`content_type='preview'`）が存在すれば`lib/llm/pipeline.ts`の`generateMatchContent(matchId, "preview", "ja")`を呼び出して再生成する
- 再生成は、LLM呼び出し（narrative生成）を伴う実コストが発生するため、Owner明示のオプトイン（フラグ指定時のみ）とする。デフォルト（フラグ無し）では再生成しない
- 再生成対象の試合一覧・件数を実行結果に明記する（`--dry-run`と組み合わせた場合は「再生成される予定の試合」を表示するのみで実際には再生成しない）

対象外:
- プレビュー生成の自動トリガー化（ダイジェストマージ・インポート実行を検知して自動的に再生成を走らせる仕組み。本specはOwnerが明示的にフラグを付けて手動実行する運用に留める）
- recap（レビュー）側の再生成（本specはpreviewのみを対象とする）
- 英語版コンテンツ（`language="en"`）の再生成

## LLM 連携

- 使用モデル: 既存の`generateMatchContent`が内部で使う`MODELS.NARRATIVE`（`gpt-4o`）をそのまま使用、変更なし
- **コスト見積もり**: 週末に対象となる試合数（Nations Championship等、目安10〜15試合/週末）× `--regenerate-preview`指定時のみ再生成。1回あたりのプレビュー生成コストは既存の通常生成と同等（見積もり不要、既存機能の再利用のため新規コストパターンではない）。Owner明示のオプトインのため、実行するかどうか自体もOwnerが都度判断できる

## 受け入れ条件

1. `scripts/import-news-digest-facts.ts --file=<path> --regenerate-preview --dry-run`で、事実がマッチした試合のうち、既存プレビューが存在し再生成対象になる試合の一覧が表示される（実際には再生成しない）
2. `--regenerate-preview`（`--dry-run`無し）で実行すると、対象試合について`generateMatchContent`が呼ばれ、プレビュー記事が実際に更新される
3. `--regenerate-preview`を指定しない場合、事実の取り込みのみが行われ、既存の動作（PR #543時点の挙動）に回帰がない
4. 既存プレビューが存在しない試合（まだプレビュー生成窓に入っていない等）は再生成の対象外として扱われ、エラーにならない
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本番DBへの実際の書き込み・再生成の実行はOwner承認後に別途実施する。本spec自体はスクリプト実装・テスト・`--dry-run`確認までで完了とする

## 未解決の質問

- 再生成によって既に公開済みのプレビュー記事の内容が変わることについて、Owner側での確認・告知が必要かはOwnerの運用判断とし、本spec内では扱わない
