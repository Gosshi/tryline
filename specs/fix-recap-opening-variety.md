# fix-recap-opening-variety

## 背景

PMF 監査（2026-06-10）で、published recap 908件中339件（37%）が `# この試合の核心` セクションの冒頭300字以内で「得点力」フレーミングを使っていることが判明した。見出し構造（核心/全体像/ターニングポイント…）が全件固定であることと合わせ、3本目以降で読者に「全部同じ」と気づかれる。

**根本原因**: `generate-recap.ts` の `dataSparseBlock` に `得点力・失点傾向` という語が明記されており、LLM がそのまま使う。非スパースケースでも `key_stats.match` の得点・失点データを説明するよう指示されているため、同様に「得点力」で始まる傾向がある。`PROHIBITIONS_BLOCK` に冒頭パターンの禁止がない。

## スコープ

対象:
- `lib/llm/prompts/shared-prompt-blocks.ts`: `PROHIBITIONS_BLOCK` に冒頭禁止句を追加
- `lib/llm/prompts/generate-recap.ts`: `dataSparseBlock` の語句変更 + 冒頭バリエーション指示追加 + `PROMPT_VERSION` 更新

対象外:
- `generate-preview.ts`（preview の冒頭変換は `fix-preview-variety.md` で別途対応）
- QA プロンプト・スコアリングロジック

## 変更詳細

### 1. `lib/llm/prompts/shared-prompt-blocks.ts` — `PROHIBITIONS_BLOCK` に追加

既存の禁止句リストの末尾に以下を追加する:

```
- 「得点力の差が注目」「得点力が際立」「得点力が問われ」「得点力が光」など「得点力」で始まる冒頭フレーズ（代わりに試合の決定的な転換点・スコア経緯・具体的なプレーから始めること）
- 「◯◯と□□の対決は」で始まるパターン（試合結果や核心的事実を先に置くこと）
- 「プレーオフの一発勝負」「一発勝負の意義」という冒頭定型句（プレーオフであることは文脈から明らか。具体的な意義・歴史・対戦構図から書き始めること）
```

### 2. `lib/llm/prompts/generate-recap.ts` — `dataSparseBlock` の語句変更

現状:
```
"- recent_form の直近5試合から得点力・失点傾向・連勝/連敗ストリークを読み取り本文に反映すること",
```

変更後:
```
"- recent_form の直近5試合から連勝/連敗ストリーク・平均得失点の傾向（攻撃型 or 守備型か）・直近の勝ち方の特徴を読み取り本文に反映すること。冒頭は「得点力」で始めず、直近の試合展開・プレースタイルの特徴・今節の文脈から書き始めること",
```

### 3. `lib/llm/prompts/generate-recap.ts` — 核心セクション指示に冒頭バリエーション例を追加

`structureInstruction` 内の `# この試合の核心` の字数・内容指示に、以下の例示を追記する:

```
- この試合の核心: 200字以内。定型句を使わず、この試合固有の事実（最終スコア・決勝点のシチュエーション・試合の転換点）から書き始めること。
  書き方の例（パターン名は出力しない）:
  ・逆転劇型: 「79分のトライで逆転——{チーム名}が3連敗から抜け出した必然」
  ・戦術型: 「前半のスクラム圧倒が後半のペナルティ量産につながった{チーム名}の勝利構造」
  ・スコア対比型: 「{点数}対{点数}という数字より、前半と後半で別々のチームになった試合だった」
```

### 4. `PROMPT_VERSION` 更新

```typescript
export const PROMPT_VERSION = "recap@4.7.0";
```
