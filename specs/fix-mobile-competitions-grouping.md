# fix-mobile-competitions-grouping

## 背景

tryline-mobile の「大会」タブ（`app/(tabs)/competitions/index.tsx`）は、`/api/v1/competitions` が返す大会×シーズンの組み合わせ（例: 「パシフィックネーションズカップ 2026」「パシフィックネーションズカップ 2025」...）を**フラットな1リスト**として並べている。

実機TestFlightでのOwner確認により、「大会ごとに分かれてなくて、2026 pnc、2023pncみたいに羅列していて探しづらい」という具体的な不満が出た。

本番APIで実測したところ、現在32件の大会×シーズンが11の大会ファミリー（`family`）に属している。Six Nationsだけで8シーズン分（2020〜2027）がフラットに混在しており、目的の大会を探すのに全件スクロールが必要な状態。

`V1Competition` 型には既に大会ファミリーを示す安定識別子 `family`（例: `"pnc"`, `"six-nations"`）と、シーズンを含まない大会名 `name`（例: `"パシフィックネーションズカップ"`）、シーズン単体 `season`（例: `"2026"`）が個別フィールドとして存在する。API・DB側の変更は不要で、モバイル側の表示ロジックのみの修正で解決できる。

## スコープ

対象: `app/(tabs)/competitions/index.tsx` の一覧表示を `family` 単位でグルーピングし、大会名を1回だけ表示、その下にシーズンをチップ形式で並べる形に変更する。

対象外:
- `/api/v1/competitions` のレスポンス形式変更（既存の `family` フィールドをそのまま使う）
- `app/(tabs)/competitions/[slug].tsx`（個別大会シーズンの詳細画面）の変更
- 折りたたみ/展開（アコーディオン）UIの導入。シーズン数が最大8件（Six Nations）程度で全チップを常時表示しても許容範囲のため、開閉インタラクションは追加しない
- Web版（tryline本体）の変更。Web側に同等のフラット一覧ページは現状存在しない

## データモデル変更

なし。`V1Competition`（`src/api/types.ts`）の既存フィールド（`family`, `name`, `season`, `slug`, `match_count`, `start_date`, `end_date`）のみを使う。

## API サーフェス

変更なし。

## UI サーフェス

`app/(tabs)/competitions/index.tsx` を以下のロジックに変更する。

### グルーピング

1. `query.data.competitions` を `family` でグループ化する
2. 各グループ内で、`match_count` 降順 → `start_date` 降順（新しいシーズンを優先）でシーズンをソートする
3. 各グループの「代表シーズン」は、グループ内で `match_count > 0` のシーズンがあればその中で `start_date` が最も新しいもの、無ければ単純に `start_date` が最も新しいものとする（開催中・直近開催の大会を優先して見せるため）

### グループの並び順

既存の `sortCompetitionsForDisplay` と同じ考え方をグループ単位に適用する:
- 代表シーズンの `match_count > 0` のグループを先に、`match_count === 0` のグループを後に
- 同条件内は `name`（大会名）の `localeCompare` 昇順

### カードのレイアウト

各大会ファミリーにつき1枚の `Card` を表示する:
- 上段: 大会名（`name`）を `styles.title`相当のスタイルで1行表示
- 中段: 代表シーズンの `season` とその `match_count`（例: `2026シーズン・12試合`)
- 下段: シーズン一覧をチップ（`Pressable` + 小さめの角丸背景）で横並び表示。**シーズンが1件のみのグループはチップ行を表示しない**（例: Nations Championshipは2026のみなので中段の表示だけで十分）
- チップは新しい順（ソート済みの順序どおり）に並べ、代表シーズンのチップは選択中であることが分かる見た目（背景色や太字など、`theme/tokens.ts` の既存トークンを使う）にする
- カード自体のタップ（チップ以外の領域）は代表シーズンの `slug` へ遷移。各チップのタップはそのチップのシーズンの `slug` へ遷移（現行の `Link href={`/(tabs)/competitions/${slug}`}` と同じ遷移先パターン）

### スタイリング

`theme/tokens.ts` の既存の `colors` / `spacing` / `typography` トークンのみを使う。新しい色やハードコードされた値を追加しない。

## LLM 連携

なし（表示ロジックのみ）。

## 受け入れ条件

1. `/api/v1/competitions` が32件（11ファミリー）を返す現在の本番データを前提に、大会タブに表示されるカードが11枚になる（32枚ではない）
2. Six Nations（8シーズン）のカードに、8個のシーズンチップが表示される。Nations Championship（1シーズンのみ）のカードにはチップ行が表示されない
3. 各ファミリーの代表シーズンは、そのファミリー内で `match_count > 0` のシーズンがあればその中で `start_date` が最新のものになっている（ユニットテストで検証: 例えば `match_count: [0, 12, 5]`、`start_date` 降順の3シーズンを持つファミリーで、`match_count > 0` の2件のうち `start_date` が新しい方が代表シーズンとして選ばれることを確認）
4. シーズンが1件しかないファミリーのグループでも、代表シーズンの選定ロジックが正しく1件を返す(0件で落ちない)
5. 代表シーズンのチップをタップすると `/(tabs)/competitions/${代表シーズンのslug}` へ遷移する。別のシーズンチップをタップするとそのシーズンの `slug` へ遷移する
6. 既存の `sortCompetitionsForDisplay` のシーズン単位ソート関数は、グルーピング用の新しい関数に置き換えるか、グルーピング関数内部から再利用する形にし、重複ロジックを作らない
7. `pnpm test` で新規ロジック（グルーピング・代表シーズン選定・グループソート)のユニットテストが通ること

## 未解決の質問

- 大会数が将来的に大きく増えた場合（例: 20ファミリー以上）にページ内検索やフィルタが必要になるか。現状11ファミリー・最大8シーズンでは不要と判断し、本specのスコープ外とする
