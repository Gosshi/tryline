# 試合詳細ページの読了後の導線を改善する

## 背景

2026-07-10、Codex（新モデル）によるデザイン評価（78/100）で指摘された課題。

`app/matches/[id]/page.tsx`（283行目付近）と `components/match-content.tsx` の現在の構成を確認すると、記事セクションは以下の順序:

```
MatchContentSection（記事本文）→ MatchLineupsSection（ラインアップ）→ StandingsTable（全順位表）→ PremiumMatchChat（AIチャット）
```

Nations Championshipのような12チーム規模の大会では、全順位表がモバイル画面で長い壁になり、読み終えたユーザーが「次はどうすればいいか」の導線（次戦・他の試合・応援チーム登録）に辿り着く前に離脱しやすい構造になっている。

## スコープ

対象:
- `StandingsTable` の初期表示を、全チームではなく該当2チーム（対戦した両チーム）を中心とした抜粋表示に変更し、「全順位表を見る」等のクリックで展開できるようにする
- ページ最下部（`PremiumMatchChat` の後、または順位表の直後）に「次に見る」ブロックを追加する。含める内容:
  - 「両チームの次戦」と「このチームを追う」（`feat-favorite-team-follow-engagement.md` の機能を利用）へのリンク
  - 同じ大会・同じ節（ラウンド）の他の注目レビュー2件（例: 直近で公開されたレビューのうち、この試合と同じ `wikipedia_round`/節の試合を優先。無ければ同大会の直近レビューでよい）
  - 「今週の全試合を見る」等、`/calendar` への導線
- ページヘッダーに `feat-spoiler-guard-ui.md` で実装するネタバレ防止トグルへのショートカット（既存のPush通知設定への導線、または簡易トグル）を追加できるか検討する（`feat-spoiler-guard-ui.md` 実装後に着手する想定でよい）

対象外:
- `StandingsTable` コンポーネント自体のデータ取得ロジック変更（表示件数の絞り込みのみ、SSR上では全データを保持しSEOへの影響が出ないようにする）
- AIチャット機能自体の変更

## UI サーフェス

- `components/standings-table.tsx`（または呼び出し元）に、抜粋表示モード（該当2チーム中心）と展開表示の両方を実装する
- `app/matches/[id]/page.tsx` の末尾に「次に見る」ブロック（両チームの次戦・このチームを追う・同節の他レビュー2件・今週の全試合カレンダーへの導線）を追加する

## 受け入れ条件

1. Nations Championship等の10チーム以上の大会の試合ページで、順位表が初期状態では全チームでなく該当2チーム中心の抜粋になっている
2. 「全順位表を見る」等の操作で全チーム表示に展開できる
3. SSR時点（JavaScript無効時）でも全順位表データがHTMLに含まれている（SEOへの影響がないことを`view-source`等で確認する）
4. ページ最下部に「次に見る」ブロックがあり、両チームの次戦情報・「このチームを追う」導線・同じ大会/節の他レビュー2件（無ければ同大会の直近レビュー）・`/calendar` への導線が含まれている
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本番デプロイ前に実際のブラウザで表示確認する。本番デプロイ自体はOwner承認後に別途行う

## 未解決の質問
