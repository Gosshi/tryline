# Web からアプリへの導線を作る（通知訴求）

## 背景

2026-08-19、iOS アプリが App Store 審査を通過した（4 回の却下を経て承認）。

しかし **web サイトにアプリへの導線が 1 つも存在しない。** `app/` `components/` を grep しても `apps.apple.com` へのリンクはゼロ。`support` と `privacy` に文言があるだけ。**公開されたが、既存訪問者に伝える手段が無い。**

### なぜ「集客」ではなく「再訪」の道具なのか

実測値を並べると、Tryline の課題は集客ではない。

| 指標 | 実測 |
|---|---|
| 大会ハブの滞在 | 107 秒 |
| カレンダーの滞在 | 120 秒 |
| 試合ページの滞在 | **3.6 秒** |
| **再訪** | **97% がゼロ** |
| 月間ユーザー | 約 110（Bing 85 / Google 25、28日） |

**月 110 人が来て、その 97% が二度と戻らない。**記事を 934 本書いてもこの数字は動いていない。

**アプリの固有価値はプッシュ通知**である（試合前通知・コンテンツ公開通知は実装済みで稼働中、`cron-send-prematch-notifications` / `cron-send-content-notifications`）。**web に無い機能はこれだけ**で、しかも再訪問題に直接効く。

したがって訴求は「アプリがあります」ではなく **「試合開始前に通知します」** とする。

### なぜハブとカレンダーだけなのか

**滞在時間が長い＝読む姿勢がある**のはこの 2 つだけ。試合ページは 3.6 秒で、何を置いても見られない。

さらに Bing 流入の **86% が大会ハブに着地**している。**入口はハブである。**

### 今が好機である理由

**南アフリカ vs ニュージーランドの 4 テストシリーズが 8/23〜9/13 に進行中**（`greatest-rivalry-2026`、全 8 試合）。

**第1戦のキックオフは日曜 00:10 JST**。以降も日曜未明が続く。**「寝ている間に終わる試合」は通知価値が最も伝わる題材**であり、5 週間繰り返し使える。

## スコープ

対象:
- Apple Smart App Banner（`apple-itunes-app` メタタグ）の設置
- 大会ハブ（`app/c/[competition]/[season]/page.tsx`）へのアプリ CTA
- カレンダーページへのアプリ CTA
- App Store URL をキャンペーントークン付きで管理する定数
- 上記に対応するテスト

対象外:
- **試合詳細ページへの CTA**（滞在 3.6 秒。置いても見られない）
- **モーダル・インタースティシャル・ポップアップ**（UX と SEO の両方を損なう）
- Android 向けの導線（**アプリが存在しない**）
- アプリ内の web 誘導（逆方向）
- App Store のメタデータ・キーワード（ASO は別件）
- 通知機能そのものの変更

## UI サーフェス

### 1. Smart App Banner（最優先・最小コスト）

`<head>` にメタタグを 1 行置く。

```
<meta name="apple-itunes-app" content="app-id=6791587357">
```

- **iOS Safari でのみ表示される**（Apple 側が判定するので、こちらで UA 判定を書かない）
- 閉じられる。レイアウトシフトを起こさない
- **他の環境では何も描画されない**ので、Android/デスクトップへの実害ゼロ

**サイト全体に出すか、ハブとカレンダーに限るかは Codex の判断でよい。**ただし試合ページに出す積極的理由は無い。

### 2. ハブとカレンダーの CTA ブロック

要件は以下。**具体的な見せ方は Codex の判断でよい。**

1. **訴求は通知。**「試合開始前に通知」を主文にする。「アプリをダウンロード」を主文にしない
2. **iOS のみ提供中であることが分かる**こと（Android ユーザーに期待させない）
3. **既存のページ性能を落とさない。**ハブは滞在 107 秒の主要導線であり、**レイアウトシフト（CLS）を起こさないこと**
4. **画面上部を占有しない。**ハブの主目的は日程と結果の確認であり、それを押し下げない
5. 大会ハブでは、**その大会の次戦が近いほど文脈が効く**。次戦情報と絡めるかは Codex の判断でよい

### 3. App Store URL の管理

キャンペーントークンを付けて、**どの面から来たか計測できるようにする。**

```
https://apps.apple.com/jp/app/id6791587357?ct=<surface>
```

`ct` は App Store Connect の App Analytics で「キャンペーン」として集計される。**面ごとに別のトークンを付けること**（例: `hub` / `calendar` / `banner`）。**URL を各所に直書きせず、定数から生成する。**

## 受け入れ条件

1. `apple-itunes-app` メタタグが出力され、`app-id=6791587357` を含む
2. App Store URL が定数から生成され、**各所に直書きされていない**
3. ハブとカレンダーで、**それぞれ異なる `ct` トークン**が付与される
4. 大会ハブに通知訴求の CTA が表示される
5. カレンダーに通知訴求の CTA が表示される
6. **試合詳細ページに CTA が追加されていない**
7. CTA の主文が「通知」であり、「ダウンロード」ではない
8. iOS 以外の環境で、**Smart App Banner が描画されない**（Apple 側の挙動に委ねる。自前の UA 判定を書かない）
9. CTA が**レイアウトシフトを起こさない**（画像・フォントの読み込みで高さが変わらない）
10. **モーダル・ポップアップ・インタースティシャルを使っていない**
11. `pnpm test` と型チェックが通る

### テスト

13. **試合詳細ページに CTA が無いことのテスト**（回帰防止）
14. `ct` トークンが面ごとに異なることのテスト

### 検証（Owner）

15. デプロイ後、iOS 実機の Safari でハブを開き、Smart App Banner が出ることを確認
16. デスクトップでバナーが出ないことを確認
17. **1 週間後に App Store Connect の App Analytics で、`ct` 別のインストール数を確認する。**面ごとの効果が分かる

## 未解決の質問

1. **レビューが 0 件である。**App Store で評価ゼロのアプリは、導線を作っても入れてもらいにくい。**導線整備と並行して知人・関係者にレビューを依頼する必要がある**が、X のフォロワーが 9 人であり依頼先が限られる。別途検討
2. モバイル/デスクトップの流入比率が未計測。**iOS のみの提供なので、デスクトップ比率が高いと CTA の効果が薄い。**GA4 で確認する価値がある
3. `ct` トークンの粒度。大会ごと（`hub-greatest-rivalry`）まで分けるか、面単位（`hub`）で足りるか。**まず面単位で始め、必要になったら細かくする**方針を推奨
4. アプリが Android に対応していないため、**Android ユーザーには何も提供できない。**PWA のインストール導線（`beforeinstallprompt`）を代替として出すかは別途判断
