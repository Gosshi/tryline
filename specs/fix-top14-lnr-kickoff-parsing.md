# Top 14 の結果が1件も取り込めない問題を直す

## 背景

**Top 14 2026-27 は開幕節から1試合もスコアが入っていない。**

2026-09-07 時点の本番 DB。

```
節   試合  finished  スコアあり  初戦
j1     7        0         0     2026-09-05  ← 開幕節、既に終了
j2     7        0         0     2026-09-12
j3     7        0         0     2026-09-19
```

lnr.fr の j1 のページには**7試合すべてがスコア付きで載っている**（2026-09-07 に確認。`Aviron Bayonnais 27 - 26 RC Toulon` など）。

**取り込みは毎回走っており、現在節も `j1` のまま**（`fetchTop14LnrCurrentRoundSlug` が `j1` を返す）なので、対象からは外れていない。**パーサが1件も返していない。**

### 診断で見えなかった理由

`fetchTop14LnrRoundResultsWithDiagnostics("2026-27","j1")` の結果は次のとおりだった。

```
unknownTeamNames: []
取得された試合: 0件
```

**チーム名の解決は成功しており、診断が「0件」としか言わないため原因が分からなかった。** 開幕から2日、誰も気づけなかった。

## 原因（2つある）

### 1. 日付のセレクタが実在しない

```ts
lib/scrapers/top14-lnr-results.ts:277-285
findFixtureDateContext:
  .closest(".calendar-results__line")
  .prevAll(".calendar-results__fixture-date")   ← 実HTMLに存在しない
```

`.calendar-results__line` は存在する。**しかし `.calendar-results__fixture-date` は0件**で、`findFixtureDateContext` が `null` を返す。

その結果 `kickoffAt` が `null` になり、**`if (!kickoffAt) return;`（`:349`）で7試合すべてが捨てられている。**

**日付自体はページにある。** `.calendar-results__inner`（試合行の2つ上の親）のテキスト先頭に `Journée 1 samedi 05 septembre` として入っている。

### 2. 時刻が存在しない

```ts
lib/scrapers/top14-lnr-results.ts:239-243
const time = normalizeFrenchText(params.timeText).match(/^(\d{1,2})h(\d{2})$/);
if (!date || !time) return null;
```

**`.match-line__time` は空文字である**（実測）。**セレクタを直して日付が取れても、時刻が無いため `parseTop14LnrKickoffAt` は null を返し続ける。**

**現在のページに試合開始時刻の表記は見当たらない。** 節ページは日付までしか持っていない可能性が高い。

## 1. 日付の取得元を変える

**`.calendar-results__fixture-date` への依存をやめること。**

実HTMLの構造（2026-09-07 実測）。

```
.calendar-results__inner       ← "Journée 1 samedi 05 septembre …" を含む
  .calendar-results__line      ← 試合1件ぶん
    .match-calendar-line
      .club-line__name ×2
      .match-line__score
```

**日付は `.calendar-results__inner` のテキストから取る。** ただし**このテキストには全試合ぶんが連結されている**ため、**先頭の日付表記だけを取り出すこと。**

**`parseDateParts` は変更しないこと。** `05 septembre` を解釈でき、`monthIndex >= 7` からシーズン開始年（2026）を補う既存のロジックがそのまま使える。

**同じ節に複数の日付がある場合の扱いを確認すること。** Top 14 は金曜〜日曜に分かれることがある。**実HTMLに日付の区切りが複数あるなら、試合ごとに直近の日付を引く形にすること。** 1つしかないと決めつけない。

## 2. 時刻が無いときの扱い

**時刻が取れない場合でも試合を捨てないこと。**

現在は `if (!date || !time) return null` で、**時刻が無いだけで試合ごと落ちる。**

**日付が取れていれば取り込むこと。** 時刻の既定値は次のいずれかとする。

- **推奨: その日の 00:00 Europe/Paris**（`toEuropeParisUtcIso` にそのまま渡せる）

**既定値を使ったことが分かるようにすること。** 後から実時刻で上書きできるよう、`external_ids` かログに記録する。

**注意**: これはカレンダー表示に影響する。**JST では日付が1日ずれる可能性がある**（Paris 00:00 = JST 07:00 なので同日になるが、**夏時間の扱いは `toEuropeParisUtcIso` に委ねること**）。

**`parseTop14LnrKickoffAt` のシグネチャを変える場合、呼び出し側をすべて確認すること。**

## 3. 0件を異常として検知する

**節ページから1件も取れなかった場合を、警告として表面化させること。**

現在は `matches: []` が正常な結果と区別できない。**開幕から2日、誰も気づけなかった原因はここにある。**

診断結果に次を含める。

- `.calendar-results__line`（または相当）の**要素数**
- そのうち**日付が取れた数**
- **時刻が取れた数**
- **チーム名が解決できた数**
- 最終的に返した試合数

**要素が1件以上あるのに返した試合が0件なら、`console.warn` で理由が分かる形にすること。**

## 検証方法

**本番で j1 の7試合にスコアが入ることを確認する。**

現在の状態（2026-09-07）。

| | |
|---|---|
| j1 | 7試合すべて `scheduled` / スコア null |
| lnr.fr | 7試合すべてスコアあり |
| 現在節 | `j1` |

**マージ後、デプロイが READY になってから実行すること。**

確認するのは次の2点。

1. j1 の7試合が `finished` になり、スコアが入る
2. **キックオフ日が 2026-09-05〜09-06 の範囲**に収まる（時刻が既定値でも日付がずれない）

**2がずれた場合、カレンダーの週の割り当てが狂うため、投入を止めて報告すること。**

## 未解決の質問

- **時刻の既定値をどうするか。** 本 spec は Paris 00:00 を推奨しているが、**カレンダー上の見え方が実際の試合時間と乖離する。** 試合ページ（`/feuille-de-match/...`）に時刻があるなら、そちらから取る選択肢もある。**ただし試合数ぶんのリクエストが増えるため、節単位方針（sui generis 権）との整合を先に判断する必要がある**
- **j2 以降も同じ構造か未確認。** j1 でしか実HTMLを見ていない
- **他の大会に同種のセレクタ不一致が無いか未確認。** 今回は「0件でも警告が出ない」ことが発見を遅らせた。**同じ盲点が他大会にもある可能性がある**
