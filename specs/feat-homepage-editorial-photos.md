# feat-homepage-editorial-photos

## 背景

GPT-5.6の調査（2026-07-20）とOwnerの実機確認で判明: トップページの「最近レビューのある大会」セクション（`app/page.tsx:619-648`）は、白背景に色付き左ボーダーのみのテキストカードで、写真が一切ない。「バッジやグラデーションを増やすだけでは、写真のあるスポーツメディアには見えない」というOwnerの指摘があった。

一方、`app/c/[competition]/page.tsx:26` の `COMPETITION_HERO_IMAGES` は、大会ファミリーごとに既存の生成画像（`public/visuals/{family}.jpg`、例: `nations-championship.jpg`, `six-nations.jpg`, `premiership.jpg` 等）を既にライセンス的に安全な形で保有している。これを流用すれば、**新規の画像調達・ライセンス確認なしに**「最近レビューのある大会」カードへ写真を追加できる。

なお、ニュースサイトのog:image再利用については、GPT-5.6の調査で「og:imageの存在は再利用許諾ではない」「無許諾での配信は権利者の許諾または明示的ライセンスが必要」と指摘されており、**本specのスコープには含めない**（下記「未解決の質問」参照）。

## スコープ

対象:
- 「最近レビューのある大会」カード（`app/page.tsx` の `reviewedFamilies.map`）に、`COMPETITION_HERO_IMAGES`（または同等の既存アセットマッピング）を使った小さいサムネイル画像（目安: カード左側または上部に16:9〜4:3程度）を追加する
- 画像マッピングが `app/c/[competition]/page.tsx` にプライベート定義されている場合、`lib/` 配下の共通モジュールに切り出し、トップページ・大会ハブページ双方から参照できるようにする（重複定義を避ける）
- 「注目大会」カード（`app/page.tsx` の Featured Competition セクション）の既存写真領域について、現状の比率（目安 約35〜40%）を大きく崩さない範囲で、テキスト情報とのバランスを見直す（大幅な再設計は本specのスコープ外、比率調整のみ）
- `next/image` の `sizes` / `fill` 等、既存パターン（`app/c/[competition]/page.tsx` のヒーロー実装）に倣う

対象外:
- ニュースサイト・第三者サイトのog:image再利用（別途Owner判断・ライセンス確認が必要。下記「未解決の質問」参照）
- 試合ごとの個別写真（実際の試合写真の調達・権利確認は別途の取り組みが必要）
- 「今後の試合」セクションへの写真追加（`feat-upcoming-fixture-visual-redesign.md` で対応方針を別途定義済み。バッジ・チームカラー中心のまま、写真は入れない）
- 新規画像の生成（`image-gen` スキルでの追加生成が必要な場合は別途Owner判断）

## UI サーフェス

- 参照: 既存の `COMPETITION_HERO_IMAGES` 使用パターン（`app/c/[competition]/page.tsx`）
- 使用トークン: `design.md` の radius/spacing定義に従う。カードの「白背景+薄ボーダー+角丸12px」という既存の均一パターンからの脱却が目的の一つでもあるため、単に画像を追加するだけでなく、画像とテキストの配置バランスにも意識を払うこと
- **完了の定義にビジュアル確認を含める**: 実装後、Owner がデスクトップ・モバイル双方でスクリーンショットを確認し、「写真のあるメディア」という印象に近づいたかを承認すること

## 受け入れ条件

1. 「最近レビューのある大会」カードに、対応する大会ファミリーの既存画像アセットが表示されていることを確認する
2. 画像アセットが存在しない大会ファミリーの場合、`DEFAULT_COMPETITION_HERO` 相当のフォールバック画像が表示されること
3. 画像マッピングが1箇所に集約され、`app/page.tsx` と `app/c/[competition]/page.tsx` の両方から参照されていること（重複定義がないこと）
4. モバイル幅（375px前後）でレイアウト崩れが発生しないこと
5. `pnpm test` / `pnpm tsc --noEmit` / `pnpm lint` / `pnpm build` が通る
6. Owner によるスクリーンショット目視確認（デスクトップ1440px・モバイル375px）で承認を得ること

## 未解決の質問

- ニュースサイトのog:image再利用（記事カードへのサムネイル表示等）は、GPT-5.6の調査で以下の運用が提案されている: 大会主催者・協会・チーム・公式放送局のpress/media利用規約を確認し、「デジタルメディア掲載可」等が明示された提供元のみ許可リスト化する。CC BY/CC BY-SA等の商用利用可能なライセンスに限定する。許諾が確認できないOG画像は保存・表示しない。この運用を実際に採用するか、対象ソースの許可リストをどう作るかはOwnerが別途判断し、必要であれば別specを起票する（`next.config.ts` の `images.remotePatterns` は現状 `images.unsplash.com` のみで、任意ドメインの追加はSSRFリスクにもつながるため、安易な拡張はしないこと）
- 試合ごとの実写真（ハイライト等）の調達は、YouTube埋め込み検討（`feat-youtube-embed-allowlist.md`）と合わせて中長期的に検討する
