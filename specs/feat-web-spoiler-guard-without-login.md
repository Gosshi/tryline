# Web のネタバレ防止を、ログインしなくても使えるようにする

## 背景

2026-10-06、GPT のサイト評価（`docs/notes/gpt-growth-audit-2026-10-06/prompt.md`）は、Tryline の打ち出しを「見逃した海外ラグビーを、日本時間で、ネタバレなしで追いつく」に絞るよう勧めた。iOS アプリの副題もすでにこの方向。Owner は、打ち出しを決める前に**ネタバレ防止を使う人がいるかを測れるようにする**ことを選んだ（2026-10-06）。

Claude Code がコードを確認したところ、Web のネタバレ防止は**実質的に誰も使えない**状態だった。

- 設定の置き場所は Web のプッシュ通知の登録（`push_subscriptions.spoiler_guard`）。`lib/auth/client.ts` の利用者の状態の取得で、ログイン中の利用者の通知登録のどれかが `spoiler_guard = true` なら有効になる。
- 切り替えのボタンは、ログイン中のメニューの通知設定（`components/notification-settings.tsx`）の中にしか無い。
- 本番の `push_subscriptions` は **0 行**、登録ユーザーは 11 人（2026-10-06）。読者（直近 28 日で約 450 人）のほぼ全員が使えない。
- 隠しているのはスコアの数字だけ（`components/spoiler-score.tsx` の `SpoilerScore`）。試合のページでは、レビュー・得点推移・得点経過など結果が分かる部分は隠していない。
- 利用者の状態はページの表示後に読み込む（`components/user-state-provider.tsx`）。そのため設定がオンでも、**読み込みが終わるまでの一瞬、スコアが見えてしまう**。

## スコープ

対象:
1. ネタバレ防止の設定を、ログインなしでブラウザに保存する。
2. 誰でも見つけられる場所に切り替えのボタンを置く。
3. 設定がオンのとき、ページの最初の描画からスコアを出さない（一瞬も見せない）。
4. 試合のページで、結果が分かる部分をまとめて隠す。
5. 使われているかを測る。

**着手順**: `specs/feat-kickoff-time-tbd.md` と同じ部品（試合カード・今週の日程・試合のページの上部）を触る。時刻未定の PR がマージされてから、その後の `origin/main` で着手する。

対象外:
- Web のプッシュ通知の中身（`push_subscriptions.spoiler_guard` は通知の設定として今のまま残す。表示には使わなくなる）。
- アプリ（すでにログインなしで使える）。
- ページの `<title>`・説明文・OG 画像・構造化データ（検索とシェアのため、サーバーの HTML には今どおりスコアが入る）。下の「既知の限界」。
- 打ち出し・トップの見出しの変更（測った数字を見てから決める）。

## データモデル変更

なし（ブラウザの `localStorage` に保存する。サーバーには保存しない）。

## 変更内容

### 1. 設定の保存

- `localStorage` のキー `tryline:spoiler-guard` に `"on"` / `"off"` を保存する。既定はオフ（今の挙動）。
- 読み書きは必ず `try/catch` で囲む（プライベートブラウズなどで例外が出る）。読めないときはオフとして扱う。
- **ログイン中の利用者も同じ設定を使う**。今の `push_subscriptions.spoiler_guard` からの判定は表示に使わなくなる（本番で `true` の行は 0 なので、移し替えは要らない）。

### 2. 最初の描画からスコアを隠す

- ルートのレイアウト（`app/layout.tsx`）の `<head>` に、ページの描画前に動く短いスクリプトを置き、設定がオンなら `<html>` に `data-spoiler-guard="on"` を付ける（テーマの切り替えでよく使うやり方）。CSP は今は設定されていない（Claude Code が `next.config.*`・`middleware.ts`・`app/layout.tsx` を確認）。
- スコアを出す部分は、**サーバーの HTML にスコアを入れたまま**、`html[data-spoiler-guard="on"]` のときは CSS で隠し、「タップして結果を見る」のボタンを見せる。これで、
  - 設定がオンなら、JavaScript の読み込みを待たずに最初から隠れる（一瞬も見えない）。
  - 検索エンジンが読む HTML は今のまま（スコアが入っている）。
  - JavaScript が無効でも、設定オンの人には隠れる（ボタンで開けないだけ。設定オンの人は JavaScript を使っている前提でよい）。
- 隠している間は、スクリーンリーダーにも読ませない（`display: none` で隠す。`visibility` や色で隠さない）。
- 対象は、今 `SpoilerScore` / `HomepageSpoilerScore` で囲っている所すべて（トップの結果の帯（ティッカー）・今週のボード・日本代表の試合・カレンダー・大会の節のページ・対戦成績・試合カード・試合のページの上部）。着手前に `rg -n "SpoilerScore|HomepageSpoilerScore" app components` で一覧を出し、PR 本文に貼る。**スコアを出しているのに囲っていない場所**が無いかも探し（`homeScore`・`awayScore` を表示している箇所）、見つけたら同じく囲う。
- 開いた（「タップして結果を見る」を押した）状態は、今と同じくその場限り（ページを開き直すとまた隠れる）。

### 3. 試合のページで結果が分かる部分をまとめて隠す

設定がオンで、試合が終わっているとき、試合のページは次を隠し、「スコアを表示」を押すと**まとめて**出す（アプリの試合画面と同じ考え方）。

- 上部のスコア（今と同じ）
- レビュー（見出し・本文・要点）。プレビューは隠さない（試合前に書いたもので結果を含まない）。
- 得点推移のグラフ・得点経過・試合の数字
- 関連するレビューへのリンクの見出しなど、結果を書いた文言

隠す範囲は、着手前に試合のページの部品を洗い出し、PR 本文に「隠すもの／隠さないもの」の一覧で書く。上と同じく CSS で隠し、最初の描画から見えないこと。

### 4. 切り替えのボタンを誰でも見つけられる場所に置く

- ヘッダー（パソコン）とスマホのメニューの、ログインの有無に関係なく見える場所に「スコアを隠す」の切り替えを置く。状態（オン／オフ）が分かること（`aria-pressed` か `role="switch"`）。
- 終わった試合のスコアの近く（試合のページの上部、今週のボードの見出しの横など、1〜2 か所）にも同じ切り替えを置く。「録画を見る前なら、スコアを隠せます」のような短い説明を添えてよい。
- 切り替えたら、そのページのスコアがすぐに隠れる／出る（再読み込み不要）。
- ログイン中のメニューの通知設定にある「ネタバレ防止」は、通知の設定として残す。文言を「通知にスコアを含めない」など、通知の設定だと分かる言葉に変える（表示の切り替えと混同しないため）。今の文言は「ネタバレ防止モード」（`components/notification-settings.tsx`、2026-10-06 確認）。PR 本文に変更前と変更後を書く。

### 5. 測る

- GA4 のイベント `spoiler_guard_toggle` を、切り替えたときに送る。パラメータ: `state`（`on` / `off`）、`cta_location`（どこで切り替えたか: `site_header`・`mobile_menu`・`match_header`・`home_board` など）。
- GA4 のイベント `spoiler_reveal` を、「タップして結果を見る」「スコアを表示」を押したときに送る。パラメータ: `cta_location`。
- 設定がオンの人のページの表示を区別できるように、`page_view` に `spoiler_guard`（`on` / `off`）のパラメータを付ける。GA4 での集計には、Owner がカスタムディメンション `spoiler_guard`・`state` を登録する（下の「実行範囲」）。
- 既存の `cta_id` の集合は変えない。

## 既知の限界

- ページの `<title>`・ブラウザのタブ・検索結果・SNS のシェアの表示には、今どおりスコアが出ることがある。試合のページの `<title>` に結果が入っているかを着手時に確かめ、入っていれば PR 本文に書く（直すかは Owner が決める。検索に影響するため、この spec では変えない）。
- 設定は端末・ブラウザごと。パソコンとスマホで別々に切り替える必要がある。

## 受け入れ条件

1. 保存のテスト: 切り替えで `localStorage` の値が変わる。`localStorage` が例外を投げても画面が壊れず、オフとして動く。
2. 最初の描画のテスト（Playwright）: `localStorage` に `on` を入れた状態でトップ・今週の日程・終わった試合のページを開き、**読み込みの途中も含めて**スコアの文字が画面に見えないこと（JavaScript を止めた状態で、`<html data-spoiler-guard="on">` を付けた HTML を開いて確認してよい）。オフなら今どおり見える。
3. 試合のページのテスト: 設定オンで、終わった試合のレビュー・得点推移・得点経過が隠れ、「スコアを表示」でまとめて出る。プレビューは隠れない。
4. ログインなしのテスト: ログインしていない状態で、ヘッダーとスマホのメニューに切り替えがあり、押すとスコアが隠れる。
5. 計測のテスト: 切り替えで `spoiler_guard_toggle` が `state` と `cta_location` 付きで 1 回送られる。開いたときに `spoiler_reveal` が送られる。
6. SEO のテスト: 設定に関係なく、サーバーの HTML（`curl` で取れるもの）にスコアと試合へのリンクが今どおり入っている（#749 の SSR の試合リンクを壊さない）。
7. 「壊して落ちる」確認（コミットしない）: `<head>` のスクリプトを外すと 2 のテストが落ちる。試合のページのレビューを隠す CSS を外すと 3 のテストが落ちる。出力を PR 本文に貼る。
8. 既存の `cta_id` の集合が変わらない。
9. `pnpm tsc --noEmit`・`pnpm lint`・`pnpm test`・`pnpm build` がすべて通る（CI の `validate`）。
10. PR 本文に、設定オンとオフのスクリーンショット（トップ・試合のページ、390 と 1440 の幅）を貼る。Owner が見てからマージする。

## 実行範囲（本番操作）

- マージ後: Owner が GA4 の管理画面で、イベントのカスタムディメンション `spoiler_guard` と `state` を登録する（`cta_location` は登録済み）。
- 2 週間後: Claude Code が `spoiler_guard_toggle`（`state = on`）の利用者数と、全利用者に対する割合、オンにした人の再訪を集計して Owner に報告する。打ち出しを「ネタバレなし」に寄せるかの判断材料にする。
