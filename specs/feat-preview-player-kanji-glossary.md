# プレビューで日本代表選手が漢字表記にならない問題（グロッサリの供給源をロスターへ拡張）

## 背景

2026-08-08、日本 vs オーストラリア戦（match_id: `2c276057-bb3a-4617-a5b1-b7742e65f034`）のプレビューで、日本代表選手が全員カタカナかつ名前先の欧米式で表記されていた。

> 日本はナオト・サイトウ、リュウノスケ・イトウのハーフ団を起点に、ディラン・ライリー、サミソニ・トゥア、タクロウ・マツナガへ配球できる。

`feat-japanese-player-kanji-names.md`（マージ済み、PR #600）で漢字表記の仕組みは導入済みだが、**同 spec のスコープは `match_events` に限定されていた**。

> `lib/llm/stages/assemble.ts` で、**`match_events` に含まれる**日本代表選手（…）について、選手名グロッサリを構築する

プレビューは実装漏れではなく、最初から対象外だった未着手スコープである。

### なぜラインナップ経路の修正では解決しないか

一見すると `assemble.ts:356` のラインナップ取得が `name_ja` を select していないことが原因に見える。

```
.select("jersey_number, is_starter, player:players(name, position)")
```

しかし**予定試合の `match_lineups` は0件**である（2026-08-08 実測、当該試合の `match_lineups` は0行）。ラインナップは試合後に取り込まれるため、**プレビュー生成時点では常に空**であり、この経路を直してもプレビューの表記は変わらない。

### 解決策: グロッサリを試合単位でなくチーム単位で作る

`japanese_name_glossary` は生成プロンプトへ渡される**表記のヒント**であり（`generate-preview.ts:198-205`、`generate-recap.ts:279-286`）、その試合の出場者に限定する必然性がない。

したがって供給源を「その試合に出た選手」から「**対戦する2チームに所属する選手のうち `name_ja` が非 null のもの**」へ広げれば、ラインナップの有無に依存せず解決する。

`generate-preview.ts` は既にグロッサリを読んでいるため、**プロンプト側の変更は不要**。不足しているのは供給側だけである。

### データ側も不足している

日本代表の登録選手81名のうち `players.name_ja` が入っているのは**11名のみ**（残る70名は `null`、2026-08-08 実測）。

既存の `scripts/backfill-japan-player-kanji-names.ts` は `JAPAN_ROSTER_SOURCE_URLS` に JRFU の記事2本（`rugby-japan.jp/news/54051`・`/news/54068`）のみをハードコードしており、そこに載っていた11名しか埋まっていない。`rugby-japan.jp` は `lib/llm/sourced-facts/allowlist.ts` の許可ドメインであり、取得自体に問題はない。

### 補足: sourced_facts 経由で漢字が入る場合がある

当該試合では、生成後に `rugby-japan.jp` 由来の sourced_facts（confidence: high）が追加され、先発メンバーが**最初から漢字で**記載されていた。

> 日本代表は齋藤直人が9番、伊藤龍之介が10番で先発する。（…）フルバックには松永拓朗を起用する布陣となった。

つまり出典がメンバー発表を漢字で報じていれば、グロッサリが空でも結果的に漢字になりうる。**ただしこれは出典頼みであり、発表前や出典が英語表記の場合には効かない。** 本 spec はその依存を外すことが目的。

### 暫定対応済み

2026-08-08 のプレビュー本文は、DB の `name_ja` と Owner の確認を根拠に8名分を手動で漢字へ置換済み（石田 吉平 / 齋藤 直人 / 松永 拓朗 / 岡部 崇人 / 江良 颯 / 竹内 柊平 / 下川 甲嗣 / 伊藤 龍之介）。**本 spec はこの手作業を不要にする。**

## スコープ

対象:
1. 対戦2チームのロスターから日本語名グロッサリを構築し、既存のイベント由来グロッサリとマージする
2. `assemble.ts` のラインナップ取得で `name_ja` を select し、ラインナップがある場合はそこからもグロッサリに供給する（レビュー側で、得点していない選手を拾えるようにするため）
3. `scripts/backfill-japan-player-kanji-names.ts` のソース記事を拡張できる形を維持しつつ、現行スコッドを埋められるようにする

対象外:
- `generate-preview.ts` / `generate-recap.ts` のプロンプト変更。**グロッサリを読む仕組みは実装済み**であり触る必要がない
- 日本代表以外のチームへの `name_ja` バックフィル（元 spec の対象外を維持。仕組みとしては汎用にするが、データ投入は日本代表のみ）
- 既存 published 記事の遡及的な一括再生成（別途 Owner 判断）
- `players` のスキーマ変更
- 姓名の順序・区切り文字の表記ルール変更。**DB の `name_ja` の値をそのまま使う**（現状は「石田 吉平」形式）

## データモデル変更

**なし。マイグレーション不要。**

## API サーフェス

### 1. ロスター由来のグロッサリ

`lib/llm/stages/assemble.ts` に、対戦2チームの `players` から `name_ja` が非 null の行を取得してグロッサリを作る経路を追加する。

既存の `buildJapanesePlayerNameGlossary`（`assemble.ts:461`）を再利用すること。**同等の関数を新設しない。**

`assemble.ts:933-962` 付近のグロッサリ組み立てで、イベント由来・ラインナップ由来・ロスター由来をマージし、**重複排除する**。

`name_ja` が非 null の選手が0名のチーム（海外チームの大半）ではクエリ結果が空になるだけで、既存挙動に影響しない。

### 2. ラインナップ取得での `name_ja`

`assemble.ts:356` の select に `name_ja` を追加する。

```
.select("jersey_number, is_starter, player:players(name, name_ja, position)")
```

### 3. バックフィルスクリプト

`JAPAN_ROSTER_SOURCE_URLS` に記事を追加すれば対象が増える現在の構造を維持する。dry-run 既定と `--confirm-owner-approved` の安全設計も維持すること。

対象記事の特定は Owner が行う。

## UI サーフェス

なし。

## LLM 連携

assemble ステージのみ。プロンプト・モデル・QA 基準は変更しない。グロッサリのエントリ数が増えるためプロンプトのトークンがわずかに増えるが、**日本代表81名でも数百トークン程度**であり、コストへの影響は無視できる。

## 受け入れ条件

1. 対戦2チームのロスターから `name_ja` が非 null の選手がグロッサリに入る。
2. **`match_events` と `match_lineups` がいずれも0件の予定試合でも、グロッサリが空にならない。** これを満たすテストがあること（本 spec の中心的な条件）。
3. `assemble.ts` のラインナップ取得が `name_ja` を select している。
4. イベント由来・ラインナップ由来・ロスター由来で同一選手が重複しない。
5. `name_ja` が null の選手はグロッサリに入らず、従来どおりカタカナ変換される（外国籍選手の表記を壊さない）。
6. `buildJapanesePlayerNameGlossary` が再利用されている。
7. `generate-preview.ts` / `generate-recap.ts` のプロンプトが変更されていない。
8. 既存のイベント由来グロッサリの挙動が変わっていない（`feat-japanese-player-kanji-names.md` のテストが引き続き通る）。
9. `scripts/backfill-japan-player-kanji-names.ts` の dry-run 既定と `--confirm-owner-approved` が維持されている。
10. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` がすべて clean。

## 未解決の質問

1. **バックフィル対象の JRFU 記事 URL が未確定。** 81名中70名が未設定で、1本の記事に全員が載っているとは限らない。複数記事の統合が要る。Owner が対象記事を特定する必要がある。

2. **`players` テーブルに存在しない選手がいる。** 2026-08-08 の実測で、この試合の先発SO「伊藤龍之介」は日本代表81名のロスターに**存在しなかった**。ロスター自体の更新が別途必要であり、グロッサリを直してもテーブルに無い選手は漢字化できない。ロスター取り込みの鮮度は別課題。

3. **姓名の区切りが全角スペースで統一されているかは未検証。** 現在の11名はすべて「石田 吉平」形式だが、バックフィル拡大時に揺れる可能性がある。揺れると本文の見た目が不統一になる。

4. **グロッサリが大きいと LLM が無関係な選手名を本文へ引き込む恐れがある。** 出場しない選手までヒントとして渡すため、「表記の対応表であって出場者一覧ではない」ことをプロンプトで明示する必要があるか、実装時に既存の `japaneseNameGlossaryBlock` の文面を確認して判断すること。
