# 海外チーム・大会の日本語（カタカナ）表示名

## 背景

GSC の検索クエリがほぼ全て「英語の選手名」で、日本語クエリがゼロ（診断: `docs/seo-japanese-query-diagnosis-2026-06.md`）。
根因は **海外チーム名（90件中78件）・全海外大会名が英語表記のまま** で、日本語ページのタイトル・h1・メタ・構造化データ・recap 本文すべてが英語名を使っていること。日本のラグビーファンはカタカナで検索する（「チーフス」「スーパーラグビー」）ため、物理的に検索に当たらない。

被リンク（権威）獲得より前に、**カタカナ表記でインデックスの土俵に乗る**ことが先決。本 spec はその基盤（日本語表示名の整備と日本語ページへの適用）を対象とする。

## スコープ

**対象:**
- `teams` / `competitions` に日本語表示名カラムを追加し、海外チーム/大会のカタカナ名を投入
- 日本語ページ（`/matches/[id]`、シーズン/大会ページ、内部リンク、パンくず）のタイトル・h1・meta・JSON-LD で日本語表示名を使用
- ナラティブ/プレビュー生成プロンプトにカタカナ用語集を渡し、**新規生成コンテンツがカタカナを使う**ようにする

**対象外（別途）:**
- 既存 929 recap 本文のカタカナ backfill（LLM 再生成コストが発生。Owner 判断で段階実施）→ 未解決の質問へ
- 英語ページ（`/matches/[id]/en`）は英語名のまま（変更しない）
- 順位表・日程などエバーグリーン日本語ページ（playbook S4/S7・別 spec）

## データモデル変更

### `teams`
- `name_ja text`（nullable）を追加。海外チームにカタカナ名を投入。
- リーグワン等で `name` が既に日本語のチームは `name_ja = name` を投入（一貫性のため）。
- 既存 `name`（英語）・`english_name` は変更しない（後方互換）。

### `competitions`
- `name_ja text`（nullable）を追加。海外大会の日本語表示名を投入。
  - 例: 「シックスネイションズ」「スーパーラグビー パシフィック」「プレミアシップ」「URC（ユナイテッド・ラグビー・チャンピオンシップ）」「トップ14」「ザ・ラグビーチャンピオンシップ」
- シーズン表記（2026 / 2025-26）は `name_ja` に含めず、既存の整形ロジック側で付与。

### 表示名の解決規則
- 日本語ページは `name_ja ?? name`（カタカナがあれば優先、なければ英語フォールバック）。
- `lib/format/competition.ts` の `formatCompetitionName` を、リーグワン特例の分岐から `name_ja` ベースの解決へ拡張。

### カタカナ名の出典（重要・正確性）
自動音訳は不可。**WOWOW / J SPORTS の日本語表記、Wikipedia 日本語版の定着表記**を出典とする。
代表例（seed。残りは同基準で補完）:

| 英語 | カタカナ |
|------|---------|
| Chiefs | チーフス |
| Crusaders | クルセイダーズ |
| Hurricanes | ハリケーンズ |
| Blues | ブルーズ |
| Highlanders | ハイランダーズ |
| Brumbies | ブランビーズ |
| Queensland Reds | クイーンズランド・レッズ |
| Fijian Drua | フィジアン・ドルア |
| Moana Pasifika | モアナ・パシフィカ |
| Western Force | ウェスタン・フォース |
| Waratahs | ワラターズ |

> Six Nations・Rugby Championship の代表は国名なので既存の日本語国名表記（イングランド代表 等）と整合させること。

## API サーフェス
新規ルートなし。`getMatch` 等のクエリで `name_ja` をセレクトに追加し、チーム/大会の型に `nameJa?: string | null` を追加。

## UI サーフェス
- `app/matches/[id]/page.tsx`: `generateMetadata` の title/description、h1、`SportsEvent`/`NewsArticle` JSON-LD の team/competition 名を日本語表示名に。
- シーズン/大会ページ・パンくず・内部リンクのチーム/大会名表示。
- 英語ページ（`/en`）は対象外。

## LLM 連携
- パイプライン段階: **ナラティブ生成・プレビュー生成**（`/specs/p1-content-pipeline.md` の該当段階）。
- プロンプトに「チーム名・大会名はカタカナで表記する」指示＋カタカナ用語集（`name_ja` から動的生成）を渡す。
- モデルは現行どおり（`lib/llm/models.ts`）。新規コストは用語集トークン分のみ（小）。

## 受け入れ条件
- `teams.name_ja` / `competitions.name_ja` カラムが追加され、海外チーム全78件・海外大会全件にカタカナ名が投入されている（NULL 残ゼロを検証クエリで確認）。
- リーグワンの日本チームは `name_ja = name`。
- `/matches/<海外試合>` の `<title>`・h1・meta description・JSON-LD のチーム/大会名がカタカナで表示される（例: 「チーフス vs クルセイダーズ — スーパーラグビー パシフィック 2026」）。
- 英語ページ `/matches/<id>/en` は英語名のまま変化しない。
- 新規生成された recap/preview の本文がカタカナのチーム/大会名を使う（生成テストで確認）。
- 既存テスト（`tests/app/matches`・`tests/lib/format` 等）が緑。日本語表示名解決のユニットテストを追加。

## 未解決の質問
1. 既存 929 recap 本文の backfill: やるか / どの大会・期間を優先するか / LLM 再生成コスト上限。（コスト要見積もり。Owner 判断）
2. URC の表記: 「URC」のままか「ユナイテッド・ラグビー・チャンピオンシップ」併記か（検索ボリュームは略称 URC が優勢の可能性）。
3. チーム名のミドルドット/スペース表記ゆれ（「クイーンズランド・レッズ」vs「クイーンズランドレッズ」）の正規化方針。検索ヒットを最大化する表記を Owner と確定。
4. `name`（英語）を将来 `name_en` にリネームして役割を明確化するか（本 spec では非破壊で `name_ja` 追加に留める）。
