# 順位表を独立ページにする

## 背景

Google Search Console（2026-07-10〜08-06）で、**Tryline に最も多くのインプレッションをもたらしているクエリは「順位」を含むもの**である。

| クエリ | インプレッション | 平均順位 | クリック |
|---|---:|---:|---:|
| シックス ネーションズ 順位 | **53** | 8.4 | 0 |
| シックスネーションズ 2026 順位 | 14 | 9.9 | 0 |
| シックス ネーションズ2026 順位 | 11 | 9.6 | 1 |

3つ合わせて**78インプレッション**。同期間の全体が約300なので、**4分の1が「順位」クエリ**である。

にもかかわらず**クリックは1件**。平均順位8〜10位、つまり1ページ目の下から2ページ目にかかる位置で、CTR がほぼゼロになっている。

### なぜ独立ページか

現在、順位表は**大会ハブページ内の一要素**として描画されている（`app/c/[competition]/[season]/page.tsx` が `StandingsTable` を使用）。専用の URL が存在しない。

そのため次の状態になっている。

- 「シックスネイションズ 順位」で着地するのは大会ハブで、**タイトルが「最新結果・次戦・日程・順位」**と要素を並べた形になる
- 検索意図は「順位表が見たい」なのに、ページの主題が順位表ではない
- **順位表そのものを主題としたタイトル・見出し・構造化データを持てない**

独立ページを作れば、クエリと主題が一致する。順位8〜10位のまま CTR が上がるだけでも流入は増える。

### 横展開が効く

順位表データは既に **12大会以上**に存在する（`competition_standings`）。

| 大会 | 行数 |
|---|---:|
| RWC 2027 | 24 |
| RWC 2023 | 20 |
| URC 2025-26 | 16 |
| Top 14 2025-26 | 14 |
| Nations Championship 2026 | 12 |
| Super Rugby Pacific 2026 | 11 |
| Premiership 2025-26 | 10 |
| Six Nations（2020〜2027 各年） | 6 |

**1つ作れば全大会・全シーズンに適用される。** 過去シーズンの順位表も「シックスネイションズ 2024 順位」のようなクエリで拾える。

`StandingsTable` コンポーネントは既に存在し、トップ・試合詳細・大会ハブの3箇所で使われている。**描画部品は流用できる。**

### 持続性

一度作れば、シーズンが進むたびに自動で更新される。**運用コストがゼロで効き続ける**タイプの施策である。

Six Nations（2〜3月）、欧州クラブ（9〜6月）、Nations Championship（7月・11月）と、**年間を通じてどこかの大会がシーズン中**であり、順位クエリは常に立つ。

## スコープ

対象:
- 順位表の独立ページを新設する
- 大会ハブから独立ページへの導線を置く
- 順位表ページ向けのタイトル・説明・構造化データ

対象外:
- **`StandingsTable` コンポーネントの変更**（既存の描画をそのまま使う）
- 順位表データの取得・更新ロジック（`p1-competition-standings.md` 等の結果を維持）
- 大会ハブから順位表を削除すること。**ハブ内の表示は維持する**（回遊のため）
- 順位表が存在しない大会への対応（ツアー等。下記参照）
- 順位の計算・並び替えロジック

## データモデル変更

**なし。マイグレーション不要。** 既存の `competition_standings` をそのまま読む。

## API サーフェス

### URL 設計

既存の大会 URL 構造（`/c/[competition]/[season]`）に揃えること。**新しい規則を発明しない。**

配下に順位表を置く形が自然だが、**実装時に既存のルーティングを確認して決めること**。`app/c/[competition]/[season]/round/` が既にあるため、それと同じ階層の付け方に合わせる。

### ページの中身

- 順位表（`StandingsTable` を流用）
- 大会名・シーズンの明示
- 大会ハブ・日程への導線
- **最終更新日時**（順位表は鮮度が価値。いつ時点かを示す）

### 順位表が無い大会の扱い

ツアー形式の大会（`greatest-rivalry-2026`、`lipovitan-challenge-cup-2026` 等）には順位表が存在しない。

**404 を返すか、大会ハブへリダイレクトするかを実装時に判断すること。** 空の順位表ページを生成してはならない（薄いページの量産になる）。

## UI サーフェス

### 大会ハブからの導線

大会ハブ内の順位表セクションから、独立ページへのリンクを置く。**ハブ内の表示は残す**（回遊が途切れないように）。

### タイトルと説明

**検索意図に一致させること。** 現在の大会ハブは「最新結果・次戦・日程・順位」と要素を並べているが、順位表ページは順位表を主題にする。

日本語の大会名を使うこと。**`competitions.name_ja` が null でも日本語表示される経路が別に存在する**（2026-08-10 に確認済み）ため、実装時に大会ハブの実装を読んで同じ解決経路を使うこと。

### 構造化データ

順位表に適した構造化データを付与すること。既存ページで使っている手法に合わせる。**新しい語彙を発明しない。**

## LLM 連携

なし。既存データの描画のみ。**LLM 呼び出しは発生しない。**

## 受け入れ条件

1. 順位表データを持つ大会・シーズンで、独立ページが 200 を返す。
2. `StandingsTable` が流用されており、同コンポーネントが変更されていない。
3. 大会ハブ内の順位表表示が維持されている。
4. 大会ハブから独立ページへの導線がある。
5. **順位表が存在しない大会で、空のページが生成されない。**
6. タイトル・説明が順位表を主題としており、日本語の大会名を含む。
7. 最終更新日時が表示される。
8. サイトマップに含まれる（既存の生成経路に乗せる）。
9. 既存ページの表示・SEO に影響がない。
10. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` がすべて clean。

## 未解決の質問

1. **URL の形。** 既存のルーティング規則に合わせるべきだが、`/c/[competition]/[season]/standings` とするか別の形にするかは実装時に既存構造を見て判断する。**決めたら報告すること。**

2. **過去シーズンをどこまで生成するか。** Six Nations は2020年から順位表がある。全シーズン生成すると薄いページが増える懸念がある一方、「シックスネイションズ 2022 順位」のようなクエリは実在する。**判断と根拠を報告すること。** 2026-08-02 に index bloat（無意味な選手ページ）を noindex 化した経緯があり、同じ轍を踏まないこと。

3. **CTR が上がるかは検証が必要。** 本 spec は「クエリと主題を一致させれば CTR が上がる」という仮説に基づく。**検証はピーク期（2027年2月の Six Nations、2026年11月の Nations Championship）の GSC 実測で行う。** 8月の実施では母数が足りず判定できない。

4. **順位表の更新頻度。** 取り込み cron が更新しているが、ページのキャッシュ戦略と噛み合っているかは実装時に確認すること。順位表は鮮度が価値であり、古い順位を出すと信頼を損なう。
