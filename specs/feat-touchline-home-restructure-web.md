# デザイン刷新（Web）: トップの構成をモック A4 に近づける

## 背景

D037 の刷新で、PR #908（部品）と #909（ページ）が本番に出た。大会ページと試合ページはモック A4 に近づいたが、トップはまだ遠い（2026-10-04、Owner 判断）。プレビューで比べると、ページの長さはモック約 1,970px に対して約 4,830px（1440 幅）。モックは 5 つのブロックだが、本番のトップには既存のブロックがすべて残っている。

| モック | 今のトップ（PR #909 後） |
|---|---|
| 最上部＋ティッカー | 同じ |
| 今週の試合（2 列で 4 試合） | 今週の残りの試合だけ（日曜は 1 試合で右半分が空く） |
| — | ニュースレター登録（今週の試合の直後） |
| 注目大会 | 注目大会（写真付き） |
| — | 今後の試合 |
| 最近のレビュー（大 1 本＋小 2 本、短い） | 無料サンプルの大きな箱（本文の抜粋と「試合後に聞けること」）＋大会ごとのレビューの束 |
| — | 最近レビューのある大会、大会アーカイブ |

Owner の方針（2026-10-04）: **ブロックは消さず、まとめるか下へ移す。** 次の 4 点で進める。

この作業は PR 3（動き、`specs/feat-touchline-redesign-web.md`）より前に 1 本の PR で出す。

## UI サーフェス

### 新しい並び順

1. 最上部＋ティッカー（変えない）
2. **試合のボード**（下の 1）
3. 注目大会（変えない）
4. **最近のレビュー**（下の 3）
5. **ニュースレター登録**（下の 2）
6. **大会へのリンク**（下の 4）

### 1. 試合のボード（今週の試合と今後の試合を統合）

今は `homepageWeekMatches`（今週の、キックオフが今より後の試合、最大 6）と、別ブロックの「今後の試合」（`homepageUpcomingMatches`、`getUpcomingMatches(5)` から今週分を除いたもの）、0 件のときの `homepageNextUpcomingMatch` に分かれている。これを 1 つのボードにまとめ、**常に 4 試合**を出す（データが足りなければ出せる分だけ）。

選び方（上から順に埋め、4 試合になったら止める）:
- ① 今週の、キックオフが今より後の試合（キックオフの早い順）
- ② `getUpcomingMatches(5)` のうち①に無いもの（早い順）
- ③ 今週の、終了した試合（キックオフの新しい順）。スコアはネタバレ防止（`HomepageSpoilerScore`）を通す

表示: 2 列（`md` 以上）、1 行の一覧（PR #909 の行の形）。並びは①②（これから）を先、③（結果）を後。
見出し: ①が 1 件以上あれば「今週の試合」、①が 0 件なら「次の試合」。右肩の週の表示（「9月第4週」など）は①があるときだけ出す。
「今後の試合」のブロックは削除する（中身はボードに統合）。`homepageNextUpcomingMatch`（`getNextUpcomingMatch()`）は②で足りるなら使わなくてよい。②も③も 0 件のときは、今どおり `getNextUpcomingMatch()` の 1 試合を出す。
ボードの下に「今週の全試合を見る →」（`/calendar`）のリンクを置く。今の `cta_id` を持つリンクがあればそれを使う。

### 2. ニュースレター登録

`<NewsletterSignup source="home" />` を、今週の試合の直後から、最近のレビューの後ろへ移す。中身・`source` は変えない。

### 3. 最近のレビュー（モックの大 1 本＋小 2 本）

- `recentReviewGroups` の各グループの `hero` と `compact` を 1 つの列にまとめ、`recapGeneratedAt` の新しい順に並べる。
- 先頭の 1 本を**大きなカード**: チーム色の面（PR #909 で入れた形）、スコア（`HomepageSpoilerScore`）、大会名、「チーム 対 チーム」、`recapExcerpt` の先頭 1 文（60 字まで、超えたら「…」）、「レビューを読む →」。
- 次の 2 本を**小さなカード**（モックの右列の形）。
- 0 本: ブロックごと出さない。1 本: 大きなカードだけ。2 本: 大 1＋小 1。
- **無料サンプルの大きな箱（本文の抜粋・「試合後に聞けること」）はやめ**、ブロックの下に次の 2 つのリンクだけを置く:
  - 「無料サンプルを読む →」（`sampleMatch` があるとき。`cta_id: "home_recent_reviews_sample_recap"` のまま）
  - 「他のレビューも 7 日間無料で読む」（`cta_id: "home_recent_reviews_pricing"` のまま）
- 大会の状況の表示（`shouldShowRecentReviewStatusPane`、グループが 1 つのときの順位・次戦）は、出す条件を変えずに小さなカードの下へ置く。

### 4. 大会へのリンク（「最近レビューのある大会」と「大会アーカイブ」を統合）

- 2 つのブロックを 1 つにまとめ、ページの一番下（フッターの直前）に置く。見出しは「大会から探す」。
- **今あるリンクの行き先はすべて残す**（検索のための内部リンク）。重複する行き先は 1 つにする。
- 見た目は小さな文字のリンクの一覧（`md` 以上で 3〜4 列）。ロゴの画像は使わなくてよい。

## 受け入れ条件

1. 並び順が上の「新しい並び順」のとおり。「今後の試合」の見出しが無い。
2. 試合のボードの選び方を純粋な関数（例: `selectHomeBoardMatches({ weekMatches, upcomingMatches, now })`）に切り出し、単体テストする:
   - 今週の未来の試合が 6 件 → その先頭 4 件
   - 今週の未来の試合が 1 件、`getUpcomingMatches` が 5 件（うち 1 件は今週分と同じ）→ 今週の 1 件＋今週分を除いた次の 3 件
   - 今週の未来の試合が 0 件、`getUpcomingMatches` が 0 件、今週の終了した試合が 5 件 → 終了した試合の新しい順に 4 件
   - すべて 0 件 → 空配列（このときはページ側で `getNextUpcomingMatch()` の 1 試合を出す）
   - 同じ試合が 2 回入らない
3. 最近のレビューの選び方を純粋な関数に切り出し、0 本・1 本・2 本・5 本のテスト（並びは `recapGeneratedAt` の新しい順）。
4. **内部リンクを減らさない**: 次を本番とプレビューで実行し、`/c/` へのリンクの集合がプレビューで減っていない（本番にあってプレビューに無い `/c/` のリンクが 0 件）。出力を PR 本文に貼る。
   ```
   curl -s <ホスト>/ | grep -o 'href="/c/[^"]*"' | sort -u > /tmp/<本番かプレビュー>.txt
   comm -23 /tmp/prod.txt /tmp/preview.txt
   ```
   プレビューが保護されていて取れない場合はそう書く（Claude Code が確認する）。
5. `cta_id` の集合（`rg -o 'cta_id: "[a-z_]+"' app components | sed 's/.*cta_id/cta_id/' | sort -u`）が変わらない。「今後の試合」のブロックにしか無い `cta_id` があった場合は、ボードの対応するリンクに同じ値を付けて残す。
6. ネタバレ防止: ボードの終了した試合と、最近のレビューのスコアが `HomepageSpoilerScore` を通る（`enabled=true` で隠れるテスト）。
7. ページの長さ（1440×900 で `document.documentElement.scrollHeight`）が 3,200px 以下。本番の値と並べて PR 本文に書く。
8. `pnpm tsc --noEmit`・`pnpm lint`・`pnpm test`・`pnpm build` がすべて通る（CI の `validate`）。
9. 既存のテストは消さない。落ちる assert は新しい期待値に書き換え、PR 本文に一覧を書く。
10. 「壊して落ちる」確認（コミットしない）: ボードの選び方で③（終了した試合）を①より先に並べると、2 のテストが落ちる。
11. スクリーンショット（1440×900 と 390×844 のページ全体）を PR 本文に貼る。Owner が見てからマージする。
