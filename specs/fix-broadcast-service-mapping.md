# 放送サービス名の対応表に WOWOW と日本テレビを追加し、表記ゆれを吸収する

## 背景

2026-08-14 の `ingest-broadcasts` cron が次を報告した。

```
2. 未対応サービス: 3件  日本テレビ系全国ネット / WOWOWライブ / WOWOWオンデマンド
4. 14日以内で放送情報なし: 4件  Australia 対 Japan (2026-08-15) ほか
```

**取り込み経路そのものは正常に動いている。** 同じ実行で 9/05 日本×カナダの3件（J SPORTS 1 / Hulu / J SPORTSオンデマンド）は投入できている。

問題は `lib/broadcasts/ingest.ts:73` の対応表に**7サービスしか登録されていない**こと。

```ts
const KIND_BY_SERVICE_NAME: Readonly<Record<string, MatchBroadcastKind>> = {
  BS日テレ: "tv",
  Hulu: "streaming",
  "J SPORTS 1": "tv",
  "J SPORTS 2": "tv",
  "J SPORTS 3": "tv",
  "J SPORTS 4": "tv",
  "J SPORTSオンデマンド": "streaming",
};
```

表に無いサービスは `unknownServices` に積まれ、**その試合の放送情報が保存されない**。

### 実害

**2026-08-15（土）14:15 の日本代表 vs オーストラリア第2戦に、放送情報が表示されていない。** JRFU 公式日程ページには `WOWOWライブ` `WOWOWオンデマンド` と明記されている（2026-08-14 実測）。日本代表戦は年に数回しかない集客の山で、「どこで見られるか」は最初に求められる情報である。

本番実測（2026-08-14）:

| 試合 | 放送情報 |
|---|---|
| 8/15 オーストラリア vs 日本 | **なし** |
| 8/16 ブルズ vs ニュージーランド | なし |
| 9/05 日本 vs カナダ | J SPORTS 1 / Hulu / J SPORTSオンデマンド |
| 9/12 日本 vs アメリカ | なし |

`match_broadcasts` は全21行、うち**未来の試合は3行のみ**。

### 表記ゆれも起きている

既存データに空白の有無だけが違う重複が存在する（2026-08-14 実測）。

```
"J SPORTS オンデマンド" と "J SPORTSオンデマンド"
"WOWOW オンデマンド"   と "WOWOWオンデマンド"
"WOWOW プライム"       と "WOWOWプライム"
```

対応表は完全一致で引くため、**空白1つで未対応になる**。

## スコープ

対象:
- `KIND_BY_SERVICE_NAME` に不足しているサービスを追加する
- サービス名の**正規化**を入れ、空白の有無で取りこぼさないようにする

対象外:
- **取得元の追加**（JRFU 日程ページ以外。「未解決の質問」1・2 を参照）
- スクレイパー本体（`lib/scrapers/jrfu-match-broadcasts.ts`）の変更
- 既存 `match_broadcasts` の表記ゆれデータのクリーンアップ（別途）
- 放送情報の UI 表示（実装済み）

## データモデル変更

**なし。** `match_broadcasts` は `onConflict: "match_id,service_name"` で upsert されている（`lib/broadcasts/ingest.ts:217`）。

## 実装詳細

### 1. 追加するサービス

**2026-08-14 に JRFU 公式日程ページで実際に確認した表記のみを追加する。推測で足さない。**

| サービス名 | kind | 確認した試合 |
|---|---|---|
| `WOWOWライブ` | `tv` | 8/15 オーストラリア戦 |
| `WOWOWオンデマンド` | `streaming` | 8/15 オーストラリア戦 |
| `日本テレビ系全国ネット` | `tv` | **9/05 カナダ戦**（8/15 ではない） |

**日本テレビは 8/15 の試合とは無関係。** 当初 8/15 に必要と誤認したが、実際は 9/05 カナダ戦の地上波中継である。

既存データに `WOWOWプライム` も存在するため、これも追加してよい（`tv`）。

### 2. サービス名の正規化

対応表を引く前に正規化する。**表記ゆれで取りこぼさないため。**

- 前後の空白を除去する
- **全角・半角スペースを除去して比較する**（`J SPORTS オンデマンド` → `J SPORTSオンデマンド`）
- 大文字小文字は現状どおり区別してよい（サービス名は固有名詞のため）

**保存する `service_name` は正規化後の値に統一する。** 既存データとの重複を増やさないため。

### 3. 未対応サービスの扱いは変えない

表に無いサービスは引き続き `unknownServices` に積み、cron 通知で報告する。**黙って捨てない現在の設計は正しい。** 誤った kind を推測で割り当てるより、報告して人が判断するほうが安全。

## UI サーフェス

**変更なし。** 表示は実装済みで、データが入れば出る。

## LLM 連携

なし。

## 受け入れ条件

1. `WOWOWライブ` / `WOWOWオンデマンド` / `日本テレビ系全国ネット` / `WOWOWプライム` が対応表に追加され、正しい `kind` が割り当てられている。
2. **`J SPORTS オンデマンド`（空白あり）が `J SPORTSオンデマンド` として解決される。**
3. 保存される `service_name` が正規化後の値に統一されている。
4. 対応表に無いサービスがあっても、**同じ試合の対応済みサービスは保存される**（1件の未対応で全滅しないこと。現状の挙動を確認して報告すること）。
5. **8/15 オーストラリア vs 日本の試合で、実データを流して `match_broadcasts` に WOWOWライブ と WOWOWオンデマンドの2件が入る。**
6. 既存の J SPORTS 系の取り込み挙動が変わっていない。
7. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` clean。

## 未解決の質問

1. **Wikipedia を放送情報の第2ソースにできるか。** Owner の指摘で、Wikipedia の試合ページにも放送局の記載がある。JRFU 日程ページは**日本代表戦しか載らない**ため、ニュージーランドの南アフリカ遠征（8/16 ブルズ戦ほか5試合）などは現在の経路では永遠に取れない。Wikipedia は許可ドメインで `?action=raw` の取得経路も確立済み（D016）。**別 spec として検討する価値がある。**

2. **紐付け不可ページ3件**（`11.14 Sat` / `11.07 Sat` / `09.19 Sat` が「一致する日本代表戦が0件」）。**11月は日本代表の欧州遠征で集客の主戦場**なので、`matches` 側にその試合が入っていない可能性を調査する必要がある。本 spec では扱わない。

3. **既存の表記ゆれデータのクリーンアップ。** `match_broadcasts` に `WOWOW オンデマンド` と `WOWOWオンデマンド` が併存している。正規化を入れると新規は統一されるが、既存行は残る。過去試合のため実害は小さいが、いずれ整理が要る。
