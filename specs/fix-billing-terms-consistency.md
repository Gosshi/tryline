# fix-billing-terms-consistency

## 背景

**特定商取引法に基づく表記と料金ページが、課金条件について矛盾している**（2026-09-05 実測）。

| ページ | 記述 |
|---|---|
| `app/legal/tokusho/page.tsx:28` | 支払時期: 「**申し込み時に即時課金**、以降は契約更新日に自動課金」 |
| `app/pricing/page.tsx:42` | 「初回登録時に **7 日間の無料トライアル**をご利用いただけます。…トライアル終了後は自動的に ¥980/月の課金が始まります」 |
| `app/pricing/page.tsx:17,20`（meta description） | 「**7日間無料**、その後 ¥980/月」 |

現行Checkoutコードはsubscription_data.trial_period_days: 7を指定する。コード上は7日間トライアルを要求している。Ownerは本番に同じコードが配備され、実際のCheckout Session/Subscriptionのtrial開始・終了、初回請求、更新・解約条件が表示と一致することを、秘密値や個人情報を渡さず確認する。

有料購読者が実質ゼロの現在は実害が出ていないが、**課金を開始する前に解消しておくべき性質のもの**。

関連する既存 spec: `fix-free-trial.md` / `fix-pricing-faq-trial.md` / `fix-ga4-purchase-event-fires-at-trial-start.md`。**これらは表示とイベントを扱っており、特商法表記との整合は扱っていない。**

## スコープ

対象:
- `app/legal/tokusho/page.tsx` と `app/pricing/page.tsx` の課金条件記述を、**Owner が確認した実際の Stripe 設定に一致させる**
- 両ページの記述が**単一の定数から生成される**ようにし、片方だけ直して再び乖離することを防ぐ
- `app/legal/terms/page.tsx` に課金・停止条件の記述があれば併せて整合させる

対象外:
- Stripe の本番設定変更（Owner の作業）
- 価格の変更
- 無料トライアルの有無そのものの方針変更（D005 の ¥980/月 フリーミアムは不変）
- iOS（RevenueCat）側の課金条件表示（`specs/fix-ios-subscription-disclosure.md` の範囲）
- 特商法表記の他項目（事業者名・所在地・返品等）

## UI サーフェス

課金条件を `lib/billing/terms.ts`（新規、または既存の定数置き場）に**単一の情報源**として定義し、pricing・特商法・terms の各ページがそこから読む。

定義する項目:
- 月額（¥980）
- 無料トライアルの有無と日数
- 初回課金のタイミング
- 更新周期と自動更新の有無
- 解約の受付方法と効力発生時期

各ページの本文・CTA・metadata・Open Graph・FAQ JSON-LDを共通の課金条件から生成する。app/api/stripe/checkout/route.tsのtrial_period_daysも同じ定義を参照する範囲に追加し、Owner確認済みの7日という現行挙動を変更しない。条件変更の実験は行わない。

## 受け入れ条件

1. 課金条件が単一のモジュールに定義され、`app/legal/tokusho/page.tsx` と `app/pricing/page.tsx` の両方がそこから読んでいる
2. **両ページに課金タイミングの文言が直書きされていない**（「即時課金」「7日間無料」といった文字列がページファイルに現れない）
3. 定数を「トライアルなし・即時課金」に変えたとき、**両ページの表示が同時に変わる**ことを検証するテストがある
4. 定数を「7日間トライアルあり」に変えたときも同様に両ページが揃うことを検証するテストがある
5. `app/legal/terms/page.tsx` に課金条件の記述がある場合、同じ定数を参照している。無い場合は「該当なし」を PR 本文に書く
6. `app/pricing/page.tsx` の FAQ JSON-LD の内容も同じ定数から生成されている
7. `pnpm test` と `pnpm typecheck` が green
8. **Stripe の本番設定・価格 ID を変更しない**（コード差分のみ）

## 確定（2026-09-06、Owner が本番 Checkout で確認）

**トライアルは実在する。** Owner が本番サイトの購読導線から Stripe Checkout を開き、支払い直前の画面を確認した。

```
Tryline Premium を試す
7 日間無料
その後、¥980/月、2026年9月13日以降
```

確認日は 2026-09-06 で、+7 日が 2026-09-13。**本番 Checkout に 7 日間の無料トライアルが適用されている。** Price 画面やテスト環境ではなく、実際の Checkout 経路での確認である。

したがって修正対象は**特商法表記**であり、料金ページの「7日間無料」は正しい。`fix-free-trial.md` / `fix-pricing-faq-trial.md` の前提も見直し不要。

### 直す箇所

`app/legal/tokusho/page.tsx` の 2 行。

| 行 | 現在 | 問題 |
|---|---|---|
| 28 | 支払時期: 「**申し込み時に即時課金**、以降は契約更新日に自動課金」 | 申込時は課金されない。初回課金はトライアル終了後 |
| 29 | サービス提供時期: 「**決済完了後**、直ちに利用可能」 | 決済完了前（トライアル開始時）から利用できる |

料金ページ側は既に正しい（`app/pricing/page.tsx:42` が「初回登録時に 7 日間の無料トライアルをご利用いただけます…トライアル終了後は自動的に ¥980/月の課金が始まります。期間中はいつでもキャンセル可能です。」と説明している）。**特商法をこの記述に合わせる。**

**トライアル日数の記述箇所を 1 箇所に集約すること。** Stripe 側の設定が変わったときに表記だけが取り残される構造にしない。

## 未解決の質問

**本 spec で解決しないと明示するもの**:

- **トライアル対象条件**（過去に解約した利用者が再度トライアルを受けられるか等）は未確認。特商法に条件を書く場合は Owner が Stripe の設定を別途確認する。**分からないまま条件を書かないこと**
- **iOS（RevenueCat）経由の課金条件**が Stripe と同一かは本 spec の範囲外。特商法は Web の Stripe 経路について記述する
