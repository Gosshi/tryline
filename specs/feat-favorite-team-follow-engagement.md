# 応援チーム登録を主要導線にし、再訪関連イベントを計測する

## 背景

2026-07-10、Codex（新モデル）による集客分析で提案された施策。「一度来た人を翌週も戻す仕組みが不足している」という指摘に対応する。

現状、応援チーム機能自体（`components/favorite-teams-banner.tsx`・`components/team-picker.tsx`・`components/user-menu.tsx`・`app/api/user/profile/route.ts`）は既に実装済みだが、以下の課題がある:
- `FavoriteTeamsBanner` はホームページで表示されるが、`sessionStorage` で一度dismissすると同一セッション内は再表示されない、控えめな案内バナーに留まっている
- 応援チーム設定自体は `components/user-menu.tsx`（ユーザーメニュー内）に隠れており、新規訪問者の目に触れにくい
- 応援チーム登録・Push許可・再訪といった「継続利用の兆し」を示すイベントがGA4で計測されていない（`lib/analytics.ts` の `trackCtaClick` はCTAクリックのみ計測）

## スコープ

対象:
- ホームページの応援チーム未登録ユーザー向け案内（`FavoriteTeamsBanner`）を、単なる案内バナーから「このチームを応援する」ボタン付きのオンボーディング的な導線に強化する（具体的なUI強化はCodexの判断に委ねるが、「登録が主要な行動として目立つ」ことが目標）
- 試合詳細ページ・チームページに「このチームを追う」ボタンを追加し、応援チーム登録への入口を増やす
- `lib/analytics.ts` に新しいイベント計測関数を追加する: 応援チーム登録（`favorite_team_added`）・Push通知許可（`push_permission_granted`）・再訪（`return_visit`、既存ユーザーが7日以内に再度訪問した場合）
- 上記イベントをGA4ダッシュボードで確認できるようにする

対象外:
- オンボーディングフロー全体の新規ページ化（現状のバナー・メニュー内設定を強化する形に留め、専用の `/onboarding` ページ等は作らない）
- レコメンドロジック（応援チームに基づく試合の並び替え自体は既存のホームページ表示ロジックを使う。新しいレコメンドアルゴリズムの開発は対象外）

## データモデル変更

なし（既存の応援チーム・Push購読の仕組みをそのまま使う）。

## API サーフェス

なし（既存のAPIルートをそのまま使う）。

## UI サーフェス

- ホームページの `FavoriteTeamsBanner` を強化し、目立つ位置・デザインで応援チーム登録を促す
- 試合詳細ページ・チームページに「このチームを追う」ボタンを追加
- `return_visit` イベントの検知方法（例: 前回訪問からの経過日数をローカルストレージ/Cookieで判定）はCodexの実装判断に委ねる

## 受け入れ条件

1. ホームページの応援チーム未登録ユーザー向け導線が、既存のバナーより目立つ形に強化されている
2. 試合詳細ページまたはチームページに「このチームを追う」ボタンがあり、クリックすると応援チーム登録が完了する
3. `favorite_team_added`・`push_permission_granted`・`return_visit` の3イベントがそれぞれ適切なタイミングでGA4に送信される（`trackEvent` 経由）
4. 既存の応援チーム機能・Push購読機能に回帰がない
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本番デプロイはOwner承認後に別途行う

## 未解決の質問

- `return_visit` イベントの具体的な検知ロジック（何日以内の再訪を「継続利用」とみなすか）はCodexの判断に委ねる。迷う場合は完了報告で質問として提示する
- 応援チーム登録の初期KPI（登録5人・Push許可3人・2週目再訪2人等の絶対数目標）はOwnerが別途GA4で確認する運用とし、本spec自体には数値目標を実装しない
