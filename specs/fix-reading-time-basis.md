# fix-reading-time-basis

> GPT-6 監査 A-3 7（P2）。読了時間の算出対象が本文と一致していない。

## 背景

`components/match-content-section.tsx:63-67` の算出はこうなっている。

```ts
const readingMinutes = content
  ? language === "en"
    ? Math.max(1, Math.ceil(content.contentMdJa.split(/\s+/).length / 220))
    : Math.max(1, Math.ceil(content.contentMdJa.length / 500))
  : null;
```

**問題は 2 つ。どちらも「表示している分数が、読者が読む本文と対応していない」ことに帰着する。**

### (1) Markdown 記法を文字数に数えている

日本語側は `contentMdJa.length` をそのまま 500 で割る。`content_md` は **Markdown 原文**であり、`#` `**` `[表示](URL)` などの記法・URL 文字列が全部カウントされている。読者が読む文字数ではない。

### (2) 有料部分が対象から外れている

`readingMinutes`（`:63`）は `content.contentMdJa` **だけ**を見る。`lockedContentMd` は同じコンポーネントが受け取っており（`:18` の型宣言、`:44` の分割代入）、`:114` で子へ渡しているのに、**読了時間には加算されていない**。

結果として Premium 記事では、**無料部分だけの分数が記事全体の分数として表示される。** ラベルは「分で読める」で、対象範囲を示していない。

監査の指摘（原文）: 「「2分」「4分」は本文量の推定値で、実際の読了実績ではない。プレビュー展開や有料部分で対象も変わる。」「P2: 「約○分」、対象本文・算定文字数を揃える。出典・タイムラインを読了分数へ無条件に足さない。」

### 誤りでないこと（調査済み・spec 化しない）

英語分岐が `contentMdJa` を使っているのは**バグではない**。`contentMdJa` は `lib/db/queries/match-content.ts:67` で `row.content_md` を写しただけの名前で、言語は `match_content.language` の別列である。英語記事は英語本文が `contentMdJa` に入る。**「日本語テキストを空白分割している」わけではない。**

## スコープ

対象:
- 算出対象を Markdown 記法でなく本文へ揃える
- 有料部分を含めるかどうかを決め、**表示が対象範囲と一致する**ようにする
- 推定値であることが分かる表記にする
- テスト

対象外:
- **実際の読了実績の計測**。それは A-3 1（計測先行）の範囲
- `parseMarkdown`（`lib/` の既存パーサ）の挙動変更
- **出典・タイムラインを読了分数へ足すこと。** 監査が明示的に禁じている
- 英語側の 220 words/min、日本語側の 500 文字/分という**速度定数の変更**
- 読了時間の表示位置・デザイン

## 変更詳細

### 1. 算出対象

Markdown 記法を除いた本文の長さで算出する。**`parseMarkdown` の結果を使えば記法は落ちる**（`:60` で既に呼んでいる）。新しいパーサを書かないこと。

### 2. 有料部分の扱い

次のどちらかに揃える。**表示と対象が一致していればどちらでもよい。**

| 方針 | 表示 |
|---|---|
| 記事全体 | `lockedContentMd` を加算する。ロック中も「記事全体で約○分」と分かる |
| 無料部分のみ | 加算しない。**無料部分の分数であることが分かる表記にする** |

**現状のように「加算せず、全体の分数のように見せる」ことだけは避ける。**

`lockedContentMd` は `lockedLoading` 中は未取得である（`:19` の型と `match-content.tsx:386` の分岐）。**読み込み中に分数が飛ぶ表示にしないこと。**

## 受け入れ条件

1. Markdown 記法（`#` / `**` / `[表示](URL)`）を含む本文で、**記法文字が分数に寄与しない**ことを検証するテストがある
2. URL を含む本文で、URL 文字列が分数に寄与しないことを検証するテストがある
3. `lockedContentMd` がある記事で、**表示と算出対象が一致している**ことを検証するテストがある
4. `lockedLoading` が true の間、分数が不安定に変化しないことを検証するテストがある
5. `content` が null のとき、現状どおり分数を表示しないことを検証するテストがある
6. 空文字・記法のみの本文で **1 分未満にならない**（`Math.max(1, ...)` の維持）ことを検証するテストがある
7. 推定値であることが分かる表記になっている
8. **速度定数（英語 220 / 日本語 500）に差分が無い**
9. **出典・タイムラインが分数に加算されていない**
10. 英語記事で `split(/\s+/)` による語数算出が維持されている
11. `pnpm lint` / `pnpm typecheck` / `pnpm test` が green

**テストの置き場所**: `tests/components/` 配下（`exclude` 非該当。確認済み）。
