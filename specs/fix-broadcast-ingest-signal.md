# 放送情報取り込みの通知を意味のあるものにする

## 背景

`cron-ingest-broadcasts` が 2026-09-12 から 10 日連続で HTTP 500。
ただしクラッシュではなく、`app/api/cron/ingest-broadcasts/route.ts` の設計である。

```ts
const hasRemainingWork = result.unlinkedPages.length > 0 || result.matchesStillMissing.length > 0;
const status = result.linked.length === 0 && hasRemainingWork ? 500 : 200;
```

**`linked` の対象は 14 日窓ではない。** `loadScheduledMatches` は
現在時刻以降・一覧ページの年の年末までの `scheduled` 試合を取る。
14 日窓が掛かるのは `matchesStillMissing`（欠損監視）だけである。

したがって現在の 500 の意味は「**JRFU に今後の試合の放送情報が 1 件も無い**」。
JRFU は日本代表戦しか載せないため、日本代表戦の放送欄が全部空の期間は必ず 500 になる。

### 何が問題か

**赤が常態なので信号として機能しない。** 10 日間赤だったが誰も気づかなかった。
そして今まさに、**11月の日本代表 3 試合の放送情報が JRFU に載ったかどうかを、この仕組みでは判別できない**。

さらに 3 点、現状の設計に穴がある。

1. **`linked` は新規追加件数ではない。** 既存と同じ行の upsert も毎日カウントされる。
   1 行あれば他が全部欠けていても 200 になるので、「緑＝全部埋まった」も成り立たない
2. **個別 JRFU ページの処理失敗は `console.error` だけで結果に残らない。**
   欠損判定を単純に 200 へ変えると、実際の取得失敗を今より見逃す
3. **正常な「放送未発表」と構造破損が同じ 500 で潰れている**

## スコープ

対象:
- `app/api/cron/ingest-broadcasts/route.ts` のステータス判定
- `lib/broadcasts/ingest.ts` の結果構造と欠損監視の範囲
- 通知内容（`notifyBroadcastIngestReport`）
- 上記のテスト

対象外:
- 新規スクレイパーの追加（WOWOW 等）。別途 Owner 判断
- JRFU パーサ本体。2026-09-22 の検証で照合ロジックは正常と確認済み
- クラブ大会の放送情報を埋めること（情報源が存在しない）
- 新規の監視ジョブ・永続ハッシュ表の追加

## 実装方針

### 1. ステータスの意味を作り直す

| 状態 | HTTP |
|---|---|
| 取得・解析・DB 書き込みが成功。変更なし | 200 |
| 日本代表戦の放送欄が正常に空 | 200 |
| 日本代表戦の放送行が新規追加／変更された | 200 |
| 未知サービス、または候補 0 件・複数件で紐付け不可 | 200 |
| **取得失敗・必須構造の解析失敗・DB 失敗・通知送信失敗** | **500** |

**500 は技術障害のときだけ。** 「放送がまだ発表されていない」は正常である。

### 2. 欠損監視を日本代表戦に絞る

取得・照合の対象範囲（年末まで）は**変えない**。
`matchesStillMissing` の判定だけを
`home.slug === "japan" || away.slug === "japan"` かつ 14 日以内に絞る。

日本代表戦の対象が 0 件なら、クラブ大会が何試合空でも欠損警告を出さない。
現在 14 日以内で放送情報が無いのは URC 16・Premiership 10・Top 14 7 の計 33 試合だが、
**JRFU はこれらを載せないので永久に埋まらない。監視対象にする意味がない。**

### 3. 変化を検知して通知する

新規ジョブは作らない。**既存の毎日 12:15 JST の実行の中で、
登録前の既存放送行と取得結果を比較する。**

- 比較キーは 試合 ID × 正規化サービス名。比較する値は `kind` と `url`
- **`verified_at` だけの更新は変化と数えない**（同じ候補の毎日 upsert を毎日「新規」と通知しない）
- 通知するのは、初めて視聴先が入った試合・追加されたサービス・`url` / `kind` の変更
- 手動登録済みと同じ情報が JRFU に載っただけの場合は、新規追加として通知しなくてよい
- **JRFU 側から案内が消えた場合、自動削除しない。** Owner の再確認対象として通知する。
  空欄は提供終了の証拠ではない
- 個別ページの取得・解析失敗を結果に残す。部分成功でも隠さない

## 受け入れ条件

1. 14 日以内の欠損がクラブ大会のみ（日本代表戦の欠損 0 件）のとき、HTTP 200 を返し、
   欠損警告を出さない。
2. 14 日以内に日本代表戦があり放送情報が未発表のとき、HTTP 200 を返し、
   **当該試合を要確認として通知する**。
3. 14 日より先の日本代表戦に放送情報が新規追加された場合も取り込まれ、通知される。
   （11月の 3 試合は 9 月時点で 14 日窓の外にあるため、これが無いと今回の目的を満たさない）
4. 同一内容で 2 回続けて取り込んだとき、重複行が増えず、2 回目に新規通知が出ない。
5. `url` または `kind` の変更は通知される。`verified_at` の更新だけでは通知されない。
6. 1 ページの取得・解析が失敗したとき、他が成功していても**その失敗が結果に残る**。
   DB 書き込み失敗・通知送信失敗は HTTP 500。
7. 未知サービス、候補 0 件・複数件の場合、DB へ書き込まれず要確認として残る。
8. 手動投入済みの行と JRFU の表記ゆれで重複を作らない。
   手動行があるだけで誤った「新規登録」通知を出さない。
9. 日付当日・翌日の照合（`allowedJstDates`）、対象外日付の拒否、
   日本代表戦以外への誤結合防止は現行どおり維持される。
