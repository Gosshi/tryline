# feat-youtube-embed-allowlist

## 背景

Ownerから「試合ハイライトやニュース動画をYouTube埋め込みで表示できないか」という提案があり、GPT-5.6が著作権面を調査した（2026-07-20）。結論: 公式YouTube埋め込みプレイヤーの利用自体は、YouTubeの通常の再生機能の範囲内であれば技術的に可能。ただし「埋め込み可能に設定されている」ことは動画自体の著作権者からの再配信許諾を意味しない。World Rugby・大会主催者・協会・公式放送局等の**公式チャンネル**の動画に限定し、ファン転載動画は対象外とする運用が現実的、との整理。

本specは、この運用ルールを技術的に強制できる**埋め込みコンポーネントと許可リストの基盤**を実装する。**どのページのどの位置に埋め込みを表示するかという具体的な配置は本specのスコープ外**とし、まず安全に使える土台を作る。

## スコープ

対象:
- 公式チャンネルのみを許可する `YOUTUBE_ALLOWED_CHANNEL_IDS`（または同等の許可リスト）を `lib/` 配下に新設する。初期リストはWorld Rugby公式チャンネル等、Ownerが指定する最小限のチャンネルIDのみとする（未確定の場合は空配列でスタートしてよい。実際の追加はOwnerが行う）
- YouTube動画IDを受け取り、以下を満たす埋め込みコンポーネント（例: `components/youtube-embed.tsx`）を実装する:
  - 公式の `<iframe>` 埋め込み（`youtube-nocookie.com` ドメインを優先し、プライバシー強化モードを使う）
  - 自動再生しない（クリックしてから読み込むlazy-load形式。サムネイル表示→クリックでiframe読み込みという2段階にする）
  - Player純正のロゴ・帰属表示・操作UIを隠さない（CSSでの上書き禁止）
  - 動画IDに対応するチャンネルIDが許可リストに含まれない場合は埋め込みを表示せず、YouTubeへの通常リンクにフォールバックする（チャンネルID確認の実装方法は、oEmbed API等を使うか、事前にDBへ記録するか、実装時に検討する）
  - 地域制限・埋め込み無効化されている動画の場合も同様にリンクへフォールバックする
- 動画メタデータ（動画ID・チャンネルID・確認日時）を記録する仕組みを用意し、削除要請等への対応（該当動画の埋め込み停止）が容易にできるようにする
- `next.config.ts` 等、YouTube埋め込みに必要な設定（CSP・iframeのallow属性等）を確認・追加する

対象外:
- 実際にどのページ（試合ページ・ニュースitem等）のどの位置に埋め込みを配置するかの決定（別途Owner判断・別specで対応）
- YouTube Data APIを使った動画検索・自動選定機能（本specは手動で選んだ動画IDを埋め込む前提の基盤のみ）
- プライバシーポリシーの文言更新（Owner側で別途対応）

## API サーフェス

新規テーブルが必要な場合、以下の情報を保持する想定（実装時に既存のマイグレーション運用に従う）:

- `video_id`: YouTube動画ID
- `channel_id`: 動画の投稿チャンネルID
- `title`: 動画タイトル（表示用、任意）
- `verified_at`: 許可リスト照合を確認した日時
- `context`: 埋め込み先（試合ID等、将来の配置決定時に紐づけるための参照。本spec時点では未使用でもよい）

## 受け入れ条件

1. 許可リストに含まれないチャンネルの動画IDを渡した場合、埋め込みではなくYouTubeへのリンクが表示されることを確認するテストがある
2. 許可リストに含まれるチャンネルの動画IDを渡した場合、クリック前はサムネイル表示のみで、自動再生されないことを確認するテストがある
3. クリック後に `youtube-nocookie.com` ドメインの `<iframe>` が読み込まれることを確認するテストがある
4. Player純正のUI・ロゴを隠すCSSが適用されていないことをコードレビューで確認する
5. `pnpm test` / `pnpm tsc --noEmit` / `pnpm lint` / `pnpm build` が通る

## 未解決の質問

- 初期許可リストに含める具体的なチャンネルID（World Rugby公式等）はOwnerが確認・指定すること
- チャンネルID照合の実装方式（YouTube oEmbed API呼び出し vs 事前DB記録）はCodexの裁量とするが、外部API呼び出しを追加する場合はレート制限・キャッシュを考慮すること
- 実際の埋め込み配置（試合ページのハイライトセクション等）は別途spec化が必要
