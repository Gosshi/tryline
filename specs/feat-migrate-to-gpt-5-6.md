# 生成モデルの GPT-5.6 系への移行

## 背景

Tryline の記事生成は `gpt-4o`（2024年8月版）を使い続けている。2026-08-07 時点で2年前のモデルであり、生成物に品質の問題が現れている。

- `fact_ja`（日本語訳）に**簡体字が混入**する（「花園ラグビー場」→「花**园**ラグビー場」）
- 誤訳が発生する（`solid effort` →「細かい努力」、`closely contested` →「細かいスコアで競り合い」）
- QA の `japanese_quality` が 4/5 止まり
- 本文の見出しが「攻撃力と守備力の対比」「最近の試合から見る勢い」のように統計名の羅列に収束しがち

同時期に、プレビューが薄い（日本語で1,500字の下限に対し実測平均715字）原因を調査した。外部ソースの枯渇とラインナップ不在という材料側の問題が主因だが、**同じ材料からどれだけ引き出せるかはモデルに依存する**ため、モデル更新は独立した改善レバーになる。

材料側の改善は規約制約とデータ空白でほぼ道が閉じており（`fix-sourced-facts-purge-prohibited-domains.md` を参照）、モデル更新は現時点で最も実行可能な打ち手である。

### 実験で判明した移行の障壁（2026-08-07 実施）

`lib/llm/models.ts` を `gpt-5.6-terra` に差し替えて実際に生成を試みたところ、次のエラーで失敗した。

```
Unsupported parameter: 'temperature' is not supported with this model.
```

**モデル ID 自体は有効である。** API が「model not found」ではなく具体的なパラメータエラーを返したため、モデルの存在とアクセス権は確認できている。

**GPT-5.6 系は `temperature` を受け付けない。** 現行実装は7箇所で `temperature` を渡しており、モデル ID の差し替えだけでは移行できない。

| 箇所 | 値 |
|---|---|
| `lib/llm/pipeline.ts:296` | ナラティブ生成 |
| `lib/llm/pipeline.ts:434` | 加筆リトライ |
| `lib/llm/stages/extract-facts.ts:79` | 0.2 |
| `lib/llm/stages/qa.ts:640` | 0 |
| `lib/llm/stages/verify-entities.ts:157` | 0 |
| `lib/llm/sourced-facts/fetch.ts:342` | 0 |
| `lib/llm/openai.ts:36` / `60` | ラッパー（`createWebSearchJsonResponse` は既定値 0 のため**未指定でも必ず送信される**） |

### 価格（2026-08-07 に OpenAI 公式価格ページで確認）

100万トークンあたり USD。

| モデル | Input | Cached Input | Output |
|---|---:|---:|---:|
| `gpt-5.6-sol` | 5.00 | 0.50 | 30.00 |
| **`gpt-5.6-terra`** | **2.00** | **0.20** | **12.00** |
| **`gpt-5.6-luna`** | **0.20** | **0.02** | **1.20** |
| （現行）`gpt-4o` | 2.50 | 1.25 | 10.00 |
| （現行）`gpt-4o-mini` | 0.15 | 0.075 | 0.60 |

`gpt-5.6-terra` は入力単価が現行 `gpt-4o` より**安く**（$2.00 対 $2.50）、出力が1.2倍になるだけである。プレビューは入力（試合データ・統計・sourced facts・プロンプト）が大きく出力が1,000〜1,500字と小さい構造のため、総コストはほぼ横ばいか低下が見込まれる。キャッシュ入力が $0.20 と現行の1/6である点も効く（プロンプトの大半は毎回同一）。

`gpt-5.6-sol` は出力が現行の3倍。今回の課題は推論力ではなく文章品質と材料活用であるため、最上位は採用しない。

## スコープ

対象:
- `lib/llm/models.ts` のモデル ID 更新
- `temperature` を送らないようにする API 呼び出しの修正
- `lib/llm/pricing.ts` への新モデル価格の追加とフォールバック挙動の是正
- 移行前後の生成物を比較できる形での検証

対象外:
- プロンプト本文の変更（モデル差の効果を切り分けるため、プロンプトは据え置く）
- QA の合格基準・文字数要件の変更
- sourced facts の収集ロジック・許可ドメインの変更
- AI チャット（`app/api/chat/[matchId]/route.ts`）のモデル変更。挙動特性が異なるため別途判断する
- 既存コンテンツの一括再生成（未解決の質問へ）

## データモデル変更

なし。`match_content.model_version` には新しいモデル ID が記録されるようになるが、スキーマ変更は不要。

## API サーフェス

### 1. モデル ID の更新

`lib/llm/models.ts`

| 定数 | 現行 | 移行後 |
|---|---|---|
| `NARRATIVE` | `gpt-4o` | `gpt-5.6-terra` |
| `WEB_SEARCH` | `gpt-4o` | `gpt-5.6-terra` |
| `FAST` | `gpt-4o-mini` | `gpt-5.6-luna` |

`WEB_SEARCH` を terra にするのは、ここが `fact_ja` を生成しており日本語品質の起点になっているため。簡体字混入と誤訳はこの経路で発生している。

### 2. `temperature` の送信停止

`lib/llm/openai.ts` の `createTextResponse` と `createWebSearchJsonResponse` が `temperature` を送らないようにする。

- `temperature` を受け取らないシグネチャに変更するのが望ましい。呼び出し側に引数が残っていると、将来また送信されうる
- 呼び出し7箇所から `temperature` の指定を除去する
- `createWebSearchJsonResponse` の既定値 `0` は特に注意。未指定でも送信されるため、除去し忘れると移行が失敗する

`temperature` に依存していた決定性（`0` 指定）は失われる。QA・事実抽出・実体検証は決定的であることが望ましい処理であり、出力揺れが増える可能性がある。移行後の挙動は検証で確認する。

### 3. 価格表の更新

`lib/llm/pricing.ts` に3モデルを追加する。

**`normalizeModelForPricing` の修正は必須。** 現行実装は未知のモデル ID をすべて `gpt-4o` へフォールバックするため、放置すると新モデルのコストが誤って計算され、コストアラートが静かに誤った値を出し続ける。

- 既知のモデルに一致しない ID が渡された場合、無言で `gpt-4o` を返さないこと
- 未知のモデルは警告を出す、あるいは型で表現するなど、気づける形にする

キャッシュ入力の単価は現行の計算式に入っていない。本 spec では入力・出力のみを扱い、キャッシュ単価の反映は未解決の質問に回す。

## UI サーフェス

なし。

## LLM 連携

本 spec そのものがモデル移行である。プロンプト・QA 基準・パイプラインの段構成は一切変更しない。**変数をモデルだけに限定することで、効果を切り分ける。**

## 受け入れ条件

1. `lib/llm/models.ts` が `gpt-5.6-terra`（NARRATIVE / WEB_SEARCH）と `gpt-5.6-luna`（FAST）を指している。
2. `lib/llm/openai.ts` の両ラッパーが `temperature` を送信しない。`createWebSearchJsonResponse` の既定値 `0` が除去されている。
3. 呼び出し7箇所から `temperature` の指定が除去されている。リポジトリ全体で `temperature` の grep が0件になる。
4. `lib/llm/pricing.ts` に `gpt-5.6-terra` / `gpt-5.6-luna` / `gpt-5.6-sol` の単価が入っている。値は背景の表と一致すること。
5. `normalizeModelForPricing` が未知のモデル ID を無言で `gpt-4o` にフォールバックしない。未知の ID が渡されたことに気づける実装になっている。テストで検証されている。
6. プレビュー1件を実際に生成でき、`Unsupported parameter` エラーが出ない。
7. プロンプト本文・QA 合格基準・文字数要件に変更がない。
8. AI チャットのモデルが変更されていない。
9. `pnpm lint` / `pnpm tsc --noEmit` / `pnpm test` / `pnpm build` がすべて clean。

## 未解決の質問

1. **`temperature` 以外の API 差分が未確認。** 今回の実験は `temperature` で止まったため、その先に別の非互換があるかは分かっていない。実装時に1件生成して確認すること。エラーが出たらそこで止めて報告すること。

2. **決定性の喪失をどう扱うか。** QA・事実抽出・実体検証は `temperature: 0` で決定的に動かしていた。GPT-5.6 系でこれが指定できないため、同じ入力でも判定が揺れる可能性がある。捏造ガードの安定性に影響しうるため、移行後に同一コンテンツで QA を複数回実行し、判定が揺れないかを確認する価値がある。

3. **キャッシュ入力単価が計算式に反映されていない。** `gpt-5.6-terra` のキャッシュ入力は $0.20 と通常入力の1/10で、プロンプトの大半が毎回同一な Tryline では効果が大きい。正確なコスト把握のためには対応が要るが、本 spec の範囲外とする。

4. **既存コンテンツを再生成するか。** 移行後に旧モデルで生成された記事が残る。全件再生成はコストと事故リスク（2026-06-12 に297件が draft 化した前例あり）があるため、まず新規生成分で品質を確認してから判断する。

5. **効果測定の方法。** 8/8 日本×オーストラリア戦（match_id `2c276057-bb3a-4617-a5b1-b7742e65f034`）は現行モデルで582文字・`japanese_quality` 4 という実測値がある。同じ試合を新モデルで生成して比較するのが最も分かりやすい。材料（sourced facts 4件）は同一条件のため、差分はモデル由来と判断できる。
