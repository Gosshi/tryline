# 大会解説ショート動画パイプラインの PoC

## 背景

Owner が YouTube Shorts の「1分でわかる◯◯」形式の解説動画を見て、Tryline でも同種のコンテンツが作れないか検討したいという相談があった。壁打ちの結果、以下の整理に至った。

- 動画コンテンツには2つの型がありうる。**型A**: 大会ごとに1本作れば良い「大会解説動画」（一度作れば大会ハブページに埋め込める評価SEO/滞在価値の強化）。**型B**: 毎週作る「週次まとめ動画」（フォローする理由を作る連載型コンテンツ、SNS成長施策）。
- `specs/fix-sns-short-video-expansion.md` に既存の決定がある: 「実装タイミング: X フォロワーが 1,000 人を超えた段階で検討開始すること」。現在の X フォロワーは 3 人であり、型B（SNS成長目的の動画連載）はこのゲートの対象内のため、今は着手しない。
- 本 spec は **型A（SEO/オンページコンテンツとしての大会解説動画）の PoC に限定**する。型Bの週次運用化・TikTok/Instagram/YouTube への実投稿は、引き続き `fix-sns-short-video-expansion.md` のゲート（Xフォロワー1,000人）の対象のままとする。本 spec の実施はこのゲートを解除するものではない。
- PoC の目的は「毎週続けられるか」ではなく、**「LLM 台本生成 + TTS + 画像連番 + 動画合成を自動化した場合、Owner が数分の目視チェックだけで公開できる品質に届くか」を1本の試作で検証すること**。

## スコープ

対象:
- 大会1つ（例: 現在進行中の Nations Championship 2026、または既にデータが揃っている大会）を題材に、「1分でわかる◯◯」形式の縦型ショート動画を1本、パイプラインで自動生成する
- パイプライン構成: ① 台本生成（LLM） → ② TTS音声化 → ③ 画像スライド生成 → ④ 動画合成（音声・画像・任意で字幕を1本のMP4に結合）
- 生成物はローカルファイル（MP4）として出力し、Owner が目視で品質評価する

対象外:
- 型B（週次まとめ動画）の自動化・定期運用化。`fix-sns-short-video-expansion.md` のゲート（Xフォロワー1,000人）の対象のまま
- TikTok / Instagram / YouTube 等への実際の投稿・API連携
- 複数大会・複数動画への横展開（本 PoC で品質確認後、別 spec で検討）
- 大会ハブページ（`/c/[competition]/[season]`）への動画埋め込みUI（品質確認後、別 spec で検討）
- `match_content` 等 DB スキーマの変更・動画メタデータの永続化（PoC はファイル出力のみで良い）
- cron 等による自動トリガー化

## データモデル変更

なし。PoC は CLI スクリプトの実行結果をローカルファイル（台本テキスト・MP4）として出力するのみで、DB への書き込みは行わない。

## API サーフェス

なし。CLI スクリプト（例: `scripts/generate-competition-explainer-video.ts`、`tools/run-ts.cjs` 経由で実行する既存パターンに従う）として実装する。

## UI サーフェス

なし（PoC の範囲では UI 組み込みを行わない）。

## LLM 連携

- **台本生成**: `MODELS.NARRATIVE`（`lib/llm/models.ts`）を使用。大会の既存データ（`competitions`・`matches`・順位表等、DB実測のみ）から、60秒程度で読み上げ可能な尺（日本語ナレーションとして目安200〜300字程度）の台本を生成する。数値・チーム名・日程等は既存DBデータの範囲内に限定し、LLMによる補完・捏造を許さない（既存の fabrication-guard 相当のチェック方針を踏襲すること）
- **TTS**: OpenAI TTS API を新規導入する。`lib/llm/models.ts` に `MODELS.TTS` として追加すること（モデルIDの直書き禁止、既存の集中管理パターンを踏襲）
- **新規依存関係の可能性**: HTML→画像のレンダリングに headless browser（例: Playwright）を、画像+音声→動画の結合に ffmpeg（CLI呼び出し or Node ラッパー）を要する可能性が高い。これらは現時点で `package.json` の依存関係に含まれていない（`ffmpeg` はローカル環境に Homebrew で入っているのみで、実行環境に依存する）。新規依存追加が必要な場合は完了報告で明示すること
- **コスト見積もり**: 台本生成（gpt-4o、入力少・出力300字程度）で1本あたり$0.01未満。TTS（`tts-1`、$15/100万文字換算）で300字なら$0.005未満。動画合成はローカル処理でLLM費用なし。**PoC 1本あたり合計 $0.05 未満**を上限の目安とし、これを超える場合はログに警告を出す

## 受け入れ条件

1. `node --env-file=.env.local tools/run-ts.cjs scripts/generate-competition-explainer-video.ts --family=<family> --season=<season>` を実行すると、台本生成 → TTS → 画像連番生成 → 動画合成が一気通貫で実行され、最終的に1本のMP4ファイルがローカルに出力される
2. 出力動画は60秒以内、縦型（9:16、例: 1080×1920）、日本語音声ナレーション付きである
3. 台本テキストが別途ログまたはファイルに出力され、含まれる数値・チーム名・日程等がDB実測値と突合できる形になっている（目視でのファクトチェックを容易にするため）
4. 生成コストの概算がログに出力され、$0.05 を超えた場合は警告が表示される
5. `pnpm tsc --noEmit` / `pnpm lint` / `pnpm test` / `pnpm build` が通る
6. 本 spec の完了は PoC の1回の試作生成までとする。動画の品質評価は Owner が目視で行い、型Bの運用化や `fix-sns-short-video-expansion.md` のゲート見直しを検討するかは Owner 判断とし、本 spec の対象外とする

## 未解決の質問

- TTS の音声（ボイス）選定は Codex の実装判断に委ねる。日本語ナレーションとして自然なものを選ぶこと
- 画像スライドのデザイン・枚数は、既存の `x-post` スキルのデータ画像デザイン方針（`app/globals.css` の CSS変数を使う、システムフォントで日本語表示崩れを防ぐ等）を踏襲することとし、詳細な枚数・構成は Codex の実装判断に委ねる。迷う場合は完了報告で質問として提示する
- 動画合成に ffmpeg CLI を直接呼ぶか、Node 用ラッパーライブラリを使うかは Codex の判断に委ねる。追加の有料 SaaS 契約が不要な方法を優先する
- 題材とする大会（Nations Championship 2026 か、データがより安定している別の大会か）は Codex の実装判断に委ねる。迷う場合は完了報告で質問として提示する
